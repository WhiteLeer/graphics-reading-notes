# Real Time Markov Decision Processes for Crowd Simulation（用于实时人群模拟的马尔可夫决策过程）

## 章节内容

本章讨论如何使用马尔可夫决策过程（MDP）控制实时人群。MDP 根据 Agent 当前状态、可执行动作、环境转移和奖励，选择下一步行动，并将决策系统与人群渲染结合起来。

作者：Sergio Ruiz 和 Benjamín Hernández

## 核心概念

MDP 通常由以下部分组成：

- **State**：位置、速度、目标、障碍物和邻近人群等当前信息；
- **Action**：前进、转向、减速、加速、等待或改变路径；
- **Transition**：执行动作后，Agent 如何进入新状态；
- **Reward**：接近目标、避开障碍、保持距离等行为的收益或代价；
- **Policy**：根据当前状态选择动作的策略。

马尔可夫假设是：下一步主要由当前状态和当前动作决定，不需要保存完整的历史轨迹。

## 人群模拟流程

```text
Agent 当前状态
    ↓
MDP 选择动作
    ↓
更新位置、速度和行为状态
    ↓
进入下一帧或下一次决策
    ↓
提交给人群渲染系统
```

决策系统需要处理目标选择、避障、邻居影响和拥挤程度；渲染系统则根据 Agent 的位置、方向、速度和状态生成动画与画面。

## 与 TA 的关系

MDP 本身主要属于 AI、Gameplay 或 Crowd Simulation Programming，并不是典型的 TA 核心算法。TA 更关注 MDP 输出的大量动态 Agent 如何被高效表现：

- GPU Instancing；
- 实例化动画和骨骼更新；
- Crowd LOD；
- 距离与遮挡剔除；
- 远处 Agent 的贴片、点或简化模型；
- 群体材质、阴影和特效；
- 人群模拟、动画和渲染之间的 Profiling。

因此可以将接口理解为：MDP 输出位置、方向、速度和状态，TA 负责把这些数据转换成稳定且高效的视觉表现。

## 客户端与服务器

单机游戏和普通背景人群通常可以直接在客户端运行 MDP。联网游戏中，重要角色的决策可能由服务器负责，客户端只接收位置和状态；而不影响游戏逻辑的背景人群通常仍可以本地模拟。

## 限制

- Agent 数量增加后，状态更新和邻域查询都会带来 CPU 或 GPU 成本。
- 奖励函数和策略设计会直接影响人群行为质量，可能出现拥挤、振荡或不自然绕行。
- 决策频率、动画更新频率和渲染帧率不一定相同，需要合理解耦。
- MDP 解决的是行为决策，不会自动解决动画表现、实例化和渲染性能问题。

## 本章结论

MDP 是一种用于人群行为决策的框架：根据当前状态选择动作，再通过环境转移进入新状态。它本身偏 AI/客户端逻辑；对 TA 的主要价值在于定义与人群渲染系统的接口，并推动实例化、LOD、剔除、动画和性能优化。
