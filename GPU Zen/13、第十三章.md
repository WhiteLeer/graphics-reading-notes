# Efficient Stereo and VR Rendering（高效立体与 VR 渲染）

## 章节内容

本章讨论 VR 应用中的立体渲染和性能优化。VR 不只是把同一画面渲染两遍，而是要为左右眼生成略有差异的视图，同时满足较高刷新率、低延迟和稳定帧时间的要求。

作者：Iñigo Quílez

## 核心思路

### 左右眼视图

左右眼需要不同的观察位置和投影参数，但场景、材质、纹理和大部分可见性信息通常是共享的。优化的关键是区分必须按眼睛执行的部分，以及可以复用的部分。

### 渲染管线复用

几何处理、可见性判断、资源准备和部分着色逻辑可以通过多视口、实例化或单次多视图提交来减少重复工作。最终仍然要生成左右眼各自的图像，但不必让 CPU 完全重复组织两套渲染命令。

### VR 的性能约束

VR 对帧率和延迟非常敏感。偶发的长帧、左右眼不同步或过高的 CPU 提交成本都可能造成明显的不适，因此目标不只是提高平均 FPS，还要控制最坏帧时间和运动到显示的延迟。

## 主要取舍

- 双眼完全独立渲染实现简单，但几何、光栅化和着色成本接近翻倍。
- 共享或多视图渲染可以减少 CPU 和部分 GPU 工作，但需要图形 API、引擎和 Shader 支持。
- 过度复用可能造成左右眼投影、视差或遮挡处理错误，不能简单把一只眼睛的最终图像复制给另一只眼睛。

## 限制

- 左右眼视图存在视差，深度相关和屏幕空间效果通常仍需要分别处理。
- 共享计算的收益取决于场景、GPU 架构和 API 实现，不能假设所有阶段都能合并。
- VR 渲染优化必须同时考虑画质、帧时间、延迟和双眼一致性。

## 本章结论

VR 立体渲染的核心不是简单地把普通渲染复制两遍，而是识别左右眼之间可复用的工作，并通过多视图、实例化或管线复用降低重复成本，同时保证低延迟和稳定帧时间。
