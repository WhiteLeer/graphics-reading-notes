# Optimizing the Graphics Pipeline with Compute（使用 Compute 优化图形管线）

## 章节内容

本章讨论如何将传统图形管线之前的大量筛选和组织工作迁移到 Compute Shader，在 GPU 上完成剔除、压缩、重排和间接绘制参数生成，从而减少 CPU 提交压力以及固定管线处理的无效几何。

作者：Graham Wihlidal

## 核心思路

传统流程通常由 CPU 负责剔除物体、统计可见数量、组织 DrawCall 并逐个提交。GPU-driven 流程则由 CPU 准备场景数据并提交少量 Compute/Indirect 命令，Compute Shader 在 GPU 上生成最终的间接绘制参数。

```text
CPU 准备场景数据
    ↓
GPU Compute：剔除、压缩、重排
    ↓
生成 Indirect Draw 参数
    ↓
Graphics Pipeline 执行有效绘制
```

## 主要优化对象

### Draw Association

将场景组织成 Batch、Mesh Section 和 Work Item，使 Compute Shader 能够按硬件友好的块处理三角形，并在后续生成间接绘制参数。

### Draw Compaction

剔除后删除没有剩余三角形的空 Draw，避免 Command Processor 仍然读取和解析大量零大小间接绘制。有效 Draw 被压缩到连续的输出缓冲区，再通过 `ExecuteIndirect` 或类似 API 执行。

### Cluster 与 Triangle Culling

先按 Cluster 做粗粒度剔除，再对三角形做细粒度剔除。常见测试包括背面、屏幕外、小三角形和视锥剔除；有可用深度时，还可以使用 Hi-Z 或深度金字塔剔除被遮挡几何。

### Batch Scheduling 与 Async Compute

使用多个固定大小的输出缓冲区，让 Compute 剔除和 Graphics 绘制重叠执行。Compute 也可以与深度预 Pass、阴影、粒子或其他低强度渲染工作并行，但必须通过 Profiling 控制 CU 和内存带宽竞争。

### De-interleaved Vertex Buffers

将 Position、Normal、UV 等属性拆分为独立数据流，使只需要 Position 的 Pass 不必读取其他属性，从而减少带宽和缓存占用。它也方便 Compute 进行网格处理和不同 Pass 使用不同顶点布局。

### Compute Tessellation

将细分因子计算甚至部分细分流程放到 Compute 中，可以提前剔除不可见 Patch，并在多个 Pass 之间复用细分结果，减少无效细分和重复计算。

## CPU 是否还执行 DrawCall

DrawCall 并没有完全从 CPU 消失。CPU 仍需要提交少量 `ExecuteIndirect`、Vulkan indirect draw/count 或类似入口；只是每个 Draw 的可见性、数量和参数由 GPU Compute 动态生成，CPU 不再逐个组织和提交大量 DrawCall。

## 代价与限制

- Compute Culling 有固定成本，场景规模太小时可能得不偿失。
- 深度剔除依赖可靠的 Z Pre-pass、Hi-Z 或遮挡信息，收益高度依赖场景。
- 逐三角形剔除需要额外带宽、同步和间接参数管理。
- Async Compute 可能与 Graphics 争用计算单元和内存带宽。
- 本章重点针对 AMD GCN、Xbox One、PS4 和高端 AMD PC，其他 GPU 架构需要重新测量。

## 本章结论

本章的本质是把 DrawCall 之前的剔除、统计、压缩和组织从 CPU 迁移到 GPU；最终绘制仍由 Graphics Pipeline 执行，但由 GPU 生成的间接参数驱动。这是一套 GPU-driven Rendering 数据管线，而不是简单地用 Compute Shader 替代 Vertex Shader。
