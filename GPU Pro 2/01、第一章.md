# Terrain and Ocean Rendering with Hardware Tessellation（使用硬件细分渲染地形与海洋）

作者：Xavier Bonaventura  
来源：GPU Pro 2，Part I，Chapter 1，pp. 3–14。

## 核心问题

传统 LOD 需要 CPU 在不同距离之间切换不同网格，并不断把网格数据提交给 GPU。近处需要高细节，远处只需要低细节，但静态 LOD 切换容易产生跳变，也会增加 CPU 与 GPU 之间的数据传输。

本章使用 DirectX 11 的 Hull Shader、Tessellator 和 Domain Shader，在 GPU 上根据摄像机距离和观察角度动态生成地形与海洋的细分几何。

## DirectX 11 细分阶段

```text
Vertex Shader
    ↓
Hull Shader：处理控制点，计算边缘和内部细分因子
    ↓
Tessellator：固定功能阶段，按因子生成参数坐标
    ↓
Domain Shader：根据参数坐标重建最终顶点
    ↓
Geometry / Rasterization
```

Hull Shader 的输出分为两部分：修改后的控制点，以及供 Tessellator 和 Domain Shader 使用的 Patch 常量数据。Tessellator 不负责生成最终世界坐标，只负责按照 quad、triangle 或 isoline 域划分 Patch，并输出 `UV/UVW` 参数。Domain Shader 再根据这些参数计算位置、法线、颜色和纹理坐标。

## 地形 Patch 与细分因子

地形被划分为规则四边形 Patch。每个 Patch 需要计算四条边和内部的细分因子。共享同一条边的相邻 Patch 必须得到相同的边缘细分因子，否则会产生裂缝。

细分因子根据摄像机距离在最小值和最大值之间变化：

```text
近处 → 高细分
远处 → 低细分
```

地形使用整数且通常限制为 2 的幂次细分因子，以减少细分变化时的几何跳变。海洋是动态波面，使用非整数变化时视觉上的波动不明显，因此限制可以更宽松。

本章还对视角进行修正：同样距离下，面向摄像机的边缘和几乎侧对摄像机的边缘对屏幕贡献不同，因此细分因子不仅取决于距离，也取决于摄像机与 Patch 边缘方向的夹角。

## 地形的 Domain Shader 重建

地形使用高度图和法线图：

1. 用 Patch 控制点插值得到 `x/z` 位置；
2. 根据世界坐标访问高度和法线纹理；
3. 将高度写入 `y` 坐标；
4. 根据最终位置生成纹理坐标；
5. 根据摄像机距离选择合适的 Mip 级别。

Mip 级别也要保持 Patch 之间的一致性，否则细分过程中会产生跳变。共享顶点的 Patch 应使用相同的 Mip 级别，并在 Patch 内进行插值。

## 海洋的 Domain Shader 重建

海洋不依赖静态高度图，而是用多个参数化波叠加生成位置。单个波由波长、振幅、方向和时间决定，多个波的位移相加得到最终水面：

```text
最终位置 = 原始位置 + 波1位移 + 波2位移 + ...
```

海洋表面法线也可以直接从波函数求导得到，不需要额外读取法线纹理。这样生成的几何分辨率由 Tessellation 因子控制，能够随着摄像机距离和视角变化。

## 关键取舍

- 细分减少了 CPU 提交高精度网格的压力，但会增加 GPU 的细分和 Domain Shader 计算；
- 共享边必须使用一致的细分因子，否则会出现裂缝；
- 只有细分没有足够精度的高度图，无法凭空恢复真实地形细节；
- 高度图地形受纹理分辨率限制，函数表示的海洋可以在运行时生成更高分辨率的波面；
- 细分因子和纹理 Mip 级别需要协同变化，否则会出现纹理或几何跳变。

## 本章总结

硬件 Tessellation 的价值是只向 GPU 提交低分辨率控制网格，再根据摄像机距离、视角和表面函数在 GPU 上补充几何。它不是无条件地“增加细节”，而是把几何生成和 LOD 选择从 CPU 迁移到 GPU，并要求 Patch 连续性、Mip 一致性和细分成本得到控制。
