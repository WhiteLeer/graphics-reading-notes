# Hierarchical Item Buffers for Granular Occlusion Culling（用于细粒度遮挡剔除的层级 Item Buffer）

## 章节内容

作者：Thomas Engelhardt、Carsten Dachsbacher

本章介绍一种完全在 GPU 上执行的细粒度可见性查询方法。它基于 Item Buffer 和 Histogram，把渲染后的像素重新解释为实体 ID，再统计每个实体在屏幕中出现的次数，从而判断对象、实例、三角形批次或其他实体是否可见。

它解决的不是完整的 GPU Driven Rendering，而是 GPU Driven 管线中的一个重要子问题：如何以可配置粒度获得可见性结果，并把结果继续提供给 Geometry Shader、Tessellation Shader、LOD 或其他昂贵渲染阶段。

## 和 GPU Driven 的关系

GPU Driven 是更大的渲染架构：

```text
GPU 读取场景数据
→ GPU 剔除与 LOD
→ GPU 生成可见列表
→ GPU 生成间接绘制参数
→ GPU 执行绘制
```

本章的 Hierarchical Item Buffer 主要负责其中的可见性统计：

```text
实体 ID
→ Item Buffer
→ Histogram
→ 可见性计数或标记
```

它可以作为 GPU Driven 的遮挡查询和筛选组件，但本身不必然负责 Compact、Indirect Draw 或完整的 GPU 绘制调度。

## 为什么需要细粒度可见性

传统遮挡查询通常以一次 Draw Call 为粒度，只能回答整个绘制调用是否产生了可见像素。但现代渲染中一个 Draw Call 可能包含大量实例，因此还需要知道：

- 哪些实例可见；
- 哪些实例完全被遮挡；
- 哪些三角形批次可见；
- 某个物体在屏幕哪个区域可见；
- 是否值得执行昂贵的几何生成、细分或阴影体挤出。

如果每个实例单独提交 Draw Call 再执行 occlusion query，CPU 提交和同步成本会很高，也失去了 Instancing 的优势。

本章的方法允许一次性渲染大量实体，并在 GPU 上统计每个实体的可见像素数量。

## Item Buffer

Item Buffer 是一个与屏幕对应的缓冲。每个通过深度测试的像素不写普通颜色，而是写入一个实体 ID：

```text
像素位置        Item ID
(10, 20)    →   1
(11, 20)    →   1
(12, 20)    →   4
(13, 20)    →   4
```

实体可以是：

- 一个对象；
- 一个 Instanced Draw 中的单个实例；
- 一个三角形；
- 一批三角形；
- 一个自定义的渲染实体。

实体粒度由分配给像素的 ID 决定。

深度测试确保 Item Buffer 中最终保留的是当前可见表面的 ID，而不是被其他物体遮挡的实体。

## Histogram 统计

Item Buffer 生成后，需要统计每个 ID 出现了多少次。这个过程可以理解为 Histogram：

```text
Item Buffer：1, 1, 1, 4, 4, 7, 7, 7

Histogram：
ID 1 → 3 个像素
ID 4 → 2 个像素
ID 7 → 3 个像素
```

只要某个实体的计数大于零，就说明它至少有一部分出现在屏幕中。计数还可以用来估计屏幕覆盖率或作为 LOD、优先级等决策依据。

## GPU Scattering 实现

在 Direct3D 10 风格的实现中，Histogram 可以通过 GPU scattering 构建：

1. 将 Item Buffer 重新解释成点列表；
2. 每个点携带一个 Histogram bin 的坐标；
3. Vertex Shader 根据 ID 计算目标 bin 的位置；
4. 将点渲染到 Histogram Render Target；
5. 开启 additive blending；
6. 每个点让对应 bin 增加一次。

这样不需要 CPU 读取 Item Buffer，也不需要为每个实体单独执行查询。

在 Direct3D 11 中，可以使用 Compute Shader 或像素阶段的原子操作直接增加 Histogram：

```text
每个线程处理一个 Item Buffer 像素
→ 读取实体 ID
→ 计算 Histogram 地址
→ InterlockedAdd(counter, 1)
```

这更直接，也可以绕过部分传统图形管线限制。

## 层级屏幕 Tile

为了支持更细的空间查询，章节把屏幕划分为 `2^t × 2^t` 个 Tile。实体 ID 不只包含基础实体 ID，还编码了它所在的 Tile：

```text
组合 ID = 基础实体 ID + Tile X + Tile Y
```

这样可以区分：

```text
实体 5 在左上角可见
实体 5 在右下角不可见
```

对 Histogram 进行 Mipmap 或层级聚合后，就能获得类似 QuadTree 的可见性结构：

```text
整张屏幕
  ├─ 左上大区域
  │   ├─ 左上小区域
  │   └─ 右下小区域
  └─ 右下大区域
```

查询时可以根据需要选择粒度：

- 查询整个对象是否可见；
- 查询对象是否在某个 Tile 中可见；
- 查询更小区域中的实体覆盖率。

## 可见性粒度

本章的“granular”指的是查询粒度可以调整，而不是固定只查询对象级别。

例如：

```text
对象级：Object 12 是否可见？
实例级：Instance 12-37 是否可见？
批次级：Cluster 4 是否可见？
区域级：Instance 12-37 是否在左上 Tile 可见？
像素级：该实体覆盖了多少像素？
```

粒度越细，ID 和 Histogram 的规模可能越大，但获得的剔除和 LOD 控制越精确。

## 应用：实例化 Shadow Volume

书中的示例使用了大量 Instanced Shadow Casters。Shadow Volume 的挤出和光栅化可能很昂贵，因此不希望对完全不可见的阴影投射体执行完整生成。

流程大致是：

1. 使用实例 ID 渲染可见性 Item Buffer；
2. GPU Histogram 统计每个实例是否在光源视角中可见；
3. Geometry Shader 查询该实例的可见性；
4. 只有可见实例才生成和绘制 Shadow Volume；
5. 被其他物体完全遮挡的实例跳过挤出。

这保留了 Instancing 的低 Draw Call 优势，同时避免为不可见实例执行昂贵几何处理。

## 与传统 Occlusion Query 的区别

传统 Occlusion Query 通常有以下特点：

- 查询粒度通常接近 Draw Call；
- 需要提交查询、等待或延迟读取结果；
- 很难直接对单个实例进行独立判断；
- CPU 参与调度较多。

Hierarchical Item Buffer 则：

- 可以在一次批量渲染中识别许多实体；
- 结果保留在 GPU 资源中；
- 可以按对象、实例、批次和 Tile 查询；
- 不需要应用程序逐个读取查询结果。

它更适合需要细粒度、GPU 内部反馈的场景。

## 与现代 GPU Driven Culling 的区别

现代 GPU Driven 通常还会继续执行：

```text
可见性结果
→ Prefix Sum / Compact
→ 生成可见实例列表
→ 生成 Indirect Draw 参数
→ Execute Indirect
```

本章的 Item Buffer 主要产生：

```text
实体可见性计数或标记
```

因此它更像 GPU Driven 中的“可见性查询模块”，而不是完整的 GPU 绘制调度框架。

## 性能瓶颈

### Scattering Overdraw

如果大量 Item Buffer 像素都指向同一个 Histogram bin，就会产生大量对同一位置的累加操作，导致 scattering 阶段严重 overdraw。

### Item Buffer 分辨率

散射成本主要与 Item Buffer 的像素数量相关，而不只与实体数量相关。即使场景中实体很少，过高的 Item Buffer 分辨率也会增加固定成本。

### Tile 粒度选择

- Tile 太大：统计便宜，但空间信息粗糙；
- Tile 太小：查询精确，但 Histogram 更大，散射和内存成本更高。

### 空白像素

没有实体覆盖的 Item Buffer 像素也可能参与散射。实现中可以把这些像素初始化为无效的 Histogram 坐标，使其在散射阶段被管线自动丢弃。

## 限制

1. 一个 Item Buffer 像素通常只能保存一个最终可见实体，无法同时记录多层被遮挡实体。
2. 需要额外的 Item Buffer 和 Histogram 存储。
3. 散射或原子加法可能造成竞争和 overdraw。
4. 对大量实体进行非常细粒度编码会扩大 ID 和 Histogram 的规模。
5. 可见性结果通常需要在当前帧或下一阶段使用，不能完全消除管线同步问题。
6. 它主要解决屏幕可见性，不自动完成 Frustum Culling、LOD 选择或间接绘制。

## 本章结论

Hierarchical Item Buffer 的核心是：

```text
用实体 ID 渲染可见像素
→ 对 ID 做 GPU Histogram
→ 得到实体和屏幕区域的可见性
→ 将结果用于昂贵阶段的剔除或 LOD
```

它把传统“CPU 查询某个 Draw Call 是否可见”扩展成 GPU 内部的批量、细粒度、层级可见性统计。它不是完整 GPU Driven，但可以作为 GPU Driven 渲染中的遮挡查询模块，为实例筛选、阴影体生成、Geometry Shader、Tessellation 和 LOD 控制提供基础数据。
