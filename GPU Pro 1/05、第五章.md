# GPU-Based NURBS Geometry Evaluation and Rendering（基于 GPU 的 NURBS 几何求值与渲染）

## 章节内容

本章讨论如何把 NURBS 曲线和曲面的求值过程从 CPU 转移到 GPU。NURBS 仍然作为精确的数学参数表示保存，但 GPU 负责计算参数空间中的采样点、法线和纹理坐标，并将结果组织成后续可渲染或可继续处理的数据。

作者：Graham Hemingway。

## NURBS 与普通 Mesh

普通 Mesh 直接保存有限个顶点和三角形，顶点之间的曲面只是离散近似。NURBS 则通过以下数据定义曲线或曲面：

- 控制点；
- 控制点权重；
- 节点向量（knot vector）；
- 曲线或曲面的阶数；
- 参数值 `u`，或者曲面中的 `u、v`。

给定参数值后，NURBS 方程可以计算出对应的精确位置。渲染时仍然需要采样并生成三角形，但“从参数到曲面点”的求值过程有明确数学定义，不是凭经验生成的近似形状。

## 为什么需要 GPU 求值

NURBS 的计算成本主要来自：

- 每个输出点都要单独求值；
- 需要在节点向量中查找当前参数所在的 span；
- 需要递归或迭代计算 B-spline basis function；
- 曲面还需要在两个参数方向上进行计算；
- trimmed surface 还要额外处理裁剪曲线。

如果全部在 CPU 上完成，再把生成的顶点上传到 GPU，CPU 计算和数据传输都可能成为瓶颈。因此本章将控制点和节点向量放入纹理，由 GPU 并行完成求值。

## 基本 GPU 工作流

本章使用 Fragment Shader 和 Framebuffer Texture 来完成早期 GPU 实现中的通用计算：

```text
控制点 / 权重 / 节点向量
            ↓
GPU Fragment Shader 并行求值
            ↓
浮点纹理保存位置、法线、UV
            ↓
直接作为后续输入，或转换为 VBO
            ↓
三角形网格渲染
```

对于曲线，可以绘制一个与目标输出尺寸一致的矩形，让每个 Fragment 的坐标对应一个参数 `u`。对于曲面，二维输出纹理的坐标对应 `(u, v)`。

这种方式的关键不是把 NURBS 直接光栅化，而是利用 GPU 的并行执行能力快速生成离散采样点。

## 曲线求值过程

每个曲线采样点大致经过以下步骤：

1. 根据输出像素位置计算参数值 `u`；
2. 在节点向量中查找 `u` 所属的 span；
3. 计算该 span 对应的 B-spline basis values；
4. 按控制点、权重和 basis values 加权求和；
5. 执行齐次坐标的权重除法；
6. 把结果写入浮点输出纹理。

NURBS 的权重使它不仅能表达普通自由曲线，还能精确表达圆、圆锥曲线等形状。

## 曲面求值

NURBS 曲面只是把曲线的一个参数扩展为两个参数 `u、v`。GPU 需要分别准备两个方向的节点向量，并对控制点网格进行二维加权求和。

除了位置，还可以利用 basis values 计算法线；参数坐标本身也可以直接作为纹理坐标。因此输出通常包括：

- 顶点位置；
- 顶点法线；
- 纹理坐标。

如果后续仍然要使用传统渲染管线，可以把这些数据复制到 VBO；如果后续处理也在 GPU 上完成，则可以继续保留为纹理，避免不必要的数据往返。

## Trimmed NURBS

一个完整 NURBS 曲面通常对应参数域中的矩形，但实际模型经常需要在曲面内部挖孔或裁掉一部分。Trimmed NURBS 的思路是把问题拆开：

1. 先求值完整的底层 NURBS 曲面；
2. 单独求值裁剪轮廓曲线；
3. 把裁剪轮廓投影或反求到曲面的参数域；
4. 用轮廓生成 trim texture；
5. 最终渲染时根据 trim texture 丢弃不属于曲面的 Fragment。

这样做不必重新构造一个拓扑复杂的裁剪后网格，而是用纹理记录曲面参数域中哪些区域有效。

## 裁剪轮廓的反求

裁剪曲线最初位于三维空间，需要找到它对应的曲面参数 `(u, v)`。本章采用相对简单的 GPU 方法：

- 在已经求值的曲面采样点中搜索距离裁剪点最近的点；
- 找到其 `u` 和 `v` 邻域；
- 用局部三角形和重心坐标估计裁剪点的参数值；
- 把结果写入参数纹理。

这种方法易于实现且可并行，但会随着曲面 LOD 增大而增加搜索成本，并且在高度非平面或多个曲面点同样接近的情况下可能不够准确。

## 性能结果的含义

书中的测试显示，GPU 求值相较于每帧完全由 CPU 重新生成顶点，可以获得显著提升；如果模型只生成一次，之后反复旋转和渲染，则避免重复求值还能进一步提升性能。

这个结果说明两件事：

- GPU 并行求值可以缓解 NURBS 的计算瓶颈；
- 更大的收益来自区分“几何是否真的改变”和“只是视角是否改变”，不改变时应复用已经生成的数据。

## 与游戏实时渲染的关系

本章的方法更适合：

- CAD 和工业模型预览；
- 高精度曲面编辑；
- 参数化模型实时修改；
- 需要保留 NURBS 表示的工具链。

对于普通游戏资产，通常会在离线阶段把 NURBS 转成 Mesh，再使用 Mesh 的 LOD、蒙皮、实例化和剔除。只有当曲面参数本身需要在运行时频繁修改，或者应用确实需要 CAD 级精度时，运行时 GPU NURBS 才更有意义。

## 代价与限制

- NURBS 求值本身比直接读取 Mesh 顶点更复杂；
- 输出仍然需要离散采样，采样密度不足会造成几何误差；
- 高阶曲线、复杂节点向量和 trimmed surface 会增加 Shader 成本；
- 裁剪轮廓反求的暴力搜索可能成为瓶颈；
- GPU 生成后如果马上读回 CPU，会重新引入同步和带宽成本；
- 不能因为 NURBS 数学上精确，就认为最终渲染结果无需 Tessellation 或 LOD。

## 本章结论

NURBS 是精确的参数化几何表示，但 GPU 仍然需要把它采样成可渲染的离散顶点。本章优化的不是 NURBS 的数学定义，而是“从参数表示生成采样几何”的执行位置和并行效率：

> 控制点和节点向量保留为参数数据，GPU 并行求值并生成位置、法线和 UV，必要时再转换为三角形网格。

它适合高精度、参数化、运行时可修改的曲面应用；对于普通游戏资产，离线转换成 Mesh 通常更简单、更稳定。
