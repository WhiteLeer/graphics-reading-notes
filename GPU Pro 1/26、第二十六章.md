# Hybrid Min/Max Plane-Based Shadow Maps（混合 Min/Max 与平面 Shadow Map）

作者：Holger Gruen  
来源：GPU Pro 1，Part VII，Chapter 2，pp. 447–454。

## 1. 本章解决的问题

大范围 PCF 或软阴影滤波需要访问较大的 Shadow Map footprint。并不是每个像素都需要完整过滤：很多像素其实可以快速判断为完全受光或完全处于阴影中。

本章在普通深度 Shadow Map 之外构建一张辅助纹理 HPSM（Hybrid Min/Max Plane Shadow Map），让运行时先进行廉价的快速拒绝，只有不确定的区域才执行昂贵的 PCF。

## 2. 普通 Min/Max Shadow Map 的问题

对于一块 Shadow Map 区域，可以保存：

- 最小深度 `minDepth`；
- 最大深度 `maxDepth`。

当前像素的光源空间深度为 `z` 时：

- `z < minDepth`：可快速判断为完全受光；
- `z > maxDepth`：可快速判断为完全阴影；
- `minDepth <= z <= maxDepth`：无法确定，需要执行完整过滤。

这对深度变化明显的区域有效，但对平坦地面等平面特征不理想。一个低分辨率 Min/Max texel 可能覆盖很大的屏幕区域，只要区域内存在深度变化，Min/Max 范围就会被扩大，最终仍无法快速拒绝。

## 3. HPSM 的混合表示

HPSM 对每个辅助 texel 选择两种表示之一：

```text
区域近似一个平面 → 保存平面信息
区域不是平面     → 保存最小/最大深度
```

因此它既能利用 Min/Max 对复杂区域进行范围判断，也能利用平面方程准确处理地面、墙面等平坦几何。

### 平面表示

将 Shadow Map 深度恢复到光源空间的三维点后，用这些点拟合平面：

```text
plane = (P0, N)
distance = dot(P - P0, N)
```

如果所有点到平面的距离都小于允许误差，就认为该区域是平面。运行时只需判断当前点位于平面的哪一侧，就能快速决定受光或阴影。

## 4. HPSM 的构建

构建流程如下：

1. 选择 HPSM 分辨率，例如原 Shadow Map 宽高的四分之一；
2. 为每个 HPSM texel 确定对应的原始 Shadow Map 区域；
3. 根据阴影滤波核半径向四周扩大该区域；
4. 读取区域内的深度值；
5. 计算深度最小值和最大值；
6. 将深度转换为光源空间三维位置；
7. 尝试用这些位置拟合平面；
8. 平面误差足够小时存储平面，否则存储 Min/Max。

区域必须根据滤波 footprint 扩展。若只把固定的 4×4 Shadow Map texel 合并为一个 HPSM texel，实际过滤时可能跨越相邻 HPSM 区域，运行时仍需要多次辅助纹理读取。

## 5. 为什么需要恢复光源空间位置

Shadow Map 中的深度通常是投影后的非线性深度，不能直接拿来拟合真实平面。需要根据光源的投影参数将其恢复到线性的光源空间：

```text
Shadow Map depth
  → 光源相机空间深度
  → 光源空间三维点
  → 平面拟合或 Min/Max 聚合
```

这样得到的平面才具有几何意义，可以用于判断当前像素相对于遮挡表面的空间位置。

## 6. HPSM 的运行时查询

对当前场景像素进行阴影判断时，先查询 HPSM：

```text
读取 HPSM texel
  ├─ Min/Max 表示
  │    ├─ z < minDepth → 完全受光
  │    ├─ z > maxDepth → 完全阴影
  │    └─ 位于范围内 → 执行完整 PCF
  │
  └─ 平面表示
       ├─ 计算点到平面的距离
       ├─ 位于遮挡侧 → 完全阴影
       └─ 位于受光侧 → 完全受光
```

它的收益来自大量“确定性区域”被快速结束，而不是让 PCF 本身变得更便宜。

## 7. HPSM 与层级 Min/Max 的区别

传统 Hierarchical Min/Max Shadow Map 通过多级层次结构快速查找范围，但可能需要沿层级向下遍历，产生多次纹理访问。

HPSM 把目标滤波区域考虑进去，尝试将信息压缩到一张辅助纹理中：

- 运行时访问层级更浅；
- 目标是用一次辅助纹理查询完成快速拒绝；
- 平坦区域使用平面表示，避免 Min/Max 对平面深度变化过于保守；
- 构建辅助纹理时需要更多预计算工作。

## 8. Gather 与 Compute Shader

HPSM 构建需要对相邻 Shadow Map 深度进行聚合。支持 Gather 的硬件可以一次取得相邻多个深度值，减少构建阶段的读取次数。

在支持 Compute Shader 的平台上，可以让线程组共享内存复用相邻区域的读取，进一步加快 HPSM 构建。这里 Compute Shader 的价值主要在于构建辅助数据，不是运行时用它替代传统 Shadow Map 查询。

## 9. 其他用途

HPSM 不只可以加速普通 Shadow Filtering，也可以加速沿光线积分的效果，例如 Sun Shafts：

```text
沿视线/光线采样多个位置
  → HPSM 快速判断完全受光或完全阴影
  → 只对不确定位置执行 PCF
```

这类应用中，HPSM 可以减少沿光线方向的大量重复阴影查询。

## 10. 代价与限制

- 需要额外的 HPSM 纹理内存；
- 每次 Shadow Map 更新后，HPSM 也可能需要重新构建；
- 平面检测需要将深度恢复为光源空间三维坐标；
- 平面误差阈值过小会导致大量区域退化为 Min/Max；
- 误差阈值过大则可能产生错误的完全受光/完全阴影判断；
- 滤波核越大，HPSM 构建区域越大，构建成本越高；
- 这仍是 Shadow Map 近似，不会解决 Shadow Map 分辨率、偏移和漏光的全部问题。

## 11. 总结

HPSM 的核心可以概括为：

```text
Shadow Map
  → 预计算局部几何摘要
  → 运行时快速判断确定区域
  → 只对不确定区域执行高质量滤波
```

它不是新的阴影生成算法，而是给大范围 Shadow Filtering 增加一个快速拒绝层。平面表示解决了普通 Min/Max 对平坦表面过于保守的问题，Min/Max 表示则覆盖复杂几何区域。
