# Touchscreen-Based User Interaction（基于触摸屏的用户交互）

作者：Andrea Bizzotto  
来源：GPU Pro 1，Part VI，Chapter 2，pp. 375–383。

## 1. 本章解决的问题

本章讨论的不是一种渲染算法，而是移动设备上“触摸输入 → 相机运动”的完整信号处理链：

1. 从触摸屏得到带时间戳的位置样本；
2. 从离散位置估计手指移动速度；
3. 抑制触摸屏噪声和过小的抖动；
4. 预测当前帧真正需要的位置；
5. 将手势映射到球面坐标相机的 yaw、pitch 和 radius；
6. 手指松开后保留惯性，使相机运动自然停止。

核心思想是：不要把每一个触摸采样点直接当成相机状态，而要把输入看成一个带噪声、带延迟的时间信号，先估计状态，再驱动相机。

## 2. 原始触摸样本

每个样本可以写成：

```text
(t, x, y)
```

其中 `t` 是采样时间，`x`、`y` 是屏幕坐标。触摸屏的采样频率和渲染帧率通常不同，因此一帧内可能读到零个、一个或多个新样本。

如果直接使用相邻样本计算速度：

```text
v(tn) = (s(tn) - s(tn-1)) / (tn - tn-1)
```

当手指实际静止时，触摸位置仍可能因硬件噪声发生微小变化，于是速度会在零附近抖动，最终表现为相机轻微晃动。

## 3. 时间窗口速度估计

本章使用一个按时间维护的循环队列，而不是只看最近两个样本。

每帧处理流程如下：

1. 将本帧以来读到的所有新样本加入队列；
2. 移除早于时间窗口的样本；
3. 如果有效样本少于两个，则速度记为零；
4. 对相邻样本计算局部速度；
5. 对窗口内的局部速度求平均；
6. 根据平台调节阈值，将足够小的速度直接归零。

可以理解为“差分求速度 + 时间窗口低通滤波”：

```text
v_avg = average( (s_i - s_(i-1)) / (t_i - t_(i-1)) )
```

窗口越大，噪声抑制越好，但响应越慢。因果滤波会引入大约 `ΔT / 2` 的延迟；书中示例使用了约 0.2 秒的窗口，并强调需要根据设备实际手感调整。

## 4. 位置预测

即使得到了速度，最后一个触摸样本的时间也不一定等于当前帧真正开始处理或最终显示的时间。可以把这段延迟拆成：

```text
Δtotal = Δread + Δframe
```

其中：

- `Δread`：从最后一次输入采样到读取输入之间的时间；
- `Δframe`：从读取输入到当前帧处理/显示之间的时间。

于是可以用最后位置和当前速度预测新位置：

```text
s_predicted = s_last + v_last * Δtotal
```

这不是为了“预测用户下一步想做什么”，而是补偿已经发生但尚未反映到输入状态里的时间延迟。对相机旋转而言，这能明显减少拖拽时的滞后感。

## 5. 球面坐标相机

本章将相机放在目标周围，用三个状态描述相机：

- `yaw`：绕目标的水平旋转角；
- `pitch`：绕横轴的俯仰角；
- `radius`：相机到目标的距离。

初始位置可以设为：

```text
Vpos = (0, 0, R)
```

先构造旋转矩阵：

```text
Mrot = Ry(yaw) * Rx(pitch)
```

再得到相机位置和方向：

```text
Vpos = Mrot * (0, 0, R)
Vy   = Mrot * (0, 1, 0)
Vz   = -(Vtarget - Vpos) / |Vtarget - Vpos|
Vx   = Vy × Vz
```

其中 `Vtarget` 是观察目标。`Vx`、`Vy`、`Vz` 加上相机位置共同构成 view 矩阵。目标不一定要在世界原点；如果目标在任意位置，可以先把问题平移到目标坐标系，再应用相同的球面旋转。

这种表示法的优点是约束自然：用户拖动只改变角度，缩放只改变半径，不需要直接修改相机的三个世界坐标，也不容易产生漂移或奇怪的翻转。

## 6. 松手后的惯性

手指抬起时，不应立即把速度设为零，否则相机运动会突然停止。可以保留抬起瞬间的速度，并让它随时间指数衰减：

```text
v(t) = v_release * exp(-k * t)
```

每帧将衰减后的角速度积分到 yaw/pitch：

```text
angle_next = angle_current + v(t) * Δtime
```

指数衰减的参数决定“滑动感”：衰减太快会像被刹住，太慢则会显得飘。实际项目还应限制最大 pitch、避免相机翻越极点，并在接近零速时主动停止更新。

## 7. 完整输入链路

```text
触摸样本
  → 时间窗口清理
  → 相邻样本差分
  → 速度平均与死区过滤
  → 延迟补偿/位置预测
  → yaw、pitch、radius 状态更新
  → 球面坐标转相机矩阵
  → 松手后的惯性衰减
```

这里的关键边界是：触摸层提供观测值，输入过滤器估计速度，相机控制器维护稳定状态，渲染系统只消费最终的相机矩阵。

## 8. 参数如何取舍

### 时间窗口

- 小窗口：响应快，但更容易抖动；
- 大窗口：更稳定，但有明显拖拽延迟；
- 触摸屏采样率、帧率和设备性能不同，不能照搬一个固定值。

### 速度阈值

- 阈值太小：静止时仍会抖；
- 阈值太大：慢速观察无法生效；
- 可以让阈值和屏幕尺寸、DPI 或相机距离相关，而不是只使用固定像素值。

### 惯性衰减

- 主要影响松手后的手感；
- 应与角速度单位和帧时间绑定，不能按“每帧固定减一个值”，否则帧率变化会改变手感；
- 应设置速度下限和最大旋转速度，防止异常输入导致相机失控。

## 9. 局限与工程补充

本章主要针对单指拖拽控制的轨道相机。实际项目还需要补充：

- 多指缩放、旋转和手势冲突处理；
- 触摸按下、移动、抬起、取消等生命周期；
- UI 区域拦截与游戏场景输入的优先级；
- 设备方向变化和坐标系转换；
- 相机碰撞、目标遮挡和 pitch 限制；
- 不同触控设备上的阈值标定。

## 10. 总结

本章的本质不是“给相机加一个拖拽脚本”，而是建立一条稳定的输入估计链：

1. 用时间窗口平均抑制触摸噪声；
2. 用位置预测补偿采样到显示之间的延迟；
3. 用球面坐标保证轨道相机状态可控；
4. 用指数衰减模拟松手后的惯性。

它适用于模型查看器、角色预览、移动端第三人称相机和任何需要稳定拖拽体验的场景。
