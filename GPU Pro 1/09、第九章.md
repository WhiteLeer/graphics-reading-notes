# Alpha Blending as a Post-Process（作为后处理的 Alpha 混合）

## 章节内容

本章针对大量半透明植被平面互相穿插的问题，提出一种屏幕空间 Alpha Masking 方案。它不尝试对所有透明片元进行严格排序，而是先分别渲染不透明场景、植被颜色和植被覆盖 Mask，最后通过全屏后处理完成近似透明合成。

作者：Benjamin Hathaway。

## 要解决的问题

植被通常由大量带 Alpha 通道的平面组成。为了增加密度，这些平面会随机交叉排列，导致：

- 一个植被模型内部存在很高的深度复杂度；
- 透明平面之间互相穿插；
- 摄像机或风改变后，深度关系不断变化；
- 没有一个简单的全局绘制顺序；
- 如果拆分所有相交几何，顶点数和带宽会大幅增加。

传统 Alpha Blending 需要从远到近排序，而这里的几何结构使这种排序很难准确完成。

## 传统方案的取舍

### Alpha Blending

透明度连续、画质自然，但依赖绘制顺序。相交平面可能不存在单一正确的排序结果。

### Alpha Test

根据阈值决定像素是否保留，可以使用深度写入，也不太依赖透明几何排序。但 Alpha 边缘会被二值化，容易出现锯齿、闪烁和过于生硬的轮廓。

### Alpha-to-Coverage

把 Alpha 转换成 MSAA 覆盖率，能够得到比 Alpha Test 更柔和的边缘，同时保留部分深度测试优势。但它依赖采样数和硬件覆盖率支持，并会增加 MSAA 的带宽和填充成本。

## 本章方案：Screen-Space Alpha Masking

本章方案属于近似 OIT。它把透明合成拆成多个 Pass：

```text
1. Opaque Pass
   生成不透明颜色和深度

2. Mask Generation Pass
   生成植被的屏幕空间 Alpha Mask

3. Foliage Color Pass
   生成植被颜色，并更新深度

4. Final Composition Pass
   全屏采样并合成不透明场景与植被
```

最终组合类似：

```text
Final = lerp(OpaqueColor, FoliageColor, Mask)
```

透明排序从几何阶段转移到了屏幕空间的 Mask 生成和最终合成阶段。

## Opaque Pass

首先渲染所有不透明物体：

- 颜色写入 `rtOpaque`；
- 深度写入 `rtDepth`。

后续植被 Pass 使用这个深度缓冲区，以便正确处理被不透明物体遮挡的部分。如果使用 MSAA，需要谨慎下采样深度，不能直接对深度做普通线性过滤，否则可能得到错误的深度样本。

## Mask Generation Pass

Mask Pass 只关心植被 Alpha，不关心完整颜色和光照。植被 Alpha 被写入屏幕空间 Mask，并使用深度测试处理不透明场景的遮挡。

本章同时维护两种统计方式：

### Additive Mask

把多个植被片元的 Alpha 累加：

```text
MaskAdd = a1 + a2 + a3 + ...
```

优点是能够表达多个透明层叠加后的密度；缺点是很容易在高深度复杂度区域饱和为白色，导致植被看起来过于不透明。

### Max Mask

每个像素只保留最大的 Alpha：

```text
MaskMax = max(a1, a2, a3, ...)
```

它类似一个 Alpha 深度缓冲，能够保留较清晰的叶片轮廓和边缘渐变，不容易快速饱和。但如果单独使用，植被会显得过于透明，因为它没有表达多层覆盖的累积效果。

## 两种 Mask 的组合

本章利用独立的颜色和 Alpha 混合状态，在一次 Mask Pass 中同时保存：

- RGB 通道：Max Mask；
- Alpha 通道：Additive Mask。

最终再通过艺术参数进行插值：

```text
Mask = lerp(MaskAdd, MaskMax, factor)
```

这样可以在“层数累积导致饱和”和“单层最大值导致过度透明”之间取得平衡。该参数通常交给美术调节，因为最佳结果取决于植被纹理、深度复杂度和场景风格。

## Foliage Color Pass

这个 Pass 负责生成植被颜色。为了维持后续透明物体的深度关系：

- 开启深度测试；
- 开启深度写入；
- 关闭 Alpha Blending；
- 使用 Alpha Test 选择颜色覆盖区域。

这里的 Alpha Reference 需要在边缘质量和重叠伪影之间折中。阈值太高会造成颜色区域比 Mask 小，最终出现 Halo 或背景颜色泄漏；阈值太低则会使重叠边缘过于厚重。

## Final Composition Pass

最后绘制一个覆盖全屏的四边形，在 Pixel Shader 中读取：

- 不透明颜色；
- 植被颜色；
- 最终 Mask。

然后进行屏幕空间插值。由于组合发生在每个像素上，它不需要重新排序原始植被平面。

本章还使用 `mask * mask` 的方式让 Alpha 边缘更快衰减，同时保持高覆盖区域的不透明度，从而减轻 Alpha Reference 不一致造成的 Halo。

## 它是不是完整 OIT

它确实具有 OIT 的目标：尽量不依赖透明几何的绘制顺序。但它不是严格的通用 OIT，因为它没有保存每个透明片元的完整颜色、深度和 Alpha，也没有逐像素排序。

更准确的分类是：

> 面向植被的屏幕空间近似 OIT，使用 Additive Mask 和 Max Mask 重建一个可控的透明混合因子。

它与 Weighted Blended OIT 的思想相近，都是通过累积统计量避免排序，但具体统计量和最终组合方式不同。

## 适用场景

它特别适合：

- 大量树木和灌木；
- Alpha 纹理叶片；
- 交叉排列的植被平面；
- 允许视觉近似但要求高性能的户外场景；
- 需要兼容较旧硬件的项目。

它不适合直接用于：

- 玻璃；
- 水和透明液体；
- 需要严格颜色叠加的透明材质；
- 折射、厚度和多层物理透射效果。

## 代价与限制

- 需要多个屏幕分辨率 Render Target；
- 额外的颜色、Mask 和深度 Pass 会增加带宽压力；
- Mask 参数需要针对场景和资产调节；
- Alpha Reference 不一致可能产生 Halo；
- Additive Mask 可能饱和，Max Mask 可能过于透明；
- 它是视觉近似，不会恢复严格的透明片元排序结果；
- 高分辨率屏幕上的额外 Render Target 可能比排序本身更昂贵。

## 本章结论

本章没有真正解决“所有透明片元的正确排序”，而是针对植被的特点，把问题改写为屏幕空间覆盖率估计：

> 用深度测试确定可见范围，用 Additive Mask 表示透明层累积，用 Max Mask 保留结构边缘，最后在全屏 Pass 中重建一个可调节的透明混合结果。

这是一种实用的、资产和场景针对性很强的近似 OIT，而不是通用透明渲染框架。
