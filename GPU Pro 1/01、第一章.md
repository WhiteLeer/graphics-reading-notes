# GPU Color Quantization（GPU 颜色量化）

## 章节内容

本章讨论如何把高精度或高动态范围的颜色数据压缩到有限数量的调色板颜色中，并使用 GPU 并行完成调色板训练和像素映射。核心实现采用 Self-Organizing Map（SOM，自组织映射），并与 LBG 和 Octree 等颜色量化方法进行比较。

作者：Chi Sing Leung、Tze-Yui Ho 和 Yi Xiao

## 核心思路

颜色量化本质上是把大量输入颜色映射到有限的代表颜色集合：

```text
原始颜色 → 找到最近的调色板颜色 → 保存调色板索引
```

运行时或输出阶段只需要保留颜色索引和调色板，就可以恢复近似的颜色。调色板越小，压缩越高，但颜色误差通常也越大。

## Self-Organizing Map

SOM 不只是寻找一组互相独立的代表颜色，还会在调色板条目之间建立二维邻域关系。训练过程中：

1. 初始化一组代表颜色；
2. 对每个输入颜色寻找距离最近的代表颜色；
3. 同时更新最近代表颜色及其邻域；
4. 将输入颜色的平均值作为新的代表颜色；
5. 随训练进行逐渐缩小邻域范围。

最终相邻的调色板条目通常也会对应颜色空间中相近的颜色。这种有序性有利于后续存储为二维纹理，也有助于颜色查找和可视化。

## GPU 实现

本章把每个输入像素看作一个“客户端”，把调色板条目看作“服务节点”：

- Vertex Shader 计算当前像素与所有代表颜色的距离；
- 找到最近的调色板索引；
- 通过点的位置把像素投递到对应的调色板区域；
- Fragment Shader 使用硬件混合累积颜色和计数；
- CPU 读取累积结果并更新下一轮调色板。

调色板被存储为二维纹理，累积纹理的每个 texel 记录颜色总和和样本数量。下一轮训练时，用颜色总和除以计数得到新的代表颜色。

## 与项目中固定色板的区别

项目中常见的像素画色板、Ramp Texture、材质 Color ID 或颜色查找表，通常由美术或程序预先定义，重点是风格统一或快速查表。

本章的 SOM 则是从输入图像中自动学习调色板，重点是：

- 在限定颜色数量下尽量减少视觉误差；
- 自动适应输入图像的颜色分布；
- 使用 GPU 加速调色板训练和映射。

因此它不是简单地准备一个标准色板供后续颜色依次读取，而是先从数据中构建一个更适合当前输入的色板。

## 结果与比较

本章将 SOM 与 LBG、Octree 进行比较。训练型方法通常能得到较低的均方颜色误差，但需要迭代训练；Octree 更容易实现和速度较快，但生成的色板质量可能较低。

SOM 的额外特点是调色板具有邻域有序性，因此不仅可以用于压缩颜色，也可以用于需要结构化颜色索引的应用。

## 代价与限制

- 调色板训练需要多轮迭代；
- GPU 训练过程中需要颜色累积和计数；
- 颜色数量越多，寻找最近代表色的计算越重；
- 调色板数量过少会造成明显色带和细节丢失；
- 训练阶段需要 CPU 与 GPU 之间交换或同步调色板数据；
- 对动态变化的图像，每帧重新训练通常不划算，更适合离线或低频更新。

## 本章结论

本章的核心是把颜色量化从逐像素 CPU 处理改造成 GPU 并行的调色板训练与索引映射。SOM 通过邻域更新得到具有空间组织性的调色板，在有限颜色数量下尽量保持图像质量。

它和项目中的固定色板系统属于同一类“颜色索引 + 查表”思想，但本章更关注如何自动学习色板，而不是如何手工定义色板。
