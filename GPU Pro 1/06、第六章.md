# Polygonal-Functional Hybrids for Computer Animation and Games（多边形与函数式几何混合）

## 章节内容

本章提出一种混合几何表示：保留传统 Polygonal Mesh，同时加入 Function Representation（FRep）或隐式曲面。目标不是完全抛弃网格，而是让不同部分使用更适合自己的表示方式。

作者：D. Kravtsov、O. Fryazinov、V. Adzhiev、A. Pasko、P. Comninos。

## 为什么需要混合表示

Mesh 很适合渲染、动画、纹理和工具链，但下面这些情况用固定拓扑的 Mesh 处理起来比较困难：

- 角色形状发生大幅变化；
- 两个物体融合或分离；
- 拓扑发生变化；
- 液体、黏性物质或软组织产生连续变形；
- 从一种结构逐渐 Morph 成另一种结构。

FRep 用一个标量函数描述空间中任意一点属于物体的程度，因此可以更自然地表示融合、切割、变形和拓扑变化。

## FRep 的基本概念

FRep 通常由标量函数 `f(p)` 和阈值 `T` 定义：

```text
f(p) > T：点在物体内部
f(p) = T：点在表面上
f(p) < T：点在物体外部
```

其中 `p` 是三维空间中的点，`f(p)=T` 对应一个等值面。函数可以是隐式函数、Signed Distance Field 或其他标量场。

函数梯度可以用来计算表面法线：

```text
n = normalize(∇f(p))
```

这使得 FRep 不仅能判断空间中的点是否属于物体，还能为渲染和碰撞提供表面方向信息。

## 函数式几何的优势

多个函数可以通过并集、交集、差集或平滑混合组合起来。例如两个 metaball 或 convolution surface 可以自动融合成连续表面，而不需要手动重新构建连接处的 Mesh 拓扑。

通过插值两个函数，还可以得到形状变换过程：

```text
f(p, t) = blend(f1(p), f2(p), t)
```

因此，函数表示特别适合制作：

- 变形和 Morphing；
- 软体、黏液和融合效果；
- 可编辑的程序化形状；
- 拓扑动态变化的角色或物体。

## 与骨骼动画的结合

本章使用骨骼作为 Mesh 和函数式对象之间的共同驱动结构。主要有三类组合方式：

1. 把 FRep 埋在 Mesh 内部，作为变形或黏性效果的隐式替身；
2. 把 FRep 附着到 Mesh 上，随骨骼一起运动和变形；
3. 把 Polygonal 对象附着到 FRep 的骨骼或隐式结构上。

例如，可以根据角色骨骼生成一组卷积曲面，初始时将其完全包在角色 Mesh 内。角色运动时，卷积曲面同步运动；当它与外部液体或其他隐式对象融合时，部分曲面就会自然露出，从而产生黏附、拉伸或包裹效果。

## GPU 上的生成流程

FRep 不能直接像 Mesh 一样交给普通光栅化管线，因此通常需要先离散化：

```text
函数参数
   ↓
在体素网格中采样函数值
   ↓
查找穿过等值面的体素单元
   ↓
Marching Cubes 提取三角形
   ↓
计算法线并写入 Vertex Buffer
   ↓
按普通 Mesh 渲染
```

GPU 可以让每个体素单元由独立线程处理。为了并行写入不连续数量的三角形，通常需要：

- 先计算每个单元会输出多少顶点；
- 标记哪些单元包含表面；
- 使用 Prefix Sum 或 Scan 计算每个单元在输出 Buffer 中的偏移；
- 第二阶段正式生成顶点和法线。

这说明函数式表示并没有消除几何生成，只是把“几何是什么”从固定顶点改成了函数，再通过 GPU 动态提取网格。

## 直接 Ray Marching 与网格提取

FRep 也可以直接通过 Ray Casting 或 Ray Marching 渲染，从而跳过 Marching Cubes。但直接求交和高分辨率实时渲染的成本较高，本章主要采用先提取等值面再按 Mesh 渲染的路线。

两种方式各有取舍：

- Marching Cubes：兼容普通 Mesh 管线，可做材质、动画和后续处理，但会产生离散网格和拓扑更新成本；
- Ray Marching：不必显式生成 Mesh，拓扑变化自然，但每个像素都可能需要多次函数求值，材质、阴影和碰撞集成也更复杂。

## LOD 与内存特点

FRep 的原始模型通常只需要保存函数参数、骨骼或少量控制数据，具有较好的分辨率独立性。改变体素网格分辨率，就可以生成不同质量的三角形结果，从而得到自动 LOD。

但这不是无条件节省内存：高分辨率体素场、临时函数值、Marching Cubes 输出 Buffer 和动态重建都会产生显著的计算与显存开销。

## 实际应用中的定位

这类混合表示比较适合：

- 具有特殊变形需求的角色；
- 液体、黏液、软体和融合效果；
- 用户实时编辑和程序化建模；
- 拓扑动态变化的对象；
- 需要自动生成多个分辨率版本的模型。

它不适合替代所有常规 Mesh。普通静态场景、硬表面资产和需要成熟动画管线的角色，仍然更适合直接使用 Mesh。

## 代价与限制

- 函数求值和体素采样可能非常昂贵；
- Marching Cubes 会带来动态顶点生成和 Buffer 管理；
- 生成的网格拓扑可能随帧变化，容易造成时间不稳定；
- 传统 UV 展开不适合复杂动态等值面，通常需要三平面或程序化纹理；
- 卷积曲面在远距离或复杂分支处的近似可能不准确；
- 初始 Mesh 到隐式骨架的拟合质量会影响结果；
- 它更强调视觉可信度，不等于严格的物理模拟。

## 本章结论

本章的关键思想是：

> 常规部分继续使用 Mesh，难以用固定拓扑表达的动态部分改用函数式表示，并在需要显示时通过 GPU 采样和离散化生成可渲染几何。

这不是“以后不保存网格”，而是把 Mesh 和函数看成互补的两种表示。它的价值集中在拓扑变化、连续融合和复杂形变，而不是替代普通游戏资产管线。
