# Visualize Your Shadow Map Techniques（Shadow Map 技术可视化）

## 章节内容

本章建立了一个与具体场景几何无关的数学模型，用来分析和可视化不同 Shadow Map 技术在视锥体中的采样误差与走样分布。它的重点不是实现一种新的阴影算法，而是把原本只能凭最终画面和经验判断的问题，转化为可比较、可绘制的误差分析结果。

作者：Fan Zhang、Chong Zhao、Adrian Egli。

## 核心问题

Shadow Map 的质量问题，本质上来自两个采样空间之间的不匹配：屏幕空间中的像素需要从光源空间的深度纹理中取得遮挡信息，但视图投影、光源方向、视锥体位置和 Shadow Map 分辨率会让不同区域获得不同的采样密度。

因此，同一张 Shadow Map 在近处、远处、不同视线方向或不同光源方向上，可能产生完全不同的走样程度。仅观察一张最终渲染图，很难判断问题究竟来自投影变换、采样密度分布，还是具体场景几何。

## 数学模型

本章将视锥体中的位置映射到屏幕空间和光源空间，比较屏幕像素覆盖范围与 Shadow Map texel 覆盖范围之间的关系，并据此表示采样误差。

模型关注的是投影和采样造成的理论误差，而不是某个具体模型的三角形分布，因此可以在不依赖场景几何的情况下，计算视锥体内不同位置的误差分布。分析也不限于某个固定的视锥体摆放方式，而是可以处理更一般的视图、光源和观察方向配置。

这里的“误差”可以理解为：屏幕上的可见细节需要多高的采样密度，而当前光源空间投影实际提供了多高的采样密度。两者差异越大，越容易出现锯齿、细节丢失或采样不稳定。

## 覆盖的 Shadow Map 技术

本章用统一的模型比较了多种投影和分配策略：

- Standard Shadow Map（SSM）
- Perspective Shadow Map（PSM）
- Light-Space Perspective Shadow Map（LiSPSM）
- Trapezoidal Shadow Map（TSM）
- Cascaded Shadow Map（CSM）

这些技术的共同目标都是重新分配 Shadow Map 的采样密度，但它们改变采样分布的方式不同。统一模型的价值在于，可以在同一套坐标和误差定义下比较它们，而不必只依赖不同场景中的主观截图。

## 可视化工具的价值

本章的可视化工具可以把误差分布画成曲线、区域图或热力图，帮助观察：

- 视锥体中哪些位置最容易发生走样；
- 某种 warping 是否把采样密度分配到了真正需要的区域；
- 不同算法在近处、远处和视锥体边缘的取舍；
- 参数或光源方向变化后，误差分布如何变化。

这类工具主要用于渲染技术研发、算法对比、参数调试和团队沟通。实际项目中通常不会把它作为玩家可见功能，而是作为 Debug View 或离线分析工具保留。它的意义不是替代最终场景测试，而是让最终画面背后的投影和采样原因变得可解释。

## 视线方向与 Warping 方向

Shadow Map warping 并不是越强越好。Warping 的方向如果与观察方向、光源方向和视锥体中的误差分布不匹配，可能会把采样密度从真正重要的区域挪走，导致某些区域改善、另一些区域恶化。

因此，评价 PSM、LiSPSM 或 TSM 时，不能只看它们是否提高了某个局部区域的分辨率，还要看它们在整个视锥体中的误差是否更均衡，以及视角和光源变化时是否仍然稳定。

## 与实际项目的关系

本章展示的是“理论分析工具”的典型价值：

1. 先用数学模型理解采样误差的空间分布；
2. 再用可视化工具比较不同 Shadow Map 技术；
3. 最后回到代表性场景，验证阴影边缘、细小遮挡物、运动稳定性和性能。

它不能单独证明某种算法在所有项目中都更好，因为最终效果还会受到 bias、PCF/PCSS 过滤、遮挡物形状、级联切换、时间稳定性和 GPU 成本影响。但它能显著减少“只凭感觉调参数”的过程。

## 代价与限制

- 模型主要描述投影和采样密度误差，不能覆盖所有阴影伪影；
- 它不替代真实场景中的遮挡几何、过滤、bias 和 temporal stability 测试；
- 可视化结果需要正确理解坐标空间和误差定义，否则容易把热力图当成最终画质结论；
- 工具本身是研发和调试基础设施，需要额外实现绘图、参数控制和算法切换。

## 本章结论

Shadow Map 的很多质量问题并不是“某个算法好或坏”这么简单，而是采样密度在视锥体中的分布问题。本章通过统一的数学模型和可视化工具，把 SSM、PSM、LiSPSM、TSM、CSM 等技术放到同一个分析框架中。

这类工具在实际项目中是有价值的，尤其适合阴影算法选型、参数调试和解释画质差异；但它应当被看作研发分析层，最终仍需要结合真实场景和性能数据做决定。
