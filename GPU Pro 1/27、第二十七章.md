# Shadow Mapping for Omnidirectional Light Using Tetrahedron Mapping（使用四面体映射的全方向光 Shadow Mapping）

作者：Hung-Chien Liao  
来源：GPU Pro 1，Part VII，Chapter 3，pp. 455–475。

## 1. 本章解决的问题

传统 Shadow Map 适合方向光：从光源方向渲染一张深度图，再把场景像素转换到光源空间进行深度比较。

点光源或全方向光从一个位置向四周发射光线，单张普通二维 Shadow Map 无法覆盖所有方向。本章使用正四面体的四个三角形面，将全方向空间拆成四个光源视锥，并把四个方向的深度结果打包到一张二维纹理中。

## 2. 基本流程

四面体 Shadow Mapping 分为两个阶段：

### 阶段一：生成四面体 Shadow Map

1. 将点光源放在四面体中心；
2. 为四个三角形面建立四个光源视图；
3. 对每个视图渲染会投射阴影的物体；
4. 记录每个方向上的最近深度；
5. 将四个面的深度区域打包到一张二维 Shadow Map。

### 阶段二：正常渲染场景

1. 将当前场景像素转换到光源本地空间；
2. 根据光源到像素的方向判断属于哪个四面体面；
3. 使用对应面的视图矩阵和投影矩阵计算二维纹理坐标；
4. 读取打包 Shadow Map 中的深度；
5. 与当前像素的光源空间深度比较，确定受光或阴影。

整体逻辑仍然是普通 Shadow Mapping，变化主要集中在“全方向映射到哪个二维区域”。

## 3. 四面体覆盖全方向

正四面体具有四个等边三角形面。从中心向每个面看，可以得到一个三角形视锥。四个视锥共同覆盖围绕光源的所有方向。

每个面的视图方向、旋转角度和投影视场需要预先计算。书中选用特定四面体朝向，是为了让四个面能够以较规则的方式排列到 Shadow Map 纹理中；理论上也可以选择其他朝向，只要保证覆盖和坐标变换一致。

## 4. Shadow Map 纹理打包

四个面不是矩形，而是三角形。实现中可以将面对应的投影结果放入二维纹理的四个区域，并为每个面设置不同的 viewport 和纹理偏移。

运行时需要分别构造：

- 面对应的光源 View Matrix；
- 面对应的透视 Projection Matrix；
- 从光源空间到纹理空间的 Scale/Offset；
- 当前面的纹理区域范围。

因此四面体方案不是简单地把六张 Cube Map 减少为四张，而是重新设计了方向分区、三角形视锥和纹理坐标生成。

## 5. 运行时面选择

设当前像素在光源本地空间中的方向为 `L`。根据 `L` 与四个面中心方向或面边界的关系，可以决定它属于哪个面。

确定面之后：

```text
LSP
  → 对应面的 View Matrix
  → 对应面的 Perspective Matrix
  → 对应面的纹理 Scale/Offset
  → 二维 Shadow Map 坐标
```

最终得到 `(u, v, z)`：

- `(u, v)` 用于读取对应面的深度；
- `z` 用于和 Shadow Map 深度比较。

## 6. 四面体与 Cube Map 的取舍

### 四面体的潜在优势

- 四个面少于 Cube Map 的六个面；
- 需要管理的光源视图更少；
- 可以将结果打包到单张二维纹理；
- 在特定硬件和纹理布局下可能减少部分开销。

### 四面体的代价

- 面是三角形，投影和裁剪更复杂；
- 方向到纹理坐标的计算更复杂；
- 三角形边界需要特别处理；
- 四个面的投影密度不完全均匀；
- 纹理过滤可能跨越无效区域或相邻面；
- 需要处理更大的投影视场和边缘畸变。

Cube Map 虽然需要六个面，但硬件支持、坐标访问和边界处理都更成熟，因此实际工程中通常更容易使用。

## 7. Stencil Buffer 优化

基础打包方案可能只使用每个纹理区域的一部分，导致 Shadow Map 有效面积不足。书中提出使用 Stencil Buffer：

1. 初始化有效三角形区域的模板值；
2. 生成各个面时改变 View Matrix 和 viewport；
3. 只允许有效三角形区域写入深度；
4. 尽量利用完整 Shadow Map 纹理。

这样可以提高纹理利用率，但会增加模板初始化和相关状态设置成本。

## 8. 面级别的视锥剔除

生成每个四面体面的 Shadow Map 时，不必提交所有阴影投射物。可以先判断：

1. 物体是否在点光源影响范围内；
2. 物体是否可能投影到当前三角形面；
3. 物体包围球或包围盒是否与当前面的三个边界平面相交。

这里和普通视锥剔除不同：普通透视视锥通常由矩形近平面和远平面描述，而四面体面对应的是三角形投影区域，因此需要根据三角形顶点和光源中心构造边界平面。

## 9. 质量问题

四面体映射会引入方向相关的投影密度变化：

- 某些方向的纹理分辨率更集中；
- 某些方向可能产生更明显的拉伸；
- 面边界附近的采样稳定性更差；
- 过滤时需要避免读取到其他面或无效区域。

因此实际质量还取决于四面体朝向、纹理分辨率、面布局、深度偏移和过滤方式。

## 10. 与现代实现的关系

现代引擎通常使用 Cube Shadow Map，并不是因为四面体方法不可行，而是因为 Cube Map：

- GPU 和 API 支持成熟；
- 面选择和纹理坐标更直接；
- 硬件比较采样和过滤更容易复用；
- 边界和调试工具更完善；
- 六个面的额外成本通常比复杂的四面体边界处理更容易接受。

四面体映射更适合作为一种“全方向投影与纹理打包”的研究型方案，或在面数量、纹理数量和特定硬件成本非常敏感时进行评估。

## 11. 总结

四面体 Shadow Mapping 的核心是：

```text
全方向光源
  → 四个三角形光源视锥
  → 打包成一张二维深度纹理
  → 根据像素方向选择面
  → 转换纹理坐标
  → 进行普通 Shadow Map 深度比较
```

它减少了全方向投影面的数量，但把复杂度转移到了三角形视锥、纹理打包、面选择和边界处理上。
