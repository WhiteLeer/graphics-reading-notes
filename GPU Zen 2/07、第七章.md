# Real-time Snow Deformation in Horizon Zero Dawn: The Frozen Wilds（《地平线：零之曙光：冰尘雪野》中的实时雪地形变）

## 章节内容

本章介绍《地平线：零之曙光：冰尘雪野》中的实时雪地形变系统。它需要支持角色、机器人、爆炸碎片等动态物体在大世界雪地中留下持久痕迹，同时满足较低 GPU 开销、较小资源改动和可扩展的场景覆盖要求。

作者：Kevin Örtegren

## 核心思路

系统不为每个脚印建立独立模型，也不直接修改整张地形网格，而是维护一张围绕玩家移动的局部形变高度场。整体流程分为两个主要 Pass：

1. **写入正交深度**：从雪层下方用正交相机渲染动态物体，得到它们相对雪面的位置和深度；
2. **形变与时间滤波**：Compute Shader 读取当前深度和上一帧的持久化形变，更新雪地高度、法线以及下一帧要保留的结果。

地形、雪堆、雪上物体和水面材质都可以读取最终结果，从而共享同一套交互数据。

## 持久化高度场

系统使用两张持久化 UNORM8 纹理做 Ping-Pong，保存相对基础地形、岩石或水面高度的雪地形变量。每帧交换读写纹理，并通过时间滤波让形变保持连续。

另外还有：

- 一张临时深度纹理，用于记录本帧动态物体；
- 一张结果纹理，打包存储高度和法线，供其他 Shader 采样；
- 通过 3×3 邻域差分计算雪面法线；
- 根据当前降雪量逐渐补回雪层。

因此它保存的不是脚印模型，而是一个可以被各种材质解释的局部空间场。

## 动态物体深度投影

为了降低深度 Pass 的成本，动态物体使用较低 LOD 的网格，而不是完整近景模型。系统从玩家附近的正交视锥中查询角色、机器人和碎片，并将它们渲染到深度缓冲区。

深度纹理的采样分布还可以非均匀化：靠近纹理中心、也就是玩家附近的区域获得更多采样，从而提升脚部和接触区域的形变细节。它本质上是一种面向交互中心的动态采样分配。

## 时间滤波与滑动窗口

上一帧的形变数据会被读回 Compute Shader 的局部共享存储，并使用带时间依赖的 3×3 min-average 滤波，逐渐收敛到目标坡度。这样可以减少深度采样造成的锯齿和跳变，但也会引入轻微的交互延迟。

为了支持开放世界，整个高度场不是固定在世界原点，而是以玩家为中心滑动。玩家移动超过一个或多个纹理像素后，系统通过偏移读取上一帧数据，把形变窗口跟随到新位置；边缘区域则逐渐淡出。书中使用约 64×64 米的局部区域和 1024×1024 缓冲区，得到约 6.25 厘米的持久化分辨率。

## 与贴花、VHM 和几何位移的关系

它不是普通的脚印贴花：贴花通常只改变表面颜色、法线或局部材质，而本章还维护了相对高度场，因此可以表现压雪、雪堆变形和部分地形起伏。

它也不等于完整的几何修改。高度和法线首先作为纹理提供给地形或材质 Shader，最终是否真实移动几何，取决于接收它的渲染路径。VHM 可以作为后续几何表现方式，但本章的核心是生成和持久化局部高度场。

## 代价与限制

- 形变区域局限在玩家附近，不能天然覆盖整个开放世界；
- 需要两张持久化高度纹理和额外结果/深度缓冲；
- 时间滤波会产生一帧左右的响应延迟；
- 低 LOD 动态网格会牺牲部分接触细节；
- 只有一层可变形雪，不能自然表示多层雪从屋顶落到地面的过程；
- 高度场不支持真正的雪堆抬升，部分隆起效果需要通过材质、法线和额外几何伪造；
- 岩石、屋檐等悬空区域可能出现没有对应雪层形变的情况，需要场景设计配合。

## 本章结论

本章的关键是把“动态物体与雪的交互”转换成局部、持久化、可滑动的高度场：用正交深度捕获接触，用 Compute Shader 做滤波和高度更新，再让所有雪地相关材质统一采样结果。

它是一种非常通用的地表交互框架，也可以扩展到沙地、泥地、草地、薄冰和水面；但它的本质仍是局部高度场近似，而不是对整个世界进行真实的体积或几何物理模拟。
