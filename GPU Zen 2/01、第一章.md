# Adaptive GPU Tessellation with Compute Shaders（使用 Compute Shader 的自适应 GPU 细分）

## 章节内容

本章讨论如何使用 Compute Shader 对任意三角形网格进行自适应细分，以改善中远距离模型投影到屏幕后产生的小三角形问题。重点是避免 CPU 生成和上传大量细分几何，并突破传统 Tessellation Shader 在细分层级、拓扑和结果复用方面的限制。

作者：Jad Khoury、Jonathan Dupuy 和 Christophe Riccio

## 核心思路

传统 Tessellation Shader 的流程是：Hull Shader 计算细分因子，固定功能 Tessellator 生成规则拓扑，Domain Shader 计算细分后的顶点。本章则使用 Compute Shader 维护隐式三角形细分结构，根据三角形的屏幕投影或视角条件决定是否继续细分。

```text
粗三角形网格
    ↓
Compute Shader 判断投影大小和细分需求
    ↓
隐式细分三角形
    ↓
写入紧凑的 GPU Buffer
    ↓
后续 Indirect Draw / Graphics Pipeline
```

## 与 Tessellation Shader 的区别

### Tessellation Shader

- 细分结果是当前 Graphics Pipeline 中的临时结果；
- 由硬件 Tessellator 生成规则拓扑；
- 不需要显式保存完整细分网格；
- 适合规则曲面和标准 Patch；
- 细分深度和拓扑受固定管线限制；
- 细分结果不方便被其他 Pass 复用。

### Compute Shader

- 细分结果可以显式写入 Vertex/Index Buffer；
- 可以使用自定义的三角形细分规则和拓扑；
- 可以在细分前后结合剔除和 GPU-driven Indirect Draw；
- 细分结果可以被多个 Pass 或多帧复用；
- 理论上支持更自由的细分层级，但需要自己管理内存、同步和工作量。

因此，Compute Shader 不是简单地替代 Tessellation Shader，而是把细分变成 GPU 上可管理、可复用的显式几何生成过程。

## 适用范围

Compute 方案更适合任意三角形网格、复杂细分规则、需要细分前后剔除，或需要将细分结果交给 GPU-driven Rendering 的场景。对于规则 Patch、一次性细分且不需要复用结果的情况，传统 Tessellation Shader 往往更直接。

## 代价与限制

- 需要额外的输出 Buffer、同步和间接绘制管理。
- 细分过度会增加内存、带宽和 Compute 工作量。
- 不代表 Compute Shader 在所有硬件上都比固定功能 Tessellator 更快。
- 细分规则、终止条件和缓冲容量必须严格控制，否则可能产生爆炸式几何增长。

## 本章结论

传统 Tessellation Shader 是“管线内临时细分”，Compute Shader 是“GPU 上显式生成和管理细分网格”。本章的价值在于获得更自由的拓扑、细分层级和结果复用能力，而不是证明 Compute 细分普遍优于硬件 Tessellation。
