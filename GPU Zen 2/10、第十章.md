# Real-Time Layered Materials Compositing Using Spatial Clustering Encoding（使用空间聚类编码的实时分层材质合成）

## 章节内容

本章介绍一种运行时分层材质合成方案，用于将钢材、油漆、橡胶、泥土、锈迹等多个材质层组合成复杂表面。它参考 Substance 等材质制作流程，但把部分合成过程从离线烘焙转移到运行时，曾应用于《Armored Warfare》的装甲车辆渲染。

作者：Sergey Makeev

## 核心思路

系统把最终材质拆分为三类数据：

- **Material Template**：材质库中的基础材质模板，例如钢、木材、橡胶或油漆，提供 Albedo、Normal、Roughness、Metalness 等表面属性；
- **Material Mask**：灰度纹理，表示某个材质层在各个像素上的混合权重；
- **Cluster 数据**：描述每个纹理区域实际使用哪些材质，以及这些材质的混合权重。

运行时 Shader 根据当前像素所属的 Cluster，读取对应的材质模板和权重，合成最终的表面属性。它看起来像一个材质，但内部仍然保留多个可替换的材质层。

## 与传统方案的区别

### 静态材质分层

传统做法是在离线阶段将所有层烘焙成最终的 Albedo、Normal、Roughness 等纹理。运行时成本较低，但每种材质组合都需要独立的一套纹理，内存占用高，也不容易运行时替换。

### 普通动态材质分层

另一种做法是在像素 Shader 中采样多张材质纹理和 RGBA Blend Mask。这种方法可以运行时组合材质，但每个通道能表达的材质数量有限，而且不同材质层只覆盖很小区域时，会浪费大量纹理通道和存储空间。

### 本章方案

本章不为每个像素固定分配一组全局材质，而是观察材质 Mask 在 UV 空间中的连通性和重叠关系，将空间上相邻、且不会互相冲突的 Mask 编入同一个 Cluster。不同 Cluster 可以复用相同的纹理通道。

## 三类运行时数据

预处理后，运行时主要使用三类资源：

1. **Cluster Indirection**：低分辨率整数纹理，记录每个区域对应的 Cluster ID。它不能使用普通线性过滤，而需要 Point 采样；
2. **Cluster Weights**：高分辨率权重纹理，存储当前 Cluster 中各材质的混合权重，可以使用 Mipmap、三线性或各向异性过滤；
3. **Cluster Properties**：结构化缓冲区或常量缓冲区，记录 Cluster 中各材质模板的索引和表面属性。

像素 Shader 先获取 Cluster ID，再读取对应材质集合和权重，最后合成 Albedo、Normal、Roughness、Metalness 等结果。

## 为什么需要空间聚类

如果多个材质 Mask 直接共享纹理通道，线性过滤和 Mipmap 可能会把不同材质区域混合到一起，产生边界泄漏。空间聚类会把参与过滤的邻域也纳入连通性分析，使可能互相影响的 texel 被分到同一个 Cluster。

实现通常只支持前几个 Mipmap 层级，例如前四级，以避免在最低分辨率下所有区域都被判定为连通。Cluster 中的材质数量也会受到 BC1/BC3 等纹理格式通道数限制，实际通常控制在每像素四到五层左右。

## 混合表示

普通 Alpha Blending 依赖严格的材质叠加顺序。为了让权重在 Cluster 内可以更自由地交换通道，本章将有序 Alpha 层转换为归一化的加权表示：

```text
Final = w0 * M0 + w1 * M1 + w2 * M2 + ...
```

所有权重之和为 1，因此可以省略一个权重，在 Shader 中用其余权重相减得到。这种表示有利于压缩和通道重排，但需要保证不同属性的混合方式正确，尤其是法线等非线性数据。

## 运行时替换与细节纹理

材质库可以在运行时替换，例如改变装甲车辆的涂装、锈蚀或污染状态，而不必重新生成整套最终材质纹理。

单个材质模板还可以使用平铺 Detail Texture 补充高频细节，从而突破唯一 UV 贴图的分辨率限制。在不增加大尺寸唯一纹理的情况下，表面仍能获得较高的局部细节。

## 代价与限制

- 每个像素仍需要进行多层材质的采样和混合；
- Cluster 的预处理需要分析 UV 连通性、重叠关系和 Mipmap 过滤；
- Cluster 中的活跃材质层数量受纹理格式和性能预算限制；
- Cluster 边界处理不当会导致 Mask 泄漏和材质边缘污染；
- 复杂材质的法线、粗糙度和高度等属性不能简单地用同一种方式混合；
- 它并没有消除多个材质的计算，只是把材质选择和存储组织得更紧凑、更可替换。

## 本章结论

本章方案可以看作一个受控的运行时通用材质 Shader：它不是把所有材质功能无条件塞进一个巨型程序，也不是把多个材质真正烘焙成一张不可变的最终纹理，而是通过材质库、Mask 和空间 Cluster，在每个像素只组合实际需要的少数材质层。

它用额外的预处理和运行时合成成本，换取了更低的材质纹理冗余、更好的运行时替换能力，以及对复杂分层材质的统一表达。
