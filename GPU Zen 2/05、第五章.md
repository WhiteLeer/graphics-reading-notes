# Skinned Decals（蒙皮角色贴花）

## 章节内容

本章讨论如何把贴花应用到会被骨骼蒙皮变形的角色模型上。普通 Deferred Decal 通常把贴花投影到当前屏幕中的刚性表面；当角色运动时，贴花容易出现“漂浮”或“游移”。本章的方案将贴花结果记录到角色网格的 UV 空间，使它可以随蒙皮自然运动。

作者：Hawar Doghramachi

## 核心思路

角色贴花不是绑定到某一根骨骼，也不是每帧重新在世界空间投影，而是分为三个阶段：

1. **贴花设置**：在命中角色表面的位置计算投影矩阵、贴花范围和朝向。
2. **更新 Lookup Map**：只有新增贴花时，才把当前蒙皮网格重新渲染到查找图中。查找图以角色网格的 UV 作为输出位置，记录该 UV 对应的贴花坐标、贴花索引和淡出信息。
3. **正常绘制角色**：每帧角色仍然按普通流程执行骨骼蒙皮。像素着色阶段用角色 UV 查询 Lookup Map，取出贴花纹理坐标和索引，再采样贴花纹理并混合到材质中。

由于查找结果存储在网格 UV 空间，而不是固定在世界空间或某根骨骼上，所以一个贴花跨越多个骨骼区域时，也能随着完整的骨骼权重混合一起变形。

## 与普通 Deferred Decal 的区别

普通屏幕空间贴花的投影关系依赖当前表面位置。对于静态墙面，这种关系稳定；但对于角色，顶点会被多根骨骼共同变换，原来的世界空间投影关系会随动作改变。

本章方案把“贴花投影结果”转存到角色自己的纹理坐标中。之后角色如何变形并不重要，只要 UV 和三角形拓扑保持不变，贴花就会跟着角色表面移动。

这也避免了给每一个贴花实例复制一套完整的漫反射、法线、粗糙度或高度纹理。多个贴花可以通过统一的纹理表、数组或图集进行索引。

## Lookup Map 与过滤

Lookup Map 还需要配合有效性缓冲区，避免采样到无效投影区域。贴花边缘可以根据入射角、近远裁剪范围和淡出参数进行衰减；本章的实现不支持贴花重叠，新增贴花时需要处理重叠区域。

为了正确计算贴花纹理的 Mipmap 导数，贴花坐标不能只在有效分支内部计算。通常需要在 2×2 像素邻域内先计算导数，并确认邻域中的贴花索引一致；否则贴花边缘可能出现错误过滤或跨贴花采样。

## 代价与限制

- 每个角色网格实例需要维护 Lookup Map 和有效性缓冲区；
- 新增贴花时需要额外更新查找图，贴花数量越多，管理成本越高；
- 本章实现不处理贴花之间的重叠；
- 角色网格需要具有适合查找的唯一 UV，重叠 UV 会让不同表面共享同一贴花结果；
- 每帧着色会增加一次查找、贴花索引选择和纹理混合；
- 它不是完整的任意表面投影系统，主要针对可控的角色网格和贴花生命周期。

## 本章结论

角色骨骼贴花的关键不是让贴花跟随某一根骨骼，而是把贴花投影结果写入角色网格的 UV 空间。这样新增贴花时才需要更新映射，之后每帧只需在正常蒙皮材质中查询并混合。它用额外的 UV 查找和管理成本，换取了贴花在多骨骼变形角色上的稳定跟随效果。
