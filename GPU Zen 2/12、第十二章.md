# A Ray Casting Technique for Baked Texture Generation（用于烘焙纹理生成的光线投射技术）

## 章节内容

本章介绍一种基于 GPU 光线投射的高模到低模纹理烘焙方案。烘焙的目标是把高多边形参考模型的法线、顶点颜色、位移、环境光遮蔽和漫反射等表面信息转移到低多边形工作模型的纹理中。

作者：Alain Galvan 和 Jeff Russell

## 与 Substance Painter 的关系

本章确实实现了一套可编程的 GPU 烘焙管线，但它不是为了全面替代 Substance Painter。Substance Painter 更侧重完整的美术生产流程，包括模型检查、Cage 调整、材质绘制、预览和导出。

本章更关注：

- 将烘焙集成到引擎或自有资源处理工具；
- 使用 GPU 并行处理大量纹理像素；
- 为特殊项目定制射线、输出通道和材质数据；
- 减少传统 CPU 烘焙工具的批处理时间；
- 给艺术家提供可绘制的 Skew Map 和 Offset Map 来修正投影问题。

因此，实际项目中可以直接使用 Substance Painter；只有在需要引擎内烘焙、批量自动生成或特殊数据格式时，才有必要采用类似本章的方案。

## 基本烘焙流程

系统使用两个模型：

- **Reference Model**：高模，用于被射线求交并提供细节；
- **Working Model**：低模，决定最终渲染几何和输出纹理 UV。

对于输出纹理中的每个像素，系统可以：

1. 根据低模 UV 找到对应的低模表面位置；
2. 计算该位置的射线起点和方向；
3. 向高模发射射线；
4. 找到最近的相交三角形；
5. 使用交点的重心坐标插值高模属性；
6. 将法线、颜色、深度、AO 或其他数据写入输出纹理。

高模需要放入适合快速遍历的加速结构，例如 k-d tree 或其他空间层次结构。GPU 实现可以同时处理大量输出 texel，因此比传统 CPU 逐点烘焙更适合大规模并行。

## Cage、射线方向与偏移

低模和高模并不一定完全互相包围。若射线从低模表面直接发出，可能从高模内部开始，或者错过想要的高模表面。常见解决方案是使用 Cage，将高模完整包围，并从 Cage 附近发射射线。

本章进一步提供两个可控参数：

- **Skew Map**：在低模面法线与平滑顶点法线之间控制射线方向；
- **Offset Map**：在最小和最大偏移范围内控制射线起点，形成一种可绘制的局部 Cage。

只沿低模面法线发射射线容易在多边形边界产生不连续；只使用平滑法线又可能造成投影扭曲。Skew Map 让艺术家可以针对局部区域在两种方向之间调整。

## 常见问题

- 射线起点在高模内部，导致错误或漏命中；
- 面法线和平滑法线差异过大，引起烘焙细节偏斜；
- 凸角、孔洞等区域的平滑法线可能指向高模外侧；
- 分割烘焙区域后，某些区域可能无法访问其他参考几何；
- 不同软件使用的切线空间和左右手坐标系不一致，导致法线方向错误；
- 高低模不匹配时，即使射线求交正确，结果也可能不是艺术家期望的对应表面。

因此烘焙并不只是“发射射线并取最近交点”，射线起点、方向、Cage、切线空间和资源分区都需要共同控制。

## 输出类型与引擎集成

该方法可以生成多种纹理数据，例如：

- 切线空间法线；
- 世界空间法线；
- 深度和位置；
- 顶点颜色或材质属性；
- 环境光遮蔽；
- 漫反射或其他自定义着色数据。

由于输出由 GPU 管线控制，它可以直接适配引擎需要的纹理格式、通道布局和坐标约定。演示实现基于 C++、OpenGL 和 GPU 光线求交代码，并提供了可运行的示例工程。

## 代价与限制

- 需要构建和维护高模加速结构；
- GPU 光线求交管线本身仍需处理复杂几何和内存访问；
- 每个纹理像素的射线方向和 Cage 设置会影响结果质量；
- 复杂高模、超高分辨率输出和多种通道会增加计算时间；
- 它是烘焙工具管线，不会自动解决模型拓扑、UV 或材质创作问题；
- 与 Substance Painter 一样，良好的高低模匹配和 Cage 调整仍然非常重要。

## 本章结论

本章的核心是把传统高模到低模的离线烘焙过程，转化为可编程的 GPU 光线投射流程。它不是简单地写一个法线 Shader，而是完整处理低模 UV、射线起点、射线方向、高模求交、属性插值和输出纹理。

它的价值在于引擎集成、自动化批处理和自定义烘焙数据；对普通美术生产而言，Substance Painter 等成熟工具仍然更完整、更方便。
