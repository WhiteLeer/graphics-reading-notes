# 使用全局光照进行交互式电影级重光照

## 章节内容

本章讨论如何把离线电影制作中的全局光照重光照思路用于交互式应用。目标不是每帧完整求解高质量路径追踪，而是预先计算场景中较稳定的光传输信息，再在运行时改变光源、材质或曝光等参数，快速获得具有间接光照和颜色反弹的结果。

核心数据可以表示从光源到场景表面之间的传输关系，并通过层次化、低秩或基函数形式压缩。运行时只需更新光源参数并组合预计算的传输系数，就能近似得到直接光、间接光和多次反弹的变化。为了适应动态物体和镜头变化，还要结合可见性、反射方向、遮挡以及不同分辨率的缓存。

章节强调了电影级效果与实时预算之间的折中：预计算越丰富，运行时越灵活但存储和采样越昂贵；压缩越强，更新越快但可能丢失高频阴影和局部遮挡。方法适合可控、较稳定的场景光照重建，而不是完全替代实时光追或通用动态全局光照。

## 讨论与补充

### 电影渲染的迭代效率

电影通常按帧独立渲染，而不是把整个片段作为一次不可分割的计算。比如 5 秒、24 FPS 的镜头包含 120 帧，可以由渲染农场中的多个节点并行处理。如果只修改某一帧的问题，通常只需要重算对应帧；如果修改了影响整个镜头的灯光、材质或摄像机，则需要重新渲染受影响的全部帧，但仍然可以并行。

制作中不会每次都直接使用最终质量，而是先使用低分辨率、低采样率、代理模型和交互式渲染进行预览。曝光、颜色、部分雾效和合成等内容还可以通过 AOV 和后期合成调整，不必重新计算全部光照。灯光位置、阴影、GI、几何和体积模拟等会改变实际光传输的修改，通常需要重新渲染；如果修改了流体、烟雾或破碎模拟，还可能需要重新缓存模拟结果。

### 电影路径追踪与 3A 游戏

高质量电影渲染大量使用 Monte Carlo 路径追踪或其变体，以处理多次间接光照、软阴影、反射折射、体积散射、景深、运动模糊、毛发和次表面散射等效果。但“物理正确”并不意味着完全没有近似，制作中仍会限制反弹次数、使用重要性采样和光照缓存、降噪、代理几何、AOV 调整以及艺术化补光。

电影与 3A 游戏的主要差别是时间预算：电影一帧可以渲染数分钟甚至数小时，而游戏通常需要在约 16.7 毫秒内完成一帧 60 FPS 的画面。因此游戏通常混合使用光栅化、烘焙光照、光照探针、屏幕空间算法、时域重建和实时光追。游戏在固定镜头中可以通过预计算和艺术调整接近电影效果，但在自由摄像机、动态物体和实时光照变化方面受到更严格的预算限制。

### 离线渲染器与 C4D、Houdini

C4D 和 Houdini 是 DCC 工具，而 Arnold、V-Ray、Redshift、Karma、Cycles 等才是具体的渲染器。C4D 更常用于建模、动画和运动图形，Houdini 更擅长程序化建模、流体、烟雾、破碎和其他复杂模拟；最终画质主要取决于渲染器、材质、灯光、采样、颜色管理和后期流程。

如果使用相同的渲染器、材质、灯光和参数，C4D 与 Houdini 可以得到接近的最终图像。二者的主要差异通常来自场景转换、体积和毛发实现、模拟缓存以及工具工作流，而不是软件名称本身。

### 本章方案所处的位置

本章讨论的交互式电影级重光照不是用实时渲染完全替代离线路径追踪，而是预先计算较稳定的光传输信息，再在运行时快速改变光源并重建近似的间接光照：

```text
预计算光线传输
→ 压缩为系数或基函数
→ 运行时改变光源
→ 快速重建近似光照
```

它位于实时渲染和离线渲染之间：比完整实时路径追踪更容易达到稳定性能，比普通实时光照具有更丰富的间接光照，但对动态几何、任意遮挡和高频光照变化的适应性较弱。
