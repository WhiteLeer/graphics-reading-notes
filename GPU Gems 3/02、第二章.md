# 动画人群渲染

## 章节内容

本章讨论如何在不为每个角色分别提交完整骨骼动画数据和绘制调用的情况下，渲染大规模动画人群。核心思路是把角色动画表示成可以被 GPU 批量访问的数据，并让顶点着色器根据实例参数恢复当前角色的姿态。

一种重要方案是把预计算的骨骼动画烘焙为纹理。纹理的行或列保存不同时间、不同骨骼的变换矩阵，实例数据保存动画索引、时间偏移、播放速度、缩放和世界变换。渲染时，顶点着色器按顶点的骨骼权重采样动画纹理，完成蒙皮，并通过实例化一次绘制大量角色。不同角色可以使用不同动画起点和速度，从而避免整齐同步。

为了让人群更自然，本章还讨论随机选择动画、LOD、距离相关的简化、角色朝向和可见性处理。远处角色可以减少骨骼数量、降低更新频率，甚至切换成公告板或预渲染动画；近处角色则使用更完整的蒙皮和材质。关键是让动画数据共享，同时把每个实例之间真正不同的少量参数放进实例缓冲区。

这种方法把大量角色的姿态计算转移到 GPU，但动画资源仍需要离线整理、压缩和布局；纹理带宽、骨骼采样、顶点数量、透明材质 overdraw 以及实例剔除仍然可能成为瓶颈。

## 讨论与补充

### 骨骼动画纹理与 VAT

本章的骨骼动画纹理与 VAT 在思路上相近：都是把动画数据放到 GPU 可访问的纹理中，再由顶点着色器采样，从而减少 CPU 逐角色更新和提交数据的工作。但二者保存的数据不同。

- 骨骼动画纹理保存的是每个动画帧、每根骨骼的变换矩阵；顶点仍然保存骨骼索引和权重，运行时由顶点着色器完成蒙皮。
- 传统 VAT 通常保存每个动画帧中每个顶点的最终位置，必要时还保存法线；顶点着色器直接采样结果，不再执行骨骼蒙皮。

因此，骨骼动画纹理保留了骨骼结构，数据量通常更容易在多个顶点之间共享，也更适合角色动画；VAT 的顶点着色器更简单，但动画通常是离线烘焙好的，运行时进行骨骼混合、IK、重定向等操作会更不灵活。

### 不同角色如何使用动画数据

不同角色不一定需要采样不同的纹理。更常见的方式是让角色共享同一张动画纹理或纹理图集，然后通过实例数据选择不同的动画区域和播放状态，例如：

```text
AnimationID
FrameOffset
PlaySpeed
RandomSeed
WorldMatrix
```

顶点着色器根据动画 ID、当前时间、播放速度和时间偏移，计算当前应该采样的帧。这样同一批角色可以播放不同动作、从不同帧开始、使用不同速度，避免整齐同步，同时继续共享网格、材质和动画资源。

只有在角色使用不同骨骼结构、动画集合或无法放入同一纹理图集时，才通常使用不同的动画纹理。角色外观差异则可以由材质、纹理数组、颜色或材质 ID 单独控制。

### GPU 蒙皮与 GPU 动画

“GPU 蒙皮”只说明顶点变形在 GPU 上完成，并不意味着一定使用骨骼矩阵纹理。常见实现包括：

1. CPU 计算骨骼矩阵，上传到 Constant Buffer、Structured Buffer 或纹理，GPU 顶点着色器根据骨骼索引和权重完成蒙皮。
2. 将预计算的骨骼矩阵烘焙为动画纹理，由 GPU 根据动画时间和骨骼编号采样，再完成蒙皮。本章的人群渲染方案属于这一类。
3. 使用计算着色器在 GPU 上计算骨骼姿态，再由 GPU 完成蒙皮，这才是更完整意义上的 GPU 动画。

因此，GPU 蒙皮、GPU 动画、骨骼矩阵纹理和 VAT 是相关但不同层级的概念：GPU 蒙皮描述计算位置，GPU 动画描述动画计算位置，骨骼矩阵纹理描述一种数据存储方式，而 VAT 描述直接存储最终顶点动画结果的方案。
