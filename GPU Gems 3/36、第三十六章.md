# GPU 上的 AES 加密与解密

## 章节内容

本章探讨把 AES 对称分组密码映射到 GPU。AES 以 128 位数据块和 128、192 或 256 位密钥工作，经过多轮 SubBytes、ShiftRows、MixColumns 和 AddRoundKey；解密使用对应的逆变换。过去 GPU 主要面向浮点，整数、位运算和非图形输出不方便，GeForce 8 系列新增的整数算术、AND/OR、移位、整数索引表和 transform feedback 改善了这一点。

实现中由 CPU 生成 key schedule，GPU 对大量独立数据块并行执行 AES 轮函数，并用纹理/缓冲区查表和 transform feedback 写回结果。章节比较不同 block-cipher operation mode 的并行性：ECB 等模式的块之间独立，适合同时处理；依赖前一块结果的链式模式会限制并行度，需要改变组织方式或使用适合并行的模式。

GPU 并不天然适合所有加密任务。密钥调度、表访问、整数指令、数据传输、输出回读和安全性都会影响收益；小数据量或强串行模式可能无法抵消 PCIe 和调度开销。本章的价值也在于展示 GPU 从图形浮点处理转向整数流处理时，哪些硬件能力和数据流设计是必要的。

## 讨论与补充

### 本章在讲什么

本章不是专门讨论游戏资源保护，而是把 AES 作为一个 GPU 通用计算案例，研究如何将传统上在 CPU 上执行的整数、位运算和查表密集型算法改造成适合 GPU 批量并行的程序。

AES 以 128 bit（16 字节）为基本数据块，经过 `SubBytes`、`ShiftRows`、`MixColumns` 和 `AddRoundKey` 等多轮变换。通常由 CPU 生成主密钥并完成 Key Schedule，得到每轮使用的 Round Key，再将大量相互独立的数据块交给 GPU：

```text
CPU 生成 Round Keys
→ 上传大量数据块
→ 一个 GPU 线程处理一个数据块
→ GPU 并行执行 AES 轮函数
→ 写回密文
```

### 工作模式与并行性

AES 本身只处理单个 16 字节块，长数据需要通过工作模式连接多个块。ECB 中各块互不依赖，容易并行；CBC 加密中当前块依赖前一块结果，并行性较差；CTR 中每个块使用独立计数器，适合并行；GCM 的 CTR 加密部分也可以并行化，并额外提供完整性校验。

因此，GPU 是否适合 AES 不只取决于 AES 轮函数，还取决于数据块之间是否存在依赖关系。

### GPU 加密的适用条件

GPU 批量 AES 适合大量相互独立的数据块，例如批量数据处理或科学计算。少量数据通常不适合专门上传 GPU，因为 PCIe 传输、Kernel 调度、结果回读和同步开销可能超过加密本身；密钥和明文进入 GPU 显存也会带来额外的安全考虑。

本章的更大意义是展示 GPU 不仅可以执行图形和浮点运算，也可以通过整数运算、位运算、查表和数据流处理执行密码算法。但它并不意味着所有 AES 任务都应该放到 GPU，现代 CPU 通常已经具有 AES-NI 或 ARM AES 扩展，普通游戏资源解密一般仍由 CPU 或专用硬件完成。
