# 使用 CUDA 进行高速 N-body 模拟

## 章节内容

本章以天体引力为例，讨论 N-body 问题的 all-pairs 计算：每个物体都要计算其他所有物体对它的作用力，直接方法复杂度为 O(N²)。它也可用于分子动力学、电磁力、流体和全局光照等。对于大规模系统，all-pairs 常作为近场精确计算内核，与 Barnes-Hut、快速多极子法或 particle-mesh 等远场近似结合。

CUDA 实现把每个目标物体映射到线程，并让线程遍历所有源物体。通过把一小块源数据加载到 shared memory，让一个 block 中的线程重复使用数据，减少全局内存读取；连续访问、循环展开、寄存器保存目标状态、合理选择 block 大小和内存布局帮助 GPU 保持计算单元满载。每次交互计算距离、平方根倒数、力和积分更新。

该问题具有规则的并行结构和较高的计算强度，适合 GPU。性能受 N、shared memory 使用、寄存器、复杂数学指令和内存带宽影响；全对全算法仍有二次复杂度，规模继续扩大时必须切换到层次化或近似算法。

## 讨论与补充

### CUDA、CUDA Core 与 Compute Shader

CUDA 不是硬件通用并行计算单元，而是 NVIDIA 提供的 GPU 通用计算平台，包含编程模型、API、编译器、运行时和工具链。CUDA Core 才是 NVIDIA GPU 中用于执行普通整数和浮点算术的一类硬件执行单元，并且 CUDA 线程并不与 CUDA Core 永久一一绑定，而是由 SM 以 Warp 为单位调度。

Compute Shader 则是 DirectX、Vulkan、OpenGL 等图形 API 提供的 GPU 通用计算程序。在 NVIDIA 显卡上，Compute Shader 最终通常也会运行在 GPU 的 SM 上，并使用 CUDA Core 等执行资源，但它并不是通过 CUDA Runtime 或 CUDA Kernel 执行的：

```text
HLSL / GLSL Compute Shader
→ DXIL / SPIR-V 等中间表示
→ 图形 API 与显卡驱动
→ NVIDIA GPU 的 SM 和执行单元
```

因此 CUDA Kernel 和 Compute Shader 可以共享底层 GPU 硬件，但属于不同的软件接口和资源模型。CUDA 更适合 NVIDIA 生态中的通用科学计算、数值计算和专用 GPU 库；Compute Shader 更容易与纹理、Render Target、渲染管线和游戏引擎结合。

其他厂商和平台也有各自的 GPU 计算接口，例如 AMD 的 ROCm/HIP、跨厂商的 OpenCL 和 Vulkan Compute，以及 Apple 的 Metal Compute，并不都是使用 CUDA 或 CUDA Core。
