# GPU 上的实时刚体模拟

## 章节内容

本章把大量刚体模拟转移到 GPU。它不直接对每个刚体的三角网格做复杂碰撞，而是把一个刚体表示为一组大小相同的粒子，再通过粒子集合近似形状。刚体的平移和旋转由质心、线性动量、角动量和四元数更新；粒子位置由刚体变换得到，碰撞反应则作用到相应刚体的动量。

每次迭代大致包括：计算粒子物理量、生成空间网格、检测和响应碰撞、计算动量、更新位置和旋转。空间网格用于把附近粒子放到同一单元，减少不必要的全局比较；物理状态以纹理等 GPU 数据结构保存，避免每帧在 CPU 与 GPU 间往返。粒子化的表示还可以自然扩展到颗粒、流体和刚体与非刚体的耦合。

这种方案以精度换取并行度和吞吐：球粒子近似可能无法准确表示薄片、尖角和复杂接触，窄相碰撞仍可由更精确的方法补充。碰撞约束、排序、网格冲突和迭代次数决定稳定性；GPU 版本适合大量相似对象，但不一定适合少量复杂刚体或强依赖 CPU 游戏逻辑的场景。

## 讨论与补充

### 计算着色器中的原子操作

计算着色器通常支持原子操作，用于多个线程同时读写同一个共享位置的场景。原子操作不会减少实际操作数量，而是保证一次读—改—写不会被其他线程插入。例如 10 个线程执行：

```hlsl
InterlockedAdd(counter[0], 1);
```

最终结果仍然是增加 10 次，只是这些针对同一地址的修改需要由硬件协调，效果等价于以某种顺序完成，因此高竞争情况下可能出现局部串行化。

原子操作可以用于计数、空间网格统计、生成碰撞对、申请输出数组位置、直方图和碰撞标记。常见形式包括 `InterlockedAdd`、`InterlockedMin`、`InterlockedMax`、`InterlockedExchange` 和 `InterlockedCompareExchange`。

### 原子操作不保证线程顺序

如果多个线程对同一个位置写入不同值，例如：

```hlsl
InterlockedExchange(value[0], threadID);
```

原子操作只保证每次写入不可拆分，不保证哪个线程先执行、哪个线程最后执行。最终值可能是任意一个线程写入的值，因为 GPU 不保证按线程 ID、线程组或 Dispatch 顺序执行。

`InterlockedCompareExchange` 可以实现“第一个成功者获胜”，但这里的“第一个”是最先完成原子操作的线程，不一定是线程 ID 最小的线程。若只需要确定的最小值或最大值，可以使用 `InterlockedMin` 或 `InterlockedMax`，因为结果与线程执行顺序无关。

如果需要稳定的数组顺序，不能只依赖原子计数器。原子计数器可以为线程分配唯一位置，但不能保证位置按线程 ID 排列。此时通常使用 Prefix Sum、排序或多 Pass 算法。内存屏障只能保证阶段之间的写入可见性，不能让同一阶段的线程按照指定顺序执行。

因此可以区分：

```text
原子操作：避免共享地址的修改丢失
内存屏障：保证不同阶段的数据可见性
Prefix Sum / Sort：建立稳定顺序
```
