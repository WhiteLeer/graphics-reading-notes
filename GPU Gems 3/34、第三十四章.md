# 使用单遍 GPU 四面体扫描转换计算有符号距离场

## 章节内容

本章用 GPU 加速 Signed Distance Field（SDF）的预计算。SDF 在规则三维网格中保存每个点到网格表面最近距离，并用符号区分内外。它可用于布料和软体碰撞、刚体与可变形体交互、建模、光线步进、路径规划和碰撞查询。

算法把三角网格周围的窄带区域表示为由四面体组成的 shell。CPU 根据三角形、边和顶点的 Voronoi 区域构造四面体，并按 z 方向排序；GPU 逐层扫描 z 平面，把与当前平面相交的四面体切片并栅格化。片元程序计算体素到对应几何特征的带符号距离，并把绝对距离写入深度缓冲，用深度测试保留绝对值最小的候选。

符号判断依赖角度加权伪法线，可处理存在孔洞、翻面、重叠面等不理想输入，但伪法线错误时仍不能保证符号正确。方法只计算用户指定的窄带，且逐 z 层读回数据；四面体重叠越多，冗余计算和带宽越大。它以较简单的几何扫描换取 GPU 加速，适合离线或预处理，不是任意动态网格每帧重建 SDF 的免费方案。

## 讨论与补充

### 运行时解析 SDF 与预生成 SDF 体数据

SDF 在 GPU 上使用有两种不同含义。像 `Crystal_SDF.shader` 中的 `BoxSdf`、`Map` 和 `Trace`，属于运行时直接评估解析 SDF：每个屏幕像素沿相机射线步进，每一步调用距离函数，根据返回距离前进，直到找到表面；法线也通过多次 SDF 采样估计。这种方案不保存三维 SDF 纹理，SDF 是按需由数学函数计算出来的。

本章研究的是另一类问题：输入不是已知的盒子、球体等解析函数，而是任意三角形网格。算法需要把网格转换成三维体数据：

```text
三角形网格
→ 3D 体素网格
→ 每个体素保存到表面的带符号距离
→ 3D SDF Texture / Buffer
```

之后粒子、碰撞、体积效果或其他 Shader 可以直接执行：

```hlsl
distance = SampleSDF(worldPosition);
```

而不必每次遍历复杂网格的所有三角形。第三十四章使用 GPU 四面体扫描转换、深度测试和伪法线等方法生成这份可复用数据，并重点处理窄带、符号判断、孔洞和重叠面等问题。

两类方案的区别是：

```text
解析 SDF：GPU 评估距离函数
网格 SDF：GPU 生成并保存距离场，之后反复采样
```

解析 SDF 内存开销低、适合已知的程序化形状，但复杂网格难以直接写出函数；预生成 SDF 适合任意模型和多系统复用，但需要 3D Texture/Buffer 的内存，并受到体素分辨率、窄带范围、更新成本和生成误差的限制。因此，本章并不是否定在 Shader 中直接写 SDF，而是解决“如何从任意网格生成可重复查询的 SDF 数据”。
