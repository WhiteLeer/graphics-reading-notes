# 使用 GPU 生成复杂的程序化地形

## 章节内容

本章把地形看作一个由密度函数定义的三维等值面，而不是只能表示山丘的二维高度场。对任意世界坐标，密度函数返回一个值：正值表示实体内部，负值表示空气，零值构成地形表面。这样可以表达洞穴、悬挑和其他任意拓扑结构。

实现上，场景被划分为固定大小的三维 block，每个 block 再划分为体素。GPU 先在三维纹理中计算体素角点的密度，再使用 Marching Cubes 根据密度符号和查表结果生成三角形。章节比较了逐体素生成、先列出非空体素再生成索引等方案，并使用 geometry shader、stream output 和可复用的顶点缓冲池把结果保存在 GPU 可直接绘制的网格中。

运行时只维护当前视锥附近需要的 block：根据包围盒进行剔除、按距离排序、复用远处 block 的缓冲区，并通过查询判断空 block，避免反复生成没有三角形的区域。生成的顶点还可以携带世界位置、法线和环境遮蔽等数据。

由于任意拓扑表面难以使用单一 UV，本章使用三平面投影，根据法线方向选择或混合三个主轴投影来减少拉伸。地形的材质、法线、环境遮蔽、LOD 和外部物体交互也都在 GPU 生成的几何基础上完成。

## 讨论与补充

### 三平面投影与其他无 UV 贴图方式

不依赖 UV 的贴图不只有三平面投影。模型坐标、世界坐标只是生成采样位置的坐标来源；将坐标转换为二维贴图坐标的方式还可以是平面投影、三平面投影、球面投影或圆柱投影。

例如直接使用 `worldPos.xz` 是世界空间的 XZ 平面投影，适合地面，但墙面容易产生拉伸；使用 `objectPos.xz` 则是模型空间投影，纹理会随物体移动。三平面投影会分别使用 YZ、XZ、XY 三个平面采样，再根据世界法线三个分量的绝对值进行混合：表面朝向 X 轴时主要使用 YZ 投影，朝向 Y 轴时主要使用 XZ 投影，朝向 Z 轴时主要使用 XY 投影。

三平面投影适合本章这种任意拓扑的程序化地形，因为洞穴、悬挑和垂直墙面很难提前制作统一 UV。代价是通常需要多次纹理采样，且法线贴图不能像颜色一样直接混合，需要先转换到统一空间。

### 密度场、SDF 与 Marching Cubes

本章不是把整个场景直接转成体素并逐体素绘制，而是用密度函数描述三维空间：

```text
density > 0：实体内部
density < 0：空气
density = 0：地形表面
```

每个体素 cell 的八个角点都会计算 density。如果八个角点全在同一侧，通常认为表面没有穿过该 cell；如果正负混合，说明零等值面穿过了 cell。Marching Cubes 根据八个角点的内外状态组成 8 位索引，再查预先定义的拓扑表，确定哪些边被表面穿过、应该生成哪些三角形。边上的交点根据两端 density 做线性插值，最终得到普通三角形网格。

密度函数不一定是真正的 SDF。它只需要能表达内外关系；真正的 SDF 还要求数值近似表示点到最近表面的距离。因此，本章的密度场和 SDF 都属于隐式标量场，但不能默认二者完全等价。

### 与 Ray Marching 方案的区别

此前讨论的 [SDF/Ray Marching 方案](codex://threads/019e6364-b295-7ae2-b10e-e15ab6e5f126) 与本章共享“用三维隐式函数表示表面”的思想，但后续处理不同：

```text
GPU Gems 3：密度场 → Marching Cubes → 三角形网格 → 光栅化
Ray Marching：SDF → 沿射线步进 → 直接计算像素颜色
```

Ray Marching 不生成网格，通常要求函数值具有距离含义，才能安全地用 SDF 值决定步长；Marching Cubes 只需要判断等值面是否穿过体素。前者适合程序化特效和隐式物体，后者可以得到普通网格，从而参与碰撞、阴影、深度和常规渲染管线。

### 可见范围与地形流式生成

只生成当前视锥附近的 block，并不意味着远景永远不可见。相机移动时，系统会生成新进入视野的 block，回收离开视野的 block，并复用有限的顶点缓冲。实际还可以使用较低分辨率的远景 block、LOD、clipmap 或 impostor 扩大可视范围。

这种方案的主要价值，是解决高度场只能表示 `height = f(x, z)`、无法表示洞穴和悬挑的问题；代价是密度采样、Marching Cubes、网格管理、分辨率、LOD 接缝和生成开销都会变得更复杂。普通没有洞穴需求的地形，传统高度图加分块网格和 LOD 往往更简单。
