# 使用层次遮挡剔除和几何着色器实现高效稳健的阴影体

## 章节内容

本章重新研究 stencil shadow volume。阴影体由遮挡物沿光源方向挤出形成，利用模板缓冲区统计观察射线穿过阴影体的次数。相比阴影贴图，阴影体不依赖光源空间的纹素分辨率，因此不会出现同类的投影锯齿，但传统实现会产生大量挤出几何和 CPU/GPU 提交开销。

章节使用 geometry shader 在 GPU 上根据模型边和光源关系生成阴影体，并用层次遮挡查询判断阴影体或其部分是否可能影响当前视图。层次结构允许先测试粗包围体，再细化到更小的节点；完全被遮挡或不可能影响屏幕的部分可以跳过。算法还要正确处理 z-pass、z-fail、前后面、闭合网格、摄像机位于阴影体内部以及无限远挤出顶点等边界情况。

该方法的价值在于结合模板阴影体的无纹素锯齿特性与 GPU 生成、遮挡剔除和批处理。它对复杂模型、开放网格、动态光源和 stencil 带宽仍较敏感，因此需要严格的几何约束和实际场景测试。

## 讨论与补充

### 阴影体与阴影贴图

阴影体不是一张纹理，而是将遮挡物的轮廓沿远离光源的方向挤出，形成一个三维体积。摄像机看到的片元如果位于这个体积内部，就认为它处于阴影中。

经典实现使用模板缓冲统计观察射线穿过阴影体的次数：进入阴影体时增加模板值，离开时减少模板值，最后模板值不为零的区域就是阴影区域。常见算法包括 Z-Pass 和用于处理摄像机位于阴影体内部情况的 Z-Fail（Carmack's Reverse）。

阴影贴图则是在光源视角下渲染深度图，正常渲染时比较接收点在光源空间中的深度与阴影贴图中的深度。二者的主要差异是：阴影贴图受纹素分辨率、投影分布和 Bias 影响；阴影体不依赖阴影贴图分辨率，轮廓理论上更精确，但需要生成和绘制额外几何。

阴影体天然更适合硬阴影。它的主要成本和限制包括：

- 需要处理遮挡物轮廓并挤出额外几何；
- 阴影体覆盖屏幕面积较大时，模板测试和填充成本可能很高；
- 点光源、开放网格、摄像机进入阴影体和无限远挤出需要特殊处理；
- Alpha Test 的树叶、栅栏等几何很难生成准确的阴影体；
- 软阴影需要多次光源采样或多个阴影体，扩展不如 PCF、PCSS 方便。

### Per-Object Shadow

Per-Object Shadow 通常仍然属于阴影贴图方案：为某个角色或物体单独生成高分辨率阴影贴图，或者将它放入专用 Shadow Atlas，再在正常渲染时采样。它并不因为“每个物体单独处理”就变成阴影体。

因此可以这样区分：

```text
Per-Object Shadow：单独管理某个物体的阴影贴图
Shadow Volume：由遮挡物几何体挤出的阴影体积
```

现代游戏通常更偏向阴影贴图、虚拟阴影贴图和实时光追，因为它们更容易支持大范围场景、软阴影、植被 Alpha Test 和现有光照管线。阴影体仍可用于特定的硬阴影、小范围点光源或对轮廓精度要求较高的场景。
