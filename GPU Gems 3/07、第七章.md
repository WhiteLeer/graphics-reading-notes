# GPU 上基于点的 Metaball 可视化

## 章节内容

本章使用表面粒子直接可视化 Metaball 的隐式曲面，而不是先用 Marching Cubes 生成三角网格。Metaball 由隐式函数定义，多个球的场函数叠加后形成平滑融合的流体表面。系统把大量粒子约束在隐式函数等值面附近，让粒子覆盖表面并在屏幕上形成连续外观。

每个粒子需要计算隐式函数及其梯度：函数值用于把粒子推回目标等值面，梯度用于获得法线和移动方向。为了让片元着色器快速求值，章节设计了适合 GPU 的数据结构来组织 Metaball 影响范围。表面粒子还需要尽量均匀分布，因此采用并行友好的位置更新方法，利用粒子上一帧位置的时间连贯性，只做小范围修正，而不是每帧从零寻找整张表面。

渲染阶段可将粒子作为带深度的点或小面片，通过混合、深度处理和法线重建把离散粒子显示为平滑曲面。方法的优势是利用时间连贯性和 GPU 并行，避免每帧重新生成网格；代价是粒子数量与表面积相关，覆盖不足时会出现孔洞或颗粒感。

## 讨论与补充

### Metaball 是什么

Metaball 通常译为“融球”或“元球”。它不是把多个普通球体的三角网格直接做布尔并集，而是使用隐式场函数表示表面。空间中的每一点都有一个由附近 Metaball 共同产生的影响值：

```text
F(p) = f1(p) + f2(p) + ...
```

当影响值达到某个阈值时，该点被认为位于表面上：

```text
F(p) = T
```

两个 Metaball 靠近时，它们的影响场会叠加，等值面会自然连接，因此看起来像液滴、黏土或蜡球彼此融合。它属于隐式曲面，不像普通网格那样直接保存完整的顶点和三角形。表面法线可以由场函数的梯度得到：

```text
normal = normalize(gradient(F(p)))
```

### 本章与 Marching Cubes 的区别

一种常见流程是：

```text
Metaball 场函数
→ 体素采样
→ Marching Cubes
→ 三角网格
→ 光栅化
```

本章不在每一帧重新生成完整三角网格，而是维护大量位于隐式曲面附近的粒子。GPU 根据场函数和梯度修正粒子位置，并将粒子作为带深度的点或小面片进行渲染，使它们共同覆盖出连续的表面。

这种方法避免了 Marching Cubes 的网格生成和上传，但需要粒子分布足够均匀、数量足够多；否则会出现孔洞、颗粒感或表面覆盖不足。因此，本章的重点不是重新定义 Metaball，而是利用 GPU 粒子直接可视化 Metaball 的隐式曲面。
