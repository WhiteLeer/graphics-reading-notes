# 线性空间的重要性

## 章节内容

本章说明为什么实时渲染中的光照、混合、纹理过滤和图像处理应当在线性空间进行。显示器和许多颜色纹理通常使用 sRGB 等非线性编码来更有效地表示感知亮度；sRGB 值不能直接当作物理线性光强参与加法、插值、alpha 混合或光照计算。

正确流程是：读取颜色纹理时进行 sRGB 到线性的解码，在 shader 中在线性空间计算材质、光照、混合和滤波，写入显示或存储为 sRGB 的目标时再编码。法线、金属度、粗糙度、遮罩、深度等数据不是颜色，通常应以线性数据读取。HDR 渲染目标一般保存线性高动态范围值，tone mapping 和曝光位于线性 HDR 处理之后、最终显示编码之前。

如果混用空间，会产生过暗或过亮的混合结果、错误的渐变、错误的 mipmap 过滤、错误的 bloom/blur 和不正确的光照能量。章节还讨论纹理格式、硬件 sRGB 转换、预乘 alpha、帧缓冲、后处理以及艺术资源导入设置，强调颜色空间必须在整条资源到显示链路中保持一致。

## 讨论与补充

### Unity 项目中的 Linear 与 Gamma 设置

Unity 的 `Color Space = Linear/Gamma` 会影响整条颜色链路，而不只是最终显示格式。

Linear 模式下，典型流程是：

```text
sRGB 颜色纹理
→ 采样时解码为 Linear
→ 在线性空间进行光照、混合、滤波
→ HDR 与 Tone Mapping
→ 输出时编码为 sRGB
```

它会影响颜色纹理采样、光照和 PBR 计算、Alpha 混合、纹理过滤、Mipmap、Bloom、模糊、Lightmap、Light Probe、反射探针以及最终颜色输出。Gamma 模式则通常直接使用存储在 Gamma/sRGB 编码空间中的颜色进行计算，因此光照、混合和后处理的结果可能不符合线性光照规律。Linear 通常能够提供更准确的渲染结果，Gamma 主要用于旧项目、旧硬件或平台兼容。

### 哪些纹理使用 sRGB

在 Linear 项目中，sRGB 标记通常只用于颜色纹理：

```text
Albedo / Base Color：开
普通颜色纹理：开
Normal：关
Metallic / Roughness / AO / Mask：关
Height / Depth：关
HDR 环境图和其他线性数据：通常关
```

颜色纹理在采样时需要从 sRGB 解码到 Linear；法线、粗糙度、金属度、遮罩、深度和 HDR 数据是数值数据，不能进行颜色解码。Tone Mapping 也不能替代 sRGB 编码：Tone Mapping 负责将线性 HDR 压缩到显示范围，最终仍需要进行 sRGB 或其他显示输出编码。

### 切换颜色空间的影响

从 Gamma 切换到 Linear 后，需要重新检查材质颜色、灯光强度、后处理参数、透明混合和 UI。烘焙光照通常也需要重新生成 Lightmap、Light Probe 等数据，因为光照计算和纹理采样的颜色空间发生了变化。现代 GPU 通常可以硬件完成 sRGB 采样和输出转换，因此 Linear 模式的额外成本一般不大，选择它主要是为了正确性和一致性，而不是为了追求转换开销上的节省。
