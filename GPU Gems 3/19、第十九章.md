# Tabula Rasa 中的延迟渲染

## 章节内容

本章总结 MMO 游戏 Tabula Rasa 中采用延迟渲染的工程经验。延迟渲染把几何和材质信息写入 G-buffer，再在后续光照阶段读取这些信息计算光照，从而把几何复杂度与光照成本分离。光源 shader 只处理可见像素，避免前向渲染中对同一物体多次执行复杂光照。

工程上需要设计材质 shader 与光源 shader 的边界、MRT 格式、深度和边缘处理、阴影贴图、光源体积、法线和材质参数编码。延迟管线的优点是多光源可扩展、光照代码与材质代码分离、光源类型容易增加；缺点是 G-buffer 带宽和显存开销高、硬件全屏 MSAA 不易直接使用、材质通道有限，并且最近片元式 G-buffer 无法表示真正的 alpha blending。

因此 Tabula Rasa 同时维护延迟和前向管线：不透明几何优先走延迟渲染，透明物体走前向渲染，低端硬件也可以使用完整前向路径。章节还讨论了阴影、折射、边缘抗锯齿、内存占用、不同 Shader Model 的兼容性，以及在实际游戏中选择双管线的原因。
