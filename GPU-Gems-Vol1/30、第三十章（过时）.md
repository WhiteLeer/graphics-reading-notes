# FX Composer

## 1. 这章在讲什么

FX Composer 是 NVIDIA 当年的 Shader / 材质开发工具，可以理解成：

```text
Shader 编辑器
    + 材质参数面板
    + 模型与场景预览
    + 纹理查看器
    + Shader 编译器
    + 性能分析工具
    + 插件系统
```

它的目标是让程序员和技术美术修改 `.fx` 文件、调节材质参数，并立即在模型上查看效果。

## 2. 和现代工具的关系

FX Composer 的需求现在已经被成熟引擎和 DCC 工具内置：

```text
FX Composer
≈ Unity Shader Graph / Material Inspector
  + Shader 编译与变体管理
  + 模型预览
  + Shader 调试工具
  + 编辑器扩展系统
```

具体的 `.fx`、Cg、Direct3D 9 和 COM 实现已经过时，不需要按照现代 Unity 的方式逐行对应。真正值得保留的是工具架构和工作流思想。

## 3. Effect 和 Material

书中把 Effect 文件和 Material 实例分开：

```text
Effect 文件
    = 材质类型 / Shader 模板

Material
    = Effect 的一次具体实例
```

例如同一个 `cartoon.fx` 可以生成：

```text
Material A：diffuseColor = 红色
Material B：diffuseColor = 蓝色
```

这对应现代 Unity 中：

```text
Shader   -> Shader
Effect 实例 -> Material
```

多个材质可以共享同一个 Shader，但拥有各自的参数和纹理。

## 4. Technique 和 Shader Variant

一个 Effect 可以包含多个 Technique：

```text
Technique A：高质量
Technique B：低质量
Technique C：旧硬件兼容
```

运行时根据显卡能力选择可用 Technique。这和现代 Shader Variant、Keyword、SubShader、Pass 的目标类似：为不同功能和硬件准备不同实现。

## 5. 参数反射和属性面板

FX Composer 能从 Effect 中读取参数信息：

```text
参数名：BumpHeight
类型：float
默认值：0.1
范围：0~1
说明：法线扰动强度
```

然后自动生成 Properties 面板。

现代 ShaderLab 中的：

```shaderlab
_BumpHeight ("Bump Height", Range(0, 1)) = 0.1
```

就体现了同类思想。Shader 参数携带名称、类型、范围和说明，编辑器据此生成 UI。

## 6. 插件系统

FX Composer 把很多功能设计成插件：

- 场景导入器；
- 网格生成器；
- 材质；
- 几何处理节点；
- 参数面板；
- 文件格式；
- Shader 工具；
- 自定义窗口。

插件只要实现约定接口，就可以被工具发现和加载。

这对应现代 Unity 的：

- Editor Extension；
- Package；
- Scripted Importer；
- Custom Inspector；
- Shader GUI；
- Render Pipeline Extension。

## 7. 连接参数和动画

工具中的参数可以连接到：

- 时间；
- 相机；
- 光源；
- 骨骼；
- 动画曲线；
- 其他场景对象。

例如：

```text
时间 -> 火焰扰动参数
光源位置 -> 材质光照方向
动画曲线 -> Bump Height
```

这和现代引擎中的 Material Property、Animator、Timeline、Shader 全局参数绑定有相似思想。

## 8. 逻辑材质和 GPU 资源分离

FX Composer 允许多个窗口同时显示同一个逻辑材质。材质参数与具体 Direct3D Device 的 GPU 资源分开：

```text
逻辑材质参数
    -> Device A 的 GPU 材质
    -> Device B 的 GPU 材质
    -> Device C 的 GPU 材质
```

这体现了：

```text
Asset / Material 数据
    ≠
具体 GPU 资源实例
```

现代引擎也会区分资源描述、材质对象、运行时 GPU 资源和不同渲染上下文。

## 9. Geometry Pipe

Geometry Pipe 可以理解为几何数据处理链：

```text
基础 Mesh
    -> 添加法线
    -> 添加切线
    -> 添加蒙皮数据
    -> 添加毛发几何
    -> 修改顶点属性
    -> 生成 Vertex Buffer
```

它允许插件在网格送入 Shader 前修改几何数据，思想上接近现代的 Mesh Processing、Procedural Mesh 和导入管线。

## 10. 蒙皮兼容策略

当模型和 Shader 的蒙皮需求不一致时，FX Composer 提供了几类兼容方式：

- 模型有骨骼、Shader 不需要：先在 CPU 蒙皮，再交给普通 Shader；
- Shader 需要骨骼、模型没有：给顶点设置单一权重和当前变换矩阵；
- 模型和 Shader 都支持：直接传递骨骼索引、权重和矩阵，由 GPU 蒙皮。

这和现代引擎在导入、CPU 蒙皮、GPU 蒙皮之间做兼容选择的思想一致。

## 11. 工程上的结论

- FX Composer 的具体功能现在大多已经被 Unity、Unreal 和 DCC 工具内置。
- `.fx`、Cg、Direct3D 9、PBuffer 和 COM 代码主要具有历史意义。
- 仍然值得保留的思想是：Shader 可实时预览、参数可反射、Material 是 Shader 模板的实例、工具可插件化，以及逻辑资源和 GPU 资源分离。
- 这一章不需要深入记忆具体 API，可以作为“图形工具架构和 Shader 工作流”的历史案例。
