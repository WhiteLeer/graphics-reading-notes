# 过滤核

## 1. 过滤和 Kernel

过滤的目标是根据输入图像 `A` 生成输出图像 `B`。输出图像中的一个像素，往往由输入图像附近的多个像素按照一定权重组合得到：

```text
B(x, y) = A 邻域像素的加权组合
```

邻域的形状、采样位置和权重集合叫作 **Filter Kernel（过滤核）**。在 Shader 中，典型形式是：

```hlsl
result =
    sample0 * weight0 +
    sample1 * weight1 +
    ...;
```

这种对邻域样本进行加权求和的过程就是卷积（Convolution）。

Kernel 并不只用于模糊。只要把采样范围和权重设计好，就可以实现：

- 模糊；
- 边缘检测；
- 锐化；
- 浮雕；
- 降噪；
- 简单的图像重采样和缩放。

但中值滤波、双边滤波、形态学操作等包含排序或非线性判断，不能简单等同于固定权重的线性卷积。

## 2. 常见 Kernel

### 2.1 Box Filter

Box Filter 让过滤范围内的像素权重相同。例如 3×3 Box Filter：

```text
1 1 1
1 1 1
1 1 1
```

最终除以 `9`。

它实现简单、速度快，但模糊质量一般，缩放时容易导致边缘变软或出现方块感。

### 2.2 高斯模糊

一个常见的 3×3 近似高斯 Kernel：

```text
1 2 1
2 4 2
1 2 1
```

最后除以 `16`，使权重总和为 1，尽量保持整体亮度。

高斯 Kernel 的中心权重更大，距离中心越远权重越小，因此通常比 Box Filter 更自然。较大的二维高斯 Kernel 通常可以拆成横向和纵向两个一维 Kernel，以降低采样数量。

### 2.3 Sobel 边缘检测

Sobel 横向 Kernel：

```text
-1  0  1
-2  0  2
-1  0  1
```

它检测左右方向的颜色变化，通常得到竖直边缘。

Sobel 纵向 Kernel：

```text
-1 -2 -1
 0  0  0
 1  2  1
```

它检测上下方向的颜色变化，通常得到水平边缘。

分别得到：

```text
Gx = 横向 Kernel 的结果
Gy = 纵向 Kernel 的结果
```

边缘强度可以计算为：

```text
edge = sqrt(Gx * Gx + Gy * Gy)
```

为了节省计算，也可以使用近似：

```text
edge = abs(Gx) + abs(Gy)
```

### 2.4 锐化

常见锐化 Kernel：

```text
 0 -1  0
-1  5 -1
 0 -1  0
```

它增强中心像素相对于邻域的差异，使边缘更清晰。由于权重中包含负数，可能产生过冲、光晕或振铃，所以锐化强度不能无限提高。

## 3. Kernel 权重总和

Kernel 的权重总和决定了整体亮度趋势：

- 总和为 `1`：通常保持整体亮度；
- 总和大于 `1`：可能整体变亮；
- 总和小于 `1`：可能整体变暗；
- 包含负权重：常用于锐化和边缘增强，也更容易出现过冲。

使用 Kernel 时不能只看形状，还要检查是否需要归一化，以及边界像素如何处理。边缘处没有完整邻域时，可以使用 Clamp、重复边界、镜像边界或补零等策略。

## 4. Bilinear、Bicubic 与自定义过滤

GPU 硬件通常直接支持 Point、Bilinear、Trilinear 和 Anisotropic 等过滤方式，但它们的过滤类型和权重受到硬件固定规则限制。

Bilinear 只考虑附近的 2×2 个纹素，速度快，但在放大或高质量缩放时可能偏糊。

Bicubic 通常考虑 4×4 个纹素，并使用三次函数计算权重，效果更平滑、边缘质量更好，但采样和计算成本更高。

一些常见的三次过滤核包括 Catmull-Rom、Mitchell-Netravali 等。它们的差异主要在于锐度、平滑度和是否容易产生振铃。

如果过滤核固定，可以直接把权重写入 Shader 常量；如果权重随采样位置变化，也可以提前生成一张小型 1D LUT，在 Shader 中查表获取权重。

## 5. 可分离过滤

如果二维 Kernel 可以拆成两个一维 Kernel，就可以使用两个 Pass：

```text
原图
  -> 横向过滤
  -> 纵向过滤
  -> 最终结果
```

二维高斯模糊就是典型例子。直接使用 2D 大 Kernel 时，半径为 `r` 大约需要 `(2r+1)^2` 个样本；拆分后只需要两次各 `2r+1` 个样本，代价明显更低。

这也是 Bloom、景深和许多后处理模糊方案中常用的优化。

## 6. `ddx` 和 `ddy`

`ddx`、`ddy` 用来估计某个值在相邻屏幕像素之间的变化：

```hlsl
float dx = ddx(value);
float dy = ddy(value);
```

例如：

```hlsl
float2 uv_dx = ddx(uv);
float2 uv_dy = ddy(uv);
```

它们可以帮助 Shader 估计当前屏幕像素覆盖了纹理中的多大范围。如果 UV 变化很大，说明一个屏幕像素覆盖了更大的纹理区域，需要更宽的过滤，否则容易产生闪烁、摩尔纹和锯齿。

GPU 纹理采样器会利用类似的信息选择 Mipmap：

```text
UV 变化小 -> 选择高分辨率 Mipmap
UV 变化大 -> 选择低分辨率 Mipmap
```

`ddx`、`ddy` 实际上是相邻像素差分，不是任意情况下都精确可靠的数学导数。它们依赖 GPU 同时处理相邻像素，因此在动态分支、非连续计算等情况下需要谨慎使用。

## 7. 程序纹理的抗锯齿

假设 Shader 用 `step` 生成黑白条纹。如果条纹频率很高，一个屏幕像素可能同时覆盖黑色和白色区域。只判断像素中心会导致：

- 锯齿；
- 闪烁；
- 摩尔纹；
- 远处纹理跳变。

更合理的做法是估计像素覆盖区域并求平均：

```text
像素区域中 40% 为黑色、60% 为白色
结果 = 0.4 * 黑色 + 0.6 * 白色
```

这就是程序纹理的区域过滤或解析抗锯齿。核心不是只判断像素中心，而是考虑一个像素覆盖的面积。

## 8. 工程上的理解

- Kernel 是通用的邻域加权工具，模糊、边缘查找和锐化只是不同权重设计的结果。
- Box Filter 快但质量一般；Gaussian 更自然；Sobel 通过正负权重提取方向变化；锐化通常也使用包含负权重的 Kernel。
- 二维过滤如果可分离，应优先拆成横向和纵向 Pass。
- 权重总和、边界处理、负权重带来的过冲都需要考虑。
- 硬件过滤追求速度和通用性，自定义 Kernel 追求质量、特殊规则和可控性。
- `ddx`、`ddy` 可以估计纹理变化范围，是 Mipmap、程序纹理抗锯齿和自定义过滤的重要基础。
