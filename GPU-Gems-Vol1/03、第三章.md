# 皮肤渲染

## 我的理解

这一章讨论的是如何在当时的实时可编程硬件上表现皮肤。皮肤 Shader 并没有真正完整地计算光线在皮下组织中的传播，而是把环境光、法线、遮挡、轮廓光和一些经验公式组合起来，让皮肤看起来更柔软、更接近真实。

从工程角度可以先把最终材质拆成：

```text
表面镜面反射
    → Cook-Torrance 或其他 Specular BRDF

皮肤漫反射 / 皮下散射
    → 局部漫反射、卷积、轮廓光或其他 SSS 近似

额外效果
    → 遮挡、背光、透射、法线细节
```

## 预卷积 Cube Map

预卷积 Cube Map 可以粗略理解为“按照光照模型预先模糊过的环境立方体贴图”，但它不是普通的高斯模糊。

### 漫反射预卷积

它对环境半球中的光照做余弦加权平均：

```text
环境光
    × max(N · L, 0)
    → 以法线方向为索引的平均光照
```

因此运行时只需：

```hlsl
float3 diffuse = Sample(DiffuseCubeMap, normal);
```

### 高光预卷积

高光预卷积需要考虑粗糙度。粗糙度越高，参与积分的环境区域越大，结果越模糊；粗糙度越低，结果越集中、越清晰。

```text
原始 HDR 环境图
    ↓ 离线或加载时卷积
多个粗糙度级别的环境图
    ↓ 通常存入 Mipmap 或 Texture Array
运行时根据粗糙度采样
```

因此，“一个 Pass”指的是角色渲染时不再执行昂贵卷积，而是直接采样已经生成的 `DiffuseCubeMap`、`SpecularCubeMap` 和高光环境图。卷积本身可以在预处理阶段用多 Pass 完成，但不属于角色每帧的主要绘制 Pass。

## Dawn 方案并不是真正的完整 SSS

真正的次表面散射是：

```text
光线在 xi 点进入
    ↓
在皮肤内部传播、吸收和散射
    ↓
从 xo 点离开
```

也就是说，表面位置 `xi` 的入射光可以影响另一个位置 `xo` 的出射光。

Dawn 的方案主要使用：

- HDR 环境光和预卷积 Cube Map；
- 皮肤颜色贴图；
- 法线贴图和切线空间到世界空间的转换；
- 半球遮挡项；
- 轮廓光和背光高光；
- 一个额外的高光或环境贴图。

这些方法能够产生类似皮肤柔软、边缘透光的外观，但没有真正执行表面不同位置之间的光照传播。因此，本章的“一 Pass 皮肤”更准确地说是 SSS 外观近似，而不是完整的 BSSRDF。

运行时可以抽象成：

```hlsl
N = TransformNormalMapToWorld(normalMap);

diffuse  = skinColor * Sample(DiffuseCubeMap, N);
specular = Sample(SpecularCubeMap, reflectionVector);
rim      = Sample(HilightCubeMap, viewDirection) * rimFactor;

result = diffuse * occlusion + specular + rim;
```

## Cook-Torrance、SSS 与 BSSRDF

普通 PBR 材质可以写成：

```hlsl
diffuse  = Lambert(N, L) * baseColor;
specular = CookTorrance(N, L, V, roughness, F0);
return diffuse + specular;
```

加入实时 SSS 后，常见工程结构是：

```hlsl
specular   = CookTorrance(...);
diffuseSSS = EvaluateSubsurfaceLighting(...);
return diffuseSSS + specular;
```

SSS 通常是替换或重新分配漫反射部分，而不是在完整漫反射上再盲目叠加一层，否则会重复计算光照。

`BRDF` 描述同一个表面点上的局部反射：

```text
光在 x 点进入
    ↓
仍然从 x 点反射出去
```

`BSSRDF` 则描述非局部的表面散射：

```text
光在 xi 点进入
    ↓
在材质内部传播
    ↓
从 xo 点离开
```

所以完整材质通常可以理解为：

```text
表面镜面 BRDF
    +
内部散射 BSSRDF
```

BSSRDF 不是简单的“SSS 加 BRDF”，而是描述 SSS 的数学模型。实时渲染通常不会完整计算 BSSRDF，而是把它近似成只与表面距离有关的散射轮廓：

```text
距离 r
    → 散射权重 R(r)
```

然后对入射漫反射光照进行卷积：

```text
当前表面附近的入射光照
    × 散射轮廓
    → 散射后的漫反射
```

因此，从工程角度可以这样理解：

```text
BSSRDF
    → 扩散近似
    → 散射轮廓
    → 纹理空间或屏幕空间卷积
```

## 实时 SSS 的几种实现

### 简单的单 Pass 近似

使用一张散射贴图或厚度贴图，配合 Wrap Lighting、Backlight 或 Rim Lighting：

```hlsl
float scatter = Sample(ScatterMap, uv);
float backlight = pow(saturate(dot(-L, N)), scatterPower);

float3 diffuse = baseColor * (lambert + backlight * scatter);
float3 specular = CookTorrance(...);
```

这类贴图描述的是：

- 哪些区域容易透光；
- 哪些区域散射更强；
- 物体厚度或艺术控制；
- 皮肤颜色和内部组织差异。

它不能独立产生随动态光照变化的完整 SSS，只能调制局部近似。

### 纹理空间 SSS

先将角色的漫反射光照渲染到 UV 空间，再在纹理上做散射：

```text
生成 UV 空间入射光照
    ↓
水平卷积
    ↓
垂直卷积
    ↓
还原到角色表面
    ↓
与镜面反射合成
```

为了减少计算，散射轮廓通常被拆成几个 Gaussian 的叠加，再使用可分离卷积。它比较接近表面邻域传播，但需要良好的 UV，并需要处理 UV 接缝、拉伸和空白区域。

### 屏幕空间 SSS

屏幕空间方案直接对当前画面中的漫反射光照做模糊：

```text
漫反射光照、深度、法线、厚度
    ↓
屏幕空间水平模糊
    ↓
屏幕空间垂直模糊
    ↓
与镜面光合成
```

深度和法线用于阻止光照跨越物体边缘。它速度较快，但无法处理屏幕外或被遮挡表面的贡献，可能产生边缘漏光和物体之间错误散射。

`SSSS`、`SSSSS` 等缩写在不同资料和引擎中并不完全统一。工程上更重要的是确认两个问题：

- 计算是在纹理空间还是屏幕空间；
- 卷积是否拆成水平和垂直两个 Pass。

通常可以把 `Separable SSS` 理解为可分离卷积，把 `Screen-Space Separable SSS` 理解为屏幕空间上的可分离卷积。

## 皮肤与玉石的区别

皮肤和玉石可以使用同一种扩散或 BSSRDF 近似框架，但材质数据不同。

### 皮肤常见数据

- 表皮、真皮和皮下组织的颜色变化；
- 红色通道更明显的远距离散射；
- 耳朵、鼻翼等薄区域的透光；
- 厚度图；
- 血管、毛孔和细节法线；
- 表面油脂造成的镜面高光。

### 玉石、蜡和大理石常见数据

- 更均匀的体积散射；
- 更明显的厚度和吸收关系；
- 内部颜色、杂质和脉络；
- 不同的 RGB 吸收和散射半径；
- 可能需要更强的体积透射。

因此，很多情况下不是换一套 Shader，而是改变：

```text
散射半径
RGB 散射颜色
吸收系数
厚度
透射颜色
高光参数
```

## DCC 离线渲染与游戏实时渲染

Blender、Maya 和 3ds Max 本身主要是 DCC 和渲染器的使用界面，具体实现取决于渲染器和模式。

```text
离线路径追踪 / Random Walk
    → 更接近真实内部传播，但需要大量采样

扩散 / BSSRDF 近似
    → 物理依据较强，成本更低

实时视口 / 屏幕空间
    → 通过模糊、厚度和经验公式近似
```

例如，Blender Cycles 可以使用 Christensen-Burley 或 Random Walk；Eevee 则使用实时近似。Arnold 也同时提供 Diffusion 和 Randomwalk。Substance Painter 的实时 SSS 本质上是屏幕空间效果，主要服务于材质预览。

因此，DCC 中的最终渲染结果不一定等于游戏中的 SSS。DCC 通常输出：

```text
Base Color
SSS Color
Thickness Map
Scatter Mask
Normal / Roughness / Specular
```

游戏引擎再使用自己的实时 SSS 方案。所谓“物理准确”也不是绝对概念：Random Walk 比屏幕空间模糊更接近物理，但仍然受采样数量、模型封闭性、材质参数和近似方法影响。
