# 角色动画

## 我的理解

这一章讨论如何在 GPU 上为 Dawn 这样的复杂角色执行动画变形，主要包括两类技术：

```text
Blend Shape / Morph Target
    → 表现脸部表情、局部肌肉和修形

骨骼蒙皮 Skinning
    → 表现身体整体运动
```

它们都可以影响顶点位置，也可能影响法线、切线和其他用于着色的数据。

## Blend Shape 与 Morph Target

在工程中，`Blend Shape` 和 `Morph Target` 通常可以近似理解为同一类技术：保存一个与基础网格拓扑一致的目标形状，然后根据权重将基础网格向目标形状偏移。

```text
基础顶点 P0
    + weight0 × DeltaP0
    + weight1 × DeltaP1
    + ...
    = 当前表情顶点 P
```

公式可以写成：

```text
P = P0 + Σ(weight_i × DeltaP_i)
```

FBX 中通常会保存基础网格、Blend Shape 目标或目标顶点差值，以及可选的法线和切线差值。导入 Unity 后，这些数据由 `Mesh` 和 `SkinnedMeshRenderer` 管理。脚本只需修改权重即可切换或混合姿态：

```csharp
skinnedMeshRenderer.SetBlendShapeWeight(index, weight);
```

修改权重本身只是修改一个标量，通常很便宜；真正的成本在于之后需要对网格顶点应用目标形状。将权重从 0 平滑插值到 100，就可以得到连续的表情动画，而不是瞬间切换。

## 为什么身体动画通常不用大量 Blend Shape？

身体动画更适合骨骼蒙皮，因为骨骼可以用少量矩阵控制大量顶点：

```text
骨骼矩阵
    + 每个顶点的骨骼索引和权重
    → 连续的身体姿态
```

一个顶点的线性蒙皮可以抽象成：

```hlsl
position =
      weight0 * Bone0 * position
    + weight1 * Bone1 * position
    + weight2 * Bone2 * position
    + weight3 * Bone3 * position;
```

如果用 Blend Shape 表达所有身体姿态，就需要为抬手、弯腿、转身、扭腰等动作保存大量整套网格差值，数据量和顶点计算都会随目标数量增长，也不方便重定向到不同骨架或不同体型。

因此常见分工是：

```text
骨骼蒙皮：身体整体运动、可重定向动画
Blend Shape：面部表情、口型、眨眼、局部肌肉和修形
```

Blend Shape 也常用于骨骼蒙皮之后的 Corrective Shape。例如肘部弯曲时，普通线性蒙皮可能造成体积塌陷，可以根据关节角度驱动一个修正形状。

## Dawn 中的实现

Dawn 使用高分辨率角色网格、骨骼蒙皮和多个面部 Blend Shape。书中受到当时 GPU 顶点输入寄存器数量限制，因此不是所有目标同时作用，而是预先准备许多目标，每帧只选择少量当前激活的目标送入 Vertex Shader。

普通的并行 Blend Shape 可以写成：

```hlsl
float4 position = neutralPosition;
position += weight0 * positionDiff0;
position += weight1 * positionDiff1;
position += weight2 * positionDiff2;
```

法线也需要同步处理，否则顶点位置已经改变，但光照仍使用旧法线，会产生错误的高光和明暗。切线、副切线同样需要保持一致。

## GPU 蒙皮时，CPU 和 Shader 的分工

要区分“动画参数计算”和“顶点实际变形”：

```text
CPU / 动画系统
    ├─ 播放动画 Clip
    ├─ 计算骨骼层级姿态
    ├─ 计算骨骼矩阵
    ├─ 计算 IK、约束和物理修正
    └─ 计算 Blend Shape 权重

GPU
    └─ 根据这些数据计算大量顶点的最终位置
```

在自定义 GPU 蒙皮系统中，顶点 Shader 或 Compute Shader 会读取骨骼矩阵、骨骼索引、骨骼权重和 Blend Shape 差值，然后计算顶点变形。

但在 Unity 中，使用 `SkinnedMeshRenderer` 时，用户通常不需要在自己的材质 Shader 里重新写这些代码：

```text
Animator
    → 更新骨骼和 Blend Shape 权重
SkinnedMeshRenderer
    → Unity 内部使用 CPU 或 GPU 完成蒙皮
自定义材质 Vertex Shader
    → 接收已经变形的顶点
    → 执行额外的顶点位移和材质计算
```

因此，即使自定义 Shader 没有显式读取骨骼矩阵和权重，角色仍然可以正常动作。自定义 Shader 与自定义蒙皮系统是两件事。

## Unity 中自定义顶点位移的顺序

从用户材质 Shader 的角度，通常可以理解为：

```text
Blend Shape
    → 骨骼蒙皮
    → Unity 将变形后的顶点交给材质 Shader
    → 自定义 Vertex Shader 位移
    → Object / World / View / Clip 变换
```

例如风吹、溶解、膨胀、受击抖动等效果，通常直接修改 Unity 传入的当前姿态顶点即可。

如果希望某个变形跟随骨骼一起变换，就需要在蒙皮前应用；如果希望它作用于最终角色姿态，就在蒙皮后应用。Unity 的普通自定义材质 Shader 通常只能方便地处理后者，因为它拿到的是已经变形后的顶点。

如果需要控制“先变形再蒙皮”或“先蒙皮再变形”的完整顺序，就需要额外保存基础姿态数据，或者自己实现蒙皮 / Compute Skinning。

## CPU 蒙皮、Vertex Shader 蒙皮和 Compute Skinning

### CPU 蒙皮

```text
CPU 遍历顶点
    → 应用 Blend Shape 和骨骼矩阵
    → 上传变形后的 Vertex Buffer
    → GPU 绘制
```

优点是 CPU 可以直接访问变形后的网格，适合碰撞、CPU 射线、动态碰撞体、布料或其他 CPU 系统；缺点是顶点遍历和上传会增加 CPU 与带宽压力。

### Vertex Shader 蒙皮

```text
CPU 上传骨骼矩阵和权重
    → 每个 Draw 的 Vertex Shader 计算蒙皮
```

优点是减少 CPU 顶点处理，适合普通实时角色；缺点是如果同一角色被主场景、阴影、深度、反射等多个 Pass 绘制，可能在多个 Pass 中重复进行顶点变形，具体还取决于引擎内部实现。

### Compute Skinning

```text
CPU 提供动画参数
    → Compute Shader 预先生成变形后的 GPU Vertex Buffer
    → 主场景、阴影、深度等多个 Pass 复用
```

它适合大量角色、GPU Driven、Indirect Draw 或需要让粒子和其他 GPU 系统读取变形结果的场景，但需要自己管理 Buffer、同步、索引和生命周期。

## 为什么 Unity 已经有 GPU 蒙皮，仍有人自己写？

普通角色不需要自己重写。Unity 的 `SkinnedMeshRenderer` 已经负责骨骼、权重、Blend Shape、包围盒、阴影和平台兼容等工作。项目只需使用内置 GPU 蒙皮，并在材质 Shader 中做额外效果即可。

自己写 GPU 蒙皮通常是为了改变整体数据流，而不是为了让一个角色正常播放动画：

- 几千或几万角色的 GPU Crowd；
- 使用 `DrawMeshIndirect` 或 ECS 批量绘制；
- 自己控制动画纹理、骨骼矩阵 Buffer；
- 将蒙皮结果同时提供给粒子、布料、碰撞和多个 Compute Pass；
- 使用 Dual Quaternion、肌肉体积保持等特殊算法；
- 需要自定义变形顺序；
- 需要缓存和复用统一的 GPU 顶点缓冲。

```text
普通角色
    → Unity SkinnedMeshRenderer + 内置 GPU 蒙皮

普通角色 + 顶点特效
    → 内置蒙皮 + 自定义 Vertex Shader

大规模角色 / GPU Driven / 特殊变形
    → 自定义 Compute Skinning 或完整 GPU 动画系统
```

## 什么时候可能回到 CPU？

GPU 蒙皮并不意味着任何场景都一定更快。以下情况可能需要 CPU 蒙皮或其他混合方案：

- CPU 需要读取变形后的顶点进行碰撞、射线或物理计算；
- 角色经常被绘制到很多临时目标，而 GPU 每个 Pass 都重复变形；
- 网格很小，上传一次比多次 GPU 顶点计算更划算；
- GPU 已经受到顶点处理或带宽限制；
- 平台不支持或不适合 Compute Skinning。

因此要用 Profiler、Frame Debugger 或 RenderDoc 验证实际瓶颈，不能只凭“GPU 并行所以一定更快”判断。

## 总结

```text
Blend Shape / Morph Target：
    用目标形状差值表达局部、高质量形变

骨骼蒙皮：
    用骨骼矩阵和权重表达整体、连续、可重定向运动

Unity 内置 GPU 蒙皮：
    普通角色通常直接使用，不需要自己实现

自定义 GPU 蒙皮：
    主要服务于大规模角色、特殊算法和 GPU 数据共享
```
