# 烟雾火焰

## 我的理解与问题

火焰一般不是用一个完整的三维火焰模型直接渲染，而是特效系统中的粒子、序列帧、Shader 和后处理共同组成的。

我一开始的疑问是：既然火焰通常用粒子系统，书中为什么还要讨论很多 Shader、Render Texture 和图像处理？后来理解到，本章讨论的重点不是“如何完整模拟真实火焰”，而是如何在有限的实时性能和显存预算下，把多种近似方案组合成看起来可信的火焰效果。

## 三种火焰方案

### 1. 完全程序化火焰

可以用粒子、噪声、扰动函数等直接生成火焰形状和运动。

优点：

- 不需要保存大量动画帧；
- 可以实时控制；
- 容易和角色、风场、物理规则结合。

缺点：

- 想得到细致的火焰轮廓，通常需要很多粒子；
- 粒子数量增加后，顶点处理、片元处理和混合成本都会增加；
- 单纯的噪声和粒子运动容易显得像“数学效果”，缺少真实火焰中的细节。

### 2. 2D 扰动或流动火焰

把火焰当作一张二维图像，通过噪声、Render Texture 和 UV 偏移让图像产生流动。

```text
火焰纹理
    ↓
噪声或流场
    ↓
扰动 UV
    ↓
得到流动的二维火焰
```

它适合蜡烛、火把等视角变化不大的火焰。问题是它本质上是屏幕朝向或平面上的效果：

- 从顶部或底部观察时容易穿帮；
- 物体靠近或远离相机时不一定自然；
- 和烟雾、遮挡、复杂运动结合比较困难。

### 3. 视频纹理或 Flipbook 火焰

把离线制作好的火焰动画保存为多帧纹理，运行时让粒子 Shader 根据时间选择不同帧。

```text
离线模拟或拍摄火焰
    ↓
得到多帧图像
    ↓
排列为序列帧 / 图集 / 3D Texture
    ↓
粒子 Shader 根据时间采样
```

这也是游戏中很常见的做法。它不模拟火焰的真实物理过程，而是直接播放已经包含了复杂细节的结果，因此少量粒子也能得到较丰富的视觉效果。

## Flipbook 是什么？

Flipbook 可以理解为“由多张连续图像组成的动画纹理”。它不一定是一个视频文件，常见存储方式包括：

- 2D Texture Atlas：把多帧排在一张大图中；
- 2D Array Texture：每一层保存一帧；
- 3D Texture：把纹理的第三个坐标当作帧索引。

Shader 根据粒子生命周期计算帧索引：

```hlsl
float frame = lifetime01 * frameCount;
```

如果直接取整数帧，可能产生跳帧；如果在相邻帧之间插值，就可以让动画更平滑：

```hlsl
float frameA = floor(frame);
float frameB = min(frameA + 1, frameCount - 1);
float t = frac(frame);
color = lerp(Sample(frameA), Sample(frameB), t);
```

本章使用 3D Texture 保存动画，本质上就是把动画帧放在体纹理的不同层中，通过改变 `z` 坐标播放动画。现代引擎中更常见的是 Flipbook Atlas、Texture Array 或 VFX Graph 的序列帧数据。

## 为什么不能只使用一张火焰动画？

如果所有粒子都从同一帧开始、使用同样的大小和速度，重复会非常明显。因此需要给粒子加入随机差异：

- 随机大小；
- 随机位置；
- 随机生命周期；
- 随机开始帧；
- 随机透明度；
- 随机旋转或翻转 UV；
- 混合两套甚至多套火焰动画。

这些变化并没有增加动画本身的复杂度，却能显著减少“所有火焰同步播放”的感觉。

## 烟雾不一定和火焰使用同样的方案

火焰适合使用高对比度、细节丰富的 Flipbook；烟雾则经常需要更强的颜色和光照控制。因此本章中火焰使用视频纹理，烟雾使用程序化粒子生成。

这说明一个重要的工程思想：

> 一个特效不必所有部分都使用同一种技术。可以让火焰、烟雾、火星、热扭曲分别使用最适合自己的方案，最后再合成。

## Alpha Blend 和 Additive Blend

早期可以使用加法混合：

```text
最终颜色 = 背景颜色 + 火焰颜色
```

加法混合的优点是粒子通常不需要严格排序，但缺点是颜色很容易饱和，火焰会变成过亮的白色，艺术家也很难控制最终颜色。

Alpha Blend 更接近“带透明度的颜色覆盖”：

```text
最终颜色 = 火焰颜色 × alpha
          + 背景颜色 × (1 - alpha)
```

它保留了更多颜色控制，也更容易把火焰和烟雾组合起来，但透明粒子通常需要按深度排序。对于只有几百个粒子的特效，排序成本通常是可以接受的。

## 粒子运动不能只靠向上移动

如果角色在移动，简单地让火焰粒子向上飘，会导致角色移动后留下空洞，或者产生孤零零悬浮在空中的粒子。

本章使用了一个实用方法：粒子刚生成时强绑定到发射器，随后随着年龄增长逐渐减弱绑定，让粒子从发射器附近过渡到自由运动。

```text
粒子刚生成：强跟随发射器
        ↓
粒子逐渐老化：跟随权重减弱
        ↓
粒子最终：自由飘散
```

这不是真正的流体模拟，但能以很低的成本保持移动火焰的连续性。

## 性能瓶颈：通常是片元和混合，而不是粒子数量

火焰粒子往往是很大的 Billboard。即使纹理透明区域最终没有显示，覆盖它们的矩形仍可能产生片元、纹理采样和混合操作。

```text
大 Billboard
    ↓
覆盖大量屏幕像素
    ↓
纹理采样 + Alpha Test / Clip + Blend
    ↓
大量 Overdraw
```

本章用了几个优化方法：

### 低分辨率图层合成

火焰先渲染到较低分辨率的 Render Texture，再和主场景合成。若分辨率降低为原来的四分之一，相关片元处理量大致也会显著下降。

### 裁剪粒子矩形

如果火焰只占据粒子矩形的一小部分，使用完整正方形 Billboard 会浪费大量透明像素。可以离线分析每一帧的有效区域，生成更贴合火焰轮廓的矩形和偏移量。

### Alpha Clip 与 Alpha Blend 的取舍

完全透明的像素可以通过 Clip 丢弃，减少后续混合；但火焰边缘通常需要半透明，因此不能只依赖 Clip。实际效果一般是：

```text
完全透明区域：Clip 丢弃
半透明边缘：Alpha Blend
```

## Glow 和 Heat Shimmer

### Glow

Glow 的基本流程是：

```text
提取火焰或高亮区域
    ↓
低分辨率绘制
    ↓
水平模糊
    ↓
垂直模糊
    ↓
叠加回原场景
```

本章使用了两次一维 Box Blur 近似二维模糊。先横向模糊，再纵向模糊，比直接使用大尺寸二维卷积更便宜。

### Heat Shimmer

热扭曲不是把火焰本身模糊，而是让火焰附近的背景发生 UV 偏移：

```text
热量遮罩 / 噪声
    ↓
转换为屏幕 UV 偏移
    ↓
重新采样场景颜色
    ↓
产生空气折射和热浪效果
```

它通常需要场景 Color Buffer，因此经常放在透明特效或后处理阶段。

## Houdini 在高质量火焰制作中的位置

Houdini 可以通过 Pyro 等系统进行火焰和烟雾模拟，也可以输出网格、Flipbook、VDB、VAT 等数据。它适合制作离线结果或批量处理流程，但游戏中通常不会直接运行完整的 Houdini 模拟。

常见流程是：

```text
Houdini Pyro 模拟
    ↓
离线渲染或导出 VDB
    ↓
烘焙 Flipbook / 体积纹理 / VAT
    ↓
Unity VFX Graph 或粒子 Shader 播放
```

因此，“高质量特效由 Houdini 制作，游戏内用序列帧播放”是常见方案，但不是唯一方案。高端设备和特定引擎也可以直接使用体积数据或实时体积 Ray Marching。

## Houdini、Unity 与角色资源检查

结合我手中的大量角色模型、动作和贴图，可以这样分工：

| 工作 | 更适合的工具 |
|---|---|
| 骨骼、动作、SkinnedMeshRenderer 验证 | Unity |
| Unity Shader、材质和运行时效果验证 | Unity |
| 批量清理模型、UV、坐标和属性 | Houdini |
| 批量重定向、修正动作、生成 LOD | Houdini |
| 生成碰撞体、代理模型、VAT、遮罩 | Houdini |
| 制作程序化 PBR 材质 | Substance Designer |

Houdini 的 KineFX/APEX 支持角色、骨骼、蒙皮、Blend Shape、重定向和程序化动画，但它不会自动复现 Unity 项目中的 ShaderLab、Shader Graph、URP/HDRP 光照和后处理。因此最终显示效果仍然应在 Unity 中检查。

## FBX、Alembic 和 VDB 的区别

### FBX

适合保存骨骼、蒙皮权重、Blend Shape 和可重新控制的动画。角色模型和动作通常优先使用 FBX。

### Alembic / ABC

Alembic 更像烘焙后的逐帧几何缓存，适合布料、破碎、流体、复杂形变和电影动画，但通常不保留可用于实时重定向的骨骼控制关系。

### VDB

VDB 是稀疏体素体积数据，适合烟、火、云、雾等体积效果，不是普通三角形网格。游戏中可以直接用体积渲染器读取，也可以转换为 3D Texture、稀疏体积或 Flipbook。

## Houdini 与 Substance Designer

如果这里的 SD 指 Substance Designer，那么：

- Houdini 更适合几何、模拟和空间属性驱动的贴图生成；
- Substance Designer 更适合专门制作平铺 PBR 材质、法线、粗糙度、高度和金属度；
- Unity 更适合最终验证游戏中的材质、Shader 和运行时表现。

## 本章总结

```text
可信的实时火焰
    = 粒子发射
    + Flipbook / 视频纹理
    + Alpha Blend
    + 烟雾和火星
    + 低分辨率合成
    + Glow
    + Heat Shimmer
```

本章最重要的不是某一个具体 Shader，而是“组合多个近似方案”：把复杂细节提前烘焙，把运行时成本集中在少量粒子、纹理采样和后处理上，再用随机化、排序和低分辨率合成隐藏重复与性能限制。
