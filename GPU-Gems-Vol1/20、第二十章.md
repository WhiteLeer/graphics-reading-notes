# 纹理平铺

## 这章解决什么问题

普通纹理铺满大面积时容易出现明显重复：

- 草地重复同一片草叶；
- 地面重复同一组裂纹；
- 墙面重复同一块砖；
- 岩石表面出现规律的纹理周期。

使用超大纹理可以减少重复，但会增加内存、带宽和制作成本。

Texture Bombing 的思路是：

> 在 UV、物体空间或世界空间中划分网格单元，再以伪随机参数将许多小图案放置到这些单元中。

## 基本 2D 流程

先把 UV 空间划分成网格：

```hlsl
float2 scaledUV = UV * cellCount;
int2 cell = floor(scaledUV);
float2 offset = frac(scaledUV);
```

然后根据 `cell` 坐标生成伪随机参数：

```text
图案位置
图案颜色
图案旋转
图案缩放
图案优先级
图案选择索引
```

最后用这些参数采样小图案，或在 Shader 中直接生成程序图案。

## 为什么要采样邻居单元

如果图案位于单元边缘，它可能跨入旁边的单元：

```text
+-------+-------+
|       |  图案 |
| 图案  |       |
+-------+-------+
```

因此不能只采样当前单元，还需要检查附近的单元。若图案尺寸不超过一个单元、偏移范围有限，二维情况下通常检查当前单元及左、下、左下邻居。

如果允许图案更大、自由旋转或跨越更多边界，就需要检查更多邻居，Shader 成本会增加。

## 重叠优先级

多个图案可能覆盖同一个像素，因此需要定义优先级：

```hlsl
if (candidatePriority > currentPriority)
{
    color = candidateColor;
    currentPriority = candidatePriority;
}
```

优先级可以来自伪随机数、距离、高度或艺术家控制的权重。

## 纹理图案和程序图案

图案可以来自纹理：

- 花朵；
- 叶片；
- 碎石；
- 污渍；
- 裂纹；
- 鱼鳞。

也可以完全程序化生成：

- 圆形；
- 球体；
- 噪声斑块；
- Voronoi 区域；
- 程序裂缝。

例如每个单元生成一个随机圆：

```hlsl
float2 d = localPosition - randomCenter;
if (dot(d, d) < radius * radius)
    color = randomColor;
```

## 多图案选择

多个小图案可以放在一张 Texture Atlas 中：

```text
+----+----+----+----+
| A  | B  | C  | D  |
+----+----+----+----+
```

根据随机数选择子图，就能让不同区域出现不同图案。图集之间需要留出边界，否则双线性过滤和 Mipmap 可能把相邻图案混合到一起。

## Voronoi 是什么

Voronoi 是一种“最近点归属”的空间划分方法：

1. 在空间中放置许多随机点；
2. 对每个像素计算它到各个点的距离；
3. 将像素归属于距离最近的点。

```text
像素 → 比较距离 A、B、C
     → 选择最近点
     → 使用该点对应的颜色或材质
```

Shader 中通常为每个网格单元生成一个随机点，然后检查邻居单元，选择距离最小的点。

Voronoi 与普通噪声的区别是：普通噪声通常生成连续变化的数值，而 Voronoi 先生成清晰的区域边界。

## Voronoi 边界和裂缝

可以记录：

- `F1`：最近点距离；
- `F2`：第二近点距离。

当 `F1` 和 `F2` 接近时，像素靠近两个区域的分界线：

```hlsl
edge = F2 - F1;
crack = smoothstep(threshold, 0, edge);
```

因此 Voronoi 可以用来生成：

- 细胞；
- 鱼鳞；
- 龟裂泥土；
- 泡沫；
- 岩石分块；
- 皮肤细胞；
- 程序裂缝。

## Texture Bombing 和 Voronoi 的区别

```text
Texture Bombing：每个单元随机放置一个小图案
Voronoi：每个单元放置一个随机点，每个像素归属于最近的点
```

Texture Bombing 更适合放置独立图案；Voronoi 更适合生成连续分区、细胞边界和裂缝。

## 2D 和 3D Texture Bombing

### 2D

使用 UV 空间划分单元：

```text
UV → 2D 网格 → 随机图案
```

优点是计算便宜、容易控制；缺点是依赖 UV，可能出现 UV 岛接缝和拉伸。

### 3D

使用物体空间或世界空间坐标划分三维立方体单元：

```text
Object/World Position → 3D 网格 → 随机图案
```

优点是不依赖 UV，适合岩石和程序化表面；缺点是需要检查更多三维邻居，通常比 2D 版本昂贵。

使用物体空间时，纹理会随物体移动；使用世界空间时，纹理可能在物体表面滑动，需要根据需求选择。

## 性能问题

主要成本来自：

```text
多个邻居单元
× 多个候选图案
× 多次纹理采样
× 旋转/缩放和优先级计算
```

依赖纹理采样还可能导致 Mipmap 和 LOD 问题。随机参数纹理通常需要谨慎设置过滤方式，避免单元边界处突然使用高 MIP 造成伪影。

## 工程判断

Texture Bombing 不是简单扰动 UV，而是：

```text
划分空间单元
    ↓
为单元生成伪随机图案参数
    ↓
检查当前单元和邻居
    ↓
选择或叠加覆盖当前像素的图案
```

它的价值是以较少的基础纹理和程序计算，降低大面积材质的周期性；代价是额外的纹理采样、邻域检查和 Shader 复杂度。
