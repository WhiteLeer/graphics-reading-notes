# 景深

## 1. 景深到底是什么

景深不是简单地把远处物体统一模糊，而是相机镜头光圈造成的成像结果：

- 对焦距离附近的物体清晰；
- 太近或太远的物体逐渐失焦；
- 离焦程度与物体距离、焦距、光圈大小等有关。

现实相机的镜头有面积。来自同一物体的光线经过镜头后，如果刚好在胶片或传感器上汇聚成一点，物体就是清晰的；如果没有在成像平面汇聚，就会形成一个小圆斑，称为 **Circle of Confusion（CoC，弥散圈）**。

CoC 越大，视觉上越模糊。光圈越大、物体距离焦平面越远，通常 CoC 越大。

实时渲染通常使用针孔相机，镜头没有面积，所有光线从同一个点出发，所以不会自然产生景深。我们必须额外近似这个效果。

## 2. CoC 的计算

GPU Gems 给出的世界空间形式可以写成：

```text
CoC = abs(
    aperture * (focalLength * (objectDistance - focusDistance)) /
    (objectDistance * (focusDistance - focalLength))
)
```

其中：

- `aperture`：光圈相关参数；
- `focalLength`：焦距；
- `objectDistance`：物体到相机的距离；
- `focusDistance`：当前对焦距离。

实际后处理中通常不重新构造完整世界位置，而是从深度缓冲读取深度，再用相机参数整理成：

```text
CoC = abs(z * CoCScale + CoCBias)
```

因此，景深 Pass 通常至少需要：

```text
场景颜色图 + 深度图 + 对焦距离 + 光圈/焦距参数
```

## 3. 几类景深实现

### 3.1 光线追踪景深

从真实镜头的不同位置发射多条光线，再把结果平均。

这是最接近物理结果的方式，还能自然结合运动模糊和软阴影。采样不足时主要表现为噪声，而不是固定的重影或条带。

缺点是每个像素需要多条光线，实时成本很高，更适合离线渲染或硬件光追能力足够的场景。

### 3.2 多次渲染并累加

把相机放在光圈范围内的多个位置，分别渲染场景，再将结果累加。

它也能获得比较正确的镜头可见性，但需要多次完整绘制场景。采样不足时，前景和背景的极端失焦区域会出现重影；模糊半径越大，所需渲染次数越多。

### 3.3 分层景深

把场景分为前景、中景、背景等层，每层单独模糊后再合成。

优点是思路简单，物体边缘比直接模糊整张图更容易处理。缺点是：

- 一个物体跨越多个深度范围时，层与层之间会出现不连续；
- 地面、墙壁等贯穿整个深度范围的物体很难划分；
- 层之间的遮挡关系不一定正确；
- 每层使用代表深度，会掩盖物体内部真实的深度变化。

因此它只适合场景结构比较简单，或能通过艺术规则控制的情况。

### 3.4 Forward Mapping：散点 / 精灵扩散

先保存颜色和深度，再把每个源像素扩散成一个圆形区域：

```text
源像素
  -> 根据深度计算 CoC
  -> 生成一个半径约为 CoC 的圆
  -> 将颜色混合到邻域
```

它更接近弥散圈的含义，但典型屏幕分辨率下会产生大量小精灵，硬件执行效率较差。还需要按照深度限制哪些像素可以互相影响，否则会让前景和背景错误混合。

### 3.5 Reverse Mapping：根据深度选择模糊级别

这是传统实时后处理常用的思路：每个输出像素根据自己的深度和 CoC，去采样颜色图的不同模糊版本。

最简单的实现是：

```text
CoC 很小 -> 采样原图
CoC 中等 -> 采样较低分辨率的图
CoC 很大 -> 采样更低分辨率的图
```

早期实现会使用颜色图的 Mipmap 或多张不同程度的模糊图，然后根据 CoC 在它们之间插值。现代方案通常还会增加多次散焦采样、前景/背景分离、半分辨率处理和更符合镜头形状的 Bokeh 采样。

## 4. 为什么景深会产生光晕和错误混合

如果只对整张颜色图做模糊，就会遇到深度不连续问题。

例如：

```text
相机 -> 模糊前景 -> 清晰背景
```

前景的颜色可能被扩散到背景上，形成脏边或光晕。

反过来：

```text
相机 -> 清晰前景 -> 模糊背景
```

背景颜色也可能错误地泄漏到前景边缘。

原因是颜色图中每个像素只有一个可见颜色和一个深度，后处理并不知道被遮挡表面在模糊范围内应该是什么颜色。因此仅凭当前屏幕颜色和深度，无法完整恢复真实镜头从不同光圈位置看到的所有信息。

常见缓解手段包括：

- 分离前景和背景，分别进行散焦；
- 采样邻域深度，避免跨越不合理的深度边界；
- 对前景颜色进行扩张，减少背景漏入前景；
- 对透明物体单独处理；
- 适当限制最大 CoC 和焦点移动范围；
- 使用抖动采样，把规则条带变成较不明显的噪声。

## 5. 工程上的理解

- 景深的核心不是“根据距离加一个模糊”，而是根据镜头模型计算每个像素的弥散圈，并处理不同深度之间的可见性。
- 光线追踪和多次相机渲染更接近真实镜头，但成本高。
- 分层、Forward Mapping 和 Reverse Mapping 更适合实时，但会牺牲可见性正确性。
- 深度缓冲只保存当前最前面的可见深度，无法保存被遮挡表面的颜色，因此普通后处理景深必然存在信息不足。
- 景深通常是后处理效果，但透明物体、粒子、角色头发等边缘复杂对象往往需要额外 Pass 或专门的合成策略。
