# 艺术化灯光

## 我的理解

本章介绍的不是一种新的阴影算法，而是一种 Pixar 风格的灯光控制思想：光照不一定要完全遵循物理结果，而应该服务于构图、情绪、角色表现和叙事。

本章使用的 Uberlight 可以理解为一个“可艺术控制的灯光 Shader”，而不是包含所有材质功能的 Uber Shader。

```text
Shadow Map：
    判断像素是否被遮挡

Cinematic Lighting / Uberlight：
    决定阴影和灯光结果应该如何被艺术化地使用
```

## 为什么需要艺术化灯光？

严格物理正确的灯光不一定能得到最好的画面。例如角色站在窗边时，真实光照可能让脸完全处于阴影中，看不清表情。

电影式灯光可能会：

- 让脸部保持可见；
- 保留眼睛高光；
- 让身体仍然处于阴影；
- 把阴影略微移开；
- 给阴影添加颜色；
- 增加一盏只影响角色的补光。

因此本章的观点是：

> 物理模型负责提供合理基础，艺术控制负责决定最终画面。

## Uberlight 的基本流程

```text
表面材质信息
    ↓
遍历每一盏灯
    ↓
计算灯光颜色、范围和形状
    ↓
采样 Shadow Map 和 Cookie
    ↓
计算 Diffuse、Specular 等表面响应
    ↓
艺术化调整阴影和高光
    ↓
累加得到最终颜色
```

简化后的伪代码是：

```hlsl
float3 result = 0;

for each light
{
    float shadow = SampleShadowMap(shadowUV);
    float3 cookie = SampleCookie(cookieUV);
    float shaping = ComputeLightShape(lightSpacePosition);
    float attenuation = ComputeDistanceFalloff(lightSpacePosition);

    float3 lightColor = light.color * cookie;
    float3 diffuse = ComputeDiffuse(N, L);
    float3 specular = ComputeSpecular(N, H);

    result += attenuation * shaping *
              (diffuse + specular) *
              lightColor;
}
```

## 1. 灯光选择

真实世界中一盏灯会照亮附近的所有物体，但艺术化灯光允许每个物体选择性接受灯光。

```text
Key Light：
    只影响主角

Rim Light：
    只影响角色轮廓

Fill Light：
    只影响脸部

Background Light：
    只影响背景
```

这和现代引擎中的 Light Layer、Rendering Layer 或 Light Channel 类似。

它可以避免额外灯光影响整个场景，例如：

- 轮廓光只照亮角色，不照亮地面；
- 角色补光不影响背景；
- 专用眼睛高光不照亮衣服；
- 只让局部物体接受一盏灯。

## 2. 灯光颜色和权重

本章把灯光贡献拆成 Ambient、Diffuse 和 Specular，并允许分别设置权重：

```hlsl
float3 lighting =
      ambientTerm  * ambientWeight
    + diffuseTerm  * diffuseWeight
    + specularTerm * specularWeight;
```

光源和材质也可以各自设置权重：

```text
光源权重 × 材质权重 × 光照响应
```

因此可以制作：

- 只提供漫反射的补光；
- 只提供边缘高光的轮廓光；
- 只影响角色眼睛的局部高光；
- 只降低阴影区域黑度的填充光。

现代 PBR 通常不会简单地用传统 Ambient 项代替真实间接光，但“分离各类光照贡献并分别控制”的思想仍然很常见。

## 3. 灯光形状

### Omni Light

本章的 Omni Light 不是简单地让光照无限衰减，而是设置多个距离区间：

```text
Near Distance
    ↓
完全强度区域
    ↓
Near Edge 平滑过渡
    ↓
Far Edge 平滑衰减
    ↓
Far Distance 后关闭
```

可以用两个 `smoothstep` 组合：

```hlsl
float attenuation =
    smoothstep(nearEnd, nearStart, distance)
  * (1.0 - smoothstep(farStart, farEnd, distance));
```

这样可以精确控制灯光开始衰减和结束衰减的位置。

### Barn Shaping

Barn Shaping 模仿电影摄影中的 Barn Door，用几何形状裁剪灯光区域。

普通聚光灯通常是圆锥：

```text
      /\\
     /  \\
    /    \\
   /______\\
```

Barn Shaping 可以让光束从圆形逐渐变为方形、矩形，或者变成被剪切过的窗户形状。

它使用可调节的 Superellipse：

```text
圆形 ←────────→ 方形
```

超椭圆可以用下式表示：

```text
|x/a|^n + |y/b|^n = 1
```

通过改变 `n`，可以控制截面从圆形到方形的变化。

Shader 通常先把世界位置变换到灯光空间，再投影到某个平面：

```hlsl
float2 projected = lightPosition.xy / lightPosition.z;
```

然后判断当前点是否落在灯光形状中，并用 `smoothstep` 控制边缘软化。

## 4. 阴影不一定是黑色

本章认为阴影太黑，通常是因为没有计算真实的间接光。

```text
真实环境：
    阴影区域仍然接受天空、地面和其他物体反射的光

简单直接光模型：
    阴影区域几乎没有光
```

因此本章允许设置 Shadow Color 和 Shadow Density：

```hlsl
float3 mixedLightColor =
    lerp(shadowColor, lightColor, shadowAmount);
```

例如：

- 户外阳光下的阴影略偏蓝；
- 室内暖光下的阴影偏棕；
- 恐怖场景中的阴影更冷、更暗；
- 舞台灯光中的阴影可以带有明显颜色。

这不是真正的全局光照，而是用参数化颜色和强度近似间接光的视觉效果。

## 5. 阴影中的高光

如果只降低漫反射，却让高光保持完整，可能出现“物体处于阴影中但依然有强烈高光”的效果。

因此本章倾向于：

```hlsl
float3 diffuse  = mixedLightColor * diffuseTerm;
float3 specular = lightColor * shadowAmount * specularTerm;
```

也就是说：

- 漫反射可以使用带颜色的阴影光；
- 高光更严格地乘以阴影强度；
- 阴影中的高光可以被削弱或关闭。

## 6. 阴影位置也可以被艺术化调整

本章允许艺术家对阴影位置进行一定程度的“作弊”。

例如角色脸部的真实阴影可能遮住眼睛，可以把阴影略微移动，使：

```text
角色脸部保持可见
    +
身体和环境仍然有阴影
```

这在物理上不完全正确，但可以保证：

- 角色表情清晰；
- 视觉焦点明确；
- 构图更加稳定；
- 灯光服务于叙事。

## 7. Shadow Map 在本章中的位置

本章使用 Shadow Map，但没有把重点放在 Shadow Map 的生成方法上。

```hlsl
float shadow = SampleShadowMap(shadowUV);
```

得到的 `shadow` 只是一个遮罩，随后被用于控制：

- 漫反射；
- 高光；
- 阴影颜色；
- 阴影密度；
- 灯光强度。

因此：

```text
第九章：
    如何用 Shadow Volume 生成阴影区域

第十章：
    已经有 shadowAmount 后，
    如何艺术化地使用它
```

本章明确强调，重要的不是采用哪一种阴影判断算法，而是如何利用阴影信息塑造最终画面。

## 8. Cookie：用纹理控制灯光

Cookie 是投影到场景上的灯光纹理。

```text
窗户纹理
    ↓
投影到墙面
    ↓
形成窗框形状的光影
```

也可以用于：

- 树叶阴影；
- 百叶窗；
- 火焰投影；
- 霓虹灯；
- 屏幕外光源；
- 特殊形状的聚光灯。

Shader 将世界坐标变换到灯光投影空间，然后采样 Cookie：

```hlsl
float3 cookieColor =
    SAMPLE_PROJECTION(_Cookie, shadowUV);

lightColor *= cookieColor;
```

Unity 和 Unreal 中的 Light Cookie 也遵循类似思想。

## 9. 完整的 Uberlight 计算

```hlsl
// 1. 变换到灯光空间
float3 P_light = TransformToLightSpace(positionWS);
float3 N_light = TransformNormalToLightSpace(normalWS);

// 2. 计算方向
float3 L = ComputeLightDirection(P_light);
float3 V = ComputeViewDirection(P_light);
float3 H = normalize(L + V);

// 3. 采样阴影和 Cookie
float shadow = SampleShadowMap(shadowUV);
float3 cookie = SampleCookie(cookieUV);

// 4. 灯光形状和距离衰减
float shaping = ComputeBarnShape(P_light);
float distanceAttenuation =
    ComputeDistanceFalloff(P_light);

// 5. 表面响应
float3 diffuse = ComputeDiffuse(N_light, L);
float3 specular = ComputeSpecular(N_light, H);

// 6. 艺术化阴影
float3 shadowLight =
    lerp(shadowColor, lightColor, shadow);

diffuse *= shadowLight;
specular *= lightColor * shadow;

// 7. 合成
float3 result =
    shaping *
    distanceAttenuation *
    (ambient + diffuse + specular);

result *= cookie;
```

它把灯光拆成了许多独立控制项：

```text
灯光选择
+ 灯光颜色
+ 灯光形状
+ 距离衰减
+ 阴影遮罩
+ 阴影颜色
+ 高光控制
+ Cookie
```

## 10. 性能优化：解析函数改成查表

Barn Shaping 的解析计算可能包含：

- 除法；
- 幂函数；
- 多次乘法；
- 平滑插值。

可以预先生成 LUT：

```text
复杂解析函数
    ↓
离线或单独 Pass 预计算
    ↓
生成灯光形状纹理
    ↓
Shader 直接采样
```

例如：

```hlsl
float shaping =
    SAMPLE_TEXTURE2D(_BarnShapeLUT, sampler, projectedUV).r;
```

如果场景和灯光参数没有变化，还可以缓存这些中间结果，只有参数变化时重新生成。

## 和现代游戏引擎的联系

现代游戏通常使用：

- PBR 材质；
- Shadow Map 或 Virtual Shadow Map；
- Light Layer；
- Light Cookie；
- Contact Shadow；
- Rim Light；
- 局部补光；
- 阴影染色；
- 后处理。

这些技术的共同点是：

```text
底层使用物理近似
    +
上层使用艺术控制
```

所以第十章不是在说“物理渲染没有意义”，而是在说明：

> 物理模型提供合理基础，但最终画面仍需要允许艺术家修改光照的作用范围、颜色、阴影和高光。

## 总结

```text
Shadow Map：
    判断某个位置是否被遮挡

Uberlight：
    决定这份遮挡信息如何参与最终灯光

Cinematic Lighting：
    物理基础
    + 灯光选择
    + 灯光形状
    + 阴影颜色和密度
    + 高光控制
    + Cookie
    + 艺术化偏移
```

本章的核心思想是：

> 实时渲染和电影渲染并不只是追求“算得更真实”，还要让灯光直接服务于画面和叙事。
