# 渲染水体焦散

## 我的理解

这里的“焦散”主要指水底或水下物体表面的动态亮斑，而不是水面本身的普通高光。水面起伏会改变光线的折射方向，使原本分散的光线在水底局部聚集，于是形成不断移动的明暗纹理。

```text
太阳光
  ↓
起伏水面折射
  ↓
水底 / 水下物体
  → 动态焦散亮斑
```

焦散不是色散：色散是不同波长的光分离，而焦散是光线经过曲面反射或折射后，在接收表面局部聚集。

## 书中方案的基本流程

```text
绘制水底基础颜色
    ↓
焦散 Pass
    → 根据水面波形计算法线
    → 根据折射方向估算光线落点
    → 采样光照图
    → Additive Blend 叠加焦散
    ↓
绘制水面反射、透明等效果
```

焦散的物理计算本质上需要追踪大量光子。GPU Gems 1 没有真正进行完整的光子追踪，而是采用一个视觉上可信的近似：从水底的采样点出发，寻找正上方的水面位置，计算该处水面法线，用 Snell 定律估算折射方向，再根据折射光线与太阳方向的接近程度判断亮度。

书中还做了进一步简化：假设太阳在正上方，且水底主要接收接近垂直方向的光线。因此，折射方向越接近垂直，焦散贡献越强；光线越倾斜，受到的吸收越多，贡献越弱。

## 水面 Shader 和焦散 Shader 的关系

水面和水底通常是不同的材质或不同的 Pass：

- 水面 Shader：负责顶点位移、反射、折射、透明度和水面自身的高光；
- 水底 Shader：负责水底物体本身的材质；
- 焦散 Pass：负责估算水面折射光对水底或其他物体的额外照明。

不同 Draw Call 之间，水面 Shader 中计算出的局部法线不会自动传给水底 Shader。因此，书中的焦散 Pass 需要根据同一组波函数参数，重新计算水面位置和法线。也就是说，确实会出现一部分重复计算：

```text
水面 Pass       → 计算波形和法线，用于水面着色
焦散 Pass       → 再次计算波形和法线，用于估算折射光
```

这也是我认为书中方案更像演示算法、而不是现代项目最终架构的原因。它适用于较简单的规则水面和少量接收区域，但当波函数很复杂、接收焦散的物体很多时，重复计算会变得昂贵。

## 是否必须使用额外 RT？

不一定。

### 直接在接收物体上计算

书中的一种实现是在水底上再绘制一个细分网格。这个焦散 Pass 对水底的每个顶点或像素重新计算折射路径，然后直接把焦散叠加到水底颜色上。

```text
Ground Pass：绘制水底基础颜色
Caustic Pass：计算焦散并直接叠加
```

这种方案不需要额外的焦散 RT，但每个接收区域都可能重复执行波形、法线和折射计算。

### 先生成共享焦散图

更适合实际项目的方案通常是先生成一张动态焦散纹理或 RT：

```text
焦散生成 Pass / Compute Shader
    ↓
Caustics RT
    ↓
水底、墙面、岩石、角色等接收物体采样
    ↓
叠加焦散光照
```

接收物体只需将世界坐标转换成焦散图坐标，然后采样：

```hlsl
float2 uv = WorldToCausticUV(worldPosition);
float caustic = Sample(CausticsRT, uv);
color += caustic * causticIntensity;
```

这样复杂的水面波形和折射计算只在生成焦散图时做一次，多个接收物体可以共享结果。因此，对于大量接收物体，共享 RT 通常更具扩展性。

不过 RT 也不是没有代价：它需要额外显存、带宽和生成 Pass，还要解决世界坐标映射、覆盖范围、分辨率、过滤以及复杂三维场景中的投影误差。

## 屏幕空间与纹理空间

本章还讨论了两种把焦散计算放到 GPU 上的方式：

- 屏幕空间：只计算当前可见的像素，不需要固定大小的焦散纹理；可见区域较小时效率较高，但可见像素很多时，计算量也会增加。
- 纹理空间：将焦散写入固定分辨率的 RT，工作量更稳定，并且可以使用 Mipmap、各向异性过滤等手段减轻锯齿；但需要选择合适的 RT 分辨率，并且会占用额外显存和带宽。

## 方案选择

```text
少量接收物体、简单水底
    → 直接在焦散 Pass 中计算

大量物体共享焦散
    → 生成共享 Caustics RT / 投影纹理

大范围海洋
    → 世界空间焦散图、分块 RT 或 Clipmap
```

因此，本章最值得保留的不是某一段旧式 Shader 代码，而是一个工程取舍：焦散计算应该放在“每个接收物体自己计算”，还是集中生成一份共享结果。前者少了 RT 和映射成本，但会重复计算；后者更适合多物体共享，但需要承担 RT 生成、采样和空间映射成本。
