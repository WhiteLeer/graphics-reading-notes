# FX Composer

## 1. 本章定位

这一章基本是 FX Composer 的使用说明，重点不是新的渲染算法，而是展示一个 Shader 开发工具应该提供哪些功能。

GPU Gems 1 首版出版于 **2004 年**，版权页标注 2004；官方网页版本显示后来有 2007 年的第五次印刷。因此本章中的 `.fx`、Cg、Direct3D 9 和 FX Composer 界面都属于 2000 年代初期技术，现在不需要按实际操作手册学习。

## 2. Materials Panel

Materials Panel 用于：

- 加载 `.fx` 文件；
- 创建材质实例；
- 在球、方块、茶壶等模型上预览；
- 修改颜色、纹理和参数；
- 观察灯光、法线和凹凸效果。

同一个 Effect 文件可以创建多个不同材质：

```text
cartoon.fx
    -> 红色材质
    -> 蓝色材质
    -> 金属材质
```

对应现代 Unity 的 Material Inspector 和 Material Preview。

## 3. Scene Graph Panel

Scene Graph Panel 用树状结构显示：

- 模型；
- 相机；
- 光源；
- 几何处理节点；
- 对象层级。

选择对象后，可以在 Properties Panel 中修改位置、旋转、缩放、灯光颜色、光源方向和网格细分等属性。

现代对应：

```text
Hierarchy + Inspector + Scene View
```

## 4. Editor Window

Editor 用于创建和修改 `.fx` 文件，提供：

- 语法高亮；
- 自动补全；
- 查找；
- 撤销/重做；
- 编译；
- 错误定位。

修改并重新编译后，所有使用该 Effect 的材质都会更新。这对应现代的 Rider、Visual Studio、VS Code 加 Unity Shader 编译反馈。

## 5. Shader Perf Panel

Shader Perf Panel 可以选择：

```text
Technique
    -> Pass
        -> Vertex Shader / Pixel Shader
```

然后查看编译后的汇编、指令调度和目标 GPU 的性能信息。

它对应现代的 Shader Inspector、RenderDoc Shader Debug、Nsight、PIX 和 GPU 厂商分析工具。不过书中面向 GeForce FX 5900 的汇编和指令数量不能直接类比现代 GPU。

## 6. Properties Panel

工具可以根据 Shader 参数类型和注解自动生成编辑控件：

```text
float  -> 数值框或滑条
float3 -> 向量编辑器
color  -> 颜色选择器
texture -> 纹理槽
matrix -> 矩阵编辑器
```

还可以把参数连接到场景对象：

```text
材质 lightPos
    -> 场景 Point Light 的 position
```

这样移动场景光源时，材质参数会自动更新。现代对应 Shader Properties、Material Inspector、Global Shader Parameters 和 MaterialPropertyBlock 等机制。

## 7. Textures Panel

Textures Panel 可以查看：

- 普通贴图；
- 程序生成的纹理；
- Render Target；
- Bloom 或模糊产生的中间结果。

它可以帮助排查后处理链条：

```text
原始场景
    -> 高亮提取图
    -> 模糊图
    -> 最终合并图
```

现代 RenderDoc、Unity Frame Debugger 和 Render Texture 调试窗口也提供类似功能。

## 8. Tasks 和 Log Panel

用于显示：

- Shader 编译错误；
- 警告；
- 文件加载信息；
- 资源缺失；
- 硬件能力不足；
- 插件加载问题。

编译错误通常可以直接跳转到 Shader 对应行，对应现代 IDE、Unity Console 和 Shader 编译日志。

## 9. 典型工作流

```text
创建或打开 Shader
    -> 创建材质实例
    -> 在预览模型上查看
    -> 调整材质参数
    -> 调整光源和相机
    -> 编译 Shader
    -> 查看错误和性能
    -> 将材质应用到场景模型
    -> 保存项目
```

## 10. 工程上的结论

- 本章具体界面和文件格式已经过时，可以快速浏览。
- Shader 工具需要实时预览、参数编辑、纹理查看和错误定位。
- Shader 的中间 Render Target 应该可以被单独检查。
- 材质参数可以连接到场景对象和动画系统。
- Shader 性能分析需要单独的工具，而不能只凭最终画面判断。
- 第三十章讲工具如何设计，第三十一章讲设计好的工具如何使用。
