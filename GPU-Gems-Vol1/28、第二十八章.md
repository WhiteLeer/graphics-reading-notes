# 图形管线性能

## 1. 优化的核心：先找瓶颈

图形管线由多个阶段组成，整条流水线的速度由最慢的阶段决定：

```text
CPU
  -> Draw/Dispatch 提交
  -> 顶点与索引读取
  -> 顶点处理
  -> 图元装配与光栅化
  -> 片元处理
  -> 深度/模板/混合/颜色写入
```

此外还会受到纹理采样、Cache、显存访问和 CPU/GPU 同步的影响。

优化循环应该是：

```text
测量
  -> 定位瓶颈
  -> 只优化瓶颈阶段
  -> 再次测量
  -> 重复
```

如果当前 GPU 像素处理已经占满，单纯减少 CPU DrawCall 可能几乎没有收益；如果 GPU 很快而 CPU 提交命令很慢，才应该优先做合批和提交优化。

## 2. 常见瓶颈

### 2.1 CPU 瓶颈

常见原因：

- DrawCall 或 Batch 太多；
- 场景遍历、剔除、排序过重；
- 物理、AI、动画占用过多；
- CPU 生成命令速度不足；
- 资源上传或回读；
- CPU/GPU 频繁同步。

本章中的 Batch 可以理解为一次 API 绘制调用提交的一组图元。现代引擎的 Batch、DrawCall、实例化和间接绘制统计口径可能不同，但核心仍是 CPU 提交和状态变更的成本。

### 2.2 顶点处理瓶颈

顶点阶段包括：

- 顶点和索引读取；
- 模型到世界空间变换；
- 蒙皮；
- 顶点动画；
- 顶点光照；
- 输出供光栅化插值的属性。

可能原因包括顶点数过多、蒙皮影响数太高、Vertex Shader 太复杂、顶点属性过多，以及顶点访问不连续导致 Cache 命中率低。

### 2.3 片元 / 像素着色瓶颈

常见原因：

- 分辨率高；
- Overdraw 严重；
- Pixel Shader 复杂；
- 纹理采样多；
- 分支和循环重；
- 后处理 Pass 多；
- 透明层数多。

透明物体通常无法像不透明物体一样依靠深度写入阻止后续片元，因此更容易产生重复的片元计算。

### 2.4 纹理带宽瓶颈

即使单次纹理采样指令不复杂，大量纹理读取仍会消耗显存带宽：

```text
Pixel Shader
    -> 读取多张大纹理
    -> 产生大量显存访问
```

大纹理、过高精度、没有 Mipmap、采样位置分散、Cache 命中率低，都可能导致纹理带宽不足。

### 2.5 帧缓冲带宽 / ROP 瓶颈

GPU 后端需要处理：

- 深度测试和写入；
- 模板测试和写入；
- 颜色读取和写入；
- Alpha Blend；
- 多个 Render Target。

高分辨率、多个 MRT、高精度 RT、大量透明混合和多次后处理会显著增加帧缓冲带宽压力。

## 3. 如何定位瓶颈

基本思路是改变某个阶段的工作量，观察 GPU 时间是否变化。

### 3.1 改变分辨率

降低分辨率后性能明显提升，通常说明可能受以下因素影响：

- 片元着色；
- Overdraw；
- 后处理；
- 帧缓冲带宽。

### 3.2 简化 Shader

将 Pixel Shader 替换成极简输出：

```hlsl
return 1;
```

如果性能明显提升，说明原 Shader 的像素计算可能是瓶颈。类似地，简化 Vertex Shader 可以测试顶点处理是否受限。

### 3.3 改变纹理和 Render Target 格式

降低纹理尺寸、使用更低级别的 Mipmap、减少纹理采样，可以帮助判断纹理带宽问题。

将 `RGBA16F` 替换为 `RGBA8`，或减少 MRT 数量，如果性能改善明显，可能是帧缓冲带宽或后端写入受限。

### 3.4 使用现代分析工具

现在通常使用：

- Unity Profiler；
- Unity Frame Debugger；
- RenderDoc；
- PIX；
- Nsight Graphics；
- Radeon GPU Profiler；
- GPU 时间戳和 Pipeline Statistics。

旧书中通过修改 GPU 时钟来判断瓶颈的方法，现在一般不作为首选。

## 4. 常见优化方向

### 4.1 CPU 侧

- 减少同步和资源锁定；
- 增大单次 Batch，减少提交次数；
- 合并材质和纹理；
- 使用 Texture Atlas、实例化或 GPU Driven；
- 避免 CPU 读取 GPU 正在使用的资源。

### 4.2 顶点侧

- 使用合理的几何 LOD；
- 减少顶点属性；
- 选择合适的索引格式；
- 优化顶点 Cache；
- 把按物体变化的计算移到 CPU；
- 把适合插值的计算放到 Vertex Shader；
- 远处角色降低蒙皮复杂度。

### 4.3 片元侧

- 使用深度预处理；
- 不透明物体尽量前到后绘制；
- 降低 Overdraw；
- 减少透明层数；
- 减少纹理采样；
- 把复杂函数放进 LUT；
- 只在必要时做归一化；
- 对远处对象使用更简单的 Shader。

### 4.4 带宽侧

- 使用合理的纹理和 RT 格式；
- 使用硬件支持的压缩纹理；
- 对会缩小显示的纹理生成 Mipmap；
- 减少不必要的高精度 RT；
- 减少 MRT 数量；
- 避免无意义的颜色清除；
- 根据场景选择深度和颜色缓冲精度。

## 5. 工程上的理解

- CPU 瓶颈不等于 GPU 瓶颈。
- 片元计算瓶颈不等于帧缓冲带宽瓶颈。
- 纹理带宽瓶颈不等于 Shader 指令瓶颈。
- “减少 DrawCall”只有在 CPU 提交或状态管理是瓶颈时才会带来明显收益。
- 最可靠的优化方式是测量、定位、修改、再测量，而不是凭经验堆优化。
