# GPU 中实现改进的 Perlin 噪声

## 章节内容

本章介绍如何在 GPU 像素着色器中实现与 CPU 参考实现一致的改进 Perlin 噪声。与直接保存预计算 3D 噪声纹理的方式相比，程序化计算可以减少纹理存储、降低明显的重复周期、支持 4D 噪声，并使用比硬件纹理过滤更高质量的插值；代价是需要在 Shader 中执行更多指令和纹理查找。

### 噪声需要满足的特征

这里的噪声不是完全无规律的随机数，而是一种可控的随机性。理想的噪声函数通常具有以下特点：

- 对同一个输入位置，总能得到可重复的伪随机值；
- 输出范围明确，通常在 `[-1, 1]` 附近；
- 空间频率受到限制，因此结果连续、平滑；
- 不容易出现明显的重复图案；
- 对输入空间做平移时，噪声的空间频率不会发生改变。

改进的 Perlin 噪声满足这些要求，因此可以作为程序化纹理、凹凸映射和其他自然效果的基础。

### 预存 3D 噪声纹理与程序化计算

一种常见做法是预先生成 3D 噪声纹理，运行时直接采样。这样可以利用硬件纹理过滤，Shader 计算量较低，但会带来纹理内存占用、有限的重复周期以及硬件线性插值质量等问题。3D 纹理中的线性插值可能产生可见伪影，尤其是在需要较平滑结果时。

本章采用在像素着色器中直接计算噪声的方案，主要优点包括：

- 不需要保存完整的 3D 噪声纹理，减少纹理内存；
- 可以使用更大的有效周期，减少重复图案；
- 可以与已有 CPU 参考实现保持一致；
- 可以计算 4D 噪声，用额外维度表示时间等动画参数，而当时硬件并不支持 4D 纹理；
- 可以在 Shader 中使用质量更高的插值函数。

缺点是需要由 Shader 自己完成插值和相关查找，不能完全依赖硬件纹理过滤，因此计算成本明显更高。原章给出的优化实现大约需要 50 条 Pixel Shader 2.0 指令。

### 改进 Perlin 噪声的基本流程

算法可以分为两个主要阶段。

#### 1. 为整数网格点生成伪随机哈希值

首先需要为 3D 空间中的每个整数坐标 `(x, y, z)` 生成一个可重复的伪随机值。Perlin 噪声使用一个包含 `0` 到 `255` 随机排列的置换表。

计算时先用 `x` 查询置换表，再把 `y` 加到查询结果上并再次查询，随后以类似方式加入 `z`。通过多次查表，可以得到当前网格区域中各个角点对应的伪随机索引。

这不是每次重新生成随机数，而是通过固定的置换表和哈希过程，使同一坐标始终得到相同结果，并且相邻网格点之间不会呈现简单的周期模式。

#### 2. 使用梯度和插值计算连续值

伪随机索引随后用于选择 3D 梯度向量。改进算法使用有限的一组梯度方向。对于一个输入点，先计算它在当前网格单元中的小数位置，再将每个角点的梯度向量与该角点指向输入点的局部向量做点积，得到角点贡献。

一个 3D 网格单元有八个角点，因此需要计算八个角点的贡献，并沿 `x`、`y`、`z` 三个方向逐级插值，得到最终噪声值。

### 改进的平滑插值函数

改进 Perlin 噪声使用五次 Hermite 多项式作为平滑函数：

```hlsl
fade(t) = t * t * t * (t * (t * 6 - 15) + 10)
```

它可以使噪声函数达到 `C²` 连续，即函数值、一阶导数和二阶导数在网格边界处更加平滑。原始版本使用的三次函数计算成本更低，但二阶导数不连续，可能导致更明显的过渡问题。

### 在像素着色器中保存置换表和梯度表

当时的像素着色器不能方便地像 CPU 那样直接索引常量数组，因此本章把置换表和梯度数据保存到纹理中，再用纹理查找访问：

- 置换表可以保存为一个 `256 × 1` 的 1D 纹理；
- 梯度向量可以保存为包含少量梯度的 1D 纹理；
- 这些纹理使用点采样，避免对离散的表项进行线性插值；
- 地址模式使用 Wrap，使查表坐标循环落在有效范围内。

置换纹理和梯度纹理可以根据 CPU 参考实现中的固定数据在初始化阶段生成，从而保证 GPU 与 CPU 使用相同的噪声定义。

### GPU 版本的 3D 噪声计算

对于输入点 `p`，算法大致如下：

1. 取 `floor(p)` 得到所在网格单元的整数坐标；
2. 取小数部分，得到点在单元内的局部位置；
3. 用平滑函数处理局部坐标，得到三方向的插值权重；
4. 对网格角点坐标进行置换表查找，得到伪随机索引；
5. 根据索引查找梯度向量；
6. 将梯度向量与各角点到输入点的局部向量做点积；
7. 对八个角点的结果进行三线性形式的逐级插值。

这里的“三线性”描述的是 3D 网格中的插值过程，并不是直接调用硬件对一张噪声 3D 纹理做三线性采样。实际的梯度计算和平滑插值都由 Shader 自己完成。

### 优化查找次数

直接照搬 CPU 参考实现，会进行多次递归的置换表查找。为了减少纹理访问，本章使用了两类优化。

第一，将原本需要多次 1D 查找得到的若干哈希结果预先组合到一张 `256 × 256` 的 RGBA 2D 纹理中，通过一次 2D 查找获得多个值。

第二，将梯度表按照置换关系提前展开和重新排列，从而消除后续的一部分置换表查找。

原始实现大约需要 81 条 Pixel Shader 2.0 指令和 22 次纹理查找；优化后约为 53 条指令，其中只有 9 次纹理查找。由于实现中有不少标量计算，原章还指出可以进一步研究如何利用向量运算提高效率。

### 顶点着色器与 4D 噪声

同样的噪声函数也可以改写到顶点着色器中。顶点着色器支持对常量内存进行变量索引时，就不一定需要把所有置换数据放到纹理中。

本章正文主要展示 3D 噪声，随书代码还包含 4D 版本。4D 噪声可以把时间作为第四个输入维度，用于生成随时间连续变化的动画噪声，而不需要把时间简单地当作一张纹理的 UV 偏移量。

### 应用与取舍

程序化噪声可以用于程序化纹理、扰动颜色、生成表面细节以及凹凸映射等效果。它的价值不只是“生成随机图”，而是用一个可重复、连续且可控制的函数，在不同位置得到自然变化。

不过，在实时应用中，为了得到一次噪声值而消耗几十条像素着色器指令，可能并不划算。因此当时的游戏通常会优先使用预计算纹理或更便宜的近似；程序化实现更适合对质量、CPU/GPU 一致性或离线渲染有较高要求的场景。随着 GPU 算力提升、内存访问相对成本增加，程序化计算的吸引力会逐渐提高。
