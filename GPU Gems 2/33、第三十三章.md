# GPU 上的高效并行数据结构

## 章节内容

本章讨论如何在 GPU 的流式、SIMD 内存模型中表示一维数组、二维数组、结构体、列表和稀疏数据结构。重点不是照搬 CPU 指针结构，而是把数据重新编码成规则的纹理流，尽量保证访问连续、相干并且可并行。

### GPU 内存模型

GPU 拥有自己的寄存器、缓存和显存地址空间。CPU 与 GPU 之间通常需要显式复制数据。GPU 的内存层次是为纹理、顶点和帧缓冲等图形访问模式设计的，不能假设它和 CPU 的通用缓存模型完全相同。

片元程序通常从纹理读取，向预先确定的渲染目标位置写入；因此数据结构必须适应固定输出位置、规则并行和有限的随机访问。依赖纹理读取可以模拟间接索引，但如果地址分布不连续，就会降低缓存命中率。

### 一维与多维数组

由于早期 GPU 主要通过二维光栅化和二维帧缓冲更新数据，一维数组常被打包进二维纹理。线性索引需要转换为二维坐标：

```text
x = index mod width
y = floor(index / width)
```

二维数组可以直接映射为纹理；三维数组则可以使用 3D 纹理，也可以将多个切片平铺到二维纹理中。平铺方式减少纹理切换，但需要在 Shader 中自行完成坐标转换。

### 结构体与向量打包

GPU 以四分量向量为基本处理单元，因此多个标量字段可以打包到 RGBA 通道中。这样既可以减少纹理数量，也能提高向量运算和缓存访问效率。但需要注意格式精度、通道排列和地址对齐。

### 列表与稀疏结构

CPU 常用指针、链表和树表示不规则结构，但 GPU 不适合指针追踪和动态分配。可以把节点字段分别存储在多个纹理中，用整数索引模拟链接；不过每次追踪都会产生依赖纹理读取。

稀疏数据结构能够节省大量空数据的存储，但访问更复杂。简单地把稀疏结构展开成稠密纹理虽然容易，却可能因为大量无效元素而失去 GPU 加速。实际选择应比较稀疏结构的查找成本与稠密计算的冗余成本。

### 计算频率与程序特化

GPU 数据可以按计算频率分为常量、Uniform、顶点和片元级别。能在更低频率预先计算的值，不应在更高频率重复计算。例如固定尺寸、缩放因子和地址转换常量可以在 CPU 或 Shader 编译时生成。

程序特化可以把已知的尺寸和常量直接嵌入 Kernel，减少运行时分支和重复运算，但会增加程序变体数量，需要在性能和管理成本之间取舍。

### 总结

GPU 数据结构的基本原则是：把复杂结构拆成规则数组，把指针关系改成索引，把随机写改成固定位置输出，并尽量让相邻线程访问相邻数据。列表、树和稀疏数组可以实现，但通常需要牺牲访问灵活性来换取并行性。
