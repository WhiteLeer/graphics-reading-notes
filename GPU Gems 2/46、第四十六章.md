# GPU 排序优化

## 章节内容

本章讨论如何在 GPU 上实现和优化排序。GPU 排序不仅可以处理计算量大的数据，还能避免把数据读回 CPU 后再排序。章节重点介绍并行 Bitonic Merge Sort，以及一种能较好保持近似有序数据中间状态的排序方式，适合粒子系统等场景。

### GPU 排序的困难

CPU 可以使用指针、分支和随机写入轻松实现排序；GPU 片元程序则受 SIMD 执行、固定输出位置和缺少 Scatter 的限制。把 GPU 结果回读 CPU 排序会产生同步和带宽开销，因此需要把比较交换重新组织为规则的多 PASS 操作。

### 数据驱动与数据无关排序

排序算法可以分为数据驱动和数据无关两类。数据驱动算法的比较路径取决于数据，通常难以映射到 GPU；数据无关算法的比较和交换位置由迭代阶段决定，适合预先安排成规则的比较网络。

### Bitonic Merge Sort

Bitonic 排序通过构造双调序列并反复合并完成排序。每个阶段都有固定的比较对象和升降方向，因此可以让每个 GPU 元素读取配对元素，执行比较交换，再把结果写回预定位置。

排序过程需要多个 PASS，每个 PASS 对应一个比较距离和方向。虽然复杂度相对较高，但访问模式规则、线程之间同步点明确，适合早期 GPU。

### 近似排序

粒子系统通常需要按相机距离排序透明粒子，但短时间内少量顺序错误可能不明显。完全排序的成本很高，因此本章还讨论保留近似有序结构的改进算法，使相邻帧之间不必完全重新打乱数据，从而提高响应速度。

### 应用

GPU 排序可用于透明物体排序、粒子系统、碰撞检测中的空间结构构建、光子映射和其他需要按键值重排的任务。应根据是否要求严格有序、键值范围、数据规模和每帧变化量选择算法。

### 总结

GPU 排序的关键不是照搬 CPU 快速排序，而是选择比较路径固定、内存访问规则的并行排序网络，并通过多 PASS 避免任意写入。若应用允许暂时的近似顺序，则可以用更便宜的增量或近似排序。
