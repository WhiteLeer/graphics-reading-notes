# GPU 程序优化

## 章节内容

本章面向熟悉 CPU 编程、但刚开始编写 GPU 程序的开发者，讨论数据并行、数据布局、计算频率、循环优化、纹理查找、分支、精度和性能测量等常见优化方向。

### 数据并行与向量化

GPU 可以在多个数据元素上同时执行相同操作，也可以利用四分量向量指令并行处理 RGBA 四个分量。可以把多个标量值打包到一个向量或纹理 texel 中，以暴露更多数据级并行性。

但打包并不总是更快。若为了凑成四元组而增加复杂的数据重排、浪费大量通道，或者访问模式变得不相干，额外成本可能超过向量运算收益。数据布局应根据具体算法和缓存行为选择。

### 计算频率

GPU 管线各阶段的工作数量不同：常量只计算一次，Uniform 在一次 Kernel 调用中计算一次，顶点阶段按顶点计算，片元阶段按片元计算。应该把能在较低频率完成的计算尽量提前，避免在大量片元中重复执行。

循环不变量、固定尺寸、矩阵逆和其他与当前元素无关的值，都可以预先在 CPU 或较低频率阶段计算。把 `size * size * 100` 这类表达式从内层循环中提取出来，通常比在每次迭代中重复计算更好。

### 纹理查找表

复杂函数可以预先烘焙成纹理，用纹理采样和硬件插值代替昂贵数学计算。LUT 适合函数固定、输入范围明确、访问空间相干的情况；如果函数参数变化频繁、输入超出范围或采样完全随机，LUT 可能需要较高分辨率和更多内存，收益会降低。

### 减少分支与冗余工作

分支是否有益取决于分支两侧的成本和线程分歧。如果分支条件在一组线程中不一致，GPU 可能需要分别执行多个路径。对于很短的条件，可以使用算术选择；对于昂贵且空间一致的路径，动态分支和 early-out 可能更好。

### 片元、带宽与多 PASS

片元阶段的工作量通常远高于顶点阶段。降低分辨率、减少过度绘制、使用更早的深度剔除、减少纹理带宽和中间 PASS，往往比微调几条 ALU 指令更重要。多 PASS 可以解决指令或寄存器限制，但会增加纹理读写、同步和带宽压力。

### 性能测量

优化必须依靠测量。应分别观察 CPU、顶点、光栅化、片元、纹理带宽和写回阶段，使用不同分辨率、数据规模和 GPU 测试。一个在小场景中有效的优化，可能在大场景中因带宽或缓存行为改变而失效。

### 总结

GPU 优化的核心是让大量线程做相似且有足够计算量的工作，同时减少冗余计算、随机访问、分支分歧、过多中间结果和不必要的数据传输。优化顺序应从算法、数据布局和工作规模开始，再处理局部指令细节。
