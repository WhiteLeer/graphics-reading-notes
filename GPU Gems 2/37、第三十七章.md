# GPU 上的八叉树纹理

## 章节内容

本章介绍用八叉树等层次结构在 GPU 上存储和查询体积纹理数据，使复杂模型能够不依赖传统 UV 参数化进行纹理映射。它特别适合几何表面复杂、UV 接缝和拉伸难以控制的对象。

### 为什么需要八叉树纹理

传统纹理映射需要为网格建立二维参数化，并给每个顶点分配 UV。复杂模型的参数化可能产生拉伸、接缝和大量浪费空间。体积纹理把数据放在包围物体的三维空间中，不再要求网格拥有良好的 UV。

如果把整个包围盒都存成稠密 3D 纹理，会浪费大量空间，因为颜色通常只在靠近表面的区域有意义。八叉树可以递归划分空间，只在需要的区域继续细分，并在不同层级保存颜色或其他属性。

### GPU 中的层次结构表示

八叉树节点通常需要保存子节点存在标记、节点数据以及指向子节点的索引。由于早期 GPU 不支持普通指针和任意内存写入，可以把节点信息编码到纹理中，用索引和纹理坐标模拟树遍历。

为了适合纹理缓存，节点通常按层或按线性数组组织。Shader 根据对象空间位置从根节点开始计算当前子节点编号，逐层查找，直到达到目标分辨率或叶节点。

### 采样与过滤

普通硬件三线性过滤依赖规则 3D 纹理，而八叉树节点的空间布局不规则，因此需要手动定位邻居和重建采样值。为了获得平滑结果，可能需要访问多个节点，并在相邻层级或邻居数据之间插值。

存储在表面附近的属性可以包括颜色、法线、材质参数或其他体数据。因为查询由物体空间位置驱动，模型可以改变拓扑或不具有传统 UV，而不会破坏纹理坐标。

### 应用与取舍

八叉树纹理适合复杂模型、体积数据和程序化表面属性。代价是树遍历、依赖纹理读取和手动过滤都会增加 Shader 成本；节点布局、缓存相干性和层级深度会直接影响性能。对于简单模型，传统 UV 纹理通常更便宜。

### 总结

本章的核心是用稀疏的空间层次结构替代二维 UV 参数化：纹理数据只存储在需要的空间区域，运行时通过位置查找层次结构。它扩展了纹理映射的适用范围，但需要用更复杂的地址计算和过滤成本换取建模自由度与空间利用率。
