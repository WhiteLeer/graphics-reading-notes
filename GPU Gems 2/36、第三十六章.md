# GPU 上的流归约操作

## 章节内容

本章讨论如何在 GPU 上完成“输入元素数量固定、输出元素数量由数据决定”的过滤和压缩操作。片元处理器天然把一个输入元素映射到一个预定输出位置，因此难以直接实现可变长度输出；本章使用扫描和搜索来模拟流过滤，并将其应用于碰撞检测和 Loop 细分。

### GPU 中的可变输出问题

普通片元程序对每个输出位置执行一次 Kernel，输入和输出数量通常固定。CPU 可以遍历数组，把满足条件的元素追加到输出列表；GPU 片元程序却不能直接把当前元素写到下一个空闲位置。

固定比例的归约，例如每次把 2×2 个 texel 合并为一个 texel，已经可以通过逐级缩小纹理实现。困难在于过滤：有些输入元素保留，有些丢弃，输出长度不再固定。

### Filtering、Scan 与 Search

假设每个输入元素经过判断得到 `0` 或 `1`：

```text
flag[i] = keep(input[i]) ? 1 : 0
```

对 flag 做前缀和扫描，可以得到每个元素在输出中的潜在位置。保留元素的扫描值决定它应该被放到输出流的哪个位置。由于早期 GPU 无法直接 Scatter，需要把“写入某个输出位置”反过来做成“输出位置搜索原输入中应该占据它的元素”。

这种方法通常需要：

1. 计算每个元素是否保留；
2. 对标记做扫描，获得累计数量；
3. 根据目标输出索引搜索对应的输入元素；
4. 输出压缩后的数据流。

扫描和搜索会增加额外成本，但避免了 GPU-CPU 回读和 CPU 端重新组织数据。

### 碰撞检测应用

碰撞检测通常先为大量候选对象生成标记，再过滤掉不可能发生碰撞的元素。GPU 可以并行处理候选对并生成过滤结果，扫描和搜索负责把有效候选压缩成连续流，之后再进行精确检测。

### Loop 细分应用

Loop 细分需要根据相邻三角形和顶点关系生成新的顶点和面。邻接关系及输出数量并不总是规则，本章展示如何使用流过滤和数据重排，把需要处理的元素压缩成 GPU 可以继续处理的流。

### 顺序与硬件支持

扫描阶段可以借助片元程序逐级完成，但要获得线性时间的高效扫描，理想硬件应提供快速的运行中累加寄存器，以及把片元发送到任意输出位置的能力。早期 GPU 缺少这些功能，因此搜索阶段是重要成本。

过滤后的元素顺序有时并不重要；如果算法允许改变顺序，就可以采用更灵活的并行方法。若必须保持顺序，GPU 实现会更加困难。

### 总结

本章的关键思想是用“标记—扫描—搜索”模拟 GPU 上的可变长度输出，把难以直接 Scatter 的压缩操作改写成规则的 Gather。它为碰撞检测、细分和其他筛选型 GPGPU 算法提供了早期通用套路。
