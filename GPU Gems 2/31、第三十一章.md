# 将计算概念映射到 GPU

## 章节内容

本章把通用计算中的数组、循环、Kernel 和数据结构映射到 GPU 的顶点处理器、片元处理器、纹理和渲染目标，帮助读者建立适合 GPGPU 的数据并行思维。

### 数据并行与独立性

GPU 最擅长的是把相同或相似的计算应用到大量数据元素，并且每个元素之间几乎没有依赖。除了数据并行性，还需要关注算术强度，也就是运算次数相对于数据传输量的比例。

规则网格是很好的 GPU 数据结构，因为它可以自然地表示为纹理。矩阵运算、图像和体数据处理、基于网格的物理模拟以及部分全局光照算法都可以映射到这种形式。

### GPU 资源的对应关系

- CPU 数组或流元素：纹理中的 texel、顶点流或片元；
- CPU 循环体：顶点程序或片元程序中的 Kernel；
- CPU 输出数组：渲染目标纹理或顶点缓冲；
- 数组索引读取：依赖纹理查找；
- 多阶段算法：多个全屏 Quad PASS 和中间纹理；
- 归约和全局统计：逐级缩小的纹理或扫描、搜索过程。

顶点处理器更适合处理较少量的结构化元素，片元处理器通常拥有更大的并行吞吐量，因此许多 GPGPU 算法会把数据编码进纹理，并通过片元程序计算。

### 网格模拟示例

本章使用基于二维网格的云模拟作为例子。每个网格单元可以存储状态变量，片元程序读取当前单元及邻域的数据，计算下一状态并输出到新的纹理。下一次迭代交换输入和输出纹理即可。

这种方法的关键不是把云的物理方程写进某个特定 API，而是把方程拆解为大量规则网格元素上的局部计算，使 GPU 能够并行处理整个网格。

### 一个简单的 GPU 计算框架

典型流程如下：

1. 将输入数组编码为纹理或顶点流；
2. 创建覆盖目标尺寸的屏幕对齐四边形；
3. 让片元程序对每个位置执行 Kernel；
4. 将结果渲染到新的纹理；
5. 必要时交换 Ping-Pong 纹理并进入下一阶段；
6. 最后通过纹理采样或读回 CPU 得到结果。

### 不适合 GPU 的任务

如果任务包含大量分支、随机写入、动态数据结构、短数据流、严格串行依赖，或者每个元素只执行很少运算却需要频繁跨总线传输，就很难获得 GPU 加速。应先重组算法，而不是只把 CPU 循环机械地改写成 Shader。

### 总结

映射到 GPU 的核心是把问题改写为“对一条长数据流统一执行 Kernel”。数据结构、内存布局、访问模式和阶段之间的传递方式，往往比单个数学公式的实现更决定性能。
