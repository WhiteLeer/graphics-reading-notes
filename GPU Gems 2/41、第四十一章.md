# 从困难数据格式延迟过滤渲染

## 章节内容

本章介绍如何渲染 GPU 计算中常见但不适合硬件直接过滤的数据格式，例如压缩体数据、稀疏数据和展平的 3D 纹理。核心方法是 Deferred Filtering：先把需要的局部数据重建为普通纹理，再让硬件在第二个 PASS 中完成高质量插值。

### 为什么困难数据格式难以过滤

为了节省内存或适应计算，云、火焰、隐式表面和模拟数据可能使用向量量化、稀疏块、Flat 3D Texture 等布局。访问一个数据点时，可能需要先读取索引纹理，再访问码本或多个邻居样本。

如果在最终渲染片元中手动完成所有重建和三线性过滤，每个可见片元都会重复读取相同的邻域数据，并执行大量地址计算和插值，导致巨大的冗余。

### 延迟过滤的两 PASS 结构

第一 PASS 在数据的原生分辨率下重建一个局部、规则的子集，并写入普通 2D 纹理。第二 PASS 使用硬件原生的双线性或三线性过滤对重建结果进行采样和渲染。

```text
困难数据格式 → 局部重建纹理 → 硬件过滤 → 最终图像
```

这样把昂贵的格式解码和邻域重建集中到一次，而不是让每个最终片元重复完成。对于 3D 数据，可以按主视方向进行轴对齐切片，并在相邻 2D 切片之间手动完成需要的三线性插值。

### 体渲染中的使用

当视线方向接近某个主轴时，选择与视线最接近的切片方向，可以减少切片数量和重建成本。第一 PASS 将压缩或稀疏数据解码为局部规则纹理，第二 PASS 沿体切片采样并累积颜色和透明度。

这种增量重建方式不需要一次把整个 3D 数据解压到显存，内存消耗可以接近当前需要渲染的 2D 区域规模。

### 总结

Deferred Filtering 的本质是把“数据格式解码”和“硬件插值”拆开：第一阶段把复杂格式变成规则的局部纹理，第二阶段把规则纹理交给 GPU 固定功能过滤。它用额外 PASS 换取更少的重复工作，适合动态体数据和 GPGPU 产生的非标准布局。
