# GPU 通用计算入门

## 章节内容

本章从实际编程角度说明如何把算法搬到早期 GPU 上运行，重点讨论内存局部性、算术强度、浮点格式、随机访问以及 GPU 不擅长的 Scatter 写入。

### 先选择适合 GPU 的算法

GPU 主要为渲染设计，而不是为通用信号处理、复杂线性代数或任意数据结构设计。算法能否加速，取决于它是否具有足够的数据并行性、顺序且规则的内存访问，以及足够高的算术强度。

GPU 对连续读取有很高带宽，但对随机读取和无规律访问不友好。CPU 可以借助可读写缓存、分块和复杂控制流隐藏访问成本；早期 GPU 的缓存更小且主要服务于纹理访问，帧缓冲写入也不会像 CPU 缓存那样被常规复用。

因此，大规模向量加法这类顺序读写、元素间独立的任务很适合 GPU；数据集很小、可以完全放入 CPU 缓存，或者需要大量随机访问的任务，GPU 未必占优。

### 让计算支配性能

仅有高带宽并不保证加速。如果每个元素只做一次简单操作，传输和启动成本可能占主导。通过增加每个元素的计算量、重用已经读取的数据、减少中间结果写回，可以提高算术强度，让 GPU 的计算单元得到充分利用。

### GPU 浮点数

早期 GPU 支持多种浮点格式，包括 32 位浮点、16 位浮点和固定点格式。不同格式在范围、精度、特殊值以及硬件支持方面存在差异。需要仔细考虑：

- 尾数位数决定有效精度；
- 指数范围决定能表示的最大和最小值；
- 16 位格式可能无法保存很大的动态范围；
- 不同厂商对 NaN、无穷、舍入和非规格化数的处理可能不同；
- 多 PASS 累积时，低精度会产生明显误差。

对于数值算法，应先分析所需范围和误差，再选择格式，而不能只因为“浮点”就认为精度足够。

### Gather 与 Scatter

片元程序天然适合 Gather：当前片元根据计算出的坐标，从纹理中读取任意位置的数据。但它不能直接执行 Scatter，即根据当前元素计算出的地址把结果写到任意位置。

例如：

```c
x = a[i];       // Gather，容易映射为纹理读取
a[i] = x;       // Scatter，需要根据 i 任意写入
```

排序、哈希、直方图和不规则邻接结构都依赖 Scatter。常见绕行方式是反转计算，把“谁应该写入这个位置”改写为“这个位置去查询应该写入它的元素”，也就是用 Gather 模拟 Scatter；或者使用排序、扫描和搜索等多 PASS 算法。

### 总结

把算法搬到 GPU 前，应该先检查数据并行性、访问局部性、算术强度、精度需求和写入模式。GPU 计算的核心难点往往不是算式，而是如何把随机写、动态结构和全局依赖改写成规则的纹理读写。
