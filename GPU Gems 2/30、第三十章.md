# GeForce 6 系列 GPU 架构

## 章节内容

本章以 GeForce 6800 和 Shader Model 3.0 为例，介绍当时一代可编程 GPU 的整体硬件结构、图形管线、通用计算能力以及性能特征。它是理解早期 GPGPU 技术限制的重要硬件背景。

### GPU 与主机系统

CPU 通过 AGP 或 PCI Express 等总线向 GPU 发送命令、纹理和顶点数据。GPU 内部显存带宽远高于 CPU-GPU 总线和 CPU 内存接口，因此适合把大量数据留在 GPU 内部处理，避免频繁回读。

### 图形管线结构

命令流、顶点和状态由 CPU 提交后，GPU 的命令解析和顶点读取单元负责取出数据。顶点处理器执行变换、蒙皮以及其他逐顶点操作；GeForce 6 首次允许顶点程序读取纹理，因此可以执行顶点纹理位移等任务。

经过光栅化后，三角形被展开为片元。片元处理器执行逐片元计算，纹理单元负责纹理读取和过滤，深度比较、混合与写回单元负责最终的可见性和颜色写入。深度剔除单元可以在片元着色之前排除明确不可见的片元。

### 作为通用处理器

如果去掉传统图形语义，GPU 可以看作由可编程顶点处理器、片元处理器、纹理读取单元和写回单元构成的高吞吐浮点处理器。顶点处理器可以生成或变换数据，光栅化器可以把顶点结果扩展为规则的片元网格，片元处理器再对这些元素执行计算。

但早期 GPU 的通用计算仍必须借助图形 API 和纹理、顶点、帧缓冲等对象表达数据。片元程序不能任意写到其他位置，很多算法需要通过纹理查找和渲染目标来间接完成。

### Shader Model 3.0 与固定功能特性

GeForce 6 支持更灵活的顶点和片元程序、动态分支、循环以及顶点纹理读取。硬件还提供几何实例化所需的 Vertex Stream Frequency，使一次 Direct3D 调用可以重复使用同一批几何体，并给每个实例使用不同的变换或实例数据。

硬件也加强了早期剔除和裁剪，能够在着色之前快速排除完全不可见的图元，并高效处理部分可见图元。

### 总结

本章展示了早期统一可编程趋势下 GPU 的本质：大量并行浮点计算能力和高显存带宽，但受限于图形管线、纹理寻址、固定输出位置以及 CPU-GPU 总线。理解这些限制，有助于理解后续章节为什么要使用 Ping-Pong 纹理、扫描、查找和多 PASS 技巧。
