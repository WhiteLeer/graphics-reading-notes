# 将 Phenomena 渲染器实现到 GPU

## 章节内容

本章介绍 mental images 如何把 mental ray 中由多个可组合 Shader 构成的 Phenomenon 转换为 GPU 程序。核心问题不是单独编写一个材质 Shader，而是把材质、纹理、光源、阴影、环境、体积和透明度等多个节点组成的 Shader Graph，在运行时收集、连接并生成一个可以下载到 GPU 执行的整体 Fragment Program；如果 GPU 或 Shader 编译器无法支持某个效果，则回退到软件渲染。

### 1. 从 mental ray 到 GPU

mental ray 是面向高质量离线渲染的渲染器，Shader 在其中是可以挂载到材质、光源、相机、体积和合成流程中的插件模块。与实时渲染中一个顶点 Shader 或像素 Shader 通常负责一个完整效果不同，离线渲染器会把复杂效果拆分成许多可复用的 Shader，再根据场景连接它们。

现代 GPU 能够执行越来越复杂的逐片元计算，因此可以把原本主要由 CPU 软件渲染器执行的部分计算转移到 GPU。但软件渲染器能够执行的功能并不一定都能直接映射到 GPU，尤其是任意递归、完整光线追踪、复杂的动态 Shader 调用等功能仍然受硬件和 Shader 语言限制。

本章的目标是让 GPU 和 CPU 使用相同或等价的 Shader 语义，在满足硬件能力时加速最终图像生成，同时保留软件渲染作为功能和兼容性后备方案。

### 2. Shader 与 Phenomenon

mental ray 中的 Shader 是独立的插件模块，可以负责：

- 材质和表面反射；
- 光源发光和衰减；
- 纹理与环境；
- 体积效果，例如雾；
- 相机镜头和后处理；
- 合成和其他渲染阶段。

例如，一个表面 Shader 可以描述 BRDF，一个光源 Shader 可以描述点光源、聚光灯或面光源的照明特性。软件渲染时，渲染器可以依次调用材质 Shader、所有相关光源 Shader、环境 Shader、体积 Shader 等。如果材质透明或需要反射、折射，还可能继续调用其他对象的 Shader。

Phenomenon 是对 Shader Graph 的进一步封装。它包含多个相互连接的子 Shader、渲染选项、材质、几何体、体积和其他元素。它对外表现为一个可复用的整体效果，但内部仍然是由多个节点组成的图。

一个 Phenomenon 通常具有：

- 输入参数，例如颜色、粗糙度、环境强度或纹理；
- 内部连接的 Shader 或子 Phenomenon；
- 一个或多个输出参数；
- 一个负责最终结果的根 Shader。

艺术家可以把不同 Shader 的输出连接到另一个 Shader 的输入。例如，木材 Phenomenon 可以暴露颜色和木纹扰动参数，不同实例只需要传入不同参数，就可以得到橡木、红木或桦木等变化。

### 3. GPU 无法直接动态调用多个 Shader

GPU 通常不能像 CPU 一样加载多个独立 Shader，然后在运行时让一个 Shader 任意调用另一个 Shader。GPU 更适合执行编译完成的整体程序。

因此，mental ray 的处理方式是：

```text
收集 Phenomenon 的所有子 Shader
        ↓
解析输入输出连接关系
        ↓
将 Shader Graph 展开并组合
        ↓
生成一个完整的 Cg Fragment Program
        ↓
编译并下载到 GPU
```

Cg 1.2 引入的 Shader Interface 和无尺寸数组等能力，使不同 Shader 组件可以使用抽象接口互相连接。运行时通过 Cg Runtime 创建具体的子 Shader 实例，再把一个节点的输出连接到另一个节点的输入。

这实际上是一种运行时 Shader 组合或 Shader Graph 展开：最终 GPU 执行的并不是一堆可动态调用的独立 Shader，而是由这些组件生成的单个专用程序。

### 4. 顶点程序与 varying 参数

本章发现，大多数效果可以共用一个较简单的顶点程序。顶点程序主要负责：

- 变换顶点位置；
- 把常用数据从顶点阶段传给片元阶段；
- 准备纹理坐标、位置、法线和表面导数。

传给 Fragment Program 的典型 varying 数据包括：

- 齐次裁剪空间位置；
- 四组纹理坐标；
- 相机空间位置；
- 相机空间法线；
- 表面参数方向上的导数 `derivU` 和 `derivV`；
- 屏幕坐标；
- 正反面标记。

除了纹理坐标之外，许多数据会先转换到相机空间，简化后续的光照和距离计算。需要时，片元程序仍可以使用矩阵把数据转换到其他空间。

### 5. 统一的 Fragment Program 入口

由多个组件组合出来的 GPU 程序需要有统一的 `main()` 入口。这个入口负责调用 Phenomenon 的根 Shader，根 Shader 再触发整个 Shader Graph 的计算。

统一入口还可以处理所有材质都需要的公共逻辑。例如，本章的实现会在入口中读取深度纹理，并丢弃位于当前深度层之前的片元，以支持后面介绍的深度剥离透明渲染。

### 6. 抽象 Shader Interface

为了让不同 Shader 之间能够互相连接，系统为常见的输入输出类型定义抽象接口，例如：

- 标量；
- 布尔值；
- 颜色；
- 向量；
- 结构体；
- 光照结果。

一个 Shader 的输入参数可以来自：

- 场景或材质提供的常量；
- 纹理采样；
- 另一个 Shader 的输出；
- 另一个 Phenomenon 的输出；
- 内部计算结果。

通过这些接口，表面 Shader 不需要写死某种具体光源，而是访问抽象的 Light Interface。只要点光源、聚光灯或其他光源实现了相同接口，就可以被同一个表面 Shader 使用。

### 7. 材质 Shader 与光源 Shader

材质 Shader 负责描述表面对入射光的响应，光源 Shader 负责描述光源的颜色、方向、衰减、光锥和阴影等信息。

光源 Shader 通常返回：

- 光源贡献的颜色；
- 从表面指向光源的方向；
- 光照方向与表面法线的点积。

阴影也可以由光源 Shader 处理。它可以采样之前 Pass 生成的阴影贴图，判断当前片元是否被光源看到；如果片元在阴影中，光源 Shader 通常返回黑色或较低的光照贡献。

这样，材质 Shader 只需要向抽象光源接口请求光照，而不必关心当前使用的是哪一种具体光源。

### 8. 凹凸贴图的组合

凹凸贴图可以被实现成一个修改法线的 Shader 节点。这个节点先根据纹理或程序计算修改后的法线，再把修改后的结果传给材质 Shader。

其连接关系可以理解为：

```text
原始法线
    ↓
凹凸 Shader 修改法线
    ↓
材质 Shader 使用新法线计算光照
```

法线修改器不一定只能读取一张普通法线贴图，也可以组合多张纹理或使用程序噪声。顶点阶段传入的 `derivU` 和 `derivV` 可以帮助 Shader 在正确的表面方向上采样和计算，使凹凸纹理随着物体旋转保持正确方向。

### 9. 环境 Shader 与体积 Shader

环境 Shader 用于处理反射、透明表面看到的环境，或者摄像机方向上没有击中场景物体的区域。由于当时 GPU 还不能高效支持完整通用光线追踪，反射和折射材质主要只能访问全局环境，而不能自由发射光线并击中任意场景物体。

体积 Shader 作用于每个片元，例如相机上的雾。它可以根据片元到相机的距离衰减颜色，形成大气效果。由于体积效果需要影响所有最终片元，因此系统会把体积 Shader 自动放在主 Phenomenon 结果的外层。

### 10. 头发的处理

mental ray 中的头发可以表示为 Bézier 曲线。为了在 GPU 上绘制，曲线会被近似转换为三角形。发丝数量很大时可能生成数百万个三角形，其中许多三角形小于一个片元。

发丝转换成几何体后，可以像普通物体一样附加 Phenomenon。传入的 varying 数据还可以包含：

- 发丝切线；
- 从发根到发梢的相对位置；
- 发丝半径或宽度。

这些数据足以让头发使用专门的光照模型。就 Shader Graph 的组合机制而言，头发 Phenomenon 和其他材质 Phenomenon 没有根本区别。

### 11. 完整渲染流程与软件回退

一帧渲染的大致流程是：

```text
收集需要生成阴影的光源
        ↓
生成阴影贴图或光源距离数据
        ↓
将场景中的 Phenomenon 转换为 Cg
        ↓
合并不同材质和光源形成 Shader Tree
        ↓
按目标 GPU 配置编译
        ↓
编译成功：GPU 渲染
编译失败或功能不支持：软件渲染
```

由于场景中可能包含透明材质，本章使用深度剥离实现顺序无关透明。每次 Pass 找到当前深度层，再在下一次 Pass 中剥离已经处理过的片元，从而逐层合并透明贡献。

当硬件 Pass 和软件 Pass 都完成后，系统会根据深度和 Alpha 将结果合并。如果显存不足、纹理无法放入 GPU、Cg 编译失败或程序超过硬件限制，就让相关对象回退到软件渲染，而不是让整个场景失败。

### 12. 优点与局限

优点包括：

- 可以复用离线渲染器中的模块化 Shader 语义；
- 让多个 Shader 组件组合成一个 GPU 程序；
- GPU 和 CPU 可以得到一致或接近的结果；
- 在纹理驻留显存且编译成功时，GPU 渲染速度可能远高于 CPU 软件渲染；
- 不支持 GPU 的部分仍可由软件渲染器完成。

局限包括：

- Shader Graph 需要预处理、展开和编译；
- 组合后的程序可能过大或超出 GPU 指令、寄存器等限制；
- GPU 不能直接支持软件渲染器的所有功能；
- 完整光线追踪和复杂动态 Shader 调用仍受限制；
- 软件与硬件之间的混合、透明度和深度剥离会增加渲染复杂度。

本章的 Cg、Cg Interface 和当时的 GPU 限制已经过时，但“将材质节点图专门化并编译成 GPU 可执行程序、失败时回退或拆分处理”的思想，仍然可以对应到现代引擎中的 Shader Graph、Shader Variant、材质专用化和 GPU/CPU fallback。

## 讨论与补充

### 1. Phenomenon 与 ShaderLab/HLSL 函数不是同一层级

它们最终都会被编译成 GPU 可以执行的完整 Shader，因此看起来很相似，但抽象层级不同。

ShaderLab 主要负责声明 Unity Shader 的资源、SubShader、Pass、Tags 和渲染状态；其中真正的函数通常是写在 ShaderLab 中的 HLSL/Cg 函数。例如：

```hlsl
float3 ApplyNormalMap(float3 normal, float2 uv)
{
    return normal;
}
```

这类函数通常在编译阶段就已经成为同一个 Vertex/Fragment Program 的一部分。运行时一般是选择已经编译好的 Shader 或 Shader Variant，而不是临时把几个独立函数重新连接。

Phenomenon 更像一个可连接的 Shader Graph：材质、纹理、凹凸、光源、阴影、环境和体积等模块具有明确的输入输出接口。mental ray 会根据当前场景收集这些模块，将它们连接起来，展开为一个专用的 Cg Fragment Program，再交给 GPU 执行。

```text
凹凸 Shader ─┐
             ├─> 材质 Shader ─┐
聚光灯 Shader ────────────────┘
```

GPU 执行时仍然不是动态加载并调用多个独立 Shader，而是执行已经组合完成的整体程序。

### 2. 与现代 Unity 的对应关系

Phenomenon 更接近 Unity 中的 Shader Graph、Sub Graph、Custom Function Node 和 Shader Variant 的组合，而不是普通的 ShaderLab 函数调用：

| GPU Gems 2 | Unity 中较接近的概念 |
| --- | --- |
| Shader | HLSL 函数、Shader Graph 节点 |
| Phenomenon | Sub Graph、Shader Graph |
| Shader Interface | 节点输入输出端口 |
| 运行时组合 | 生成 Shader、编译 Variant |
| Fragment Program | 编译后的 Pass 程序 |

Unity 的 Custom Function Node 可以把自定义 HLSL 注入 Shader Graph，Sub Graph 可以复用一组节点；但最终仍然要生成完整的 Shader 代码并编译。Unity 官方文档也明确把 Custom Function 描述为向 Shader Graph 中注入自定义 HLSL 代码。

还要区分 Shader Graph 节点与 ShaderLab Pass：Phenomenon 中的多个节点通常会被组合到同一个 Fragment Program；Unity 中多个 Pass 通常意味着对象会被多次绘制。Pass 是渲染调用层面的划分，不等同于 Shader Graph 内部函数或节点的划分。
