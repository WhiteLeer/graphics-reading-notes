# Apple Motion 中的 GPU 图像处理

## 章节内容

本章以 Apple Motion 为例，说明如何把图像处理算法放到 GPU 上执行，以及在设计 GPU 图像处理管线时需要面对的限制。核心思想是：图像处理是否适合 GPU，主要取决于每个输出像素能否独立地由输入图像和邻域数据计算得到；如果算法依赖严格的执行顺序、全局统计或不规则写入，GPU 实现就会更加困难。

### GPU 图像处理的优势

Motion 将大量图像处理任务交给 GPU，以获得远高于 CPU 实现的吞吐量。在当时的测试环境中，GPU 版本的处理速度可以达到 CPU 版本的数倍甚至十几倍。图像处理通常具有大量相互独立的像素运算，正适合由 GPU 同时处理。

但 GPU 并不是对所有算法都更快。设计实现时必须考虑 GPU 的并行执行模型、纹理采样方式、指令数量、精度、临时缓冲区以及多 PASS 之间的数据传递成本。

### 适合 GPU 的算法类型

#### Image In，Image Out

输入一张或多张图像，输出一张图像，并且每个输出像素都可以独立计算。这是最适合 GPU 的类型，例如颜色调整、亮度和对比度调整、简单的颜色空间转换等。

#### Image In，Statistics Out

输入图像，输出直方图、平均亮度等全局统计数据。这类任务在数学上并不一定复杂，但 GPU 的每个线程通常负责不同像素，最终却要把大量结果汇总到固定位置，容易产生并发写入和同步问题，因此实现难度更高。

#### 颜色变换

颜色变换通常对每个像素独立进行，适合在像素着色器中完成。简单变换可以直接用数学公式计算；复杂变换也可以使用预先生成的查找表。查找表能够把复杂的颜色映射转换为纹理采样，相关方法可参考第二十四章。

#### 独立的邻域运算

如果输出像素只依赖输入图像的一个局部邻域，且每个输出像素都可以独立完成计算，也适合 GPU。例如卷积、边缘检测和高斯模糊。通常需要多次采样邻域纹理，并通过多个 PASS 和中间的 pbuffer 保存阶段结果。

#### 顺序相关的邻域运算

如果后一个像素必须依赖前一个像素已经计算出的结果，算法就不适合直接映射到 GPU。GPU 不保证片元着色器按照某个固定的像素顺序执行，因此类似滑动窗口盒式滤波这类严格依赖执行顺序的算法，需要重新设计或改用其他实现方式。

#### 条件执行

在当时的 GPU 上，片元程序的分支能力有限，甚至没有真正的动态分支。遇到条件逻辑时，常见做法是同时计算多个分支的结果，再根据条件选择最终值。这样可以实现算法，但会增加指令数量。

### 着色器语言与 CPU 参考实现

本章使用较底层的 ARB fragment program，是因为当时高层 GPU 编程语言和工具链还不成熟。底层语言能够更直接地控制指令和资源，但代码可读性、调试体验和可维护性较差，也需要开发者自行面对硬件差异和资源限制。

实际工程中建议保留一个 CPU 参考实现，用于验证算法正确性、定位 GPU 版本的问题以及对比不同硬件的结果。Motion 当时主要面向具备目标 GPU 能力的设备，因此没有把所有效果都设计成必须在低端设备上运行的 CPU 回退方案。

### 指令数量、纹理指令与多 PASS

不同 GPU 对算术指令、纹理指令和纹理间接寻址次数有不同限制。例如早期 ATI R3xx 硬件和 NVIDIA NV3x 硬件的指令上限并不相同，单个着色器可能因为超过硬件限制而无法运行。

当纹理采样依赖前一次采样结果时，会产生 dependent texture read；纹理间接寻址层数也可能受到限制。解决这些问题的手段包括把部分计算转移到顶点阶段、拆成多个 PASS，或者使用中间 pbuffer 保存结果。但多 PASS 会增加渲染和带宽成本，而且中间缓冲区的格式可能降低精度，因此应当作为受限制时的最后手段。

### 数值精度与跨硬件差异

不同 GPU 对除零等特殊情况的处理可能不同。为了避免 ATI 和 NVIDIA 等硬件产生不一致结果，应在除数中加入足够小的 epsilon，避免直接进行不稳定的除法。

8 位图像通道通常不足以保存多次累积运算的中间结果。例如运动模糊会把多个时间样本累加到一起，如果中间结果仍然使用 8 位精度，就容易出现量化误差和条带。能够使用时，应选择 16 位或 32 位浮点格式。

如果硬件不支持足够高的浮点精度，可以用两个通道存储 8.8 定点数，分别表示整数部分和小数部分，再通过两个 PASS 处理 RG 与 BA 等通道，以换取更高的有效精度。

### 顶点属性与纹理坐标限制

当一个图像处理 PASS 需要访问很多输入纹理时，纹理坐标或顶点属性数量也可能成为限制。可以使用直通顶点着色器，把多个纹理坐标传递给片元程序，以便在同一个 PASS 中访问更多输入。

### 双线性过滤造成的图像软化

如果只是把图像按原尺寸复制到另一张纹理，双线性过滤也可能因为子像素精度和采样位置造成轻微软化。需要精确一一对应时，应使用最近点采样，或者把大矩形细分成更小的网格，并由 CPU 为顶点计算更准确的纹理坐标。

### Alpha 边缘与预乘 Alpha

直通 Alpha 的透明纹理中，透明像素的 RGB 通常仍然可能是黑色。双线性过滤或模糊会把这些透明黑色像素与不透明边缘混合，导致边缘出现黑边或颜色渗漏。

解决方法是使用预乘 Alpha：在存储颜色时先将 RGB 乘以 Alpha，使透明区域的颜色贡献与透明度一致。模糊等会混合颜色的操作也更适合在预乘 Alpha 空间完成；但某些颜色校正操作更适合直通 Alpha，因此需要在不同处理阶段之间进行相应的转换。

### 调试 GPU 图像处理

GPU 图像处理的问题可能表现为白色、黑色或完全没有输出。可以采用以下方式定位：

- 输出固定的黄色等常量，确认着色器确实执行；
- 使用 CPU 参考版本与 GPU 结果比较；
- 将中间结果写入帧缓冲，并把数值缩放到可显示的 0 到 1 范围；
- 把复杂管线拆开，逐 PASS 检查中间图像；
- 在不同 GPU 上测试，排查硬件限制和精度差异。

### 总结

GPU 图像处理适合大量独立的像素运算，能够显著提高吞吐量，但并不是把 CPU 算法直接搬进像素着色器就结束了。工程实现必须围绕 GPU 的并行模型和资源限制重新组织算法，特别注意全局统计、执行顺序、纹理间接寻址、多 PASS 精度损失、Alpha 表示方式以及跨硬件差异。

## 讨论与补充

### 1. GPU 图像处理适合什么类型的任务

我的理解是：可以转化为纹理输入和纹理输出、并且具有较高并行度的运算，通常都适合放到 GPU 执行。

更准确地说，除了能够表示为纹理读写之外，还要看输出像素之间是否相对独立。如果每个输出像素都能根据输入纹理及其局部邻域独立计算，那么颜色变换、卷积、模糊、边缘检测等任务就很适合 GPU；如果算法需要全局统计、严格的执行顺序，或者多个线程共同写入固定位置，就不能只因为它“计算量大”或“看起来并行”就直接搬到普通像素着色器中。

因此，本章可以概括为：

> 能够转化为规则的纹理读写，并且各输出像素可以独立计算的高并行任务，通常适合交给 GPU。

直方图、全局统计、递推滤波等任务也可能通过归约、分阶段计算或其他并行算法实现，但实现难度和同步成本更高。
