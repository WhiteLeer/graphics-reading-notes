# Nalu Demo 中的毛发动画与渲染

## 章节内容

本章介绍 Nalu Demo 中实时渲染长金色水下毛发的完整方案，涵盖毛发几何生成、控制毛发动力学、碰撞、毛发插值、基于 Marschner 模型的反射，以及用于毛发自阴影的 Opacity Shadow Map。核心思想是只对少量控制毛发进行昂贵计算，再通过曲线细分和插值生成大量最终渲染毛发。

### 1. 实时毛发的主要难点

毛发同时具有数量多、单根纤细、运动复杂、需要碰撞和自阴影等特点。普通 Shadow Map 很难处理密集细毛发的半透明遮挡，普通表面 BRDF 也不能很好描述光线在毛发纤维内部的反射和透射。

Nalu 的毛发由约 4095 根渲染毛发组成，渲染数据约有 123000 个顶点。如果把所有渲染毛发都直接送入动力学和碰撞计算，成本会过高。因此系统将毛发分成：

```text
少量控制毛发 → 动力学和碰撞
大量渲染毛发 → 插值生成和最终绘制
```

### 2. 控制毛发与毛发生成

系统使用 Maya 中制作的头皮网格描述发型。控制毛发从头皮网格顶点沿顶点法线方向生长，头皮本身在最终渲染时不可见。

控制毛发数量较少，负责：

- 描述整体发型；
- 进行物理模拟；
- 处理碰撞；
- 提供艺术家可控制的形状；
- 作为大量最终毛发的插值基础。

由于完全依赖程序动力学会损失艺术控制，Nalu 还添加了一些手工修正和控制工具，用来调整不符合创作要求的运动结果。

### 3. 每帧的毛发数据流

毛发完全动态，每帧都需要重建最终渲染毛发：

```text
控制毛发动画
        ↓
转换为 Bézier 曲线
        ↓
曲线细分，增加顶点
        ↓
根据头皮拓扑插值出更多毛发
        ↓
写入动态 Vertex Buffer
        ↓
使用线段原语渲染
```

原章中控制毛发的顶点数量从 7 个增加到 36 个，用于改善毛发曲线的平滑度。

### 4. Bézier 曲线细分

控制毛发最初只有少量离散顶点，直接连接会出现折线。系统根据控制毛发顶点计算切线，再构造 Bézier 控制点，并通过 Bézier 曲线求值得到更多中间顶点：

```text
离散控制毛发
        ↓
计算切线
        ↓
构造 Bézier 控制点
        ↓
求取曲线上的中间位置
        ↓
得到平滑毛发
```

### 5. 使用重心坐标插值增加毛发密度

头皮网格每个三角形的三个顶点都带有一根平滑控制毛发。系统使用这三根毛发在三角形内部插值出新的毛发。

如果三根控制毛发为 `A`、`B`、`C`，则内部毛发可以表示为：

```text
Y = bA × A + bB × B + bC × C
```

其中：

```text
bA + bB + bC = 1
```

通过随机生成满足条件的重心坐标，可以在头皮三角形内部分布更多毛发。插值毛发与控制毛发保持相同的顶点数量，从而能够沿毛发长度方向一致地插值每个控制点。

### 6. 基于粒子的毛发动力学

每根控制毛发由多个粒子组成，每个粒子对应毛发上的一个顶点。毛发粒子沿远离头皮的方向可以使用逐渐变大的间距，从而在不增加过多顶点的情况下表现较长毛发。

本章使用 Verlet 积分计算粒子运动：

```text
当前位置
上一帧位置
外力
        ↓ Verlet 积分
下一帧位置
```

Verlet 相比简单 Euler 积分更适合带距离约束的链状结构，并且比 Runge-Kutta 更容易实现。

### 7. 毛发长度约束

相邻粒子之间需要保持固定长度：

```text
P0 —— P1 —— P2 —— P3
```

当两个粒子距离过大时，将它们拉近；距离过小时，将它们推开。由于修改一段会影响相邻段，因此需要反复迭代约束，使整条毛发逐渐收敛到合理长度。

### 8. 毛发碰撞

Nalu 尝试了多种碰撞方式，最终使用一组球体近似头部和身体：

```text
头部、肩膀、身体
        ↓
球体碰撞体
```

控制毛发粒子与这些球体进行碰撞。单纯使用粒子点碰撞存在问题：如果一段毛发的两个端点都在球体外部，中间线段仍然可能穿过球体。

为改善这个问题，系统使用类似“珍珠串”的配置，在毛发粒子附近增加碰撞球，使较长的毛发段也不容易穿透身体。直接做线段与球体的精确碰撞更准确，但实现和稳定性成本更高。

### 9. 鱼鳍的布料模拟

Nalu 的鱼鳍最初绑定在骨骼上，但看起来过于僵硬。系统复用了毛发动力学代码，把鱼鳍作为布料进行模拟，再与传统蒙皮结果混合。

权重图控制每个顶点的混合比例：

```text
靠近根部：更多蒙皮 → 更硬
靠近尖端：更多物理 → 更软
```

最终结果为：

```text
最终位置 = skinning × (1 - physicsWeight)
          + physics × physicsWeight
```

这说明同一套粒子和约束系统不仅能处理毛发，也能用于鱼鳍、布料等软性结构。

### 10. 毛发反射模型

毛发可以近似为细长的半透明圆柱体。Nalu 使用 Marschner 毛发反射模型，将光线与单根毛发之间的重要传播路径分为三类：

- `R`：光线在毛发表面直接反射；
- `TT`：光线进入毛发并从另一侧透射出来；
- `TRT`：光线进入毛发，在内部反射一次后再离开。

总反射可以写成：

```text
S = SR + STT + STRT
```

这三类路径分别贡献表面高光、透射颜色和内部反射高光，是毛发区别于普通粗糙表面的重要原因。

### 11. 使用 LUT 加速 Marschner 模型

Marschner 模型参数较多，如果每个像素实时计算完整函数，成本很高。因此将反射函数分解为多个二维函数：

```text
Sp = Mp × Np
```

其中：

- `M` 描述入射角和出射角的影响；
- `N` 描述绕毛发轴方向的反射分布。

经过分解后，可以将这些函数保存为 2D LUT。运行时根据光线方向、视线方向和毛发切线计算查询参数，再从纹理中读取反射结果。

部分函数只有单通道，可以打包到同一张纹理的不同通道中。原章还近似认为：

```text
MTT ≈ MTRT
```

从而将 LUT 数量从三张减少到两张。

### 12. 避免昂贵的反三角函数

Shader 中直接计算角度需要使用反三角函数。为了降低开销，系统使用向量点积代替部分角度计算：

```hlsl
sinThetaI = dot(light, tangent);
sinThetaO = dot(view, tangent);
```

然后将光线和视线投影到垂直于毛发切线的平面，计算相关的余弦项。这样可以使用点积、乘法和开方完成大部分参数准备。

Nalu 的 LUT 使用 CPU 预计算，示例中使用 `128 × 128` 的 8 位纹理。若需要更高精度，可以使用 16 位浮点纹理。运行时还可以修改高光宽度、强度、颜色和折射率等参数，并重新计算 LUT。

### 13. 固体毛发几何的扩展

虽然示例主要使用线段表示毛发，但反射模型也可以扩展到实体几何。此时可以使用实体表面的主切线代替线段切线，并额外考虑实体表面的自遮挡。

原章使用类似 Wrap Lighting 的近似项：

```text
(wrap + dot(N, L)) / (1 + wrap)
```

用于模拟光线从毛发表面背后或侧面渗出的效果。

### 14. Opacity Shadow Map

普通 Shadow Map 通常只保存一个深度值，并进行二值遮挡判断。但毛发非常密集且每根毛发很细，使用普通 Shadow Map 容易产生严重别名，也无法表达光线穿过部分毛发后的剩余能量。

Opacity Shadow Map 保存的是光线穿过毛发后的透射率：

```text
T = 到达某个光源空间深度位置的光线比例
```

它可以表示连续的遮挡程度，而不是只有 0 或 1。

### 15. 多深度层的透明阴影

沿光源方向保存多个深度切片：

```text
z0、z1、z2、...、z15
```

每个切片保存到对应深度位置为止的累计毛发密度。任意深度位置的密度可以通过相邻切片插值得到，再转换为透射率：

```hlsl
shadow = exp(-k * density);
```

密度越高，透射率越低，阴影越暗。

原章使用 16 个深度层，并在相邻层之间线性插值。

### 16. 使用通道打包和 MRT 优化

如果每个深度层单独渲染，需要 16 个 Pass。由于每层只需要一个标量，可以将 4 个深度层打包到一张 RGBA 纹理：

```text
4 个深度层 → 1 张 RGBA 纹理
```

再使用 4 个 MRT 同时写入 4 张 RGBA 纹理：

```text
4 张纹理 × 4 个通道 = 16 个深度层
```

这样可以把 16 次渲染降低到一次 Pass。Shader 只让满足深度条件的毛发片元写入对应通道，之后在采样阶段对相邻深度层进行插值。

## 讨论与补充

### 1. 风格化角色头发与 Nalu 方案的区别

NPR 或风格化角色的头发通常主要作为预先制作好的普通模型来渲染，而不是每帧重新生成数千根独立发丝。常见结构为：

```text
主体发块/发束网格
        ↓ 跟随头部骨骼或角色蒙皮
刘海、鬓角、马尾、发梢
        ↓ 单独骨骼链、物理骨或 Blend Shape
少量特殊发丝
        ↓ 顶点动画或局部模拟
```

这里的“静态”主要指几何形状由美术预先制作，不代表运行时完全不动。主体发型可以通过角色蒙皮跟随头部，动态发束则通过骨骼链或二级物理产生摆动。

这种方案与 Nalu 的控制毛发、曲线细分、插值生成大量渲染毛发不同：

```text
Nalu：控制毛发 → 动力学 → 曲线 → 插值 → 动态毛发几何
风格化角色：预制发型网格 → 蒙皮/骨骼 → 少量动态控制
```

风格化方案的优势是轮廓稳定、美术控制力强、成本低，并且适合 Toon Ramp、发束高光和边缘光等 NPR 着色；缺点是发束穿插、长发穿模和毛发之间的真实碰撞较难处理。

### 2. 发型几何与多 Pass 的关系

头发是否使用预制模型，和 Shader 是否使用多 Pass 是两个独立问题。预制头发网格仍然可以使用多 Pass 来处理：

- 发丝方向高光；
- 边缘光；
- 透明或 Clip；
- 特殊阴影；
- 风格化颜色分层。

多 Pass 不会自动决定头发是长发还是短发，真正决定表现能力的是几何表示方式：Shell 更偏向短毛，Hair Cards 可以表现长发，Strand/Curve 则更适合高质量动态长发。

关于具体商业游戏的内部实现，如果没有公开技术资料，不能仅凭画面断言其全部方案；但“主体发型模型 + 少量骨骼控制的动态发束”确实是风格化角色常见的工程路线。
