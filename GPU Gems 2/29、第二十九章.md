# 流式架构与技术趋势

## 章节内容

本章从半导体技术、处理器设计和内存带宽趋势出发，解释为什么 GPU 逐渐采用流式、数据并行的计算模型，并说明这种模型与通用计算问题之间的关系。

### 技术趋势与内存鸿沟

晶体管数量持续增加，使处理器能够放入更多算术单元，但计算能力的增长速度往往快于内存访问速度的增长。处理器越来越容易“算得快、等数据”，这就是内存鸿沟问题。

继续单纯增加复杂的控制逻辑、缓存和分支预测并不能解决所有问题。另一条路线是放入更多相对简单的算术单元，让它们同时处理大量数据，并通过高带宽内存系统供给数据。GPU 正是沿着这条路线发展。

### 流式计算模型

流可以看作一组类型相同、按顺序排列的数据元素，例如顶点流、纹理流、粒子流或一维数组。Kernel 是作用于单个流元素的计算函数，将输入流映射为输出流：

```text
output[i] = kernel(input[i])
```

只要每个元素之间几乎没有依赖，就可以把同一个 Kernel 同时应用到大量元素。

流式模型通常包含：输入流、Kernel、输出流，以及把多个 Kernel 串接起来的计算管线。中间结果可以继续作为下一阶段的输入。

### 算术强度与通信

程序性能不仅由算术运算数量决定，还取决于数据搬运量。算术强度可以粗略表示为：

```text
算术强度 = 执行的运算次数 / 传输的数据量
```

算术强度高、数据访问规则且可并行的任务最适合 GPU。若每个元素只做很少计算，却频繁访问随机内存，GPU 的算术吞吐量无法转化为实际性能。

### CPU 与 GPU 的分工

CPU 擅长复杂控制流、随机访问和串行任务；GPU 擅长长数据流上的统一计算。高效的异构程序通常让 CPU 负责组织任务、准备数据和处理不规则逻辑，让 GPU 执行规模大、规则且高度并行的 Kernel，同时尽量减少 CPU 与 GPU 之间的往返传输。

### 总结

流式架构不是某个具体 API，而是一种组织计算的思想：把问题表达为大量数据元素上的同类操作，用高吞吐的并行处理器执行，并通过提高算术强度和访问局部性来弥补内存鸿沟。

## 讨论与补充

### 1. 流式计算的理解

这里的“流”更准确地说是流式计算或流式编程，重点不是 CPU 与 GPU 之间的数据传输，而是将大量同类型数据组织成数据流，让 GPU 对其中的每个元素执行相同或相似的 Kernel。

例如：

```text
输入流：大量粒子位置
Kernel：更新位置
输出流：更新后的粒子位置
```

适合 GPU 流式计算的数据通常具有以下特点：

- 元素数量多；
- 每个元素执行相同或相似的计算；
- 元素之间依赖较少；
- 内存访问连续、规则；
- 每个元素有足够多的计算量，即算术强度较高。

不适合的情况包括强串行依赖、大量复杂分支、随机内存访问、需要任意位置写入、数据量太小，以及频繁在 CPU 和 GPU 之间传输数据。

因此，本章的核心可以概括为：

> 流式计算是利用 GPU 的大规模并行能力，对数据流中的大量元素统一执行 Kernel；但只有数据并行度高、依赖少、访问规则且计算量足够的任务，才能真正从中受益。
