# Mipmap 层级测量

## 章节内容

本章介绍一种让 GPU 直接测量场景实际使用了哪些 Mipmap 层级的方法，并将结果反馈给纹理管理系统，从而释放完全不会被看到的高分辨率 Mipmap，降低显存和运行时纹理生成成本。

### 为什么需要测量 Mipmap

GPU 选择 Mipmap 层级时会综合屏幕分辨率、抗锯齿、纹理过滤、各向异性、物体距离、表面朝向以及驱动优化等因素。仅根据物体距离估计并不可靠，尤其是地形、峭壁和网络游戏中自由度很高的相机。

传统的人工方法是把每个 Mipmap 层染成不同颜色，再观察画面中哪些颜色出现。这适合美术检查，但需要人工参与。本章把这个过程自动化。

### GPU 测量方法

首先制作一张校准纹理，让不同 Mipmap 层使用不同颜色或不同 Alpha。渲染目标物体时，GPU 会按照正常纹理采样流程选择 Mipmap。然后对渲染结果进行 GPU 内部的统计，判断哪些层的标记像素实际出现过。

关键点是不要把帧缓冲复制回 CPU 再统计，因为 GPU 到 CPU 的回读会产生很大开销。统计结果应尽量留在 GPU 上，只有最终的少量测量结果才反馈给纹理管理器。

### 结果的使用

在 Direct3D 的托管资源系统中，可以将测得的最高需求层级传给 `IDirect3DBaseTexture9::SetLOD`，让系统释放不需要的高分辨率层。对于运行时生成纹理的 MMO，还可以只生成实际使用到的层级，减少生成计算和系统内存副本。

### 工程取舍

校准纹理本身会产生额外渲染开销，因此可以缩小测试视口和校准纹理尺寸。测量结果通常是阈值式的阶梯，而硬件实际的 Mipmap 混合是连续的。可以改变校准纹理或阈值，得到更细致的“层级重要程度”信息。

地形特别适合这种方法：平坦地形常常以较倾斜的角度出现在屏幕中，需求层级较低；峭壁或朝向相机的表面则可能需要更高层级。章节中的 Leviathan 地形引擎通过该方法获得了显著的纹理内存节省，并且在可接受阈值下没有明显视觉损失。

### 总结

该方法不需要重新实现 GPU 的 Mipmap 选择公式，而是让 GPU 按真实渲染流程进行一次校准，再测量实际显示结果。因此它自然包含了过滤方式、各向异性、视角和驱动行为等复杂因素，适合运行时纹理管理，但不适合所有场景；如果相机运动范围固定，离线分析可能更简单。

## 讨论与补充

### 1. Mipmap 的存储开销与使用取舍

生成 Mipmap 会为原始纹理生成一系列逐级缩小的纹理。对于完整的二维 Mipmap 链，纹素数量大致为：

```text
1 + 1/4 + 1/16 + 1/64 + ... ≈ 4/3
```

因此相比只保存最高分辨率纹理，理论上会增加约 33% 的纹素存储。实际文件和显存占用还会受到纹理压缩格式、内存对齐和平台实现的影响。

如果所有 Mipmap 都常驻显存，运行时确实会多占这部分内存。但 Mipmap 同时能够：

- 减少远处纹理闪烁和摩尔纹；
- 让纹理缩小采样更稳定；
- 减少远处采样时的纹理带宽和缓存压力；
- 配合三线性过滤实现更平滑的层级过渡。

因此是否生成 Mipmap 需要根据纹理用途决定：

- 3D 场景材质通常建议开启；
- UI、像素画和部分 Sprite 经常关闭；
- LUT、ID 图、查找表和其他精确数据纹理通常关闭；
- 不参与缩小采样的特殊纹理可以关闭；
- 显存紧张时，可以配合 Mipmap Streaming，只让当前需要的层级常驻。

Unity 的 Mipmap Streaming 可以根据相机视角和显存预算加载、保留或释放不同 Mipmap 层级，因此开启 Mipmap 不一定意味着完整链条始终全部占用 GPU 显存。

更准确的理解是：

> Mipmap 会增加纹理存储成本，但能改善缩小采样质量并降低远处采样压力；是否开启，应根据纹理是否参与 3D 缩小采样、显存预算和数据语义决定。
