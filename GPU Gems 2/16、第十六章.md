# 精确的大气散射

## 章节内容

本章介绍一种完全在 GPU 上运行的实时大气散射方法。它基于 Nishita 等人的大气散射模型，考虑大气密度随高度呈指数衰减，并分别处理 Rayleigh 散射和 Mie 散射，使同一套算法能够覆盖地面、飞行和太空视角，而不局限于贴近地面的摄像机。

本章的重点不是简单绘制一张天空颜色贴图，而是沿摄像机到场景点的视线，对大气中的散射和吸收进行数值积分，并通过数学近似把原本过于昂贵的嵌套积分压缩到可以在 GPU 上实时执行的规模。

### 1. 为什么大气散射困难

大气中的一个像素颜色取决于：

- 摄像机到场景点之间的大气密度；
- 太阳光从太阳到散射点的路径；
- 散射点到摄像机的路径；
- 散射粒子的类型和密度；
- 光线与太阳方向之间的夹角；
- 场景点自身反射或发出的光。

许多实时模型假设摄像机始终靠近地面，并把大气密度近似为常量。这种方法速度快，但在高空、飞行模拟或太空视角下会失真。本章使用更完整的模型，让密度随高度变化。

### 2. 视线与大气边界

对于摄像机看到的一个场景点，先确定视线穿过大气的线段：

```text
摄像机 ───────────── 场景点
        A          B
```

如果摄像机位于大气内，A 通常就是摄像机位置；如果摄像机在大气外，则需要求摄像机视线与大气外球面的交点作为 A。

如果场景点位于大气内，B 就是场景点；如果场景点在大气外，也需要计算视线与大气边界的交点作为 B。

于是，问题变成对从 A 到 B 的线段进行积分。

### 3. 数值积分

大气散射方程包含难以解析求解的嵌套积分，因此使用数值积分近似。最基本的做法是把线段分成若干段，在每段中点计算函数值，再乘以段长度并累加，类似梯形法或矩形法：

```text
线段 A-B
  ↓
划分为 n 个采样段
  ↓
计算每个采样点的大气密度和散射
  ↓
加权求和
```

采样点越多，结果越准确，但 Shader 计算量也越大。

在每个视线采样点 P，还要计算太阳光从太阳到 P 的路径，以及 P 到摄像机的路径。前者和后者都存在沿路径的衰减和散射，因此直接实现会形成嵌套循环。

### 4. Rayleigh 散射与 Mie 散射

Rayleigh 散射主要由空气中的小分子造成，短波长的蓝光散射更强，因此：

- 白天的天空呈蓝色；
- 太阳光经过较长大气路径后，蓝光和部分绿光被散射掉；
- 日出和日落时太阳更偏红、橙色。

Rayleigh 散射的波长依赖通常近似为：

```text
散射强度 ∝ 1 / wavelength^4
```

Mie 散射主要由灰尘、污染物、水滴和其他较大的气溶胶粒子造成。它对不同波长的散射差异较小，因此会产生：

- 灰白色的雾霾天空；
- 太阳周围的白色光晕；
- 云雾、雨滴和冰粒相关的散射现象。

最终需要分别计算 Rayleigh 和 Mie 的贡献，再合成天空或场景表面颜色。

### 5. 相位函数

相位函数描述光线在某个方向上被散射的强度。它主要取决于入射光方向和观察方向之间的夹角，以及控制前向/后向散射的参数 `g`。

```text
g 接近 0       → 散射较对称
g 为负         → 更偏向前向散射
g 为正         → 更偏向后向散射
```

Mie 散射通常具有明显的前向散射，因此可以形成太阳周围的光晕。Rayleigh 散射可以用更简单、近似对称的相位函数表示。

### 6. 光学厚度与出射散射

光学厚度可以理解为光线沿路径经过了多少大气粒子：

```text
光学厚度 ≈ 路径长度 × 路径上的平均大气密度
```

光学厚度越大，光沿路径被散射或吸收的程度越强。出射散射计算从某个点沿光线到另一个点累积大气密度，再根据 Rayleigh/Mie 散射常量得到衰减值。

大气密度通常按高度指数衰减：

```text
density(h) = exp(-h / scaleHeight)
```

Rayleigh 和 Mie 可以使用不同的散射常量和尺度高度。实际计算中，依赖波长的项需要分别对 RGB 三个通道计算。

### 7. 入射散射

入射散射描述太阳光如何在视线上的每个点 P 被散射到摄像机：

```text
太阳光 → P → 摄像机
```

对于每个 P，需要考虑：

- 太阳光到 P 的路径衰减；
- P 到摄像机的路径衰减；
- P 处的大气密度；
- Rayleigh 或 Mie 的散射常量；
- 相位函数；
- 太阳光强度。

把沿 A-B 的所有 P 的入射散射累加，就能得到天空颜色、远景雾化和太阳附近的散射光。

### 8. 地面和物体表面的散射

如果视线最终击中了地面或其他物体，除了大气本身的入射散射，还要处理表面的反射光：

```text
表面反射光 × 从表面到摄像机的出射衰减
+ 大气沿视线产生的入射散射
```

表面反射的太阳光还需要先考虑太阳到表面的路径衰减，即太阳光到达表面之前已经被大气散射掉多少。

天空本身没有普通物体表面反射项，因此主要计算视线中的大气散射。

### 9. 从昂贵积分到实时 Shader

如果直接计算，每个顶点的入射积分和出射积分都需要多次采样；再乘上 Rayleigh/Mie 两种散射和 RGB 三个通道，计算量非常大。

本章先讨论使用二维查找表存储部分光学厚度，但最终为了适应当时 Shader Model 2.0 的限制，进一步对查找表结果进行数学分析，使用近似公式消除查找表，并把计算压缩到较小的 Shader 中。

优化后的思路是：

```text
原始嵌套积分
    ↓
分离光学厚度和散射项
    ↓
利用路径之间的差值消除不需要的部分
    ↓
拟合光学厚度随高度和角度的变化
    ↓
在 GPU Shader 中直接计算
```

书中给出的数量级示例是：暴力计算可能达到每顶点约 3000 次计算，经过优化后可以压缩到约 60 次左右。

### 10. Shader 组织

Demo 使用球体作为地面和天空穹顶。天空穹顶反转正面方向，从内部绘制。地面使用普通矩形地球纹理，月亮使用带光晕纹理的 Billboard。

书中为不同摄像机位置和目标类型准备了不同 Shader：

- Ground From Atmosphere；
- Sky From Atmosphere；
- Ground From Space；
- Sky From Space；
- Space 中物体使用的 Shader。

把摄像机在大气内和大气外拆成不同 Shader，可以减少运行时条件分支。顶点 Shader 主要计算从视线起点到终点的方向、Rayleigh 和 Mie 的预计算项以及颜色贡献；片元 Shader 再根据光线方向计算相位函数并合成最终颜色。

### 11. HDR 与曝光

大气散射结果很容易超出普通 `0～1` 颜色范围，因此本章使用浮点颜色缓冲保存 HDR 结果，然后在最终全屏 Pass 中进行曝光映射：

```hlsl
colorMapped = 1 - exp(-exposure * color);
```

`exposure` 类似相机光圈或人眼瞳孔：场景过亮时降低曝光，场景过暗时提高曝光。最后将映射后的颜色输出到普通显示范围。

这也是本章与全屏后处理的联系：大气 Shader 负责产生 HDR 散射颜色，最后通过全屏 Shader 完成曝光和显示变换。

### 12. 方法特点与限制

优点包括：

- 可以实时运行在 GPU 上；
- 比固定密度的地面大气模型更适合飞行和太空视角；
- 能同时表现 Rayleigh 和 Mie 散射；
- 支持地面、天空和大气外物体；
- 可以与 HDR 和曝光结合得到更自然的亮度范围。

限制包括：

- 仍然是单次散射或有限近似，多次散射没有完整求解；
- 大气尺度高度、行星半径和密度参数需要合理设置；
- 采样数量、Shader 复杂度和浮点精度会影响质量；
- 云、降水、闪电、彩虹和月光光晕还需要额外模型；
- 书中的 Cg/GLSL 实现和 Shader Model 2.0 限制已经过时，但沿视线积分、相位函数、光学厚度和分离预计算的思想仍然是现代大气渲染的基础。

## 讨论与补充

### 1. 从全球大气到窗户尘埃光束

本章的基础模型主要描述覆盖整个星球的大气层，密度通常随高度变化，因此更容易产生天空发蓝、地平线泛白和远景空气透视等全局效果。

窗户透进来的丁达尔光束需要的是局部、非均匀的参与介质：房间中有尘埃，阳光从窗户进入，窗框和墙体遮挡部分光线，尘埃再把可见光散射到摄像机。它不能只靠全局高度雾完成。

### 2. 局部体积密度

工程上通常不为每个尘埃粒子建立几何体，而是把大量尘埃近似为连续的体积密度场：

```text
Density(x, y, z)
```

密度可以来自：

- 盒状或球状局部体积；
- 3D 密度纹理；
- 程序噪声；
- 烟雾模拟或 VDB 数据。

3D 纹理存的通常是密度、散射系数或吸收系数，而不是已经算好的最终颜色。密度为零的区域没有体积散射，密度较大的区域会产生更明显的雾和光束。

### 3. 体积光线步进

对屏幕像素沿摄像机方向取样：

```text
摄像机 ── P1 ── P2 ── P3 ── 场景表面
```

每个采样点读取密度，并计算光源到该点的光照，再沿视线累积散射：

```hlsl
float3 accumulated = 0;
float transmittance = 1;

for (int i = 0; i < stepCount; i++)
{
    float3 P = rayOrigin + rayDirection * distance;
    float density = SampleDensity(P);
    float3 light = EvaluateVolumeLight(P);

    accumulated += transmittance * density * scatteringCoefficient
                 * phaseFunction * light * stepLength;
    transmittance *= exp(-extinctionCoefficient * density * stepLength);
}
```

最终结果大致是：

```text
体积散射光 + 场景表面颜色 × 体积透射率
```

这仍然只是沿大气或体积路径进行数值积分，不是遍历 BVH 的光线追踪。

### 4. 光源遮挡与光束形状

相机方向的步进还不够。对每个体积采样点，还要判断它是否能看到光源：

```text
光源 → 体积采样点
```

通常将采样点转换到光源空间并查询阴影贴图，得到光源可见性：

```hlsl
visibility = SampleShadowMap(lightSpacePosition);
inScatter = density * visibility * lightIntensity * phaseFunction;
```

窗户开口处的体积能够看到太阳，墙体或窗框后面的体积看不到太阳，于是形成清晰的光束。方向光会沿窗户形状投射出近似平行的光束，点光源或聚光灯则会形成发散或锥形光束。

### 5. 丁达尔效果与 Mie 散射

尘埃、水滴和烟雾主要表现为 Mie 散射，通常具有较强的方向性。使用具有前向散射特征的相位函数，可以让光源方向接近观察方向时的光束更加明亮：

```text
phase(cosθ, g)
```

其中 `g` 控制前向或后向散射。真实实时系统通常会使用局部体积、阴影贴图、体积步进和近似的多次散射，而不是把尘埃逐粒子渲染出来。

### 6. 现代实时工程实现

逐屏幕像素进行大量步进会比较昂贵，因此现代引擎通常把摄像机视锥体划分为三维 Froxel 网格：

```text
局部密度体积
    ↓
体素化到 Froxel 网格
    ↓
注入光源和阴影信息
    ↓
沿视线合成体积光
```

常见优化包括：

- 半分辨率或四分之一分辨率；
- 按深度使用非均匀切片；
- 只计算影响当前体积的光源；
- 使用阴影贴图或体积阴影；
- 蓝噪声抖动；
- 时域重投影；
- 双边上采样；
- 远处使用更大的步长。

离线渲染则可以使用体积路径追踪计算多次散射，实时渲染通常用单次散射加多次散射近似来控制成本。
