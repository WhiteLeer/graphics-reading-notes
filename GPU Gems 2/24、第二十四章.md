# 用查找表加速颜色变换

## 章节内容

本章介绍使用 1D 和 3D 查找表加速颜色变换的方法。复杂的颜色校正、色调映射和电影调色操作可以先在预处理阶段烘焙到 LUT 中，运行时对每个像素执行一次查表和插值，从而以基本不依赖颜色操作数量的成本处理高分辨率图像。

### 1. LUT 的基本思想

查找表的作用是把昂贵的函数计算转换成简单的数组或纹理访问：

```text
输入值 → LUT → 输出值
```

如果某个函数会被大量重复查询，并且输出可以在有限范围内用采样点近似，就可以先计算一组结果并缓存。运行时遇到采样点之间的输入，可以使用最近邻、线性或三线性插值估计结果。

例如，对于灰度值变换：

```text
output = f(input)
```

可以预先记录：

```text
LUT[0]   = f(0)
LUT[1]   = f(1 / N)
...
LUT[N-1] = f(1)
```

### 2. 一维 LUT

1D LUT 只需要一个输入参数：

```text
LUT(x) = y
```

它适合表示：

- 亮度曲线；
- Gamma；
- 对比度；
- Levels；
- 单通道颜色曲线；
- 显示器 Gamma 表。

对 RGB 三个通道分别使用三张 1D LUT，可以实现每个通道独立的颜色平衡：

```text
R' = LUT_R(R)
G' = LUT_G(G)
B' = LUT_B(B)
```

Photoshop 中的 Curves 和 Levels 等操作，很多都可以用每通道 1D LUT 加速。

### 3. 1D LUT 的限制

1D LUT 只能让一个输入通道独立影响一个输出通道，无法表达通道之间的交叉影响。

例如灰度转换：

```text
Y = 0.2126R + 0.7152G + 0.0722B
```

输出同时依赖 R、G、B，不能用三张互相独立的 1D LUT 完整表达。色相、饱和度、颜色分级和许多专业调色操作也存在类似的跨通道关系。

### 4. 三维 LUT

3D LUT 将完整的输入颜色 `(R, G, B)` 作为三维坐标：

```text
LUT(R, G, B) = (R', G', B')
```

可以把它理解为一个 RGB 颜色立方体。每个网格节点记录一个输入颜色经过颜色变换后的输出颜色。

例如 `32 × 32 × 32` 的 3D LUT 包含：

```text
32 × 32 × 32 = 32768 个颜色节点
```

每个节点保存一个 RGB 输出值：

```text
LUT[r][g][b] = float3(outputR, outputG, outputB)
```

3D LUT 可以表达：

- 色相和饱和度变化；
- 复杂颜色分级；
- 颜色通道交叉变换；
- 电影色调；
- 用户指定的颜色范围变形；
- 专业调色系统中的颜色映射。

### 5. GPU 中的 3D LUT 采样

运行时先从普通 2D 纹理中读取原始图像颜色，再将这个颜色作为 3D LUT 的坐标：

```hlsl
float3 color = Sample(sourceTexture, uv).rgb;
float3 corrected = Sample(lut3D, color).rgb;
return float4(corrected, alpha);
```

硬件三线性过滤会在相邻的 8 个颜色节点之间插值，因此输入颜色位于 LUT 网格之间时，也能得到平滑的输出。

### 6. Identity LUT 与颜色处理流程

为了生成 3D LUT，可以先创建 Identity LUT。它表示不改变颜色的映射：

```text
IdentityLUT(R, G, B) = (R, G, B)
```

然后把这张颜色网格当成普通图片，交给已有的颜色处理工具进行任意颜色操作：

```text
Identity LUT
        ↓
颜色校正、Gamma、色调、饱和度、电影调色
        ↓
变换后的 LUT
```

之后实际高分辨率图像只需要通过变换后的 3D LUT 采样，就能一次性应用之前烘焙进去的所有颜色操作。

### 7. 运行时性能收益

假设有一系列颜色操作：

```text
Gamma
→ 对比度
→ 色相
→ 饱和度
→ 颜色分级
→ 电影风格变换
```

如果全部在每个像素中直接计算，成本会随着操作数量增加。若预先把这些操作合并到一张 LUT：

```text
多个颜色操作
        ↓ 预计算
一张 3D LUT
        ↓
每个像素一次 3D 查表
```

运行时成本主要是原图采样、3D LUT 采样和输出，不再与已烘焙的颜色操作数量线性相关。

原章给出的典型情况是，用 `32 × 32 × 32` 的颜色网格替代对高分辨率图像逐像素执行复杂颜色处理，能够获得数量级的加速。对于视频播放，LUT 可以缓存并重复用于后续帧。

### 8. 3D LUT 的限制

3D LUT 并不能表达所有图像处理操作。它通常要求：

#### 8.1 变换只依赖当前像素颜色

LUT 只知道当前像素的 RGB 值，不知道邻居像素和空间位置，因此不能直接表示：

- 模糊；
- 边缘检测；
- Bloom；
- SSAO；
- 局部对比度；
- 基于屏幕位置的遮罩；
- 依赖其他像素的图像分析。

#### 8.2 变换需要足够连续

LUT 依赖网格插值。如果颜色变换在很小范围内发生剧烈跳变，插值可能产生明显误差。此时需要增加 LUT 分辨率，或者使用其他方法实现离散分类。

#### 8.3 输入颜色范围需要明确

普通 LUT 通常只覆盖有限范围，例如：

```text
R、G、B ∈ [0, 1]
```

HDR 颜色可能超过 1：

```text
RGB = (3.0, 1.5, 0.2)
```

这会超出普通 LUT 的定义域，需要使用 Clamp、曝光压缩、扩展 HDR LUT 或非均匀采样等方式处理。

### 9. Shader 中的 LUT 组织

3D LUT 的颜色节点也可以先展开成一张 2D 图片，方便使用普通图像工具处理。以 `32 × 32 × 32` 为例，可以将 32 个 `32 × 32` 的切片排列为一张 2D 图像：

```text
32 个 32 × 32 切片
        ↓ 排列
256 × 128 的 2D LUT 图像
```

离线调色工具只需要处理这张代理图片，最后再将它重新解释为 3D LUT 数据。

在支持 3D 纹理的 GPU 上，运行时直接使用 `Texture3D` 和三线性过滤；如果目标平台不方便使用 3D 纹理，也可以在 Shader 中根据 RGB 坐标手动计算切片位置并采样 2D LUT 图集，但需要自行完成切片之间的插值。

### 10. 精度与插值

LUT 分辨率越低，颜色空间采样越稀疏，越容易出现：

- 色带；
- 颜色跳变；
- HDR 高亮细节丢失；
- 复杂颜色变换误差。

三线性过滤可以减轻节点之间的离散感，但不能完全弥补过低的 LUT 分辨率。原章指出，8 位存储在部分颜色变换中可能不足以避免色带；如果需要更高质量，可以使用 16 位或浮点纹理。

### 11. HDR 与非均匀采样

对于 HDR，均匀地将整个 `[0, +∞)` 映射到有限 LUT 网格是不现实的。因此可以：

- 对输入做 Clamp；
- 先进行曝光或色调压缩；
- 使用对高亮区更密集的非均匀采样；
- 使用额外的参数恢复超出基础范围的亮度。

非均匀 LUT 可以把更多采样节点分配给视觉上更敏感的颜色区域，减少有限表格容量带来的误差。

### 12. 本章方案的整体流程

```text
生成 Identity LUT
        ↓
通过任意颜色处理流程变换 LUT
        ↓
上传高分辨率源图和 3D LUT
        ↓
每个像素读取源颜色
        ↓
以源颜色查询 3D LUT
        ↓
输出颜色校正结果
```

本章的核心价值是：将复杂且重复的颜色函数预先合并成一个小型颜色空间映射，在 GPU 上通过纹理硬件快速完成高分辨率颜色处理。

## 讨论与补充

### 1. ACES 与 LUT 的关系

ACES 本身是颜色管理和色调映射变换的定义，LUT 则是实现或缓存该变换的一种方式。ACES 不等于 LUT，也不要求所有实现都必须使用 LUT。

ACES 的完整输出变换可能包含：

```text
ACES RGB
  ↓
颜色空间转换
  ↓
亮度 Tone Scale
  ↓
色度压缩
  ↓
色域压缩
  ↓
白点限制
  ↓
显示编码
```

其中简单的亮度 Tone Scale 可以直接用数学公式在 Shader 中计算；如果一组 ACES 变换参数固定，也可以预先烘焙为 1D 或 3D LUT。

### 2. 什么时候使用 1D LUT 或 3D LUT

如果只需要处理独立的亮度曲线或单通道映射，可以使用 1D LUT：

```text
LUT(luminance) = mappedLuminance
```

但完整颜色变换可能同时改变色相、饱和度、色域以及 RGB 通道之间的关系，因此更适合用 3D LUT：

```text
LUT(R, G, B) = (R', G', B')
```

### 3. 实时引擎中的常见组合

实际引擎可以使用不同组合：

```text
HDR 场景颜色
    ↓
曝光
    ↓
Tone Mapping：数学 Shader 或预计算曲线
    ↓
颜色分级：3D LUT
    ↓
显示编码
```

也可以把固定的 Tone Mapping、颜色分级和风格化效果合并到一张 LUT 中。若曝光、显示峰值亮度等参数经常变化，则通常需要重新生成 LUT，或者把这些动态部分保留在 Shader 中。

### 4. 公式与 LUT 的工程取舍

数学公式的优点是 HDR 输入范围连续、参数可动态调整，缺点是需要更多 ALU 计算。LUT 的优点是运行时主要进行纹理采样和插值，并且可以把多个颜色操作合并，缺点是存在纹理内存、采样精度、插值误差和定义域限制。

Unity 中选择 ACES 模式并不必然代表实现使用 LUT；具体实现取决于渲染管线和版本。常见做法是 Tone Mapping 使用 Shader 公式或专用曲线，颜色分级使用 3D LUT，也可以为了性能将固定流程合并为一张 LUT。
