# 蓝图渲染与草图式绘制

## 章节内容

本章介绍两种基于图像空间的非真实感渲染方法：蓝图渲染和草图式绘制。它们都不是直接修改普通光照模型，而是先把三维几何体的深度、法线、颜色和边缘等信息渲染到纹理，再通过多 Pass 图像处理、深度剥离、深度精灵和噪声扰动，生成能够表现隐藏结构、手绘边缘和不规则色块的结果。

蓝图渲染主要突出可见和被遮挡的重要边缘，适合建筑、机械结构、关卡编辑和技术可视化；草图式绘制则对边缘和内部颜色区域施加不确定性扰动，模拟蜡笔、手绘或概念草图效果。

### 1. 蓝图与草图式渲染的共同基础

两种方法都依赖三个基本步骤：

```text
保存中间渲染结果
        ↓
从深度/法线中提取边缘
        ↓
利用深度精灵把图像结果重新放回三维深度关系
```

### 2. 中间渲染结果与 G-Buffer

首先把三维几何体渲染到纹理中，生成可供后续 Pass 使用的中间数据，例如：

- 法线缓冲；
- 深度缓冲；
- 颜色层；
- 边缘图；
- 草图式绘制需要的颜色图。

法线和深度会被编码到二维纹理中。后续可以绘制覆盖屏幕的四边形，在片元 Shader 中读取这些纹理，而无需重新访问原始几何体。

这和延迟渲染中的 G-Buffer 思路相似：先保存几何属性，再在后续阶段根据这些属性完成不同的图像处理。区别在于，本章的目标是边缘提取和非真实感绘制，而不是传统的光照计算。

### 3. 从深度和法线提取边缘

对每个屏幕像素读取它周围的深度和法线：

```text
当前法线       与邻居法线差异大 → 可能是折痕或物体边界
当前深度       与邻居深度差异大 → 可能是轮廓或深度断层
```

片元 Shader 可以计算邻域差异，并把差异强度写入 Edge Map：

```hlsl
float normalDiff = CompareNeighborNormals(uv);
float depthDiff  = CompareNeighborDepths(uv);
float edge       = Combine(normalDiff, depthDiff);
```

这样可以得到轮廓边、物体边界、折痕和深度层之间的边界。Edge Map 后续会作为颜色和 Alpha 的来源，用于绘制蓝色线条或草图边缘。

### 4. 深度精灵

深度精灵是一个带有每像素深度值的屏幕四边形。普通屏幕四边形的深度由光栅化器统一生成，但深度精灵会在片元 Shader 中用深度纹理中的值替换当前片元深度：

```text
深度纹理 → 片元 Shader 写入片元深度
                  ↓
            执行普通深度测试
```

如果纹理中的深度等于远裁剪面，说明该位置没有有效几何体，可以直接丢弃片元以减少填充开销。

深度精灵的意义是：虽然最终绘制的是一个二维四边形，但它仍然可以按照原始三维几何体的深度与场景中的其他物体正确遮挡。

### 5. 蓝图渲染与深度剥离

蓝图渲染不仅要显示当前可见的边缘，还要显示被其他表面遮挡的结构边缘。因此需要获得多个深度层。

普通深度测试只能保留每个像素最靠近相机的片元，无法直接知道第二层、第三层片元。深度剥离通过多次渲染逐层提取：

```text
第 1 次 Pass → 最靠近相机的深度层
第 2 次 Pass → 剥离第 1 层后得到的下一层
第 3 次 Pass → 再得到下一层
```

每一层都会保存：

- Depth Layer Map；
- Color Layer Map；
- Normal Layer Map；
- Edge Map。

下一层的深度测试需要排除上一层及更近的片元。可以使用片元 Shader 执行额外深度比较，并通过 Occlusion Query 判断当前 Pass 是否还产生了足够多的有效片元，从而决定是否继续剥离。

### 6. 蓝图边缘合成

得到多个深度层的 Edge Map 后，按照从前到后的深度顺序逐层合成：

1. 绘制一个屏幕四边形；
2. 读取当前层的 Edge Map 和 Depth Map；
3. 使用深度精灵写入该层的深度；
4. 根据边缘强度生成蓝色或其他蓝图颜色；
5. 使用边缘强度作为 Alpha 进行混合。

通常只需要合成前几层。越深的层能够贡献的可见像素越少，继续剥离的收益会迅速降低。因此可以设置最小有效片元比例，达到阈值后提前停止，以平衡质量与性能。

深度 Masking 进一步允许只剥离到某个目标结构达到指定可见比例为止，这样可以控制蓝图中显示多少隐藏结构。

### 7. 草图式绘制的基本流程

草图式绘制首先生成两张主要纹理：

- Edge Map：边缘强度；
- Shade Map：表面颜色或简化后的色块。

然后使用噪声纹理扰动访问这两张图的 UV：

```text
原始 UV
  ↓
Perlin 噪声生成不确定性偏移
  ↓
扰动 Edge Map UV
扰动 Shade Map UV
  ↓
得到不规则边缘和色块
```

边缘和颜色可以使用不同的扰动强度或不同的二维矩阵，使线条和色块向相反方向偏移。最终把边缘强度与颜色合成，形成类似蜡笔或手绘的效果。

由于扰动后的 UV 可能访问到原始几何边界之外的区域，因此颜色块可以略微越过物体轮廓，产生手绘时“涂出边界”的感觉；边缘也可以多次用不同偏移重复绘制，模拟反复描线。

### 8. 草图式绘制中的深度问题

如果只绘制带纹理的屏幕四边形，会出现两个问题：

- 内部扰动区域没有对应的原始深度；
- 越过几何边界的区域没有正确深度。

结果就是草图图层无法和场景中的其他三维物体正确遮挡。

解决方法是把原始深度图也按照边缘偏移和颜色偏移分别采样，再取合适的最小深度作为最终深度：

```text
边缘扰动对应的深度
颜色扰动对应的深度
              ↓
        选择最终片元深度
              ↓
        重新进行深度测试
```

这就是把二维风格化图像重新放回三维深度关系中的过程。

### 9. Shower-Door Effect 与几何相关扰动

如果噪声只固定在屏幕空间，摄像机移动时，纹理会像贴在玻璃门上一样随屏幕滑动，这种现象称为 Shower-Door Effect。

为了降低这种问题，可以额外保存几何属性到 G-Buffer，例如：

- 表面位置；
- 法线；
- 曲率或其他对象属性。

然后使用这些几何属性作为噪声函数的输入，使扰动和物体表面而不是纯屏幕位置相关。

本章还会把模型沿顶点法线稍微膨胀，生成原始几何体附近的额外几何信息，使边界外的区域也能获得与物体相关的属性。这样，边界外的草图扰动不会完全脱离原始几何体。

### 10. 方法特点与限制

蓝图渲染适合：

- 建筑结构和室内空间；
- 机械和技术零件；
- 关卡编辑器中的隐藏结构提示；
- 需要表达前后层次关系的可视化。

草图式绘制适合：

- 概念设计预览；
- 卡通化角色和场景；
- 建筑草图；
- 非真实感艺术效果。

两种方法的主要代价是需要多个中间纹理和 Render Pass。蓝图渲染还受到深度复杂度影响：场景中重叠层越多，需要的深度剥离次数越多。草图式绘制虽然可以使用噪声和深度扰动获得手绘效果，但如果扰动只依赖屏幕空间，仍可能出现纹理游动和几何对应关系不稳定的问题。

## 讨论与补充

### 1. 全局风格化效果通常使用后处理

如果效果要统一作用于已经合成的整个画面，例如调色、LUT、Tone Mapping、暗角、颗粒、全局噪声或屏幕空间风格化扰动，通常使用全屏后处理。

后处理本身并不是 RT 的替代方案，而通常就是读取颜色 RT 并绘制全屏 Pass：

```text
场景 → ColorA
ColorA → 全屏效果 → ColorB
ColorB → 下一个效果 → ColorA
ColorA → 屏幕
```

多个效果之间通常使用 Ping-Pong 的两个颜色目标，因为 GPU 一般不能安全地同时从同一张 Render Target 采样并写回。现代 RenderGraph 会自动管理这些临时资源，并可能让不同阶段复用或别名同一块显存，因此不一定需要长期保存很多张 RT。

### 2. 不要求使用延迟渲染

前向和延迟渲染都可以进行后处理：

```text
前向渲染 → 场景颜色 → 后处理
延迟渲染 → G-Buffer → 光照合成 → 后处理
```

延迟渲染额外提供了法线、深度、粗糙度和材质 ID 等 G-Buffer 数据，方便 SSAO、边缘检测、屏幕空间描边等效果；但调色、Tone Mapping、Bloom 和暗角只需要最终颜色，与前向或延迟没有直接关系。

### 3. 后处理与材质 Shader 的选择

更适合放在全屏后处理中的效果：

- 需要读取邻近像素的屏幕空间效果；
- 需要统一处理所有物体的颜色；
- 调色、LUT、曝光、Tone Mapping、颗粒和暗角；
- SSAO、景深、运动模糊、屏幕空间反射和全局轮廓。

更适合放在材质 Shader 中的效果：

- 只属于某种材质或某个物体；
- 需要物体自己的法线、UV、材质参数或光照模型；
- 角色皮肤、水晶折射、草地风摆、溶解、卡通漫反射等。

一个完整效果也可以分成两部分。例如卡通渲染可以在材质 Shader 中计算 Toon 明暗，再用全屏 Pass 根据深度和法线绘制统一轮廓。

### 4. 是否每个效果都要单独一张 RT

不一定。调色、暗角和颗粒等可以合并到同一个全屏 Shader 中，减少 Pass 和 RT 读写；但如果后一个效果依赖前一个效果的结果，或者需要不同分辨率、迭代模糊、深度、法线或运动矢量，就需要拆分为多个阶段。

Unity 的 Full Screen Pass Renderer Feature 可以在指定注入点执行全屏材质，并按需要提供 Color、Depth、Normal 和 Motion 等输入。
