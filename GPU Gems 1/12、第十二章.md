# 各类灯光的阴影贴图

## 章节内容

点光源的全向阴影贴图（Omnidirectional Shadow Mapping），解决单一深度贴图只能覆盖方向光源的局限。

**作者**: Philipp S. Gerasimov

### 核心概念

点光源的全向阴影贴图（Omnidirectional Shadow Mapping），解决单一深度贴图只能覆盖方向光源的局限。

### 我的理解

**问题**：标准Shadow Map只能从单一方向投影，点光源需要全向覆盖。

### 解决方案：Cube Map Shadow

**核心思路**：使用立方体贴图（6个面）存储全向深度。

```cpp
// 1. 生成阶段（从点光源渲染6次）
for (int face = 0; face < 6; face++) {
    // 设置立方体贴图面的视角
    Matrix4 view = GetCubeFaceView(lightPos, face);
    Matrix4 proj = PerspectiveProj(90, 1.0, nearPlane, farPlane);  // 90°FOV覆盖一个面

    SetRenderTarget(shadowCubeMap, face);
    SetViewProj(view, proj);

    // 渲染场景深度
    RenderSceneDepthOnly();
}
```

**立方体面方向**：
```
Face 0: +X (right)
Face 1: -X (left)
Face 2: +Y (up)
Face 3: -Y (down)
Face 4: +Z (forward)
Face 5: -Z (back)
```

### Shader实现

```hlsl
// 顶点着色器：计算世界空间位置
struct VS_OUTPUT {
    float4 pos : POSITION;
    float3 worldPos : TEXCOORD0;
};

VS_OUTPUT VS_Main(float3 position : POSITION) {
    VS_OUTPUT output;
    output.pos = mul(float4(position, 1.0), WorldViewProj);
    output.worldPos = mul(float4(position, 1.0), World).xyz;
    return output;
}

// 像素着色器：采样立方体阴影贴图
samplerCUBE shadowCube : register(s0);
float3 lightPos;
float lightFarPlane;

float4 PS_Main(VS_OUTPUT input) : COLOR {
    // 1. 计算从光源到片元的向量
    float3 lightToFrag = input.worldPos - lightPos;

    // 2. 采样立方体贴图获取存储的深度
    float closestDepth = texCUBE(shadowCube, lightToFrag).r;

    // 3. 计算当前片元深度
    float currentDepth = length(lightToFrag);

    // 4. 深度比较
    float shadow = (currentDepth - bias > closestDepth) ? 0.0 : 1.0;

    // 5. 应用光照
    float3 lighting = ComputeLighting(...) * shadow;
    return float4(lighting, 1.0);
}
```

### 性能优化

**1. 多Pass渲染开销**：
```
标准Shadow Map：1次场景渲染
Cube Shadow Map：6次场景渲染（6个面）
→ 渲染开销增加6倍
```

**优化策略**：
- 降低立方体贴图分辨率（512×512 vs 2048×2048平面阴影）
- 仅在点光源附近物体渲染
- 多个点光源共享立方体贴图池
- 使用几何着色器一次性渲染到6个面（GeForce 8+）

**2. 深度存储**：
```hlsl
// 线性化深度存储（而非透视深度）
float depth = length(worldPos - lightPos);
depth = depth / lightFarPlane;  // 归一化到[0,1]
return float4(depth, depth, depth, depth);
```

### 与Dual-Paraboloid对比

| 特性 | **Cube Map** | **Dual-Paraboloid** |
|------|--------------|---------------------|
| **采样面数** | 6 | 2 |
| **渲染开销** | 高（6个Pass） | 中（2个Pass） |
| **接缝问题** | 轻微（边缘） | ⚠️ 明显（赤道） |
| **采样简单性** | ✅ texCUBE | ❌ 需要特殊计算 |
| **视口变形** | ✅ 无 | ⚠️ 抛物面变形 |
| **现代支持** | ✅ 主流选择 | ⚠️ 较少使用 |

### 现代应用

```
现代引擎中：
- Cube Shadow Map仍是点光源阴影标准方案
- 结合PCF/VSM实现软阴影
- 使用Geometry Shader优化渲染（一个Pass输出6个面）
- Unity/Unreal的点光源阴影默认使用Cube Shadow Map
```

## 讨论与补充


### 我的理解

不同光源的 Shadow Map 投影方式不同：

```text
方向光：
    正交投影，一张或多张平面 Shadow Map

聚光灯：
    透视投影，一张平面 Shadow Map

点光源：
    360° 发光，六张图组成 Cube Shadow Map
```

这里的“烘焙”需要区分两种情况：

- 静态 Lightmap：离线预计算并保存；
- 动态 Shadow Map：从光源视角实时或按需渲染深度。

本章主要讨论第二种动态 Shadow Map。

### 为什么点光源需要全向阴影？

方向光的光线近似平行，聚光灯只覆盖一个圆锥区域，因此可以用一个平面投影覆盖。

点光源则向所有方向发光：

```text
        ↑
    ←   ●   →
        ↓
    前后、上下都存在光线
```

如果只使用一张平面 Shadow Map，就无法覆盖点光源背后的其他方向。因此需要一个覆盖完整球面的阴影数据结构。

### Cube Shadow Map

最直接的方法是使用 Cube Map 的六个面：

```text
+X、-X
+Y、-Y
+Z、-Z
```

每个面都相当于从点光源位置朝一个方向、使用 90° 视角渲染得到的 Shadow Map：

```text
六个方向的平面 Shadow Map
        ↓
Cube Shadow Map
```

它和环境立方体贴图在结构上类似，但保存的不是环境颜色，而是：

```text
从点光源出发，
沿各个方向遇到的最近遮挡物距离
```

### 动态生成流程

#### 第一阶段：从点光源生成阴影贴图

```text
设置点光源为虚拟摄像机位置
    ↓
分别渲染 +X、-X、+Y、-Y、+Z、-Z
    ↓
保存各方向的遮挡物深度或距离
```

对于完全动态阴影，每帧或在光源、遮挡物发生变化时更新 Cube Shadow Map。静态场景则可以缓存或离线生成。

#### 第二阶段：主相机渲染时查询

对于主相机中的一个接收阴影像素：

```text
worldPosition - lightPosition
    ↓
得到光源到像素的方向
    ↓
使用方向采样 Cube Shadow Map
    ↓
计算当前像素到光源的距离
    ↓
比较当前距离和 Shadow Map 距离
    ↓
判断是否在阴影中
```

伪代码：

```hlsl
float3 toPixel = worldPosition - lightPosition;

float receiverDistance =
    dot(toPixel, toPixel);

float shadowDistance =
    SAMPLE_TEXTURECUBE(
        _ShadowCube,
        sampler_ShadowCube,
        normalize(toPixel)
    ).r;

float shadow =
    receiverDistance <= shadowDistance
    ? 1.0
    : 0.0;
```

如果当前像素距离点光源更远，说明中间存在遮挡物：

```text
receiverDistance > shadowDistance
    → 当前像素处于阴影中
```

### 为什么使用平方距离？

通常距离是：

```text
distance = length(toPixel)
```

但阴影判断只需要比较两个距离的大小，因此可以比较平方距离：

```text
squaredDistance = dot(toPixel, toPixel)
```

这样不需要执行平方根：

```text
length(toPixel)
    → 需要开平方

dot(toPixel, toPixel)
    → 只需要乘法和加法
```

生成 Shadow Map 和主场景查询时都使用平方距离即可。

但平方距离并不是完全没有问题：

- 数值范围更大；
- 远处精度可能变差；
- Bias 不能简单地当作线性距离偏移；
- 需要注意精度和阴影 Acne。

### 聚光灯为什么只用一张平面图？

聚光灯只覆盖一个圆锥区域：

```text
        光源
         ●
        / \
       /   \
      /     \
     /_______\
```

它可以被一台位于光源处的透视摄像机覆盖：

```text
聚光灯
    ↓
透视投影
    ↓
一张平面 Shadow Map
```

聚光灯的投影参数通常包括：

- FOV：聚光灯角度；
- Aspect：投影宽高比；
- Near Plane；
- Far Plane；
- Light View Matrix。

因为聚光灯不需要覆盖光源背后的五个方向，所以使用 Cube Map 会浪费资源。

### 方向光为什么使用正交投影？

方向光可以看成位于无穷远处，光线方向基本平行：

```text
→ → → → → → →
```

它不需要透视缩放，因此使用正交投影。

不过太阳光通常覆盖非常大的场景范围，所以现代实现往往使用 CSM：

```text
近处区域：高分辨率正交 Shadow Map
中距离区域：中等分辨率
远处区域：低分辨率
```

### Cube Shadow Map 和环境 Cube Map 的区别

它们的采样形式相似，都是：

```text
方向向量
    ↓
Cube Map 采样
```

但保存的数据完全不同：

| 类型 | 保存内容 | 用途 |
|---|---|---|
| 环境 Cube Map | 各方向环境颜色 | 反射、IBL |
| Cube Shadow Map | 各方向遮挡深度 | 点光源阴影 |

因此 Cube Shadow Map 不是环境贴图，只是复用了 Cube Map 的空间组织方式。

### 软阴影

本章可以通过对 Cube Shadow Map 进行多方向采样，得到软化的阴影边缘：

```hlsl
float shadow = 0;

for (int i = 0; i < sampleCount; i++)
{
    float3 sampleDirection =
        normalize(toPixel) + filterOffset[i];

    float shadowDistance =
        SAMPLE_TEXTURECUBE(
            _ShadowCube,
            sampler_ShadowCube,
            sampleDirection
        ).r;

    shadow += receiverDistance <= shadowDistance
              ? 1.0
              : 0.0;
}

shadow /= sampleCount;
```

这本质上是 Cube Shadow Map 上的 PCF。

但固定范围 PCF 只是让边缘变模糊：

```text
固定范围 PCF
    → 软化边缘
    → 不是真正根据光源大小计算半影
```

更准确的软阴影需要考虑：

- 光源大小；
- 遮挡物距离；
- 接收面距离；
- 光源与遮挡物的相对关系。

### 性能成本

点光源的主要成本来自全向渲染：

```text
每个点光源
    → 六个方向 Shadow Map
    → 可能还要进行 PCF 多次采样
    → 再进行一次光照 Pass
```

多个动态点光源会非常昂贵，因此现代引擎通常会结合：

- 光源影响范围剔除；
- Shadow Atlas；
- Shadow Cache；
- 延迟光照；
- Clustered Lighting；
- 局部阴影分辨率；
- 重要光源优先级；
- Ray-Traced Shadow 或其他混合方案。

### 与 Shadow Volume 的关系

点光源也可以用 Shadow Volume，但两者思路不同：

```text
Shadow Volume：
    从遮挡网格生成三维阴影几何体
    用 Stencil 判断是否处于阴影体内

Cube Shadow Map：
    从点光源六个方向记录深度
    主相机渲染时进行距离比较
```

Cube Shadow Map 更容易和：

- GPU 蒙皮；
- 硬件曲面细分；
- Alpha Clip；
- PCF；
- 软阴影；

结合，因此现代管线中更常见。

### 总结

```text
方向光：
    正交投影
    常配合 CSM

聚光灯：
    透视投影
    一张平面 Shadow Map

点光源：
    六个 90° 方向
    组成 Cube Shadow Map

全向阴影的核心：
    光源到像素的方向
    + 光源到像素的距离
    + Cube Shadow Map 中的遮挡距离
```

本章的核心结论是：

> Shadow Map 的投影形式由光源的空间覆盖范围决定。聚光灯只有一个有限圆锥，所以使用平面透视投影；点光源覆盖 360°，因此需要 Cube Shadow Map。
