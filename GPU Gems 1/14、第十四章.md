# PSM

## 章节内容

透视阴影贴图（Perspective Shadow Maps, PSM）通过后透视变换优化深度贴图分辨率分配，减少透视走样。

**作者**: Simon Kozlov

### 核心概念

透视阴影贴图（Perspective Shadow Maps, PSM）通过后透视变换优化深度贴图分辨率分配，减少透视走样。

### 我的理解

**标准Shadow Map的问题**：

```
透视走样（Perspective Aliasing）：
- 近处物体占据更多屏幕像素
- 远处和近处使用相同的Shadow Map分辨率
- 导致近处阴影块状化（undersampling）

示例：
        相机
         |
    近处 |         远处
    ████ |         ▓
    ████ |         ▓

阴影贴图分辨率分配：
    近处: 10 texels → 锯齿严重！
    远处: 10 texels → 浪费分辨率
```

### PSM核心思想

**关键洞察**：从相机视角变换阴影贴图，使分辨率分配与屏幕空间像素密度匹配。

**变换流程**：

```
标准Shadow Map：
World Space → Light View Space → Light Proj Space → Shadow Map

PSM：
World Space → Light View Space → Camera View Space → Camera Proj Space → Shadow Map
                                   ↑
                              关键创新！
```

### 算法详解

**1. 标准Shadow Map渲染**：

```cpp
// 从光源视角渲染
Matrix4 lightView = LookAt(lightPos, sceneCenter, up);
Matrix4 lightProj = Ortho(bounds);  // 正交投影

Matrix4 lightMatrix = lightProj * lightView;
RenderDepth(lightMatrix);
```

**2. PSM渲染**：

```cpp
// 从光源视角变换到相机空间
Matrix4 lightView = LookAt(lightPos, sceneCenter, up);

// ⭐ 关键：应用相机的透视变换
Matrix4 cameraView = GetCameraView();
Matrix4 cameraProj = GetCameraProj();  // 相机的透视矩阵

// 复合变换
Matrix4 psmMatrix = cameraProj * cameraView * Inverse(lightView);

RenderDepth(psmMatrix);
```

**几何意义**：
```
1. 将场景从光源空间变换到相机空间
2. 应用相机的透视变换
   → 近处物体被"放大"
   → 远处物体被"缩小"
3. 阴影贴图分辨率自动匹配屏幕空间密度
```

### Shader实现

```hlsl
// 顶点着色器（PSM深度渲染）
float4x4 psmMatrix;  // lightView^-1 * cameraView * cameraProj

struct VS_OUTPUT {
    float4 pos : POSITION;
    float depth : TEXCOORD0;
};

VS_OUTPUT VS_PSM(float3 position : POSITION) {
    VS_OUTPUT output;

    // 应用PSM变换
    float4 posLightSpace = mul(float4(position, 1.0), lightView);
    output.pos = mul(posLightSpace, psmMatrix);

    // 存储线性深度
    output.depth = output.pos.z / output.pos.w;

    return output;
}

float4 PS_PSM(VS_OUTPUT input) : COLOR {
    return float4(input.depth, input.depth, input.depth, 1.0);
}
```

```hlsl
// 像素着色器（阴影采样）
sampler2D psmShadowMap : register(s0);
float4x4 psmMatrix;

float4 PS_Main(float3 worldPos : TEXCOORD0) : COLOR {
    // 1. 变换到PSM空间
    float4 posLightSpace = mul(float4(worldPos, 1.0), lightView);
    float4 posPSM = mul(posLightSpace, psmMatrix);

    // 2. 透视除法
    float3 projCoords = posPSM.xyz / posPSM.w;

    // 3. 变换到纹理坐标[0,1]
    projCoords = projCoords * 0.5 + 0.5;
    projCoords.y = 1.0 - projCoords.y;  // 翻转Y

    // 4. 采样深度
    float closestDepth = tex2D(psmShadowMap, projCoords.xy).r;
    float currentDepth = projCoords.z;

    // 5. 深度测试
    float shadow = (currentDepth - bias > closestDepth) ? 0.0 : 1.0;

    // 应用光照
    float3 lighting = ComputeLighting(worldPos, lightPos);
    return float4(lighting * shadow, 1.0);
}
```

### 优缺点分析

**优点**：
```
✅ 近处阴影质量显著提升
✅ 无需额外内存开销
✅ 算法简单，易于实现
✅ 适合第三人称游戏（角色周围高分辨率）
```

**缺点**：
```
❌ 远处阴影质量下降（分辨率被"偷"给近处）
❌ 仅在光源和相机方向接近时效果好
❌ 边界裁剪问题（相机背后物体投影到无穷远）
❌ 需要处理特殊情况（光源在相机后方）
```

### 边界裁剪问题

**问题描述**：
```
相机背后的物体通过透视变换投影到无穷远
→ 阴影贴图需要覆盖无限范围
→ 分辨率严重浪费或裁剪错误
```

**解决方案**：
```cpp
// 1. 裁剪相机视锥背后的物体
if (Dot(lightDir, cameraForward) < 0) {
    // 光源在相机后方，使用标准Shadow Map
    return StandardShadowMap();
}

// 2. 限制近平面（避免极端变形）
float nearClip = max(cameraNear, minNearPlane);
Matrix4 clippedProj = PerspectiveProj(fov, aspect, nearClip, cameraFar);

// 3. 使用裁剪平面
// 仅渲染相机可见物体到阴影贴图
```

### 与其他技术对比

| 技术 | **近处质量** | **远处质量** | **复杂度** | **适用场景** |
|------|------------|------------|-----------|-------------|
| **标准Shadow Map** | ⭐⭐ | ⭐⭐⭐ | 低 | 通用 |
| **PSM** | ⭐⭐⭐⭐⭐ | ⭐ | 低 | 角色周围 |
| **CSM** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 中 | 大场景⭐ |
| **PSSM** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 中 | 现代标准⭐ |

### 现代改进：LiSPSM

**Light-Space Perspective Shadow Maps**（后续研究）：

```
改进：
1. 考虑光源和相机的相对位置
2. 自适应调整透视变换强度
3. 解决边界裁剪问题

核心公式：
n' = lerp(n_uniform, n_perspective, weight)

weight基于光源-相机夹角：
- 夹角小（平行）：更多透视
- 夹角大（垂直）：更少透视
```

### 实际应用建议

```cpp
// 混合策略（现代引擎常用）
if (IsCloseupScene() && IsLightInFront()) {
    // 近景使用PSM
    return PSM();
} else {
    // 其他情况使用CSM
    return CascadedShadowMap();
}

// 或使用PSSM（结合CSM和PSM优点）
return ParallelSplitShadowMaps();
```

## 讨论与补充


### 这章在解决什么问题

普通阴影贴图使用光源视角进行投影，但它的纹素并不会均匀对应屏幕像素。经过摄像机透视投影后，靠近摄像机的阴影纹素可能覆盖很大的屏幕区域，于是近处阴影容易出现锯齿、闪烁和泳动；远处反而可能拥有相对过多的阴影分辨率。

PSM 的目标是重新设计光源的投影，让阴影贴图的纹素分布更接近摄像机最终看到的透视分布：近处获得更多有效纹素，远处减少浪费，从而缓解 perspective aliasing。

### PSM 的基本思路

普通阴影贴图大致是：

```text
场景 → 光源视角投影 → 阴影贴图
```

PSM 则尝试把场景先放入摄像机的 post-projective space，再从这个空间构造光源投影：

```text
场景 → 摄像机投影后的空间 → 特殊的光源投影 → 阴影贴图
```

它相当于对阴影贴图的空间分布做一次透视重排，使阴影贴图更关注屏幕上占据较大面积的区域。

### PSM 和 Reverse-Z 的区别

两者都可以看作“重新分配投影/深度空间”，但目标不同：

| 技术 | 主要解决的问题 | 处理对象 |
| --- | --- | --- |
| Reverse-Z | 改善摄像机深度缓冲的精度分布，降低 Z-Fighting | 摄像机深度缓冲 |
| PSM | 改善阴影贴图纹素在屏幕上的分布，降低阴影锯齿 | 光源视角的阴影投影 |
| CSM | 将摄像机视锥体拆分，用多张贴图分别分配分辨率 | 摄像机视锥体 |

因此 PSM 不是 Reverse-Z 的阴影版本。Reverse-Z 主要改变深度值的存储和比较方式；PSM 主要改变光源投影后阴影纹素的位置。

### PSM 和 CSM 的关系

两者都在缓解同一个核心问题：摄像机近处的阴影需要更多分辨率。

- PSM：试图用一张经过透视变形的阴影贴图解决；
- CSM：把视锥体切成多段，每段使用一张独立的阴影贴图。

PSM 的优点是理论上可以用一张贴图提高分配效率；缺点是投影变形复杂，对光源和摄像机的相对位置很敏感，并且需要处理特殊的裁剪、虚拟摄像机和非均匀 bias。

CSM 需要多次渲染阴影贴图，但实现更直接、行为更可预测，也容易加入级联混合、稳定投影、PCF 等工程方案。因此现代实时渲染通常优先使用 CSM，而不是把 PSM 作为默认方案。

PSM 与 CSM 在理论上并非绝对互斥，也可以研究在每个级联中使用其他投影变形；但这会叠加复杂度，通常没有足够的工程收益。

### PSM 的主要问题

#### 1. 光源位置敏感

当光源位于摄像机后方、接近摄像机方向，或者光源与场景的相对位置不理想时，PSM 的虚拟投影空间会产生严重变形。为了覆盖潜在的阴影投射物，可能还需要把虚拟摄像机向后移动，这会浪费阴影贴图分辨率。

#### 2. 近裁剪面影响很大

PSM 使用透视投影后的空间，近裁剪面的位置会明显影响深度和纹素分布。理论上可以通过读取深度缓冲或分析场景来动态调整，但读取 GPU 深度会造成回读和同步问题，CPU 端场景分析也会增加复杂度。

#### 3. Bias 不再容易设置

普通正交阴影贴图常用较固定的 depth bias 或 normal bias。PSM 的纹素面积和深度分布不均匀，统一 bias 可能在某些区域产生 acne，在另一些区域又造成 peter-panning，因此需要结合世界空间尺度、斜率和局部纹素大小调整。

#### 4. 时间稳定性较差

摄像机或光源轻微移动，可能导致投影空间重新变化，进而出现阴影闪烁、泳动或清晰度突然变化。实时游戏通常更重视稳定性和可调试性，这也是 CSM 常被选用的重要原因。

### 工程判断

PSM 是有理论价值的阴影贴图投影优化，并不是错误或纯粹的骗局；但它更像是对单张阴影贴图的高级投影技巧，而不是现代项目中的通用阴影架构。

实际项目中通常根据需求选择：

- 传统方向光实时阴影：CSM + PCF/PCSS；
- 大规模动态场景：Virtual Shadow Maps、阴影缓存或分块阴影；
- 静态场景：Lightmap、Shadow Mask、烘焙阴影；
- 高端平台：根据预算使用光线追踪阴影。

因此，如果已经使用稳定的 CSM，一般没有必要再额外使用 PSM。Unity 的常规渲染管线和 Unreal 的公开阴影设置也主要围绕方向光级联阴影等方案，而不是把 PSM 作为普通开关。
