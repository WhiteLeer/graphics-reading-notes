# GPU 做 3D 渲染

## 章节内容

医学超声数据的实时3D可视化，应用实时着色技术。

**作者**: Thilaka Sumanaweera

### 核心概念

医学超声数据的实时3D可视化，应用实时着色技术。

### 特殊挑战

**非笛卡尔网格**：
- 超声数据采集于锥形网格
- "与CT和MRI相比，超声数据体积渲染更复杂"
- 数据从探头向体内发散
- 需要特殊坐标变换

### 实时着色应用

**顶点和片段着色器**：
- 顶点程序：生成金字塔形坐标的纹理坐标
- 片段程序："3D投影纹理查询"并应用颜色映射
- 实现快速体积渲染

### 体积数据处理

**切平面技术**：
- 逐层渲染
- "平行于屏幕的切平面"从远到近合成
- 配合alpha混合实现透明度

### 医疗成像需求

**4D超声**：
- 三维空间 + 时间维度
- "特别适用心脏功能和胎儿异常（腭裂）诊断"
- 满足动态成像帧率要求


## 讨论与补充


### 本章主线

本章是第三十九章体积渲染的一个具体案例：将随时间变化的三维超声数据实时显示出来。真正值得关注的不是医学领域本身，而是当体积数据不是规则立方体网格时，如何修正纹理坐标并正确采样。

### 与第三十九章的关系

第三十九章可以概括为：

```text
规则体积数据 + 3D Texture + 切片/采样 + Alpha 累积
```

第四十章则进一步处理：

```text
非规则体积数据 + 坐标变换 + 3D Texture + 体积渲染
```

所以它确实是在延续上一章的思路，但新增的工程难点是数据空间和纹理空间不再简单对应。

### 为什么超声数据更复杂

CT、MRI 数据通常近似规则的笛卡尔网格：

```text
x、y、z 方向的采样间隔比较规则
```

超声波则从探头向人体内部发散，采样网格更像棱锥、圆锥或楔形：

```text
探头
  ↓
  \        /
   \      /
    \    /
     \  /
      \/
```

越远离探头，同样的角度范围对应的横向空间范围越大。如果把它直接当作普通立方体采样，结果会出现拉伸、错位或空间比例错误。

### 主要实现

本章使用 3D Projective Texture Mapping：

```text
生成体积切片
    → 顶点 Shader 计算投影纹理坐标
    → 按深度方向修正横向坐标
    → 片元 Shader 采样 3D 超声纹理
    → 查询颜色/透明度 LUT
    → Alpha Blend 累积
```

直观地说，越靠近体积深处，纹理坐标的横向缩放越大，从而把规则纹理空间映射回超声数据原本的发散空间。

### 非规则体积数据的一般处理方式

遇到非规则采样数据时，通常有几种思路：

1. **预先重采样**：把数据转换成规则的 3D 网格，再使用普通 3D Texture；
2. **运行时坐标变换**：在顶点或片元 Shader 中根据数据空间计算采样坐标；
3. **投影纹理映射**：利用投影关系，把规则代理几何体映射到非规则数据空间；
4. **直接使用更复杂的数据结构**：例如稀疏体素、分块体积或非结构化网格。

本章选择的是第二、第三种路线，因为当时的 GPU 已经适合执行纹理投影和片元采样，但通用计算能力还不如现代 Compute Shader。

### 4D 数据

这里的“4D 超声”不是四维空间，而是：

```text
三维空间 + 时间
```

也就是一系列随时间变化的三维体积。每帧获取一个新的体积数据，再重复体积渲染流程。心脏等快速运动对象需要更高的体积更新频率。

### 对实时图形开发的启发

本章对普通游戏的直接使用场景有限，但有一个很通用的结论：

> 体积渲染的难点不只是“如何采样 3D Texture”，还包括数据空间、纹理空间和观察空间之间的映射。

因此，处理以下数据时也可能遇到类似问题：

- 球面、柱面或锥形采样数据；
- 雷达和声呐数据；
- 地震或科学计算数据；
- 非均匀流体缓存；
- 需要从 DCC 或外部设备导入的体积数据。

### 我的理解

第四十章可以压缩为一句话：

> 它不是提出了全新的体积渲染模型，而是说明当 3D 数据不是规则立方体时，需要通过投影和坐标修正，让切片正确地采样原始体积。

具体的 OpenGL、Cg 和固定功能纹理投影写法已经过时，保留“非规则数据的坐标映射”这一工程思想即可。
