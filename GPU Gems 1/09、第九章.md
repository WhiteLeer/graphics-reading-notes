# 阴影体和阴影贴图

## 章节内容

模板阴影体（Stencil Shadow Volume）的高效实现技术，支持实时动态阴影。

**作者**: Morgan McGuire

### 核心概念

模板阴影体（Stencil Shadow Volume）的高效实现技术，支持实时动态阴影。

### 算法原理

**1. 核心思想**

构造3D几何体"包围物体投射的所有阴影"。使用模板缓冲计数光线与阴影体表面的交点。

**判断规则**：
```
点P在阴影中 ⟺ 射向无穷远的光线进入交点数 > 退出交点数
```

**2. 模板缓冲实现**

**渲染设置**：
- 禁用深度写入
- 渲染阴影体到模板缓冲

**计数规则**：
- 正面多边形深度测试失败时：模板值递减
- 背面多边形深度测试失败时：模板值递增
- 结果：区分阴影/光照像素

### 优化技术

**3. Depth-Pass vs. Depth-Fail**

| 方法 | 计数方向 | Cap要求 | 优势 |
|------|--------|---------|------|
| **Depth-Pass (z-pass)** | 向观察者 | 无需（"uncapped"优化） | 更快 |
| **Depth-Fail (z-fail)** | 远离观察者 | 需要light和dark cap | 更稳定 |

**4. 性能优化技术**

**方向光优化**：
- 阴影边成为三角形（非四边形）
- 因为光线在无穷远处收敛

**XY裁剪**：
- 限制渲染到投影光范围
- 使用scissor测试
- 减少填充率开销

**深度边界**：
- 使用`glDepthBoundsEXT`
- 跳过光范围外的像素

**有限体积**：
- 阴影几何仅扩展到光源半径
- 而非无穷远

**5. 实现要求**

**数据结构**：
- 双顶点缓冲：标准顶点 + 无穷远扩展副本（w=0）
- 边邻接信息（一致的缠绕顺序）

**投影矩阵**：
- 无限远投影矩阵
- 防止远平面裁剪

**轮廓检测**：
- 每帧通过 N·L 点积判断朝光面
- 确定阴影体边缘

> [!tip] 实战建议
> Depth-pass + uncapped优化是最优组合，除非相机可能进入阴影体。

## 讨论与补充


### 我的理解与问题

阴影体是一种通过构造三维阴影区域，再利用 Stencil Buffer 判断像素是否位于阴影区域内部的阴影算法。

我原本的疑问是：现在游戏里是不是基本都使用 Shadow Map，Shadow Volume 是否已经被弃用？更准确的结论是：

> 阴影体没有在理论上失效，但在现代主流游戏引擎中已经不是默认的主流方案；阴影贴图及其变体更容易适应复杂场景、软阴影、植被和大量动态光源。

### 阴影体不是体积纹理

Shadow Volume 不是一张 Volume Texture，而是真正的三维几何体：

```text
遮挡物
  ↓
从光源方向观察其轮廓
  ↓
将轮廓边沿远离光源方向拉伸
  ↓
形成包围阴影区域的几何体
```

如果一个像素对应的场景点位于这个阴影体内部，就说明从光源到该点的路径被遮挡，应当减少或取消这盏光的贡献。

### 如何生成阴影体？

#### 1. 判断面朝向

对于每个三角形，根据面法线 `N` 和指向光源的向量 `L` 计算：

```text
dot(N, L) > 0：面朝向光源
dot(N, L) < 0：面背向光源
```

#### 2. 寻找轮廓边

一条边如果连接：

- 一个朝向光源的面；
- 一个背向光源的面；

那么这条边就是从光源看过去的 Silhouette Edge。

```text
朝向光源的面  |  背向光源的面
       \\     /
        \\   /
         轮廓边
```

#### 3. 拉伸轮廓边

把轮廓边的顶点沿远离光源的方向拉伸，形成阴影体的侧面 Quad。

点光源的方向取决于顶点到光源的位置关系；方向光可以看成位于无穷远处的点光源。

#### 4. 添加两个 Cap

阴影体还需要两个封口：

- Light Cap：靠近光源的一端；
- Dark Cap：远离光源的一端。

远端 Cap 可以被拉伸到无穷远。GPU Gems 中使用齐次坐标 `w=0` 表示无穷远方向，从而避免需要选择一个非常大的有限距离。

### Stencil Buffer 如何判断阴影？

Shadow Volume 通常只写入 Stencil Buffer，不写入颜色，也不修改深度。

```text
渲染阴影体
    ↓
根据深度测试结果修改 Stencil
    ↓
Stencil 为 0：像素不在阴影体内部
Stencil 非 0：像素位于阴影体内部
    ↓
光照 Pass 根据 Stencil 决定是否添加光照
```

从摄像机到场景点的视线可以看成一条射线。它进入阴影体一次、离开阴影体一次。通过统计进入和离开的次数，就能判断最终是否处于阴影体内部。

### Z-Pass 和 Z-Fail

#### Z-Pass

从摄像机向场景方向遍历时：

- 通过深度测试的阴影体面修改 Stencil；
- 常见问题是摄像机位于阴影体内部时，计数可能不正确。

#### Z-Fail

也常被称为 Carmack’s Reverse。它统计深度测试失败的阴影体面：

- 对正面和背面使用相反的 Stencil 增减操作；
- 不要求摄像机一定位于阴影体外部；
- 但需要正确封闭阴影体，并且通常需要处理无穷远的 Dark Cap。

这体现了 Shadow Volume 的核心不是“把黑色几何体画到屏幕上”，而是：

```text
用几何体定义可见性区域
    ↓
用 Stencil 做穿越计数
    ↓
得到阴影遮罩
```

### Shadow Volume 与 Shadow Map

| 特性 | Shadow Volume | Shadow Map |
|---|---|---|
| 基本数据 | 三维阴影几何体 | 光源视角深度图 |
| 判断方式 | Stencil 穿越计数 | 深度比较 |
| 阴影边缘 | 理论上与贴图分辨率无关 | 受分辨率影响 |
| 软阴影 | 标准实现不擅长 | PCF、VSM 等容易近似 |
| Alpha 植被 | 不容易正确处理 | 可使用 Alpha Clip |
| 动态模型 | 需要更新阴影体 | 重新渲染深度即可 |
| 多光源 | 每盏光都要处理阴影体 | 可使用图集、缓存和分页 |
| 常见问题 | 几何和 Fill Rate 成本 | 锯齿、Bias、漏光 |
| 现代主流程度 | 小众、特殊用途 | 主流 |

### 为什么现代游戏主要使用 Shadow Map？

#### 1. 更适合复杂场景

Shadow Map 只需要从光源视角渲染深度，而不需要显式构造每个遮挡物的轮廓边和阴影体。

#### 2. 更容易支持软阴影

通过多个深度采样、滤波或概率统计，可以得到软边缘近似：

```text
Shadow Map
    ↓
PCF / VSM / EVSM / 其他滤波
    ↓
软阴影
```

#### 3. 更适合植被和透明裁剪

树叶、草和角色头发通常是网格加 Alpha Clip。Shadow Map 可以在生成深度时执行同样的 Clip，而 Shadow Volume 只能根据几何外轮廓生成阴影，可能把一个矩形 Billboard 当成完整矩形投影。

#### 4. 更适合现代 GPU 管线

Shadow Map 可以和：

- Cascaded Shadow Map；
- Shadow Atlas；
- Virtual Shadow Map；
- GPU Driven；
- Shadow Cache；
- Nanite；

等技术结合。Unreal Engine 当前同时支持传统 Shadow Map、Virtual Shadow Map、Distance Field Shadow 和 Ray-Traced Shadow，其中 Virtual Shadow Map 面向高分辨率大型动态场景。

### 阴影体的优点

阴影体并不是没有价值：

- 硬阴影边缘准确；
- 不依赖 Shadow Map 分辨率；
- 不容易出现传统 Shadow Map 的 Bias 问题；
- 对少量动态物体和少量点光源很有效；
- 能处理某些 Shadow Map 不方便处理的几何关系。

例如类似 Doom 3 的场景：

```text
少量动态点光源
+ 明确的封闭网格
+ 硬阴影
+ 复杂光影氛围
```

使用阴影体是合理的。

### 阴影体的限制

#### 1. 需要轮廓边和邻接信息

网格需要知道每条边相邻的两个面。如果模型有裂缝、非流形边或没有正确闭合，阴影体可能出现错误。

#### 2. 几何处理和 Overdraw 较高

每个光源都可能需要生成并渲染大量 Shadow Volume。多个阴影体重叠时，Stencil Pass 的片元处理会增加。

#### 3. 标准实现主要是硬阴影

如果想模拟面光源，需要用多个位置略有不同的点光源叠加，成本很高。

#### 4. GPU 蒙皮会带来额外问题

如果角色由 GPU 蒙皮或顶点 Shader 变形，CPU 不一定能直接得到最终变形后的网格。Shadow Volume 若在 CPU 上寻找轮廓边，就可能使用错误的几何。

#### 5. 阴影接收对象仍需参与主场景绘制

阴影体只是标记 Stencil，并不会直接生成最终颜色。还需要在光照 Pass 中根据 Stencil 重新计算或叠加光照。

### 本章的现代意义

今天我们不一定会在普通 Unity 或 Unreal 项目中主动实现 Shadow Volume，但这一章仍然很有价值，因为它集中展示了：

```text
邻接网格
→ 轮廓边检测
→ 几何体外挤
→ 深度测试
→ Stencil 计数
→ 多 Pass 光照
```

它还能帮助理解为什么现代算法会选择 Shadow Map：

> Shadow Volume 直接构造“阴影区域”；Shadow Map 则把光源可见性压缩成深度数据，再在主渲染中查询。

### 总结

```text
Shadow Volume：
    用几何体定义阴影区域
    用 Stencil 判断像素是否进入阴影体

Shadow Map：
    从光源视角保存深度
    在主相机中比较光源空间深度

现代结论：
    Shadow Volume 没有被理论淘汰
    但 Shadow Map 及其变体更适合现代大型游戏
```

### Per-Object Shadow：角色专用阴影

我联想到过一种专门提升角色阴影质量的 `Per-Object Shadow`。需要明确：

> Per-Object Shadow 通常不是 Shadow Volume，而是给单个重要物体分配独立的小范围 Shadow Map。

#### 为什么需要单独处理角色？

级联阴影通常覆盖整个相机视锥：

```text
整个场景
    ↓
级联 Shadow Map
    ↓
主角只占很小的纹素区域
    ↓
角色阴影可能模糊、抖动或出现锯齿
```

Per-Object Shadow 则围绕主角或其他重要动态物体建立单独的阴影视锥：

```text
角色包围盒
    ↓
单独渲染高分辨率 Shadow Map
    ↓
只覆盖角色附近区域
    ↓
和主阴影结果合并
```

这样可以把有限的阴影贴图分辨率集中给主角、敌人或重要动态物体。

#### 和 Shadow Volume 的区别

| 特性 | Per-Object Shadow | Shadow Volume |
|---|---|---|
| 核心数据 | 单独的 Shadow Map | 三维阴影几何体 |
| 判断方式 | 光源空间深度比较 | Stencil 穿越计数 |
| 提高质量的方式 | 给物体更多 Shadow Map 纹素 | 构造更准确的阴影体 |
| 软阴影 | 容易配合滤波实现 | 标准实现不擅长 |
| 角色蒙皮 | 重新渲染角色深度 | 需要处理变形后的轮廓边 |
| 现代使用情况 | 仍然常见 | 已不是主流 |

因此，`Per-Object Shadow` 属于 Shadow Map 的分配和组织策略，不属于 Shadow Volume。

#### 为什么适合角色？

角色通常：

- 距离摄像机较近；
- 会持续移动和变形；
- 需要稳定的接触阴影；
- 在整个级联阴影中占用面积很小；
- 但阴影瑕疵很容易被玩家注意到。

实际方案可能是：

```text
远景环境：普通级联 Shadow Map
主角附近：Per-Object / Inset Shadow
角色脚下：Contact Shadow 或 Blob Shadow
```

在 Unreal 的传统 Stationary Light 工作流中，Per-Object Shadow 还需要处理两个方向：

1. 静态世界投射到可移动角色上的阴影；
2. 可移动角色投射到静态世界上的阴影。

它通常根据物体包围盒生成专用阴影视锥，因此角色的包围盒或 Physics Asset 必须足够准确。包围盒过小会造成阴影截断，过大则会浪费阴影贴图分辨率。

#### Unity 中的对应实现

Unity 默认并不统一使用 `PerObjectShadow` 这个名称，但可以自行实现类似流程：

```text
主场景级联 Shadow Map
        +
角色专用高分辨率 Shadow Map
        ↓
合并到屏幕空间阴影或主光照结果
```

也可以使用更便宜的近似方案：

- 角色脚下 Blob Shadow；
- Capsule Shadow；
- 屏幕空间 Contact Shadow；
- 角色专用 Shadow Map；
- 根据角色骨骼或 Physics Asset 生成的简化阴影代理。

#### 本章相关结论

```text
Shadow Volume：
    用几何体定义阴影区域
    用 Stencil 判断像素是否位于阴影体内

Per-Object Shadow：
    给单个重要物体分配独立 Shadow Map
    用更高的局部纹素密度提升阴影质量
```

所以“高质量角色阴影”并不意味着一定使用阴影体。现代引擎更常见的是级联 Shadow Map 加角色专用 Shadow Map，必要时再叠加 Contact Shadow 或 Blob Shadow。
