# AO

## 章节内容

环境光遮蔽（AO）- 智能环境光照项，根据表面各点能看到的外部环境比例变化。

> [!note] 作者注
> Matt Pharr后来成为PBRT的主要作者之一。

**作者**: Matt Pharr (NVIDIA), Simon Green

### 核心概念

环境光遮蔽（AO）- 智能环境光照项，根据表面各点能看到的外部环境比例变化。

> [!note] 作者注
> Matt Pharr后来成为PBRT的主要作者之一。

### 技术原理

**核心洞察**：
- 预处理模型，计算表面各点能看到多少外部环境
- 计算有多少被其他几何体遮挡
- 本质是漫反射项，支持复杂光照分布

### 预计算方法

**基础算法**：
1. 在三角形中心生成半球形光线集合
2. 追踪检测遮挡情况
3. 计算**可访问性**：未被遮挡的射线占比
4. 计算**平均方向**：未遮挡光线的加权方向（"弯曲法线"）

**采样技术**：
- **拒绝采样法**生成随机方向
- 在单位立方体中随机生成向量
- 拒绝超出单位球体或指向下方的方向
- 确保均匀分布

**硬件加速方案**：
- 围绕物体放置球形阴影贴图灯阵列（128-1024个灯）
- 多次渲染累积阴影贡献
- 模拟大面积光源

### 实时着色器集成

**三步流程**：

1. **坐标转换**：3D方向→纬度-经度纹理坐标
2. **模糊计算**：基于可访问性确定过滤范围
3. **环境查询**：模糊采样后乘以可访问性值

**性能**：
- 仅需约10条GPU指令
- 支持实时性能

### 效果对比

- **简单漫反射**：反差生硬，缺乏细节感
- **应用AO后**：裂缝暗化、暴露部分明亮、投影自然

### 关键优势

✓ 不依赖特定光照环境（预计算与照明独立）
✓ 兼容旧硬件（仅需顶点颜色传递）
✓ 易于集成纹理和传统光源
✓ 支持动画（通过关键姿态插值）

## 讨论与补充


### AO 解决的问题

普通漫反射主要根据表面法线和光源方向计算，但它不知道当前点周围是否被其他几何体包围。

墙角、凹槽、角色腋下、腿部内侧和物体接触地面的位置，即使法线方向适合接收光照，也不应该像完全暴露在天空下一样明亮。

Ambient Occlusion 的核心思想是：

> 统计一个表面点周围有多少方向可以接收到环境光。

如果大部分方向都被周围几何体遮挡，环境光贡献就应该减弱。

### Accessibility

GPU Gems 使用 Accessibility 表示环境可见度，可以近似定义为：

```text
Accessibility = 未被遮挡的半球方向数量 / 采样方向总数
```

例如：

```text
Accessibility = 1.0：几乎完全暴露
Accessibility = 0.1：大部分方向被遮挡
```

最简单的运行时使用方式是：

```hlsl
ambient = ambient * accessibility;
```

它不是完整的全局光照，只是对环境光可见程度的近似修正。

### Bent Normal

Accessibility 只告诉我们“有多少方向可见”，没有告诉我们“光主要从哪个方向到达”。

因此还可以累加所有未遮挡的采样方向，得到平均未遮挡方向：

```hlsl
float3 sum = 0;
int visibleCount = 0;

for each sampleDirection
{
    if (!occluded(sampleDirection))
    {
        sum += sampleDirection;
        visibleCount++;
    }
}

bentNormal = normalize(sum);
accessibility = visibleCount / sampleCount;
```

Bent Normal 不是普通几何法线的简单扰动，而是考虑周围遮挡后，未被遮挡环境光的平均入射方向。

普通法线表示：

```text
表面朝向哪里
```

Bent Normal 表示：

```text
环境光更容易从哪里到达
```

在更精确的实现中，采样方向还可以按 `max(dot(direction, normal), 0)` 加权：

```hlsl
sum += sampleDirection * max(dot(sampleDirection, normal), 0);
```

### 离线预计算流程

对于模型上的每个点、顶点或纹理像素：

```text
以表面点为起点
        ↓
在法线半球内生成大量射线
        ↓
检测每条射线是否撞到几何体
        ↓
统计未遮挡射线
        ↓
计算 Accessibility
        ↓
计算 Bent Normal
        ↓
保存到顶点属性或纹理
```

例如一个点向上方向开放、向下方向被地面遮挡，那么它的 Bent Normal 会偏向上方；如果某个点被右侧墙体遮挡，Bent Normal 可能偏向左侧开放区域。

### 运行时环境光照

如果只有 Accessibility，可以直接调制环境光：

```hlsl
ambientColor *= accessibility;
```

如果还有 Bent Normal，可以用它采样环境贴图：

```hlsl
float3 environmentColor = SampleEnvironment(bentNormal);
environmentColor *= accessibility;
```

这样既考虑了环境光可见比例，也粗略考虑了环境光来自哪个方向。

GPU Gems 还利用环境贴图的 MIP 级别完成模糊采样：Accessibility 越高，可以使用更大范围的环境光；Accessibility 较低时，使用更小的方向范围。

### 硬件加速的预计算方法

除了离线 Ray Tracing，也可以在预处理阶段使用大量位于半球上的 Shadow-Mapped Lights：

```text
在半球上布置许多光源
        ↓
每个光源生成一张阴影结果
        ↓
累计所有光源的可见性
        ↓
得到 AO 和 Bent Normal
```

这种方式本质上用许多阴影测试近似半球积分，通常需要很多光源和 Pass，适合预处理，不适合普通运行时直接使用。

### 与其他 AO 方案的区别

| 方案 | 数据来源 | 是否依赖当前画面 | 典型用途 |
| --- | --- | --- | --- |
| Baked AO | 离线射线/烘焙 | 否 | 静态模型、Lightmap |
| GPU Gems AO | 离线 Accessibility/Bent Normal | 否 | 静态物体、有限姿势角色 |
| SSAO | 当前帧深度和法线 | 是 | 动态场景 |
| HBAO/GTAO | 当前帧深度/法线和更好的几何估计 | 是 | 更高质量实时 AO |
| Ray-Traced AO | 实时光线 | 是 | 高端平台 |

GPU Gems 这一章重点是预计算 AO 与 Bent Normal，不是今天常说的纯屏幕空间 SSAO。

### 局限

#### 动画

角色改变姿势后，身体各部分之间的遮挡关系会改变，原先预计算的 AO 和 Bent Normal 可能失真。

一种近似方法是为多个参考姿势预计算数据，再根据当前骨骼姿势插值，但它仍然不能覆盖所有姿势。

#### 屏幕空间限制

SSAO 只能利用当前画面中的深度和法线，因此可能看不到屏幕外遮挡物，并出现边缘漏光、遮挡不连续等问题。

#### 不是完整全局光照

AO 只描述遮挡程度，不描述光线如何反弹，不能完整替代：

- 间接光照；
- Lightmap；
- 光照探针；
- 光线追踪；
- 漫反射全局光照。

### 工程判断

AO 更适合看作环境光的遮挡修正项，而不是独立的光照模型：

```text
Accessibility：环境光有多少方向可见
Bent Normal：环境光大致从哪里到达
环境贴图/漫反射：这些方向上的光是什么颜色
```

三者结合后，可以用很低的运行时成本近似复杂的环境光遮挡效果。
