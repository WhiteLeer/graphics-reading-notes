# 用纹理快速估计过滤宽度

## 章节内容

使用纹理操作快速估算滤波宽度，服务于程序纹理反走样。

**作者**: Matt Pharr

### 核心概念

使用纹理操作快速估算滤波宽度，服务于程序纹理反走样。

### 核心问题

程序纹理需要反走样处理：
- 计算像素周围区域的平均值
- 而非单点采样
- 避免锯齿状伪影

### 纹理操作方法

**巧妙技术**：
- 利用mipmap各层级填充特定值
- 每层存储对应分辨率的log2值×16
- 硬件自动选择合适mipmap层级
- 反推出滤波宽度

### 偏导数替代

**某些硬件不支持ddx()/ddy()**：
- 通过tex2D()查询特殊构建纹理
- 返回值告诉实际选择的mipmap层级
- 间接获得空间导数信息

### 性能与限制

**优势**：
- 仅需3条指令
- 性能相当

**缺陷**：
- 极端情况可能高估或低估
- 超出mipmap范围时不准确

**改进**：
- 缩放纹理坐标重新查询提高精度

## 讨论与补充


### 1. 为什么需要 Filter Width

程序纹理由 Shader 根据坐标计算，而不是从普通贴图采样。例如：

```hlsl
float checker(float2 uv)
{
    return fmod(floor(uv.x) + floor(uv.y), 2);
}
```

当棋盘格在画面中很大时，一个屏幕像素通常只覆盖黑色或白色区域；但当棋盘格缩小到远处时，一个屏幕像素可能同时覆盖黑白两种区域。

如果只计算像素中心，就会随机得到黑色或白色，产生：

- 锯齿；
- 闪烁；
- 摩尔纹；
- 相机移动时的图案跳变。

正确思路是对一个屏幕像素覆盖的纹理区域求平均，而不是只计算一个点。这个覆盖范围就是 **Filter Width（过滤宽度）**。

### 2. 现代 GPU 的 `ddx`、`ddy` 方法

如果硬件支持导数指令，可以估计当前值在相邻屏幕像素之间的变化：

```hlsl
float2 fw = max(abs(ddx(uv)), abs(ddy(uv)));
float width = max(fw.x, fw.y);
```

理解为：

```text
UV 变化小 -> 当前像素覆盖的纹理范围小 -> 过滤范围小
UV 变化大 -> 当前像素覆盖的纹理范围大 -> 过滤范围大
```

这种方法是近似的，并且把两个方向合成为一个标量，属于各向同性的过滤宽度。更精确的各向异性方法需要分别保留屏幕 X、Y 方向的变化。

现代 Shader 中也常使用：

```hlsl
float width = fwidth(value);
```

然后用它控制平滑过渡：

```hlsl
float edge = smoothstep(threshold - width,
                        threshold + width,
                        value);
```

这类写法常用于程序化圆形、SDF 字体、线条、条纹和程序化网格的抗锯齿。

### 3. 早期硬件的替代方案

本章针对不支持 `ddx` / `ddy` 的旧硬件，利用 GPU 自动选择 Mipmap 的过程来间接估计过滤宽度。

#### 3.1 制作特殊 Mipmap

创建一张特殊纹理，它不保存真实颜色，而是在不同 Mipmap 层级存储不同数值：

```text
Mip 0 -> 代表高分辨率层级
Mip 1 -> 代表下一层级
Mip 2 -> 代表再下一层级
...
```

更具体地，可以存储该层级纹理宽度的 `log2` 值。

#### 3.2 借助硬件选择 Mipmap

使用程序纹理的 UV 采样这张特殊纹理：

```hlsl
float encoded = tex2D(filterMap, uv).r;
```

GPU 会根据 UV 在相邻像素之间的变化速度自动选择 Mipmap：

- UV 变化慢，使用高分辨率 Mipmap；
- UV 变化快，使用低分辨率 Mipmap；
- 处于两个级别之间时，硬件会进行插值。

因此，返回的数值可以间接表示当前 UV 的变化速度。

#### 3.3 还原过滤宽度

如果纹理中编码的是 `log2(width)`，就可以近似计算：

```hlsl
float filterWidth = exp2(-log2Width);
```

整体过程是：

```text
程序 UV 的变化速度
    -> GPU 自动选择 Mipmap
    -> 读取特殊 Mipmap 中的编码值
    -> 估计 Filter Width
```

本质上是把 Mipmap 选择机制反过来当作测量工具。

### 4. 这种方案的局限

它只是 `ddx` / `ddy` 的替代方案，不是精度更高的实现：

- 需要额外绑定一张特殊纹理；
- 占用额外纹理采样资源和显存；
- 过滤宽度受 Mipmap 层数和范围限制；
- 变化太快或太慢时可能无法继续区分；
- 只能得到近似的各向同性宽度；
- 精度和方向信息不如真正的导数。

例如过快变化的不同输入都可能落到最高级 Mipmap，导致过滤宽度无法继续细分。

### 5. 工程上的理解

- 程序纹理也必须考虑一个像素覆盖的区域，否则远处容易出现严重混叠。
- `ddx`、`ddy`、`fwidth` 是现代 Shader 估计过滤范围的标准工具。
- 本章的 Mipmap 技巧主要是历史方案，但体现了一个很有价值的思路：复用硬件已有机制，用预处理数据换取运行时计算。
- 估计 Filter Width 后，不能只把图案计算在像素中心，通常还要对该范围做积分、平滑或近似平均。
