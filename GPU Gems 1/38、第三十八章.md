# GPU 做 2D 流体模拟

## 章节内容

GPU上的实时流体动力学模拟，求解不可压缩流的Navier-Stokes方程。

**作者**: Mark J. Harris (UNC Chapel Hill)

### 核心概念

GPU上的实时流体动力学模拟，求解不可压缩流的Navier-Stokes方程。

### 物理基础

**Navier-Stokes方程**：
- 支配速度和压力场
- "流体的速度导致流体沿流动传输对象、密度和其他量"

**四个关键加速项**：
- **Advection（对流）**：速度的自传输
- **Pressure（压力）**：通过流体传播力
- **Diffusion（扩散）**：粘性效应
- **External forces（外力）**：用户输入和体力

### 数学框架

**Helmholtz-Hodge分解定理**：
- 任何矢量场可分解为无散度分量和压力梯度
- 引出**Poisson-pressure方程**求解
- 在计算中间速度更新后保持不可压缩性

### GPU实现策略

**纹理作为数据**：
- 纹理=数据数组
- 片段程序=并行计算kernel

**模拟管线**：
1. **Advection**：半拉格朗日积分回溯粒子路径（大时间步稳定）
2. **Diffusion**：通过隐式拉普拉斯算子求解粘性
3. **Force Application**：添加外部加速度
4. **Projection**：通过迭代Poisson求解强制零散度

### 迭代求解器

**Jacobi迭代**：
- 在GPU上高效求解Poisson方程
- 收敛比multigrid方法慢
- 通常40-80次迭代平衡精度和性能

### 性能收益

**加速效果**：
- NVIDIA GeForce FX硬件上
- 相比等效CPU模拟"最多6倍加速"
- 证明交互式应用的实时能力


## 讨论与补充


### 本章主线

本章用 GPU 模拟流体状态，重点不是直接生成一张真实水面网格，而是计算速度场、密度场、压力场等数据，再把这些数据渲染成烟雾、染料、云雾或其他流体效果。

书中的实现使用浮点纹理和片元 Shader，把纹理像素当作二维流体网格中的单元。现代实现通常会改用 Compute Shader、RWTexture、StructuredBuffer 等，但整体的并行计算思路没有改变。

### 这是不是“用计算着色器做流体”

从现代工程角度看，是的。更准确地说：

- GPU Gems 1 使用的是“全屏四边形 + 片元 Shader + 浮点纹理”的早期 GPGPU 方案；
- 现代 Unity、Unreal 或自研引擎通常使用 Compute Shader 执行这些计算；
- 计算完成后，还需要普通 Shader 将速度、密度等结果渲染出来。

因此不要把“计算流体”和“渲染流体”混为一谈：

```text
流体模拟：计算速度、压力、密度等状态
流体渲染：根据密度、温度、光照等状态生成最终画面
```

### 网格数据

每个二维网格单元通常需要保存：

- `Velocity`：流体速度和方向；
- `Density/Dye`：烟雾浓度或染料颜色；
- `Pressure`：压力场；
- 边界、障碍物或外力信息。

可以将这些数据存放在纹理中：

```text
纹理中的一个像素 ≈ 一个流体网格单元
RGBA 通道       ≈ 该单元的一个或多个数值
```

### 一次模拟的典型步骤

```text
添加外力
  → 平流 Advect
  → 扩散 Diffuse
  → 求压力 Pressure Solve
  → 投影 Projection
  → 得到新的速度和密度
```

#### 平流

根据当前速度，反向寻找一个网格单元在上一时刻的位置，再从旧纹理采样数据。这样可以把烟雾或染料沿着速度场搬运。

#### 扩散

模拟速度或染料向相邻网格传播。实际实现通常要通过多轮迭代近似求解，而不是一次计算得到精确结果。

#### 压力求解

流体通常近似为不可压缩流体，需要满足：

```text
∇ · velocity = 0
```

也就是局部不能凭空被压缩或膨胀。压力求解的目标是找到一个压力场，用于修正速度。

#### 投影

从速度中减去压力梯度，使速度场更接近无散场。压力求解往往要执行多轮迭代，每轮读取上一轮压力纹理并写入另一张纹理。

### Ping-Pong 与多 Pass

GPU 计算一般不能安全地在同一次处理中既读取又覆盖同一资源，因此需要两份纹理轮换：

```text
本轮：读取 Buffer A，写入 Buffer B
下一轮：读取 Buffer B，写入 Buffer A
```

每一个模拟步骤也可能是一个或多个 Pass。这样做不是因为 Shader 写得不够集中，而是因为平流、扩散、压力求解和投影具有不同的计算依赖，拆开后更容易并行和同步。

### 物理准确性与实时效果

GPU 只是执行计算的位置，并不能保证模拟结果物理准确。实时流体通常是“物理启发的近似”：

- 网格分辨率有限；
- 通常只模拟二维或低分辨率三维网格；
- 压力场只迭代有限次数；
- 使用半拉格朗日平流来保证稳定性，但会损失细节；
- 时间步长可能较大；
- 边界条件和外力通常由项目人为设定；
- 模拟区域、更新频率和精度都受到性能限制。

所以即使算法来自流体力学，实时结果也不等于严格求解 Navier-Stokes 方程。

### 游戏中的实际做法

游戏通常不会只依赖一个严格的流体求解器，而是组合多个近似和视觉增强：

```text
低分辨率流体模拟
    → 上采样
    → Curl Noise 增加旋涡细节
    → Vorticity Confinement 增强小尺度运动
    → 密度、温度和颜色映射
    → 体积光、阴影和时间累积
```

最终目标往往是“看起来像流体”，而不是让每个细节都符合真实物理。因此常见的工程方案包括：

- 烟雾：低分辨率速度场 + 密度场 + 体积渲染；
- 火焰：粒子、Flipbook、噪声、体积纹理或简化流体混合；
- 云雾：3D Noise、流体场和 Ray Marching 混合；
- 水面：波函数、FFT、顶点动画和屏幕空间效果；
- 高质量预制特效：Houdini 等离线模拟后烘焙成 VDB、VAT、序列帧或体积缓存。

### 实时模拟与离线模拟

| 类型 | 目标 | 常见特点 |
| --- | --- | --- |
| GPU 实时流体 | 可交互和稳定帧率 | 低分辨率、强近似、可控性强 |
| Houdini 等离线流体 | 细节和物理一致性 | 高分辨率、计算时间长、可烘焙 |
| 游戏特效 | 画面观感和资源预算 | 模拟、噪声、粒子和美术控制混合 |

因此，“流体模拟”不等于“最终画面一定真实”。模拟只提供一个动态基础，视觉质量还取决于密度重建、光照、阴影、噪声细节、透明度和艺术控制。

### 我的理解

本章最值得保留的结论是：

> GPU 流体的核心是把流体状态离散到网格中，用多个并行 Pass 逐步更新；实际项目则在物理合理性、稳定性、可控性和观感之间取平衡。

所以现代项目常见的方案不是“纯物理模拟”或“纯序列帧”二选一，而是根据效果和预算混合使用：重要交互部分采用实时近似，远景或固定演出使用烘焙资源，再用 Shader 和后处理统一观感。
