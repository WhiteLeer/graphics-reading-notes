# 加速算法

## 章节内容

本章讨论如何组织场景、几何和光源，使系统可以尽早排除不可能影响当前结果的对象。加速算法通常不是一种单独的剔除开关，而是层次结构、包围体、排序、LOD 和可见性测试的组合。

### 1. 空间数据结构

BVH 将对象或三角形放入层次包围体中。遍历时先测试父节点包围盒，若父节点不可见或不相交，就能跳过整个子树。BVH 适用于不同形状的对象，容易更新和重建，也可用于光线追踪、碰撞和可见性查询。

AABB 计算便宜，但旋转后包围会变松；OBB 更紧但测试复杂；球体、胶囊和 k-DOP 也可作为不同场景的包围体。四叉树适合地形和二维平面，八叉树适合三维空间，网格分桶适合对象分布均匀的场景。HLOD 把空间中相近的对象合并成更高层级的代理几何或代理材质，重点是降低远处对象数量和 DrawCall，并不等同于 BVH。

### 2. CPU 剔除

CPU 可以执行自定义逻辑、Layer、距离、视锥、粗略遮挡和 LOD 选择。视锥剔除通常用对象包围盒与六个裁剪平面测试；层次结构可以让一次失败排除整棵子树。

遮挡剔除可以使用离线可见性单元、门户系统、遮挡体层次结构或上一帧结果。CPU 端通常做粗粒度判断，适合在提交 DrawCall 前删除整个对象或实例组，但过于复杂的细粒度判断会消耗 CPU，动态场景也难以维护。

### 3. GPU Driven 与 GPU 剔除

GPU Driven 把实例数据、包围体、LOD 参数和间接绘制参数放入 GPU 可访问的 Buffer，由计算着色器执行视锥、距离、LOD、遮挡或自定义判断，再写入 Indirect Draw 参数。CPU 只需提交较少的调度和间接绘制命令。

GPU 剔除可以保留大量候选实例而不让 CPU 逐个遍历，但会付出 GPU 计算、Buffer 读写和同步成本。若实例很少或 CPU 本来就空闲，把任务搬到 GPU 不一定更快。

### 4. 光栅化和片元级剔除

背面剔除根据三角形绕序和朝向删除背向相机的图元。裁剪、三角形边界测试和退化图元处理发生在光栅化附近。片元阶段还会进行 Alpha Clip、深度测试、模板测试和 Early-Z。它们比 CPU 对象剔除更细，但片元已经产生后才被排除，节省的主要是后续像素工作。

Early-Z 可能在片元着色前进行深度测试；如果 shader 修改深度、使用某些副作用或存在复杂 discard，硬件可能只能在片元着色后做 Late-Z。深度预处理 pass 可以先写入深度，让后续昂贵 pass 更容易使用 Early-Z。

### 5. 光源和阴影剔除

多光源渲染也需要剔除：根据光源包围体、Tile 或 Cluster 列表，只让影响某个屏幕区域或深度切片的光源参与着色。阴影投射者和阴影接收者需要在光源视角下单独进行视锥、距离、层级和遮挡筛选，不能简单地认为主相机看不见的物体永远不需要生成阴影。

### 6. LOD 与可见性层次

LOD 可以根据距离、屏幕尺寸、速度、重要性和预算切换几何、材质、阴影和动画精度。HLOD、Impostor、广告牌和点云都是更激进的表示替换。为了避免 popping，可以使用淡出、交叉混合、geomorph 或时域稳定。

## 讨论与补充

### 既有整理

### BVH、HLOD 与空间数据结构

BVH（Bounding Volume Hierarchy）是将物体组织成树，并为节点保存包围体。查询时先测试父节点：如果父包围体不可能相交，就可以直接跳过整个子树。

```text
根包围体
├── 子包围体 A
│   ├── 物体 1
│   └── 物体 2
└── 子包围体 B
    ├── 物体 3
    └── 物体 4
```

BVH 不等于剔除算法，它是帮助剔除、求交和空间查询快速进行的数据结构。它可以用于：

- 光线追踪；
- 碰撞检测；
- 视锥体剔除；
- 遮挡剔除；
- GPU 实例剔除；
- 光源影响范围查询。

四叉树和八叉树则是递归划分空间：二维区域分成 4 块，三维区域分成 8 块。它们可以用于寻路中的空间查询，但本身不是 A* 或 Dijkstra 这样的寻路算法。寻路算法负责搜索路径，四叉树/八叉树负责快速找到某个位置附近的节点、障碍物或可行走区域。

HLOD（Hierarchical LOD）和 BVH 看起来相似，因为它们都具有层次结构和包围体，但目标不同：

- BVH 主要回答“哪些对象可能相关或可见”；
- HLOD 主要回答“这一组对象应该使用多高的细节表示”。

HLOD 的父节点通常还会保存一个合并模型、低模或 Impostor。距离较近时遍历子节点，距离较远时直接绘制父节点代理，因此 HLOD 可以减少 Draw Call、网格数量和材质切换。实际系统中可以使用 BVH、八叉树或场景图来组织 HLOD。

### 多级剔除

剔除不是一个单独阶段，而是从场景级一直延伸到片元级的多级过程：

```text
CPU/GPU 物体剔除
    ↓
图元裁剪、背面剔除
    ↓
光栅化生成片元
    ↓
Early-Z / 模板测试
    ↓
像素着色器中的 clip/discard
    ↓
Late-Z、混合与写入
```

#### CPU 剔除

CPU 可以执行自定义逻辑、视锥体剔除、距离剔除、粗粒度遮挡剔除、Portal 剔除、LOD/HLOD 选择，以及决定物体是否参与阴影、反射或其他 Pass。

典型流程是：

```text
场景结构 / BVH / 八叉树
    ↓
CPU 判断可见性和 LOD
    ↓
Visible Object List
    ↓
只提交可见物体的 Draw Call
```

CPU 物体剔除发生得很早，被剔除的物体可以省掉后续的 Draw Call、顶点读取、顶点处理、光栅化和像素处理。但如果 CPU 每帧遍历的对象太多，剔除本身也可能成为瓶颈。

#### GPU 剔除

GPU 剔除不是简单地把所有 CPU 代码原样搬过去，而是让 GPU 直接读取实例数据，并通过 Compute Shader 或其他 GPU 程序筛选可见实例：

```text
Instance Buffer
    ↓
GPU 视锥体 / LOD / Hi-Z 遮挡测试
    ↓
Visible Instance List
    ↓
Indirect Draw 参数
    ↓
GPU 绘制
```

常见的 GPU 剔除对象包括实例、Cluster 和 Meshlet。它主要减少 CPU 遍历和 Draw Call 提交，但剔除计算本身仍有成本。

#### 视锥体剔除

测试物体包围体和摄像机视锥体的关系：

- 完全在视锥体外：剔除；
- 完全在视锥体内：保留，并可减少子节点测试；
- 与边界相交：保守保留或继续细分测试。

视锥体剔除只能判断物体是否在相机范围内，不能判断它是否被墙体或其他物体遮挡。

#### 遮挡剔除

遮挡剔除处理“在视锥体内、但被其他物体完全挡住”的对象，例如墙后的建筑或山后的物体。

它可以通过 CPU、GPU、Portal、Occlusion Query、Hierarchical Z-Buffer 或预计算可见集实现。GPU 细粒度遮挡剔除常使用深度金字塔/HZB，判断实例、Cluster 或 Meshlet 的包围体是否被遮挡。

遮挡测试通常需要先得到遮挡物的深度，因此 GPU 方案可能使用上一帧或当前可用的深度结果。为了避免错误剔除，实际系统通常采用保守策略：宁可多绘制一些，也不要把真正可见的物体剔除掉。

#### LOD 与距离剔除

- LOD：仍然绘制对象，但换成更简单的表示；
- 距离或细节剔除：屏幕贡献太小，直接不绘制。

常见层级是：

```text
近处：高模
中距离：低模
远处：Impostor / Billboard
极远处：直接剔除
```

通常先进行剔除，再对剩余可见对象选择 LOD，避免为已经不可见的对象计算细节等级。

#### 光栅化和图元级处理

光栅化相关的处理对象是三角形或图元，而不是完整物体：

- 背面剔除：删除背向相机的三角形；
- 屏幕外裁剪：切掉超出视锥体或裁剪空间的几何部分；
- 小三角形处理：删除或合并几乎不覆盖像素的三角形。

背面剔除适合封闭的不透明实体，但不适合双面材质、草叶、透明薄片和某些毛发卡片。

#### 片元级处理

Early-Z、深度测试和模板测试不应简单称为“着色器剔除”：

- Early-Z：在像素着色器之前进行深度测试，失败的片元不会运行像素着色器；
- Late-Z：像素着色器之后再进行深度测试；
- 模板测试：根据模板值决定片元是否继续；
- `clip()` / `discard`：在像素着色器内部丢弃片元。

`clip()` 或 `discard` 通常发生在像素着色器已经启动之后，因此它不能替代 CPU/GPU 物体剔除，也不一定能节省前面的像素着色成本。它常用于 Alpha Test、树叶、草和头发卡片。

### 不要混淆的三个概念

- **剔除（Culling）**：整个对象或图元不再继续处理；
- **裁剪（Clipping）**：只切掉超出范围的几何部分；
- **深度测试（Depth Test）**：判断当前片元是否被已有深度遮挡。

可以简记为：

```text
物体剔除：这个对象不要了
图元剔除：这个三角形不要了
片元测试：这个像素不要了
```
