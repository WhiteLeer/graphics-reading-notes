# 着色基础

## 章节内容

本章介绍着色基础，包括着色模型、光源、材质系统、抗锯齿、透明度、Alpha 合成和 Gamma/sRGB。它同时适用于写实渲染和风格化渲染，是后续基于物理着色章节的基础。

### 1. 着色模型

着色模型用于根据表面、光源和观察方向计算物体外观。一个着色模型通常会接收：

- 表面位置；
- 表面法线；
- 观察方向；
- 材质参数；
- 光源方向和强度；
- 环境或未受光照时的基础颜色。

着色模型可以是写实的，也可以是风格化的。不同的数学公式、参数和组合方式可以产生不同外观。

一个简单的着色模型可以将表面分成两部分：

```text
lit：受到光照的部分
unlit：没有直接受到光照的部分
```

最基础的漫反射模型会使用表面法线 `N` 和光线方向 `L` 的点积：

```text
max(0, N · L)
```

当光线正对表面时，点积较大；当光线以较大角度照射时，点积变小；光线位于表面背面时，点积为负，需要被限制为 0。这就是 Lambert 漫反射模型的基本思想。

Gooch 等风格化模型会使用冷色和暖色表示阴影与受光区域，而不是简单地把未受光照部分变成黑色。通过高光、边缘和颜色过渡，还可以构造卡通、工程可视化等效果。

### 2. 光源

光源可以按照形状、位置和方向进行抽象。着色器通常需要得到光线方向和光照强度，至于这些值如何计算，可以由不同类型的光源决定。

#### 2.1 方向光

方向光可以看作来自无限远处的光源。场景中的所有位置都使用相同的光线方向，通常不需要计算距离衰减，适合表示太阳光。

#### 2.2 点光源

点光源从一个位置向各个方向发光。表面上的光线方向需要根据光源位置和表面位置计算，光照强度通常会随距离衰减。

物理上常见的衰减形式是平方反比：

```text
intensity ∝ 1 / distance²
```

但直接使用平方反比在距离接近 0 时会产生极高的值，因此实际引擎通常会使用限制、范围或窗口函数对衰减进行修正，并在性能需求较高时使用近似衰减函数。

#### 2.3 聚光灯

聚光灯同时具有位置和方向。它通常使用内圆锥、外圆锥和半影区域控制光照强度：

```text
内锥内：强度较高
内锥到外锥：平滑衰减
外锥外：没有光照
```

#### 2.4 面光源

现实中的光源通常具有面积和形状，会从多个方向照亮表面上的一个点。面光源能够产生更自然的高光和软阴影，但需要处理光源表面上的多个采样点，因此计算更复杂。

### 3. 光照计算的位置

着色计算可以在不同阶段执行：

- 每个物体一次；
- 每个 Draw Call 一次；
- 每个顶点一次；
- 每个像素一次。

逐顶点着色的计算结果会在三角形内部进行插值，因此适合变化平缓的光照。对于高光、细小光源或快速变化的表面，逐顶点结果可能不准确，通常需要逐像素计算。

顶点法线在插值后可能不再保持单位长度，因此实际实现中常常需要在插值前和插值后重新归一化法线。

表面法线、光源和顶点数据还需要统一坐标空间。常见选择包括世界空间、观察空间和模型空间。选择哪一种空间需要综合考虑性能、数据传输和实现复杂度。

平面着色可以让一个三角形的属性保持不插值。现代实现通常可以通过把图元属性绑定到特定顶点，并关闭对应的插值来实现，而不一定需要几何着色器。

### 4. 材质系统和着色器组合

材质系统负责描述表面的各种输入，例如：

- 基础颜色；
- 光滑度或粗糙度；
- 法线；
- 透明度；
- 发光；
- 风格化参数；
- 时间和位置相关参数。

这些参数可以来自顶点、常量、纹理、缓冲区或程序计算。

复杂材质通常由多个独立功能模块组合而成，例如：

- 表面着色；
- 顶点变形；
- 蒙皮；
- 曲面细分；
- 实例化；
- 裁剪；
- 透明和后处理。

功能组合会产生大量 Shader Variant，因此材质系统需要在以下方案之间取舍：

- 编译时使用预处理或变体，删除不需要的代码；
- 运行时使用动态分支，保留一个更通用的着色器；
- 使用模块化函数和共享代码；
- 使用 Ubershader，再通过编译选项或动态分支裁剪功能。

动态分支可以减少变体数量，但可能导致额外计算和线程发散；静态变体更容易优化，但会增加编译时间、包体和变体管理成本。

### 5. 采样、滤波与锯齿

屏幕和纹理都是离散采样系统。连续几何或颜色信号被低采样率表示时，就会产生锯齿和走样：

- 几何边缘出现阶梯；
- 细线闪烁或消失；
- 纹理细节产生摩尔纹；
- 旋转物体出现错误的运动方向。

采样率不足时会发生 Aliasing。Nyquist 极限说明，采样频率需要足够高，才能正确表达目标信号中的最高频率。

采样后通常需要使用滤波器进行重建或抑制高频：

- Box Filter：简单但会产生阶梯状结果；
- Tent Filter：对相邻样本进行线性插值，结果更连续；
- Sinc Filter：理想低通滤波器，但实现成本更高。

缩小纹理或信号时，应该先进行低通滤波，避免高频内容折叠到低频。放大时则需要根据采样点重建连续结果。

### 6. 抗锯齿方法

抗锯齿的基本思路是增加采样数量、改善采样分布，或者在图像空间估计和修正边缘。

常见方法包括：

- Supersampling / FSAA：每个像素执行多个完整样本，质量高但成本高；
- MSAA：增加覆盖和深度样本，通常不对每个样本重复执行完整像素着色；
- 旋转网格和抖动采样：改善采样分布；
- 时间抗锯齿：使用不同帧的样本并进行累积；
- 后处理抗锯齿：根据颜色、深度或法线边缘进行图像空间修正。

不同方法需要在几何边缘、透明边缘、着色高频细节、性能和稳定性之间取舍。时间抗锯齿可能产生拖影和闪烁，后处理方法可能误判纹理边缘或使文字和尖角变模糊。

### 7. 透明度和 Alpha 合成

最简单的透明材质可以看作对背景颜色进行衰减。普通 Alpha Blend 可以写成：

```text
Result = Source × Alpha + Destination × (1 - Alpha)
```

其中 Source 是当前透明物体颜色，Destination 是当前帧缓冲中的颜色。

普通透明混合通常需要：

1. 先绘制不透明物体；
2. 再绘制透明物体；
3. 透明物体按照从后往前的顺序排序；
4. 通常开启深度测试，但关闭深度写入。

这种方法简单、快速，不需要大量额外内存，但会受到透明物体相交和排序错误的影响。

更复杂的方案包括：

- Alpha Clip；
- Depth Peeling；
- A-Buffer；
- Per-Pixel Linked List；
- Weighted Blended OIT；
- 多层透明混合。

其中深度剥离会逐 Pass 提取不同深度层，结果更准确但成本较高；加权混合是顺序无关且较快的近似方法，但不完全考虑透明表面的前后顺序。

### 8. Alpha 表示、合成与颜色编码

Alpha 可以表示不透明度、覆盖率或合成权重。预乘 Alpha 会将颜色预先乘以 Alpha，适合图像过滤、边缘抗锯齿和多次合成，但必须与匹配的混合公式一起使用。

显示设备通常使用非线性颜色编码。渲染过程中应在线性空间进行光照、混合和抗锯齿，再将结果编码为适合显示的颜色空间。

## 讨论与补充

### 1. 预乘 Alpha

预乘 Alpha 不是把透明物体变成 Opaque，而是改变颜色的存储方式和对应的混合公式。

普通 Alpha：

```text
RGB = 原始颜色
A   = Alpha
```

预乘 Alpha：

```text
RGB' = RGB × Alpha
A    = Alpha
```

普通 Alpha 的混合公式通常是：

```text
Result = SrcRGB × SrcAlpha
       + DstRGB × (1 - SrcAlpha)
```

预乘 Alpha 的混合公式通常是：

```text
Result = SrcRGB'
       + DstRGB × (1 - SrcAlpha)
```

因此常见的预乘 Alpha 混合状态为：

```text
SrcBlend = One
DstBlend = OneMinusSrcAlpha
```

如果存储方式和混合公式匹配，两种方式在理想情况下可以得到相同的最终颜色。预乘 Alpha 不会自动改变：

- 深度测试；
- 深度写入；
- 透明物体排序；
- 是否进入透明渲染队列。

### 2. 为什么预乘 Alpha 更适合透明边缘

预乘 Alpha 不只是为了弥补有限精度造成的细节误差，它会改变纹理过滤、插值和合成时的计算行为。

透明贴图的边缘可能同时包含半透明像素和完全透明像素。如果颜色和 Alpha 分开插值，透明区域中的黑色 RGB 可能被带到边缘，产生黑边。

预乘 Alpha 后，颜色已经包含了透明度：

```text
Alpha = 0 → RGB' 通常也接近 0
```

所以它通常更适合：

- 透明纹理过滤；
- Mipmap；
- 抗锯齿边缘；
- 粒子和 UI；
- 多次图像合成。

### 3. 为什么不全部使用预乘 Alpha

预乘 Alpha 也有代价：

- 低 Alpha 区域的原始颜色会被压低，有限位深下可用精度减少；
- 当 Alpha 为 0 时，原始 RGB 基本无法恢复；
- 美术编辑和资源制作通常希望颜色与透明度独立保存；
- 有些 Alpha 实际上表示遮罩、覆盖率或其他数据，不应该直接乘到 RGB 上；
- 如果预乘纹理仍使用普通 Alpha 的混合公式，就会被重复乘 Alpha，造成颜色过暗。

因此可以粗略理解为：

```text
资源制作阶段：普通 Alpha 更方便独立编辑颜色和透明度
过滤、抗锯齿和合成阶段：预乘 Alpha 通常更稳定
```

关键不是“哪一种永远更好”，而是整条管线必须统一约定：纹理表示方式、过滤方式和 Blend State 必须匹配。

### 4. sRGB 与 Gamma

sRGB 是一种非线性颜色编码方式，可以近似表示为：

```text
sRGB   ≈ Linear^(1 / 2.2)
Linear ≈ sRGB^2.2
```

但严格来说，sRGB 是分段函数，并不完全等于简单的 Gamma 2.2。

它的目的不是改变颜色含义，而是让有限的 8-bit 数值分布更符合人眼对亮度的感知，从而减少暗部浪费和色带。

### 5. 线性空间与颜色计算

光照、颜色相加、Alpha 混合、抗锯齿等计算通常应该在线性空间中执行：

```text
sRGB 纹理
    ↓ 解码
Linear 颜色
    ↓ 光照、混合、抗锯齿和后处理
Linear 结果
    ↓ 编码
sRGB 显示颜色
```

直接对 sRGB 数值进行光照或混合，可能导致：

- 颜色过暗；
- 光照叠加不正确；
- 透明边缘发黑；
- 抗锯齿边缘偏暗。

### 6. 哪些纹理使用 sRGB

通常只有表示颜色的纹理才使用 sRGB 解码：

```text
Base Color / Albedo：通常使用 sRGB
```

以下纹理通常是直接参与计算的数据，应保持线性：

```text
Normal Map
Roughness
Metallic
AO
Mask
Height
Depth
ID
Alpha
```

它们不是需要符合人眼亮度感知的颜色，不能按照颜色纹理的方式进行 Gamma/sRGB 转换。

### 我之前的总结

```text
预乘 Alpha：改变颜色表示和混合方式，不等于 Opaque
sRGB：非线性颜色编码，近似但不完全等于 Gamma 2.2
渲染计算：通常在线性空间进行，最后编码为 sRGB
颜色纹理：通常使用 sRGB
数据纹理：通常保持线性
```
