# 高效着色

## G-Buffer

G-Buffer 是一组保存“当前帧每个可见像素表面信息”的 Render Target。它的内容可以根据后续光照或其他算法自定义，例如：

- 深度或位置；
- 法线；
- Albedo；
- Roughness、Metallic、AO；
- 材质 ID；
- 物体 ID；
- UV、切线空间或运动向量；
- SSS 厚度、光照遮罩等自定义数据。

G-Buffer 不是固定格式，但每增加一个 Render Target 或每提高一个通道的精度，就会增加显存占用和读写带宽。

需要注意，G-Buffer 保存的是每个像素的数据，不是每个材质的一份数据。如果只存 `MaterialID`，后续还需要通过材质表找到材质参数；如果还要采样纹理，则必须额外保存 UV、PrimitiveID 或能够推导 UV 的数据。

## 延迟渲染与透明物体

不透明物体比较适合延迟着色，因为一个像素通常只需要保存一个最终可见表面：

```text
几何 Pass → G-Buffer → 光照 Pass
```

透明物体则可能在一个像素上存在多个按深度排列的表面：

```text
透明层 1 → 透明层 2 → 透明层 3 → 背景
```

传统 G-Buffer 只保存一层数据，因此透明物体不能直接像不透明物体一样处理。强行支持透明延迟渲染时，需要额外的多层存储或 OIT，例如深度剥离、A-Buffer、每像素链表和加权混合。

因此实际工程中常见的是混合方案：

- 不透明物体使用 Deferred Shading；
- 透明物体使用 Forward 或 Clustered Forward；
- 特殊透明效果再单独使用 OIT、折射或体积方法。

前向透明本身也很复杂，通常需要后到前排序、深度测试策略和混合。区别在于：前向透明虽然难，但材质和混合关系比较直接；传统延迟管线如果要保存多层透明表面，会引入额外的 per-pixel 数据结构和带宽成本。

## Decal 与 Paint Map

### 小型贴花

弹孔、刀痕、血迹和脚印可以使用带透明纹理的小平面，但这种方法容易出现穿插、Z-Fighting 和曲面贴合问题。

### Deferred Decal

更常见的做法是渲染一个代表贴花影响范围的盒体：

```text
Decal Box
    ↓
根据深度重建世界坐标
    ↓
转换到贴花局部空间
    ↓
判断像素是否在贴花体积内
    ↓
投影采样贴花纹理
    ↓
修改 Albedo、Normal、Roughness 等 G-Buffer 数据
```

这样弹孔不仅能改变颜色，也可以改变法线和粗糙度。Unreal 的 Deferred Decal 就采用了通过盒体投影并影响 G-Buffer 的思路。

### Paint Map

Paint Map 不是固定的一种资源，也通常不等于 G-Buffer。它更像是跨帧保存的涂料状态：

- 逐物体 UV Paint Map：适合角色、武器和独立道具；
- 世界空间 Paint Map：适合地形和大范围环境；
- 分块 Paint Map：适合大型世界和流式加载；
- Decal/绘制列表：适合少量动态贴花；
- Paint Render Texture：适合不断累积喷涂结果。

G-Buffer 通常每帧重新生成，而 Paint Map 可以跨帧保留。Paint Map 可以在生成 G-Buffer 时被采样，用来影响 Albedo、Normal、Roughness、Emission 或占领权重。

因此，喷漆类效果更可能是持久化的世界/物体纹理或分块 Render Texture，而不是单纯的一张 G-Buffer RT。

## 深度重建世界坐标

使用屏幕 UV 和深度值，可以重建当前像素可见表面的世界坐标：

```text
屏幕 UV + 深度
    ↓ 逆投影矩阵
视空间位置
    ↓ 逆视图矩阵
世界空间位置
```

这里的 UV 是屏幕 UV，不是模型 UV。实际计算必须考虑投影矩阵、深度范围、反向 Z、透视除法和深度精度。

这种方法只能得到最前方可见表面，无法从一张普通深度图恢复被遮挡的后表面、透明物体的多层深度或屏幕外几何。

## 硬件 TBDR 与软件 Tiled/Clustered Shading

### 硬件 TBDR

移动 GPU 常见的 Tile-Based Deferred Rendering 会把屏幕划分为 Tile，并对每个 Tile 的几何、可见性和片元进行处理：

```text
几何分配到 Tile
    ↓
Tile 内完成可见性和片元处理
    ↓
结果保存在片上 Tile Memory
    ↓
Store/Resolve 到最终 Render Target
```

它的主要收益是减少对外部显存的往返访问。这里的 “Deferred” 指延迟 Tile 内的光栅化和片元处理，不等于传统的 G-Buffer 延迟着色。每个 Tile 通常是独立完成并写回自己的屏幕区域，而不是最后把所有 Tile 的颜色重新做一次全局合并。

如果后续 Pass 仍需要读取某个 Render Target，就可能发生 Store/Load，把片上 Tile 数据写回外部显存后再重新加载，从而产生带宽和性能成本。

### 软件 Tiled Shading

软件 Tiled Deferred/Forward Shading 主要是为了优化多光源：

```text
屏幕划分为二维 Tile
    ↓
为每个 Tile 建立影响光源列表
    ↓
像素只遍历自己 Tile 的光源
```

### Clustered Shading

Clustered Shading 在 Tile 的基础上增加深度方向，将视锥体划分为三维 Cluster：

```text
屏幕 X/Y + 深度 Z
    ↓
Cluster → Light List
    ↓
像素根据屏幕位置和深度找到所属 Cluster
```

它可以减少二维 Tile 因深度不连续而包含过多光源的问题。Clustered Shading 既可以用于 Deferred，也可以用于 Forward。

总结：

```text
硬件 TBDR：GPU 按 Tile 组织几何和片元处理，降低显存往返
软件 Tiled：按二维 Tile 组织光源列表
软件 Clustered：按三维 Cluster 组织光源列表
G-Buffer：当前帧的可见表面数据
Paint Map：跨帧保存的涂料或环境状态
```
