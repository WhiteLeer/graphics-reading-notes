# 变换

## 章节内容

本章介绍实时渲染中用于移动、旋转、缩放、变形和投影的各种变换。内容从基本的平移、旋转、缩放和剪切开始，进一步讨论矩阵组合、刚体变换、法线变换、欧拉角、四元数、蒙皮、Morph Target、几何缓存以及正交和透视投影。

### 1. 变换的作用

变换可以将点、向量、颜色或其他几何数据转换为新的状态，用于：

- 移动物体、光源和相机；
- 改变物体朝向和大小；
- 实现动画和层级关系；
- 将数据转换到同一个坐标系；
- 将三维场景投影到二维屏幕。

线性变换可以使用矩阵表示。平移本身不是严格意义上的三维线性变换，但使用齐次坐标后，可以和旋转、缩放等操作统一为 `4×4` 仿射变换矩阵。

### 2. 基本变换

#### 2.1 平移

平移将点从一个位置移动到另一个位置。平移矩阵的最后一列通常保存位移量。由于向量的齐次坐标为 `W=0`，同一个平移矩阵不会改变纯方向向量。

#### 2.2 旋转

旋转可以让点或向量绕经过原点的轴旋转。绕坐标轴的旋转可以使用对应的旋转矩阵表示。旋转属于刚体变换，不会改变物体的长度、角度和形状。

如果要绕任意点旋转，通常需要：

```text
平移到原点
    ↓
执行旋转
    ↓
平移回原位置
```

#### 2.3 缩放

缩放可以分别改变 `x`、`y`、`z` 方向上的大小：

- 三个方向使用相同系数：均匀缩放；
- 三个方向使用不同系数：非均匀缩放。

非均匀缩放会改变物体的角度关系，因此会影响法线变换和后续光照计算。

#### 2.4 剪切、反射和其他线性变换

剪切会让一个坐标分量受到另一个坐标分量影响，例如：

```text
x' = x
y' = y
z' = z + kx
```

剪切可以改变物体形状，但某些剪切变换仍然保持面积或体积。反射可以看作沿某个平面翻转坐标方向，也可以使用矩阵表示。

### 3. 矩阵组合与刚体变换

矩阵乘法不满足交换律，因此变换顺序会影响结果。在列向量约定下：

```text
M = T × R × S
P1 = M × P0
```

实际执行顺序从右到左：

```text
先缩放
再旋转
最后平移
```

刚体变换只包含平移和旋转，不包含缩放、剪切或反射。刚体变换不会改变物体的长度、角度和形状，因此常用于相机、骨骼节点和物理物体。

### 4. 法线的变换

法线不能在存在非均匀缩放或剪切时直接使用模型矩阵变换。设模型矩阵左上角的 `3×3` 部分为 `A`，则切线可以直接变换：

```text
T' = A × T
```

为了保持法线和变换后切线的垂直关系，法线需要使用逆转置矩阵：

```text
N' = (A⁻¹)ᵀ × N
```

最后还需要归一化，因为变换可能改变法线长度。

如果法线直接由变换后的三角形边向量重新叉乘得到，则得到的已经是变换后表面的法线，不需要另外使用逆转置矩阵。

### 5. 欧拉角与方向变换

欧拉角通过依次绕多个坐标轴旋转来表示方向。不同旋转轴顺序会得到不同结果，内旋和外旋也会产生不同的组合方式。

欧拉角适合表示简单的方向控制，但存在：

- 旋转顺序依赖；
- 插值不均匀；
- 多组欧拉角可能表示同一个方向；
- 万向节锁；
- 从旋转矩阵提取欧拉角时存在特殊情况。

本章还介绍了如何从旋转矩阵提取欧拉角，以及如何限制物体只绕某个轴旋转。

### 6. 绕任意轴旋转

绕任意归一化轴旋转时，可以先构造一个坐标系变换，将目标旋转轴对齐到标准坐标轴，然后执行标准轴旋转，最后再变换回原坐标系：

```text
目标轴对齐到标准轴
    ↓
绕标准轴旋转
    ↓
变换回原坐标系
```

这种方法说明了坐标系变换在构造复杂旋转中的作用。

### 7. 四元数

四元数使用四个分量表示旋转。单位四元数可以表示任意三维旋转，并且适合进行旋转组合和插值。

四元数具有：

- 加法；
- 乘法；
- 共轭；
- 范数；
- 逆；
- 归一化。

单位四元数可以通过轴角形式构造，并转换为旋转矩阵。四元数转换为矩阵时不需要大量三角函数，适合运行时使用。

四元数的两个重要性质是：

- `q` 和 `-q` 表示同一个旋转；
- 单位四元数位于四维单位球面上。

四元数球面线性插值，也就是 SLERP，可以沿单位球面上两个旋转之间的最短弧进行插值，通常比直接插值欧拉角更平滑、更稳定。

### 8. 顶点混合与蒙皮

顶点混合用于让网格跟随骨骼运动。每个顶点通常保存若干骨骼索引和对应权重：

```text
顶点位置
    ↓
骨骼变换 0 × 权重 0
骨骼变换 1 × 权重 1
骨骼变换 2 × 权重 2
    ↓ 加权求和
变换后的顶点
```

最基础的线性混合蒙皮可以在 GPU 上执行。网格顶点和连接关系可以长期保存在 GPU 缓存中，每帧主要更新骨骼节点的变换。

线性蒙皮的缺点包括：

- 关节处可能折叠；
- 可能出现体积损失；
- 可能产生扭曲或自相交。

双四元数混合可以更好地保持关节附近的刚性和体积，但实现更复杂。

### 9. 顶点变形、Morph Target 与 Blend Shape

顶点变形需要解决两个问题：

- 顶点对应关系；
- 顶点状态之间的插值方式。

Morph Target 或 Blend Shape 会保存同一网格的另一组顶点位置和法线，通过权重控制原始形态与目标形态之间的混合。

多个目标形态可以叠加使用，例如同时控制嘴巴、眉毛和眼睛。负权重也可以用于产生目标范围之外的表情效果，但过大的权重可能导致不自然的形变。

蒙皮和 Morph Target 可以组合使用：先根据骨骼改变整体姿态，再使用 Blend Shape 修正面部、肌肉或关节细节。

### 10. 几何缓存回放

对于某些高质量过场动画，可以直接保存每一帧的几何状态，然后在运行时播放这些几何数据。这种方法称为几何缓存回放。

它适合：

- 复杂模拟结果；
- 难以实时计算的高质量动画；
- 过场动画；
- 顶点数量固定但形变复杂的对象。

缺点是会占用大量存储和带宽，通常不适合需要实时交互的角色动画。

### 11. 正交投影

正交投影可以将长方体可视空间变换为标准观察体。投影前后的平行线仍然平行，距离相机远近不会改变物体的投影大小。

正交投影常用于：

- 编辑器视图；
- 2.5D 游戏；
- UI 和图标；
- 阴影贴图；
- 工程和建筑可视化。

### 12. 透视投影

透视投影模拟人眼和相机观察物体的方式。距离相机越远，物体的投影越小；平行线可能在远处汇聚。

透视投影通常由视野角、宽高比、近裁剪面和远裁剪面等参数决定。投影后还需要除以齐次坐标的 `W` 分量，得到 NDC。

透视投影的深度通常不是线性分布的，可以近似表示为：

```text
z_ndc = A + B / d
```

其中 `d` 是观察空间中的距离。由于近处占用了更多深度精度，远处两个相近表面可能映射到相同或非常接近的深度值，从而产生 Z-Fighting。

改善深度精度的方法包括：

- 合理设置近裁剪面和远裁剪面；
- 提高深度缓冲精度；
- 使用 Reversed-Z；
- 使用多个深度范围或级联视锥体；
- 避免两个表面过于接近。

## 讨论与补充

### 1. 变换矩阵的组合顺序

在列向量约定下，如果模型变换为：

```text
M = T × R × S
```

则：

```text
P1 = M × P0
   = T × R × S × P0
```

实际作用顺序是从右到左：

```text
temp0 = S × P0
temp1 = R × temp0
temp2 = T × temp1
P1    = temp2
```

因此这里是先缩放，再旋转，最后平移。

矩阵乘法不满足交换律，所以：

```text
T × R ≠ R × T
```

变换顺序不同，最终结果也不同。

### 2. 刚体变换

刚体变换只包含平移和旋转，不包含缩放：

```text
M = T × R
```

刚体变换不会改变物体的长度、角度和形状。

### 3. 为什么法线不能直接使用模型矩阵

模型矩阵可以写成：

```text
M = [ A  t ]
    [ 0  1 ]
```

其中：

- `M` 是 `4×4` 矩阵；
- `A` 是左上角的 `3×3` 矩阵，包含旋转、缩放和剪切；
- `t` 是平移部分。

法线是方向，不是位置，因此不需要平移。使用 `A` 可以忽略平移部分。

但如果存在非均匀缩放，不能简单使用：

```text
N' = A × N
```

因为这样可能导致变换后的法线不再垂直于变换后的表面。

### 4. 法线的逆转置变换

设原来的法线和切线满足：

```text
N · T = 0
```

切线是表面上真实存在的方向，因此直接变换：

```text
T' = A × T
```

我们需要让变换后的法线继续满足：

```text
N' · T' = 0
```

由此可以得到：

```text
N' = (A⁻¹)ᵀ × N
```

Shader 中通常写成：

```hlsl
float3x3 normalMatrix = transpose(inverse((float3x3)M));
float3 worldNormal = normalize(mul(normalMatrix, normal));
```

这里的关键不是“法线和切线都是顶点数据”，而是二者的几何语义不同：

```text
切线：表面上的方向，跟随表面直接变换
法线：描述垂直关系的约束，需要使用逆转置保持垂直
```

### 5. 也可以变换切线后重新计算法线

如果有两条独立的表面切线 `T1` 和 `T2`，也可以：

```text
T1' = A × T1
T2' = A × T2
N'  = normalize(cross(T1', T2'))
```

这种结果与使用逆转置变换法线在理想情况下是等价的。逆转置方法更常用，是因为模型通常已经保存了顶点法线，不需要每帧根据三角形重新计算。

需要注意，只有一条切线不足以唯一确定一个表面法线，通常需要两条独立切线或完整的切线空间。

如果 `A` 只有旋转，或者是旋转加均匀缩放，直接使用 `A × N` 通常也可以；非均匀缩放和剪切则需要逆转置。

### 6. 欧拉角

欧拉角可以用多个轴的旋转来表示物体朝向，但有几个问题：

- 旋转轴的顺序会影响结果；
- 插值时旋转速度可能不均匀；
- 可能出现万向节锁问题。

因此骨骼动画、相机动画等场景经常使用四元数来表示和插值旋转。

### 7. 透视除法与深度精度

透视投影后，顶点会带有与深度相关的 `w` 分量。进行透视除法时：

```text
z_ndc = z_clip / w_clip
```

由于 `w_clip` 通常与观察空间深度 `d` 相关，最终深度大致具有这样的形式：

```text
z_ndc = A + B / d
```

因此深度不是在线性距离上均匀分布的：

```text
近处：距离变化一点，深度值变化明显
远处：距离变化很大，深度值变化很小
```

远处不同表面可能被映射到非常接近的深度值，有限精度的 Z-Buffer 无法区分它们，就可能出现：

- Z-Fighting；
- 表面抖动；
- 深度排序不稳定。

常见解决方式包括：

- 合理设置 Near 和 Far，尤其不要把 Near 设置得过小；
- 提高深度缓冲精度；
- 使用 Reversed-Z；
- 避免让两个几何表面过于接近。

### 我之前的总结

```text
模型变换：M = T × R × S，实际从右到左执行
刚体变换：只包含平移和旋转
切线变换：T' = A × T
法线变换：N' = (A⁻¹)ᵀ × N
透视除法：产生非线性的深度分布
```
