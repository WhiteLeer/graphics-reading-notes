# 未来

## 1. 这章的核心不是预测，而是建立判断标准

本章并不是在断言某种技术一定会取代其他技术，而是在提醒我们：

> 没有永远最优的渲染算法。算法是否有效，取决于当时的硬件、带宽、功耗、工具链和应用需求。

同一种技术在不同平台上的瓶颈可能完全不同：

```text
桌面 GPU：可能更受计算量或显存带宽影响
移动 GPU：可能更受功耗、外部内存访问和带宽影响
VR：还要额外受帧率、延迟和双眼渲染成本影响
离线渲染：可以用更长时间换取更多样本和更高质量
```

因此，学习一个技术时不能只记“它能实现什么效果”，还要问：

```text
它解决了什么问题？
它消耗哪类资源？
它适合什么场景和硬件？
它会和哪些技术发生冲突？
```

## 2. 性能瓶颈会逐渐从计算转向数据和带宽

硬件计算能力持续提升，但内存带宽、缓存和数据搬运速度未必同步提升。因此性能优化不只是减少 Shader 运算，也包括：

- 提高缓存命中率；
- 减少 CPU/GPU 或显存/系统内存之间的数据传输；
- 减少纹理、G-Buffer、Render Target 的重复读写；
- 控制资源格式和精度，避免无意义的带宽消耗；
- 利用压缩、Tile、Mipmap 和局部存储。

这和前面讨论的 GPU Driven、纹理缓存、TBDR、G-Buffer 压缩等内容是同一条主线：

> 很多时候，搬运数据比计算数据更贵。

## 3. 光栅化不会立即消失

即使出现更强大的渲染技术，光栅化仍会长期存在，不只是因为它速度快，还因为：

- 现有图形 API 围绕光栅化建立；
- 游戏引擎、材质系统和工具链都依赖它；
- 大量 Shader、资产和生产流程不能立即迁移；
- 已经开始制作的游戏通常在早期就确定了目标平台和渲染方案。

但现代 GPU 也不再只是“固定的光栅化流水线”，而是大型可编程并行处理器，可以混合执行：

```text
传统光栅化
计算 Shader
GPU Driven
光线追踪
后处理
机器学习推理
```

所以更准确的趋势不是“光栅化被替代”，而是“光栅化与其他计算方式共同组成渲染器”。

## 4. 光线追踪会先作为局部能力加入

完全路径追踪在理论上很统一，但实时应用面临两个核心问题：

```text
样本少 → 噪声大
样本多 → 性能成本高
```

因此更现实的路线是先将光追用于局部效果：

```text
光追阴影
光追反射
光追环境光遮蔽
光追折射
```

屏幕上“有哪些物体”仍可以由光栅化完成，而光线追踪负责部分光照传播：

```text
光栅化：负责主可见表面
光线追踪：负责部分光线传播效果
```

这种混合渲染更容易接入现有引擎，也更容易根据硬件能力关闭或降低某一类光追效果。

## 5. 降噪和重建与光追同样重要

实时光追通常不能为每个像素发射足够多的光线，因此需要利用：

- 时域累积；
- 空间滤波；
- 降噪；
- 超分辨率；
- 神经网络重建。

这说明实时渲染的竞争点不只是“每帧计算多少样本”，还包括：

> 如何利用少量样本，推断出更高质量且稳定的图像。

“低分辨率渲染 + 时域重建”与光追降噪本质上属于同一类思想：用时间、邻域和额外信息弥补当前帧样本不足。

## 6. 体素、点云和 SDF 是特定场景的替代表示

### 体素

适合体积效果、可自由修改的世界和类似 Minecraft 的场景。缺点是数据量大，动态物体和高分辨率场景成本较高。

### 点云

适合激光雷达、自动驾驶、三维扫描等传感器产生的空间数据。

### SDF

符号距离场用函数表示空间位置到物体表面的有符号距离，适合：

- 程序化建模；
- 布尔运算；
- 光线步进；
- 可自由变形的物体；
- 体积和隐式表面。

它们都不是马上全面替代网格的通用方案，而是针对特定约束“打破常规”的工具。场景表示的选择，仍然要看动态性、存储、编辑方式、渲染方式和目标平台。

## 7. 对实际学习和项目的启发

不要为了追逐术语而堆叠技术。更合理的流程是：

```text
先确定视觉目标和平台约束
→ 找出主要瓶颈
→ 选择能解决该瓶颈的技术
→ 用实际数据验证收益
```

例如：

```text
纹理带宽高 → 先查 Mipmap、压缩和缓存局部性
像素过度绘制高 → 先查深度、排序、遮罩和分辨率
CPU 提交过多 → 再考虑实例化、GPU Driven 和间接绘制
光照效果不足 → 再判断是否需要局部光追，而不是直接全路径追踪
```

本章也鼓励通过论文、引擎源码、Shadertoy、Three.js 和自己的实验来学习。对我来说，最重要的不是记住更多名词，而是能把一个效果拆成：

```text
数据从哪里来
→ 哪个阶段处理
→ 访问了哪些资源
→ 消耗计算、带宽还是延迟
→ 如何用实验确认瓶颈
```

## 本章总结

```text
1. 没有永远最优的渲染算法，必须结合平台和约束判断。
2. 性能瓶颈会越来越多地表现为带宽、缓存和数据搬运问题。
3. 光栅化不会马上消失，但会和计算 Shader、光追等方式混合使用。
4. 实时光追的关键不只有求交硬件，还包括采样、降噪和重建。
5. 体素、点云、SDF 适合特定场景，不是无条件替代网格。
6. 学习和优化的重点是理解问题、资源和验证方法，而不是追逐术语。
```
