# 碰撞检测

## 章节内容

碰撞检测不仅是判断两个对象是否相交，还包括射线查询、最近距离、接触点、穿透深度、碰撞响应、连续碰撞和大量粒子之间的相互作用。实时系统通常使用宽阶段、中阶段和窄阶段逐步减少候选，而不是让所有对象直接进行精确测试。

### 1. 宽阶段、中阶段与窄阶段

宽阶段使用空间哈希、均匀网格、四叉树、八叉树、BVH 和包围体，快速找出可能接触的对象对。它宁愿产生少量误报，也不能漏掉真正碰撞。

中阶段使用 AABB、OBB、球体、胶囊、凸包等更紧的代理几何。角色通常用胶囊和盒体，车辆可以用多个凸体，静态场景可以使用分块碰撞网格。

窄阶段才使用 SAT、GJK/EPA、射线-三角形、凸体-三角形或专用解析公式求精确结果。碰撞模型通常远比渲染模型简单，以换取稳定性和可控成本。

### 2. BVH、动态更新与射线

静态网格可以预构建 BVH；动态对象每帧改变姿态后，可以先 refit 包围盒，只有拓扑或空间分布变化很大时才 rebuild。射线查询同样先遍历包围体，再测试叶节点中的三角形。

BSP、KD-Tree、空间哈希和扫掠排序（SAP）适合不同分布。SAP 会沿一个或多个轴排序 AABB 的端点，利用区间重叠快速找候选，适合对象运动平滑、数量中等的场景。

### 3. CPU、GPU 与粒子碰撞

CPU 适合复杂控制逻辑、少量重要对象、需要立即得到结果的碰撞。GPU 适合大量粒子、布料、流体和实例的并行测试，但结果回读 CPU 会破坏性能，因此通常把碰撞后的响应也留在 GPU。

特效粒子可以从深度缓冲估计与场景表面的相交：把粒子片元投影到屏幕，比较粒子深度和场景深度，再根据法线估计反弹方向。它便宜但只对当前相机可见的表面有效，也不是真正的三维碰撞。

SDF 为每个空间位置提供到表面的有符号距离和梯度，可以在粒子更新时快速判断穿透并得到法线。静态场景适合预计算 SDF，动态场景则需要更新或使用近似。粒子间交互可用邻域网格、空间哈希、近邻搜索、SPH、PBD 或约束模型。

### 4. 连续碰撞与响应

离散检测可能在高速运动时穿过薄物体。连续碰撞检测（CCD）沿运动轨迹测试 swept volume 或求 time of impact，再在接触时刻处理响应。它更可靠但更昂贵，通常只对高速或重要对象开启。

碰撞响应需要法线、接触点、穿透深度、相对速度、摩擦和恢复系数。检测到相交并不等于知道应该如何移动物体；稳定的物理系统还需要迭代求解多个接触约束。

## 讨论与补充

### 既有整理

### 1. 碰撞处理不只是判断是否相交

碰撞处理可以拆成三个部分：

```text
碰撞检测 Collision Detection
    ↓ 是否可能发生碰撞？

碰撞确定 Collision Determination
    ↓ 具体在哪里相交？距离和时间是多少？

碰撞响应 Collision Response
    ↓ 碰撞后如何改变速度、位置或姿态？
```

例如一个球撞墙：

```text
检测：球和墙是否可能相撞？
确定：球什么时候接触墙，接触点和法线是什么？
响应：沿墙面反弹、停止，或者产生摩擦？
```

所以游戏中的碰撞系统通常不只是一个 `bool IsColliding`。

### 2. 为什么不能直接测试所有物体

如果场景中有 `N` 个动态物体，直接两两测试需要：

```text
N × (N - 1) / 2
```

这是平方级增长：

```text
100 个物体   → 4950 对
1000 个物体  → 约 50 万对
10000 个物体 → 约 5000 万对
```

因此碰撞检测的关键不只是让每一次精确相交测试更快，而是：

> 尽可能早地排除绝大多数不可能碰撞的物体对。

### 3. 从粗到细的三阶段

大型碰撞系统通常分为：

```text
Broad Phase 宽阶段
    ↓ 找到可能碰撞的物体对

Mid Phase 中阶段
    ↓ 找到两个物体内部可能重叠的部分

Narrow Phase 窄阶段
    ↓ 对具体几何体执行精确测试
```

#### 宽阶段

宽阶段只使用粗略包围体，例如：

```text
球体、AABB、OBB、胶囊体、BVH 节点、空间网格
```

它要回答的是：

```text
这两个物体有没有可能相撞？
```

宽阶段允许误报，但不能漏报：

```text
包围体重叠，但真实物体不碰撞：可以接受，交给后续阶段
真实物体碰撞，但包围体不重叠：不能接受，因为会漏掉碰撞
```

#### 中阶段

如果两个复杂物体的整体包围体重叠，中阶段会继续检查它们内部的层次结构，例如：

```text
物体 A 的 BVH
    vs
物体 B 的 BVH
```

通过递归比较 BVH 节点，找到真正可能接触的网格块或凸面。

#### 窄阶段

窄阶段才使用较精确的几何算法，例如：

```text
球体-球体
球体-平面
胶囊体-三角形
凸多面体-SAT
凸体-GJK
三角形-三角形
```

可能需要求出：

- 交点；
- 穿透深度；
- 最近点；
- 接触法线；
- 首次碰撞时间。

### 4. BVH 在碰撞检测中的作用

BVH 不只用于光线追踪和渲染剔除，也可以用于碰撞检测：

```text
场景 BVH
├── 物体 A 的 AABB
│   ├── 子网格包围盒
│   └── 三角形包围盒
└── 物体 B 的 AABB
    ├── 子网格包围盒
    └── 三角形包围盒
```

检测时：

```text
根节点不重叠
    → 整棵子树跳过

根节点重叠
    → 继续比较子节点

叶子节点重叠
    → 执行真正的几何相交测试
```

因此，BVH 的作用不是直接判断所有三角形，而是把“不可能碰撞”的大量三角形批量排除掉。

它和其他场景查询的思想相同，只是查询目标不同：

```text
碰撞检测：排除不可能相撞的几何体
渲染剔除：排除不可能可见的几何体
光线追踪：排除不可能被光线击中的几何体
```

### 5. CPU 还是 GPU 做碰撞检测

碰撞检测通常在 CPU 上执行，但并不是固定只能由 CPU 执行。GPU 更适合大量规则、相互独立的测试，例如：

```text
大量粒子
大量 AABB 测试
空间网格查询
布料或流体
GPU 粒子系统
GPU Driven 场景中的批量检测
```

CPU 更适合：

```text
复杂控制逻辑
不规则数据结构
碰撞响应
物理约束求解
对象生命周期管理
```

选择 CPU 或 GPU 时要考虑：

```text
数据是否规则？
并行度是否足够？
结果是否马上要回传 CPU？
后续碰撞响应能否继续留在 GPU？
```

如果 GPU 只负责计算碰撞，随后又把大量结果回读到 CPU，回读和同步成本可能抵消 GPU 的计算收益。

### 本章阶段性总结

```text
碰撞检测：判断是否可能发生碰撞
碰撞确定：求具体接触信息
碰撞响应：决定碰撞后的运动
宽阶段：快速找可能碰撞的物体对
中阶段：继续细分到可能重叠的局部结构
窄阶段：执行精确几何测试
BVH：批量排除不可能碰撞的子树
CPU/GPU：根据规则性、并行度和回读成本选择
```

### 6. 射线碰撞与 BSP 动态碰撞

有些场景不需要完整物体的精确碰撞，只需要知道几个关键位置是否接触环境。例如汽车可以在四个车轮位置各发射一条射线：

```text
距离 = 0：车轮刚好接触地面
距离 > 0：车轮离开地面
距离 < 0：车轮已经穿入地面
```

根据射线距离和表面法线，可以处理贴地、悬挂、车身姿态和简单反弹。它的前提是汽车与环境的主要接触确实发生在车轮处。撞墙、翻滚或驶入隧道时，可能需要其他方向的射线、球体、胶囊体或完整碰撞体。

射线与大量三角形测试时，也需要 BVH、空间网格、八叉树或 BSP 加速。

BSP 的分割平面可以贴合墙、地板和天花板，适合检测角色沿场景移动。一个重要的转换是：

```text
移动球体 vs 障碍物
    ≈
移动点 vs 被球体半径膨胀后的障碍物
```

这就是 Minkowski Sum 的思想。实际游戏中可以使用胶囊体处理角色与墙面的碰撞，再使用射线或球体检测脚下地面和斜坡。

### 7. 限时碰撞检测

实时碰撞检测有固定时间预算。限时检测的目标不是一定遍历完整棵 BVH，而是保证在预算耗尽前返回尽可能有用的结果。

普通查询常使用深度优先遍历，尽快到达某个叶节点；限时查询更适合使用广度优先遍历：

```text
先检查根节点
→ 检查一层子节点
→ 再检查下一层
```

这样即使时间耗尽，也能让场景各个区域都至少经过粗略检查，而不是只把一条路径检查得很深。实现上通常使用队列，也可以按距离、速度、上一帧碰撞状态等设置优先级。

### 8. 可变形模型：Refit 与 Rebuild

刚体只改变旋转和平移，预先建立的 BVH 通常可以继续使用；布料、旗帜和水面会改变顶点位置，包围体也必须更新。

如果网格拓扑不变，可以使用 Refit：

```text
更新叶节点包围盒
→ 合并子节点，更新父节点
→ 一直更新到根节点
```

`AABB Refit` 很快，但变形剧烈时包围盒可能逐渐变松，导致误报变多。`Rebuild` 会重新组织层次结构，质量更好但成本更高。因此实际系统通常是：

```text
每帧 Refit
→ 树质量下降后偶尔 Rebuild
```

### 9. 连续碰撞检测（CCD）

离散检测只检查两个采样时刻，可能出现高速物体穿过薄墙的隧穿现象。CCD 会检查整个运动区间，求首次接触时间。常见方式包括：

```text
Ray Cast：点沿路径移动
Sphere/Capsule/Box Cast：有体积的碰撞体沿路径扫过
Conservative Advancement：根据当前距离和相对速度安全推进，再重复查询
```

CCD 计算更贵，所以通常只给子弹、高速投射物和重要高速物体开启；普通慢速物体仍使用离散检测。

### 10. 碰撞响应

检测到碰撞后，至少需要接触法线、穿透深度和碰撞前速度。把速度分解为：

```text
法线分量：v_n = (v · n)n
切线分量：v_t = v - v_n
```

完全弹性碰撞会反转法线分量、保留切线分量：

```text
v' = v_t - v_n
```

恢复系数 `e` 用于表达能量损失：

```text
v' = v_t - e v_n
```

通常还需要位置修正：

```text
position += normal * (penetrationDepth + skinWidth)
```

速度修正决定下一步运动，位置修正负责把已经穿透的物体推出去。摩擦主要削弱切线速度；多个接触点则通常需要约束和迭代求解器处理。

### 11. 粒子碰撞

#### 特效粒子：深度缓冲

雨滴、火花和碎屑常使用屏幕空间深度碰撞：

```text
预测粒子下一位置
→ 投影到碰撞摄像机的 UV
→ 采样 Scene Depth
→ 比较粒子深度和场景深度
→ 读取深度法线或重建法线
→ 修正位置和速度
```

它只知道摄像机看到的最前表面，因此便宜但不精确：屏幕外、被遮挡和不可见背面的几何体通常不会参与碰撞。它适合只影响画面的粒子，不适合重要游戏逻辑。

#### SDF 碰撞

SDF 通常预先烘焙成 3D Texture，每个体素保存到最近表面的有符号距离：

```text
外部：正值
表面：0
内部：负值
```

运行时粒子采样 SDF；当 `distance < particleRadius` 时，表示粒子接近或进入表面。SDF 梯度还可以提供近似碰撞法线。静态全局 SDF 或单个物体 SDF 都很常见；动态变形物体则需要更新或重建 SDF。

#### 粒子之间的相互作用

除了限制邻域和空间加速，还需要定义交互模型：

```text
排斥/分离：防止粒子重叠
弹簧和距离约束：布料、绳索、软体
SPH：根据密度、压力和黏性模拟流体
PBD：直接迭代修正位置约束
粒子-网格耦合：粒子写入网格场，再从网格采样结果
```

粒子-网格方法可以避免大量粒子两两交互，更适合规则的 GPU 计算，但需要额外的网格存储和粒子/网格数据交换。

#### GPU 粒子与 CPU 粒子

```text
GPU 粒子：数量大、可直接与 GPU 渲染连接、减少上传
CPU 粒子：逻辑灵活、易调试、方便影响游戏状态
```

GPU 粒子的限制包括不规则邻域访问、分支发散、调试困难，以及结果回读 CPU 带来的同步和延迟。因此常见方案是 GPU 负责大量视觉粒子，CPU 只处理少量重要碰撞事件和游戏逻辑。

### 12. 动态相交测试

动态相交测试把两个运动物体转换为一个相对运动物体：

```text
vRelative = vA - vB
```

球体-平面可以根据球心到平面的有符号距离，求球心到达“距离等于半径”的时间；球体-球体可以把两个球的半径相加，再转换为相对运动的点与静止球相交，最后求一元二次方程的最早有效根。

球体-多边形则把运动球体缩成点，把多边形膨胀：

```text
面 → 加厚的面
边 → 圆柱体
顶点 → 球体
```

再测试运动点与膨胀后形状的相交。

动态 SAT 追踪投影区间在时间上的运动。每条轴都会得到一个有效时间区间：

```text
tEnter = 所有轴开始重叠时间的最大值
tExit  = 所有轴停止重叠时间的最小值
```

如果 `tEnter <= tExit`，说明所有轴存在共同重叠时间，两个动态凸体会碰撞。这和射线-AABB 的区间测试很相似。

### 本章最终总结

```text
碰撞检测：判断是否可能发生碰撞
碰撞确定：求接触点、距离、法线和穿透
碰撞响应：修正位置、速度和约束
SAP/网格/BVH：宽阶段筛选候选
BVH/OBB Tree：中阶段细分局部几何
SAT/GJK：窄阶段凸体测试和距离查询
CCD/动态相交：处理运动过程中的碰撞
深度/SDF：粒子碰撞的近似或世界空间表示
GPU 粒子：适合大规模视觉模拟，但回读 CPU 代价高
```
