# 图形渲染管线

## 章节内容

本章介绍实时渲染的基本图形管线：场景数据从应用阶段开始，经过几何处理、光栅化和像素处理，最终写入帧缓冲并显示在屏幕上。章节重点是各阶段的功能和数据流，而不是某个具体 API 或硬件的固定实现。

### 1. 管线架构

渲染管线由多个阶段组成，每个阶段负责总任务的一部分，并把结果传递给下一个阶段。不同阶段可以同时处理不同的数据，因此流水线能够提高整体吞吐量。

不过，管线速度通常受最慢阶段限制。某个阶段耗时较高时，它就会成为瓶颈，其他阶段可能出现等待或空闲。

书中区分了两种概念：

- 功能性阶段：规定需要完成什么任务；
- 实现结构：规定由哪些硬件或程序完成这些任务。

同一个功能性阶段可能由多个硬件单元完成，也可能和其他阶段合并；一个复杂阶段也可能被拆分成多个子阶段。因此，以下四阶段是功能上的概括，并不表示现代 GPU 内部必然存在四个完全独立的模块。

### 2. 四个主要阶段

```text
应用阶段
    ↓
几何处理阶段
    ↓
光栅化阶段
    ↓
像素处理阶段
    ↓
帧缓冲与显示
```

#### 2.1 应用阶段

应用阶段通常运行在 CPU 上，由应用程序驱动。它负责处理输入、更新场景，并准备传给后续阶段的渲染图元。

常见工作包括：

- 键盘、鼠标、手柄和 VR 设备输入；
- 相机位置、方向和动画更新；
- 动画、物理模拟和碰撞检测；
- 全局加速算法和剔除；
- 场景、材质、灯光和网格数据准备；
- 决定哪些点、线和三角形需要提交给后续阶段。

应用阶段通常可以利用 CPU 多核心并行执行。它也不是只能使用 CPU：计算着色器可以把部分应用阶段任务交给 GPU，使 GPU 作为高度并行的通用处理器使用。

#### 2.2 几何处理阶段

几何处理阶段主要执行逐顶点和逐三角形操作，可以进一步划分为：

```text
顶点着色
    ↓
可选的曲面细分、几何着色、流式输出
    ↓
投影
    ↓
裁剪
    ↓
屏幕映射
```

顶点通常要经过以下坐标空间：

```text
模型空间
    ↓ 模型变换
世界空间
    ↓ 观察变换
观察空间 / 相机空间
    ↓ 投影变换
裁剪空间
    ↓ 透视除法
标准化设备坐标 NDC
    ↓ 屏幕映射
窗口坐标
```

顶点着色器主要负责计算顶点位置，以及法线、颜色、纹理坐标等供后续阶段使用的数据。模型变换决定物体的位置、方向和缩放；多个实例可以共享同一份网格，但使用不同的模型变换。观察变换会将相机移到原点，并调整坐标系方向，使投影和裁剪更容易执行。

投影分为正交投影和透视投影：

- 正交投影的可视空间通常是长方体，平行线投影后仍然平行，远近不会改变物体的投影大小；
- 透视投影的可视空间是视锥体，距离相机越远的物体投影越小，平行线可能在远处汇聚。

投影矩阵会把可视空间变换为标准立方体。投影后的顶点位于裁剪空间中，仍然是齐次坐标；随后通过透视除法得到 NDC：

```text
x_ndc = x_clip / w_clip
y_ndc = y_clip / w_clip
z_ndc = z_clip / w_clip
```

顶点处理后还可以选择使用三个阶段：

- 曲面细分：根据距离等因素生成合适数量的三角形，通常包含壳着色器、曲面细分器和域着色器；
- 几何着色：读取图元并生成新的顶点和图元，例如把粒子点扩展为始终朝向相机的四边形；
- 流式输出：将 GPU 处理后的几何数据写入缓冲区，供 CPU 或 GPU 后续阶段使用，常用于粒子模拟。

裁剪阶段会处理视锥体或标准立方体之外的图元：

- 完全在内部：直接保留；
- 完全在外部：直接丢弃；
- 与边界相交：计算交点，生成新的顶点和图元。

除了视锥体的裁剪平面，程序还可以定义额外裁剪平面，用于切片等效果。

屏幕映射会把 NDC 转换为窗口坐标和屏幕坐标。不同图形 API 对坐标原点和深度范围的约定可能不同，例如 OpenGL 和 DirectX 在屏幕原点、NDC 深度范围等方面存在差异。像素中心通常位于整数坐标加 `0.5` 的位置。

#### 2.3 光栅化阶段

光栅化负责找出图元覆盖的像素或采样点，并把顶点数据插值到这些位置。它可以分为：

```text
三角形设置 / 图元装配
    ↓
三角形遍历
```

三角形设置阶段会计算边界方程、三角形微分、深度插值数据和属性插值数据。三角形遍历阶段会检查采样点是否位于三角形内部，并为覆盖的采样点生成片元。

常见覆盖判断方式包括：

- 像素中心采样；
- 超采样；
- 多重采样抗锯齿；
- 保守光栅化。

生成的片元包含插值后的深度、颜色、法线、纹理坐标以及其他顶点着色器输出的数据。光栅化还需要进行透视正确的属性插值。

#### 2.4 像素处理阶段

像素处理阶段可以分为像素着色和合并：

```text
像素着色
    ↓
合并 / ROP
```

像素着色器使用光栅化阶段插值后的数据，执行纹理采样、光照、材质和其他逐像素计算，并输出一个或多个颜色值。

合并阶段负责将当前片元与已有缓冲区内容组合起来。它通常由 ROP，也就是 Raster Operations Pipeline 或 Render Output Unit，完成。ROP 不是完全可编程的，但可以通过图形 API 配置。

合并阶段通常涉及：

- 深度测试和深度写入；
- 模板测试和模板写入；
- 颜色写入；
- Alpha 测试或片元丢弃；
- 颜色混合；
- 多渲染目标写入。

深度缓冲通常与颜色缓冲具有相同的屏幕尺寸，每个像素保存当前最近的深度：

```text
新片元深度更近
    → 更新颜色缓冲和深度缓冲

新片元深度更远
    → 丢弃或不更新
```

普通深度缓冲每个像素只保存一个深度值，因此透明物体不能直接依靠它正确处理。透明物体通常需要先绘制不透明物体，再将透明物体从后往前排序绘制，或者使用 OIT 等顺序无关透明技术。

Alpha 通道可以保存不透明度，也可以参与 Alpha Clip。像素着色器可以根据任意条件丢弃片元，被丢弃的片元不应影响颜色缓冲和深度缓冲。

模板缓冲可以记录某些位置是否允许后续绘制。例如先将一个区域写入模板缓冲，再限制后续图元只能在该区域内更新颜色缓冲。

颜色、深度、模板等缓冲区合在一起称为帧缓冲。为了避免用户看到正在绘制的中间结果，通常使用双缓冲：GPU 在后置缓冲中绘制，完成后再与正在显示的前置缓冲交换。

### 3. 完整管线示例

以一个交互式 CAD 模型为例：

1. 应用阶段接收鼠标输入，根据鼠标移动更新模型盖子的旋转矩阵，并更新相机动画、相机参数、灯光和模型图元。
2. 几何处理阶段使用模型、观察和投影矩阵变换顶点和法线，执行顶点数据计算、投影、裁剪和屏幕映射。
3. 光栅化阶段找出线段和三角形覆盖的像素，对顶点属性进行插值并生成片元。
4. 像素处理阶段采样模型纹理，计算片元颜色，执行深度和模板测试，并把结果写入颜色缓冲。

### 4. 本章结论

本章介绍的是实时渲染中最常见的一套管线，但它不是唯一可能的管线。离线渲染也有自己的发展路径，电影渲染曾经大量使用微多边形，后来逐渐转向光线追踪和路径追踪。

实时渲染也经历了从固定功能管线到可编程 GPU 的发展。本书后续内容默认使用可编程 GPU，但光栅化、深度测试、纹理采样、ROP 和帧缓冲等功能仍然通常由专用硬件或高度配置化的硬件完成。

## 讨论与补充

### 1. CPU、GPU 与数据同步

CPU 和 GPU 可以并行工作：

```text
CPU 准备第 N+1 帧
GPU 渲染第 N 帧
```

常见性能问题不是“CPU 或 GPU 不能工作”，而是二者之间出现了不必要的等待或数据传输：

- CPU 等待 GPU 完成；
- GPU 等待 CPU 提供数据；
- GPU 结果同步读回 CPU；
- CPU 和 GPU 之间传输大量数据。

较差的方式通常是阻塞等待或反复轮询；更常见的优化方向是使用异步计算、fence、环形缓冲和多帧并行，尽量避免 CPU 立即等待 GPU 的结果。

### 2. CPU 与 GPU 的职责

传统实时渲染中，CPU 通常负责：

- 游戏脚本和逻辑；
- 用户输入；
- 资源管理；
- 动画、物理和碰撞检测；
- 场景更新；
- 数据准备和绘制命令提交。

GPU 通常负责：

- 顶点、像素和其他 Shader 计算；
- 纹理采样；
- 光栅化相关操作；
- 深度、模板和混合等绘制阶段操作；
- Compute Shader。

这不是固定的硬件分工。Compute Shader 可以承担剔除、粒子、物理或动画等任务；GPU Driven 也可以把原本由 CPU 完成的绘制决策转移到 GPU。

### 3. Dispatch 与 GPU Driven

`Dispatch` 是启动 Compute Shader 的命令：

```text
Dispatch
    ↓
Compute Shader 执行大量并行线程
```

它本身不等于 GPU Driven。GPU Driven 通常还包括：

- GPU 进行视锥体或遮挡剔除；
- GPU 选择 LOD；
- GPU 生成可见实例列表；
- GPU 填写 Indirect Draw 参数；
- GPU 继续执行间接绘制。

GPU Driven 也可以和实例化结合使用。

### 4. 区分三种数量

需要区分：

```text
CPU 发起的绘制 API 调用数
GPU 实际执行的逻辑绘制命令数
实际绘制的物体或实例数
```

传统直接绘制中，它们可能比较接近；使用实例化或 Indirect Draw 后，它们可能完全不同。

例如：

```text
CPU：调用一次 DrawIndexedInstanced
GPU：执行一次实例化绘制命令
实际绘制：1000 个实例
```

GPU Driven 中还可能出现：

```text
CPU：调用一次 ExecuteIndirect
GPU：执行多条间接绘制记录
```

因此“减少 Draw Call”通常首先指减少 CPU 发起的绘制提交，并不一定代表 GPU 的实际绘制工作量也按同样比例减少。

### 5. 数据组织与批量绘制

#### 5.1 绘制命令需要哪些信息

一次绘制通常需要确定：

- 使用的 Shader 和 Pipeline State；
- 材质参数和纹理资源；
- Vertex Buffer 和 Index Buffer；
- 顶点或索引数量；
- 绘制范围和实例数量；
- 深度、模板和混合状态。

如果对象使用相同的 Shader Variant、Pipeline State 和兼容的资源访问方式，可以把材质参数放进 Material Buffer，并通过 MaterialID 访问不同材质。

但仅仅把数据放进 Buffer，并不会自动把任意 Mesh 变成一次普通 Draw。不同 Mesh 通常还需要共享几何 Buffer、Mesh Table、Instancing、Multi-Draw Indirect 或 ExecuteIndirect 等机制。

如果 Shader Variant、混合状态或深度状态不同，通常需要拆分绘制批次。

#### 5.2 GPU Driven 的典型数据结构

```text
Instance Buffer
    ├─ Transform / TRS
    ├─ MaterialID
    ├─ MeshID
    └─ 其他实例参数

Material Buffer
    ├─ 材质数值参数
    ├─ BaseColorTextureID
    ├─ NormalTextureID
    └─ 其他纹理索引

几何资源
    ├─ Mega Vertex Buffer
    ├─ Mega Index Buffer
    └─ Mesh Table

Indirect Argument Buffer
    ├─ indexCount
    ├─ instanceCount
    ├─ firstIndex
    └─ baseVertex
```

这里不存在一个固定的“Mesh Buffer”类型。通常是：

- Vertex Buffer 和 Index Buffer 保存实际几何数据；
- Mesh Table 保存每个 Mesh 的数据范围、索引偏移、顶点偏移、包围盒和 LOD 信息；
- Instance Buffer 保存每个实例的变换、MeshID 和 MaterialID。

纹理本身通常使用 Texture Array、Texture Atlas 或 Bindless Texture Table 管理，而不是放进普通数值 Buffer。

#### 5.3 CBuffer 的布局

CBuffer 主要保存 float、int、向量、矩阵、数组和结构体等常量数据，不能直接保存 `Texture2D`、`SamplerState` 或 `StructuredBuffer` 这类资源对象。

GPU 通常以 16 字节的寄存器组织 CBuffer 数据，因此应注意字段的 packing 和对齐。推荐使用 `float4`、`uint4` 等明确组织数据，但并不是每个字段都必须单独占用 16 字节。

如果 CPU 侧和 Shader 侧对字段偏移的理解不同，可能出现颜色、矩阵、材质参数或纹理 ID 错乱，而且问题可能只在某些平台出现。

### 6. 透明渲染

#### 6.1 Z-Buffer 与透明物体

普通 Z-Buffer 通常为每个屏幕像素保存一个深度值，因此它适合解决不透明物体的可见性问题。

透明物体需要组合多个前后表面，通常不能只依赖单层 Z-Buffer。传统 Alpha Blend 的常见处理是：

```text
不透明物体：先绘制，开启深度写入
透明物体：后绘制，开启深度测试，关闭深度写入
透明物体之间：通常从后往前排序
```

这种方法会受到物体相交、物体内部排序、CPU 排序成本和 Overdraw 的影响。

常见替代方案包括：

- Alpha Clip：不进行半透明混合，直接保留或丢弃 fragment；
- Depth Peeling：逐层提取透明表面；
- Per-Pixel Linked List / A-Buffer：保存每个像素的多个 fragment 信息；
- Weighted Blended OIT：使用加权累积近似透明合成。

保存透明 fragment 不只是保存深度，通常还要保存颜色、Alpha、深度以及必要的其他属性。
