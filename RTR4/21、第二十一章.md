# 虚拟现实与增强现实

## 本章核心

VR/AR 的渲染目标不只是“画面正确”，还必须让画面与用户的头部运动、双眼视觉和现实环境保持一致。最重要的约束是：

- 动显延迟（motion-to-photon latency）要低；
- 左右眼必须得到符合各自视点的图像；
- 光学系统造成的畸变必须被校正；
- 渲染不能因为掉帧、抖动或错误的深度暗示而破坏舒适度；
- 在有限的移动 GPU 功耗和带宽下维持较高刷新率。

## 1. VR、AR、MR 与设备类型

- VR：主要用虚拟内容取代现实视野。
- AR：在现实视野上叠加数字内容。
- MR：现实环境与虚拟内容可以进行更深入的三维融合和交互，例如真实墙壁遮挡虚拟物体，虚拟物体落在真实桌面上。

设备可以按连接方式和显示方式理解：

| 类型 | 特点 |
|---|---|
| 独立头显 | CPU、GPU、传感器和显示设备都在头显内，移动性好，但性能和功耗受限 |
| PC 系留头显 | 由 PC 完成主要渲染，头显负责显示、追踪和输入，画质上限高，但有连接和延迟问题 |
| Video See-Through | 摄像头拍摄现实世界，经过处理后与虚拟内容合成，再显示给用户；可控性好，但会引入摄像头和处理延迟 |
| Optical See-Through | 通过透明光学元件直接看到现实世界，再把虚拟内容叠加上去；现实画面没有摄像头延迟，但遮挡和变暗能力较弱 |

“VR/AR 硬件属于安卓还是苹果”并不是对硬件的分类。更准确的划分是：硬件设备、SoC/GPU、操作系统、XR Runtime 和 SDK 的组合。

- Meta Quest 等独立头显通常使用移动 SoC 和定制系统，不等于普通安卓手机。
- Android XR 属于 Android 家族的 XR 平台，但有专门的空间、追踪和输入 API。
- Apple Vision Pro 使用 Apple 芯片和 visionOS，不是简单地把 iOS 搬到头显上。
- PC VR 头显更像 PC 的显示和追踪外设，主要由 PC 上的 SteamVR、OpenXR 或厂商 Runtime 驱动。

当前比较稳定的是 Unity/Unreal/OpenXR 等开发基础；硬件能力、输入方式、商店和设备特性仍然存在较大差异。因此，VR/AR 已经有稳定的开发生态，但还没有像 Android 或 iOS 那样统一的消费生态。

## 2. 动显延迟与帧时间

动显延迟指从用户开始移动头部，到显示出与新头部姿态匹配的图像之间的时间：

```text
头部运动
  ↓
传感器读取与姿态估计
  ↓
姿态预测
  ↓
CPU 准备与 GPU 渲染
  ↓
合成器、畸变校正和显示扫描
  ↓
眼睛看到图像
```

VR 中的延迟比普通显示器更敏感。因为用户的前庭系统已经感知到头部运动，但眼睛看到的画面如果没有及时跟上，就会产生视觉与身体感知的不一致，引起漂浮感、眩晕或模拟病。

90 FPS 只表示每帧的时间预算约为：

```text
1 / 90 ≈ 11.1 ms
```

它不等于完整的动显延迟。CPU、GPU、合成器、显示器和传输过程可能重叠执行，但每一环都会影响最终延迟。

## 3. 为什么左右眼需要不同的图像

现实中两只眼睛看到的画面确实不同，但不是两张完全无关的图像。由于左右眼的位置不同，它们看到的是同一场景的两个略有差异的透视投影：

- 左眼更容易看到物体的左侧；
- 右眼更容易看到物体的右侧；
- 近处物体的视差明显，远处物体的视差较小。

大脑会融合这两幅图像，通过双目视差感知深度，这种深度感知称为立体视觉（stereopsis）。因此 VR 要为每只眼睛使用不同的相机位置和投影矩阵：

```text
左眼视点 + 左眼投影 → 左眼图像
右眼视点 + 右眼投影 → 右眼图像
                         ↓
                    大脑融合出深度
```

两眼之间的距离称为瞳孔间距（IPD）。如果 IPD 或左右眼相机设置不正确，物体的深度和大小会不自然，也容易引起眼睛疲劳。

如果给两只眼睛完全相同的画面，仍然可以依靠透视、遮挡、阴影、纹理密度和运动视差产生一些深度感，但缺少正确的双目视差，立体感会明显减弱。

### 会聚-调焦冲突

现实中，眼睛看不同距离的物体时会同时改变：

- 会聚（vergence）：两眼转动，使视线交汇到目标；
- 调焦（accommodation）：晶状体改变形状，使目标清晰。

传统头显可以通过左右眼图像让眼睛产生不同的会聚需求，但显示面和光学系统的调焦距离通常比较固定。于是眼睛可能需要“看起来聚焦在远处”，但实际仍然对焦在较近的显示面上，这就是会聚-调焦冲突。变焦显示器等技术试图缓解这个问题。

## 4. XR 的一帧如何显示

典型流程可以简化为：

```text
预测下一次显示时刻
  ↓
查询每只眼睛的预测位姿和投影参数
  ↓
渲染左右眼视图
  ↓
提交给 XR Compositor
  ↓
合成图层、执行畸变和色差校正
  ↓
输出到头显显示器
```

应该优先使用平台提供的 SDK、Runtime 和 Compositor。畸变校正、色差校正、显示时序和最终姿态处理属于系统级工作，自己重写很容易出现画面不稳定、视野错误或明显不适。

### 光学畸变

头显镜片通常会造成枕形畸变，因此渲染图像会预先施加相反方向的桶形畸变，使图像经过镜片后恢复正常。

如果直接对每个屏幕像素计算畸变方程，成本可能较高。实践中常将图像作为纹理映射到经过预扭曲的网格上，再进行一次绘制。

### Hidden Area Mesh

经过镜片和视野裁剪后，渲染目标的部分角落实际上不会被用户看到。可以使用 Hidden Area Mesh 或模板/深度遮罩，提前丢弃这些区域的片元，从而降低像素着色和填充率压力。

## 5. 双眼渲染优化

左右眼必须产生两张不同的最终图像，但不代表所有工作都必须完全重复。

- Single-Pass Instanced：一次提交中处理两个眼睛的实例。
- Multiview：让 GPU 在一次渲染流程中生成多个视图。
- 共享场景数据：左右眼可以共享网格、材质、光源列表和部分计算结果。
- 眼睛远处的物体可以降低立体视差相关的计算精度。

这些方法可以减少 Draw 提交、顶点处理和部分管线开销，但最终的片元结果仍然通常需要分别生成，不能把左右眼完全合并成一张图。

## 6. 注视点与分辨率优化

用户中央视野的分辨率和清晰度要求最高，外围区域的感知能力较弱，因此可以降低外围区域的渲染成本。

- 固定注视点渲染：假设用户始终注视屏幕中心。
- 眼动注视点渲染：根据眼动追踪，把高分辨率区域放在用户当前注视点。
- 多分辨率着色：中心区域使用较高分辨率，外围区域使用较低分辨率。
- Lens-Matched Shading：让渲染分辨率更贴合镜片和显示区域的实际映射。
- 动态分辨率：GPU 超出预算时降低渲染分辨率，优先保证稳定帧率。

注视点渲染不仅是“把画面缩小”，而是根据人眼感知和光学映射重新分配像素预算。外围降分辨率、后处理和泛光等效果可能需要重新设计，否则会出现边缘断层或不连续。

## 7. 硬件 TBDR 与 XR 渲染

TBDR 是 GPU 的硬件架构，不是 VR 专属技术。许多移动 GPU 会把屏幕划分成 Tile，并尽量在片上 Tile Memory 中完成可见性、片元处理和混合，以减少外部内存读写。

```text
几何分配到 Tile
  ↓
Tile 内完成可见性和片元处理
  ↓
结果保留在片上 Tile Memory
  ↓
必要时 Store/Resolve 到系统内存
```

它与软件上的 Tiled/Clustered Shading 要区分：

- 硬件 TBDR：GPU 如何组织光栅化和片上数据；
- 软件 Tiled Shading：按屏幕 Tile 建立光源列表；
- 软件 Clustered Shading：按屏幕 X/Y 和深度 Z 建立三维光源列表。

VR/AR 设备特别重视这些优化，因为它们往往同时面临高分辨率、高刷新率、双眼渲染、移动功耗和有限内存带宽。

但硬件 TBDR 不代表应该无条件使用传统 G-Buffer 延迟渲染。移动 XR 中，大量 G-Buffer 写入外部内存仍可能造成带宽压力，因此常见方案包括 Forward、Forward+、Tiled Forward、Clustered Shading、片上 Tile 数据复用、动态分辨率和纹理压缩。

## 8. VR/AR 中需要谨慎的图形效果

一些在普通屏幕上没有明显问题的技术，在 VR 中可能破坏稳定的双眼视觉：

- 普通屏幕空间 TAA 的历史帧重投影可能与左右眼视差不匹配；
- 过强的运动模糊会让头部转动时画面拖影；
- 景深的焦点变化可能与真实调焦不一致；
- 大型屏幕空间法线/凹凸效果在近距离立体观察时容易穿帮；
- 频闪、高频纹理和画面抖动可能引起不适；
- HUD 如果没有正确处理双眼深度，会产生冲突。

VR 中通常更重视清晰、稳定、低延迟的图像。MSAA、合理的几何细节和平台提供的重投影机制，很多时候比直接套用普通屏幕上的后处理更可靠。

## 9. Timewarp、Spacewarp 与重新投影

如果完整场景渲染没有及时完成，系统可能暂时重复上一帧，产生抖动或卡顿。为了减轻头部旋转带来的错误，可以在接近显示时使用更新后的姿态对已经渲染好的图像进行扭曲，这就是 Timewarp 一类技术。

它可以有效修正部分相机旋转误差，但不能真正重建场景中物体因为平移、动画或遮挡变化而产生的新内容。

更进一步的 Spacewarp/重投影会结合运动向量、深度等信息生成中间帧，但它仍然是估计结果，可能产生边缘撕裂、遮挡错误或物体变形。因此它主要用于提高感知稳定性和降低延迟，不能完全替代稳定的原生渲染帧率。

## 本章总结

```text
VR/AR 渲染
  ├─ 低动显延迟：姿态预测、晚锁定、Timewarp
  ├─ 双眼正确视图：IPD、左右眼相机和投影
  ├─ 显示适配：畸变、色差、合成器
  ├─ 像素优化：Hidden Area Mesh、注视点、动态分辨率
  ├─ 移动 GPU：TBDR、Tile Memory、带宽优化
  └─ 视觉舒适：稳定帧率、谨慎使用 TAA、运动模糊和景深
```

最重要的理解是：VR/AR 的性能优化不能只看“每帧画面是否算出来”，还要看这幅画面是否在正确的时间、以正确的姿态、通过正确的光学映射到达每只眼睛。
