# 多边形技术

## 章节内容

三角形是 GPU 最基础、最容易高效光栅化的表面图元，但实际输入的模型通常来自 CAD、DCC、摄影测量、扫描、程序化建模或其他数据转换流程，并不一定适合直接渲染。本章讨论如何把不规则的多边形数据转换为可靠的三角形网格，再通过整合、排序、简化、LOD 和压缩降低渲染成本。

### 1. 多边形数据的来源与目标

模型可能来自：直接编写的几何文件、程序化建模、DCC 建模和雕刻、摄影测量、三维扫描、医学扫描等值面，或者这些方法的组合。不同来源的数据有不同的拓扑、精度和属性，格式转换也不一定无损。

实体建模系统通常用内部的实体和边界表示物体，再由 faceter 将其转换为三角形或四边形。用于有限元分析的 faceter 可能追求面积均匀，用于 3D 打印的 faceter 可能更关注实体闭合，这些结果不一定适合实时渲染。Blender、Maya 等表面建模工具则直接编辑表面网格，也可能使用样条或细分曲面作为内部表示。

本章中的几个术语分别对应不同目标：

- **三角化 / 细分**：把多边形转换成三角形或其他易处理图元；
- **整合**：合并顶点和面，建立邻接关系，并生成法线等派生数据；
- **优化**：重新排列顶点和索引，改善缓存命中和渲染效率；
- **简化**：删除视觉上不重要的几何特征；
- **压缩**：减少模型存储、传输和显存占用。

目标不是盲目减少数据，而是在视觉精度、渲染速度、内存、带宽和加载时间之间平衡。

### 2. 曲面细分与三角化

图形 API 和硬件通常针对三角形做了特殊优化，因此复杂多边形最终需要三角化。三角化的目标可能是：得到普通三角形、先分割为凸多边形、满足最大面积或最小角度限制，或者为后续光照、碰撞和数据采样提供合适的顶点密度。

#### 平面性与投影

多数三角化算法假设多边形处于同一平面，但输入可能包含扭曲的非平面四边形，形成 hourglass 或 bowtie 形状。一个快速修复方法是把顶点投影到由近似法线定义的平面。近似法线可以用 Newell 公式，通过多边形在三个坐标平面上的投影面积计算。

投影后仍可能发生自相交，这时需要更健壮但更昂贵的算法。直接检查任意两点连线是否穿过多边形边可以解决简单情况；耳切法则不断寻找由连续三个顶点组成、内部不包含其他顶点且不与边相交的“耳朵”，移除后递归处理剩余多边形。

#### 凹多边形、孔洞与模板缓冲

凸多边形可以高效地表示为三角扇或三角带。某些凹多边形也可以使用三角扇，但需要先判断其是否为星形。多个轮廓或带孔洞的多边形需要把各个环连接起来，或使用更复杂的三角化算法。

另一种技巧是直接让 GPU 参与填充：用三角扇把多边形绘制到模板缓冲，以奇偶规则记录某个像素被覆盖的次数。奇数次表示在区域内，偶数次表示在外部或孔洞中；第二个 pass 再只绘制模板标记的区域。这个方法可以处理多轮廓多边形，但需要多个 pass、清空模板缓冲，而且不适合直接使用深度缓冲。

#### 四边形的对角线

凸四边形通常有两种三角化方式。选择对角线时，应该尽量减少新边两侧顶点属性的差异：没有附加属性时可以优先选择较短的对角线；如果顶点上有烘焙颜色、光照或其他数据，则可以选择插值差异较小的对角线。

三角形只能在内部建立仿射插值，无法完整表示任意四边形上的透视扭曲。弯曲四边形上的纹理可能因此发生变形。可选方案包括预先扭曲纹理、增加表面细分、运行时投影纹理、双线性映射或使用更高阶曲面表示。简单增加三角形数量只能缓解而不能从根本上消除不匹配。

### 3. 网格裂缝、T 顶点与退化三角形

相邻网格或曲面在共享边界上没有使用相同的边界顶点时，会出现裂缝。曲面细分中，这个问题称为边缘缝合：两侧必须生成位置一致、顺序一致的边界顶点。

平面网格中还可能出现 T 顶点，即一个网格的边界顶点落在另一条边的中间，但没有被另一侧的拓扑共享。即使理论位置相同，有限精度也可能造成裂缝或着色不连续。解决方法是把 T 顶点加入相邻面并重新三角化，或直接重新划分过长、过瘦的三角形。

三角形有两个顶点重合、三个顶点共线或面积接近零时，就是退化三角形。它可能浪费顶点处理和光栅化工作，还会导致法线、插值和碰撞结果异常，应在整合阶段检测并删除或修复。

### 4. 网格整合

#### 顶点合并与索引网格

原始数据常是 polygon soup 或 triangle soup：每个多边形都独立保存自己的顶点。这会浪费存储，并导致顶点着色器重复处理。整合后，网格通常由顶点数组和索引列表组成：

```text
Vertex Buffer：位置、法线、UV、切线、颜色等
Index Buffer：每个三角形引用的顶点索引
```

共享顶点能减少存储和顶点变换次数，但只有完整顶点属性都相同时才能真正共享。如果位置相同但 UV、法线、切线或材质数据不同，就必须拆成多个顶点。这也是硬边、UV 接缝和材质边界会增加顶点数的原因。

#### 定向与半边结构

三角形顶点顺序决定法线方向。可以用边哈希或半边结构找出相邻面，再检查共享边的遍历方向：如果两个面沿共享边使用了相同方向，就需要翻转其中一个面。遍历整个连通区域后，可以保证网格内部朝向一致。

一致朝向不代表一定朝向物体外部，还可以计算封闭网格的带符号体积，判断是否需要把所有面和法线整体翻转。正确朝向对于背面剔除、折痕检测、碰撞检测、碰撞响应和阴影体都很重要。

如果每条边恰好被两个面共享，并且没有多余边界、非流形连接或拓扑冲突，网格可以近似视为封闭、水密的实体。实体性也是 3D 打印、背面剔除和许多几何算法的前提。

#### 法线与平滑组

网格建立邻接关系后，可以根据平滑组或折痕角生成顶点法线。两个相邻面的二面角小于设定阈值时，可以放入同一平滑组；超过阈值则保留硬边。常见折痕角范围大约是 20–50 度，但实际由模型和风格决定。

直接平均相邻面的法线可能受三角化方式影响：一个四边形拆成两个三角形后，这两个三角形可能被错误地计算成双倍权重。按面在顶点处形成的角度进行加权，通常比简单平均更稳定，也不依赖面被拆成多少三角形。需要注意圆锥顶点等奇点，它们可能需要多个不同法线才能正确表现。

### 5. 三角扇、三角带与网格布局

三角形列表最简单，但每个三角形都独立发送三个顶点，顶点重复最多。三角扇共享一个中心顶点和前一个边，后续三角形只需要继续提供一个新顶点，因此适合凸多边形和某些扇形区域。

三角带让后续三角形复用前一个三角形的两个顶点，每增加一个三角形通常只需要增加一个顶点。由于相邻三角形的绕序会交替变化，需要交换顶点顺序来维持一致的正反面。复杂网格通常需要使用退化三角形或重新开始标记连接多个条带。

现代 GPU 通常会使用后变换顶点缓存。即使不手动组织为三角带，只要索引顺序合理，也可以复用已经处理过的顶点。网格优化器会重新排列三角形和顶点，使局部索引访问尽量符合缓存大小，从而降低顶点着色器实际执行次数。这个过程不减少三角形数量，却可能显著改善性能。

### 6. 网格优化与存储布局

优化可以从多个层面进行：

- 删除重复、孤立和退化顶点、边、面；
- 只保留实际需要的顶点属性；
- 合并共享顶点，减少顶点缓冲大小；
- 重新排列三角形和索引，提高顶点缓存命中率；
- 将材质、渲染状态和空间上相近的部分组织成更适合批处理的网格；
- 让顶点格式与 GPU cache line 对齐，减少无效读取。

顶点共享并不总是越多越好。如果共享会破坏硬边、UV 接缝或材质边界，就必须拆分。网格拆分还应考虑剔除粒度、材质切换、实例化、阴影和流式加载之间的权衡。

### 7. 网格简化与 LOD

网格简化是在尽量保持视觉特征的前提下减少三角形。主要类型包括：

- **静态简化**：离线生成多个离散 LOD，运行时按距离或屏幕占比选择；
- **动态简化**：运行时连续改变三角形数量，即 CLOD；
- **视图相关简化**：不同区域根据相机距离和重要性使用不同密度，地形最常见。

最常见的局部操作是边坍缩：把一条边的两个顶点合并为一个，删除相关三角形，并更新邻接关系。坍缩操作通常按局部代价排序，只重新计算受影响邻域的候选边，因此可以用堆或优先队列高效执行。

简化必须避免法线翻转、面交叉、轮廓破坏和拓扑崩坏，并尽量保护：

- silhouette 和边界边缘；
- 硬边和折痕；
- 材质变化与纹理接缝；
- 逐顶点颜色、烘焙光照和重要接触关系；
- 体积、对称性和动画骨骼附近的结构。

二次误差度量（QEM）是常用的通用代价函数。它把顶点移动后到相邻原始平面的距离平方和作为代价，并可加入额外平面或权重来保护尖锐边缘、材质边界和轮廓。地形等特殊数据有时更适合使用 Hausdorff 距离。

纹理是简化中的难点：边坍缩会改变 UV 到表面的映射，造成纹理拉伸、接缝偏移和材质边界错误。需要对 UV 误差加入代价约束，或在简化后重新烘焙纹理。顶点聚类是更快但更粗糙的方案：把模型放入三维网格，将同一单元内的顶点合并。它速度快、健壮，但容易损失轮廓和细节。

复杂模型的细节也可以烘焙到法线贴图或其他纹理中，让低模承担大部分几何形状，小按钮、皱纹和微小凹凸转为纹理表示。LOD 切换会产生 popping；地貌（geomorph）可以在两个 LOD 之间平滑插值。渐进式网格还可以记录坍缩顺序，从低模逐步恢复高模，并支持渐进传输。

### 8. 压缩与精度

压缩的目标是减少磁盘、显存、网络传输和总线带宽，但解码也有成本。只有节省的 I/O 和带宽大于解压成本时，压缩才真正有利。

连接关系可以使用 Draco、OpenCTM、Open3DGC 等编码器压缩；顶点属性则可以使用固定比率压缩，使每个顶点独立可解码，从而允许在 GPU 顶点着色器中解压。索引也可以选择更小的整数格式：顶点数量不超过 65536 时通常可以使用 16 位索引，而不是 32 位索引；更小的网格还可能使用 8 位索引，但要考虑对齐和 API 开销。

标量属性可以使用量化：将范围 `[min, max]` 映射到整数，再在着色器中通过 scale 和 offset 恢复。颜色、温度、权重等数据有时不需要完整浮点精度，可以改为半精度、短整数或纹理索引。

法线、切线和副切线如果构成正交基，就不必全部存储：知道其中两个即可通过叉乘恢复第三个，并额外保存手性符号。旋转还可以用四元数和手性位表示，利用四元数单位长度约束省略最大分量，以更少 bit 恢复完整旋转。

坐标精度同样重要。大型世界中，远处的世界坐标会消耗大量浮点精度，使近处小物体抖动、顶点断裂或阴影贴图跳变。常见解决方案包括局部坐标、相机相对坐标、原点重定位、分区坐标和不同层级使用不同精度。不要只看文件格式是否使用 float，还要考虑整个变换管线中的坐标范围。

### 9. 本章要点

高效网格不是单一的“减面”。可靠流程通常是：先修复输入数据和三角化问题，再建立共享顶点、拓扑、朝向、法线和切线；之后根据 GPU 缓存重新排序，按视觉重要性生成 LOD，并对顶点属性和索引进行适当压缩。最终应该从屏幕误差、带宽、缓存、加载和渲染成本整体评估，而不是只比较三角形数量。

## 讨论与补充

### 网格优化的方向

网格优化需要同时关注：移除重复点、边和面，优化顶点数据，优化顶点索引顺序，优化网格拓扑，LOD 减面，以及把高模细节烘焙到法线或其他纹理中。

### 顶点缓存与索引顺序

GPU 会缓存已经处理过的顶点。如果索引顺序很差，同一个顶点会反复读取并重新执行顶点处理；如果顺序合理，后续三角形可以复用缓存结果。模型拆分、硬边、UV 接缝和随机化顶点顺序都可能降低命中率。

### 简化与 LOD

LOD 不只是减少三角形数量，还需要保护轮廓、材质边界、法线变化、纹理接缝和重要形状。小三角形过多时，LOD 也能减少顶点和光栅化压力，但应根据屏幕误差而不是固定面数选择等级。
