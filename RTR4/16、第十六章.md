# 多边形技术

## 网格优化的目标

网格优化不是单纯地减少三角形，而是在视觉质量、渲染速度、内存占用和数据正确性之间取得平衡。

需要重点关注：

- 三角形的面积和形状，尽量避免过于细长或退化的三角形；
- 重复顶点、孤立顶点和空的点面；
- 顶点格式，是否真的需要位置、法线、切线、UV、颜色等全部数据；
- 网格是否存在裂缝、错误朝向或非流形结构；
- LOD 的减面程度是否仍能保持轮廓、材质边界和重要细节；
- 顶点和索引的排列是否有利于 GPU 顶点缓存。

## 顶点缓冲与索引缓冲

直接用三角形列表时，同一个顶点可能被多个三角形重复保存。索引网格将数据拆成两部分：

```text
Vertex Buffer
    顶点位置、法线、UV、切线、颜色等

Index Buffer
    每个三角形引用哪些顶点
```

这样多个三角形可以共享一个顶点，减少存储、内存带宽以及顶点着色器中的重复变换。

但要注意：GPU 共享的是“完整顶点记录”。如果两个三角形共享位置，却使用不同的 UV 或法线，那么它们在顶点缓冲中通常仍需要拆成两个顶点。这也是模型出现硬边、UV 接缝时顶点数量增加的原因。

## 顶点缓存顺序

GPU 会缓存已经处理过的顶点。如果索引顺序合理，后续三角形可以复用缓存中的变换结果；如果顺序很差，同一顶点会反复从内存读取并重新执行顶点处理。

因此，网格离线优化通常还会重新排列三角形和顶点顺序，让索引访问尽量符合顶点缓存的工作方式。这个优化不一定减少三角形数量，却可能减少顶点着色器实际执行次数。

## 网格简化与 LOD

网格简化是在尽量保持外观的前提下删除不重要的几何细节。常见的边坍缩操作会将一条边的两个顶点合并，从而删除相关三角形。

LOD 可以是：

- 静态 LOD：提前生成多个离散模型；
- 动态简化：运行时连续地调整三角形数量；
- 视图相关简化：根据相机距离、屏幕占用或局部细节需求决定不同区域的精度。

简化时不能只看三角形数量，还要保护轮廓、折痕、纹理边界、法线变化和物体之间的重要接触关系。

## 压缩

网格压缩可以减少磁盘文件、显存和传输带宽，但压缩和解压也需要时间。只有当节省的 I/O、带宽和缓存成本大于解压成本时，压缩才会带来实际收益。

因此，本章的主线可以概括为：

> 先保证网格拓扑和顶点数据正确，再通过顶点共享、缓存排序、LOD 和压缩，让同一份视觉信息以更低的成本进入 GPU。
