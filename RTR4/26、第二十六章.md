# 实时光线追踪

## 1. 光栅化与光线追踪

- 光栅化：从三角形出发，判断它覆盖哪些屏幕像素，然后对这些像素进行着色。
- 光线追踪：从像素或场景中的某个位置发射射线，判断射线是否与场景中的几何体相交，再根据交点继续计算光照、阴影、反射或折射。

光栅化擅长高效地生成第一层可见表面；光线追踪擅长处理光线传播相关的问题，例如：

- 阴影光线是否被遮挡；
- 反射方向上是否存在其他物体；
- 折射光线穿过物体后到达什么位置；
- 两点之间是否可见；
- 光线是否进入了参与介质或物体内部。

实际项目通常不是二选一，而是使用混合渲染：光栅化负责主要画面，光线追踪负责反射、阴影、环境光遮蔽、全局光照等局部效果。

## 2. 经典光线追踪与现代实时光追

经典 Whitted 光线追踪的基本流程是：

```text
相机发射光线
    ↓
找到最近交点
    ↓
计算直接光照
    ↓
发射阴影光线
    ↓
发射反射/折射光线
    ↓
递归继续追踪
```

Whitted 是一种经典的递归光线追踪算法，重点是通过反射、折射和阴影光线得到结果。它并不等于现代完整的路径追踪，也不等于所有实时光线追踪方案。

现代实时光追通常会受到以下限制：

- 每个像素只能发射很少的光线；
- 不能递归很多次；
- 需要加速结构快速查找相交物体；
- 光线结果通常存在噪声；
- 需要时间累积、空间滤波或神经网络进行降噪。

因此，“支持光追”并不意味着整个场景都用路径追踪重新渲染。常见做法是光栅化生成 G-Buffer 或第一层可见表面，再从这些表面发射少量光线，最后将光追结果与光栅化结果合成。

## 3. 加速结构

如果让每条射线都与场景中的每个三角形求交，复杂度会非常高。因此需要使用 BVH 等空间加速结构。

BVH 的基本思想是：

```text
场景包围盒
    ↓
更小的包围盒
    ↓
更小的包围盒
    ↓
最终三角形
```

射线先与包围盒求交。如果连包围盒都没有命中，就可以跳过其中的全部几何体；只有命中包围盒时，才继续访问子节点，最终与三角形求交。

通常需要区分两类结构：

- BLAS：描述单个网格或几何体内部的三角形结构；
- TLAS：描述场景中各个实例的位置、旋转、缩放和对应的 BLAS。

静态场景的加速结构可以预先构建并长期复用。动态物体则需要更新或重建，这也是动态物体光追成本较高的原因之一。

## 4. Lumen 与 Whitted 的区别

Lumen 不是 Whitted 光线追踪的简单改名，也不是单纯的“开启光追”。它是一个实时全局光照和反射系统，会根据硬件和场景条件综合使用：

- 屏幕空间追踪；
- 软件光线追踪，例如基于 SDF 或卡片表示的追踪；
- 硬件光线追踪；
- Surface Cache；
- 时间累积和降噪。

Whitted 描述的是一种经典光线递归算法；Lumen 描述的是一整套面向实时 GI、反射和可扩展性的渲染系统。二者不是同一层级的概念。

## 5. 为什么实时光追需要降噪

如果每个像素只发射一条或几条光线，结果会有明显噪声。实时光追因此通常采用：

- 时间累积：复用前几帧的样本；
- 空间滤波：参考附近像素进行平滑；
- 双边滤波：同时考虑空间距离、深度和法线，减少跨物体泄漏；
- 方差估计：噪声越大的区域使用更大的滤波范围；
- 运动矢量和重投影：把前一帧结果映射到当前帧；
- 神经网络降噪：从大量训练数据中学习噪声样本到稳定结果的映射。

降噪不是简单的全屏模糊。它必须尽量保持：

- 几何边缘；
- 接触阴影；
- 反射中的细节；
- 运动物体的时间稳定性。

如果前一帧被遮挡的表面突然出现，就会发生 disocclusion。这时历史数据不再可靠，需要减少或清除对应区域的时间累积，否则会产生拖影和错误的光照。

## 6. 光线追踪中的纹理过滤

光栅化天然以 2×2 像素 quad 为单位，可以通过 DDX、DDY 估计纹理覆盖范围并选择合适的 Mipmap。

光线追踪中的光线可能彼此独立，不能直接假设它们天然组成规则的 2×2 像素组。因此需要额外记录或估计光线覆盖范围，例如：

- 光线微分；
- 光线锥；
- 根据命中距离、法线、曲率等信息估计纹理足迹。

否则反射中的纹理可能出现严重闪烁、锯齿或过度锐利的问题。

## 7. DLSS 与实时光追

DLSS 不是单纯的硬件开关，而是 NVIDIA 提供的软件算法和 SDK，结合 RTX 显卡中的专用硬件执行。它可以与 Lumen、硬件光追和路径追踪配合，但不负责替代光照系统。

### 7.1 Super Resolution：超分辨率

传统流程：

```text
4K 场景 → 4K 渲染 → 4K 输出
```

DLSS 超分流程：

```text
较低分辨率场景 → DLSS 神经网络重建 → 4K 输出
```

输入通常包括当前画面、历史画面、运动矢量和深度等信息。由于实际渲染的像素更少，它主要降低像素着色、部分后处理和部分屏幕空间光追计算的成本。

但 DLSS 不会自动减少所有工作：CPU 逻辑、物理、Draw Call、场景管理以及部分几何处理仍然存在。因此它对 GPU 像素瓶颈最有效，对 CPU 瓶颈帮助有限。

DLAA 可以看作不降低内部渲染分辨率的 DLSS 抗锯齿模式，主要用于画质，而不是性能提升。

### 7.2 Frame Generation：帧生成

帧生成会根据前后真实帧、运动矢量、深度和光流信息，推断两张真实帧之间的画面：

```text
真实帧 A → AI 生成帧 → 真实帧 B
```

生成帧不是新执行了一次完整的游戏模拟，因此不会重新计算：

- 物理；
- 碰撞；
- AI；
- 动画逻辑；
- 游戏输入。

所以需要区分：

- 真实渲染帧率：游戏真正计算了多少帧；
- 显示帧率：屏幕最终显示了多少帧。

帧生成可以提高显示帧率和运动流畅度，但基础真实帧率过低时，操作响应仍然较差，并且更容易出现运动、UI、粒子和遮挡变化方面的伪影。它通常适合建立在一个已经足够高的基础帧率上，而不是用来挽救极低帧率。

### 7.3 Ray Reconstruction：光追重建

实时光追往往只有很少的样本，需要降噪。Ray Reconstruction 使用神经网络辅助或替代传统手工降噪器，从有限光追样本中重建更稳定的结果。

它主要改善：

- 光追反射；
- 光追阴影；
- 全局光照；
- 路径追踪中的噪声和闪烁。

它与超分辨率、帧生成是不同功能：超分重建分辨率，帧生成重建时间上的中间帧，Ray Reconstruction 重建光追采样结果。

### 7.4 Reflex：延迟优化

Reflex 主要调整 CPU 和 GPU 的提交、执行和排队关系，尽量减少输入到最终显示之间的等待。

它不能直接提高画质，也不能替代超分。帧生成提高的是显示帧率，而 Reflex 主要用于控制由排队和帧生成可能带来的延迟。

## 8. Tensor Core、RT Core 与 CUDA

可以这样区分 NVIDIA GPU 中的几类资源：

- CUDA Core / Shader Core：执行普通顶点、像素和计算着色器；
- Tensor Core：执行适合 AI 的矩阵运算，DLSS 神经网络会使用它；
- RT Core：加速 BVH 遍历以及射线与包围盒、三角形的求交；
- 光流相关硬件：分析连续画面中的运动信息，可服务于帧生成等功能；
- 显存和缓存：保存纹理、网格、加速结构及中间结果。

CUDA 则是 NVIDIA 的通用 GPU 计算平台，不是某一个硬件单元。它包含编程模型、编译器、运行时和各种计算库。

```text
HLSL / GLSL + DirectX / Vulkan
    → 普通图形渲染路径

CUDA C++ + CUDA Runtime
    → NVIDIA 通用计算路径
```

游戏普通渲染通常使用 HLSL、GLSL、DirectX、Vulkan 或 Compute Shader，而不是直接用 CUDA 绘制整个画面。CUDA 更常用于 AI 推理、离线烘焙、视频处理、工具链和通用 GPU 模拟。

## 9. 本章的核心认识

- 光栅化和光线追踪是两种不同的可见性求解方式，现代渲染器通常混合使用。
- Whitted 是经典递归光追算法，Lumen 是面向实时 GI 和反射的完整系统。
- BVH 通过层次包围盒减少无意义的射线-三角形求交。
- 实时光追的核心难点不只是“如何发射射线”，还包括加速结构更新、样本不足、降噪、时间稳定性和纹理过滤。
- DLSS 超分降低真实渲染像素，帧生成增加显示帧，Ray Reconstruction 改善光追重建，Reflex 优化延迟。
- CUDA 是 NVIDIA 的通用 GPU 编程平台，不等于 DLSS，也不等于 CUDA Core。
