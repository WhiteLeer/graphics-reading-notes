# 着色基础

## 核心理解

### 1. 预乘 Alpha

预乘 Alpha 不是把透明物体变成 Opaque，而是改变颜色的存储方式和对应的混合公式。

普通 Alpha：

```text
RGB = 原始颜色
A   = Alpha
```

预乘 Alpha：

```text
RGB' = RGB × Alpha
A    = Alpha
```

普通 Alpha 的混合公式通常是：

```text
Result = SrcRGB × SrcAlpha
       + DstRGB × (1 - SrcAlpha)
```

预乘 Alpha 的混合公式通常是：

```text
Result = SrcRGB'
       + DstRGB × (1 - SrcAlpha)
```

因此常见的预乘 Alpha 混合状态为：

```text
SrcBlend = One
DstBlend = OneMinusSrcAlpha
```

如果存储方式和混合公式匹配，两种方式在理想情况下可以得到相同的最终颜色。预乘 Alpha 不会自动改变：

- 深度测试；
- 深度写入；
- 透明物体排序；
- 是否进入透明渲染队列。

### 2. 为什么预乘 Alpha 更适合透明边缘

预乘 Alpha 不只是为了弥补有限精度造成的细节误差，它会改变纹理过滤、插值和合成时的计算行为。

透明贴图的边缘可能同时包含半透明像素和完全透明像素。如果颜色和 Alpha 分开插值，透明区域中的黑色 RGB 可能被带到边缘，产生黑边。

预乘 Alpha 后，颜色已经包含了透明度：

```text
Alpha = 0 → RGB' 通常也接近 0
```

所以它通常更适合：

- 透明纹理过滤；
- Mipmap；
- 抗锯齿边缘；
- 粒子和 UI；
- 多次图像合成。

### 3. 为什么不全部使用预乘 Alpha

预乘 Alpha 也有代价：

- 低 Alpha 区域的原始颜色会被压低，有限位深下可用精度减少；
- 当 Alpha 为 0 时，原始 RGB 基本无法恢复；
- 美术编辑和资源制作通常希望颜色与透明度独立保存；
- 有些 Alpha 实际上表示遮罩、覆盖率或其他数据，不应该直接乘到 RGB 上；
- 如果预乘纹理仍使用普通 Alpha 的混合公式，就会被重复乘 Alpha，造成颜色过暗。

因此可以粗略理解为：

```text
资源制作阶段：普通 Alpha 更方便独立编辑颜色和透明度
过滤、抗锯齿和合成阶段：预乘 Alpha 通常更稳定
```

关键不是“哪一种永远更好”，而是整条管线必须统一约定：纹理表示方式、过滤方式和 Blend State 必须匹配。

### 4. sRGB 与 Gamma

sRGB 是一种非线性颜色编码方式，可以近似表示为：

```text
sRGB   ≈ Linear^(1 / 2.2)
Linear ≈ sRGB^2.2
```

但严格来说，sRGB 是分段函数，并不完全等于简单的 Gamma 2.2。

它的目的不是改变颜色含义，而是让有限的 8-bit 数值分布更符合人眼对亮度的感知，从而减少暗部浪费和色带。

### 5. 线性空间与颜色计算

光照、颜色相加、Alpha 混合、抗锯齿等计算通常应该在线性空间中执行：

```text
sRGB 纹理
    ↓ 解码
Linear 颜色
    ↓ 光照、混合、抗锯齿和后处理
Linear 结果
    ↓ 编码
sRGB 显示颜色
```

直接对 sRGB 数值进行光照或混合，可能导致：

- 颜色过暗；
- 光照叠加不正确；
- 透明边缘发黑；
- 抗锯齿边缘偏暗。

### 6. 哪些纹理使用 sRGB

通常只有表示颜色的纹理才使用 sRGB 解码：

```text
Base Color / Albedo：通常使用 sRGB
```

以下纹理通常是直接参与计算的数据，应保持线性：

```text
Normal Map
Roughness
Metallic
AO
Mask
Height
Depth
ID
Alpha
```

它们不是需要符合人眼亮度感知的颜色，不能按照颜色纹理的方式进行 Gamma/sRGB 转换。

## 本章总结

```text
预乘 Alpha：改变颜色表示和混合方式，不等于 Opaque
sRGB：非线性颜色编码，近似但不完全等于 Gamma 2.2
渲染计算：通常在线性空间进行，最后编码为 sRGB
颜色纹理：通常使用 sRGB
数据纹理：通常保持线性
```
